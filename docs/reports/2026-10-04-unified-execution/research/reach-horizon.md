Работа здесь — исследование, предложения контрактов и разбор условий активации; она не закрывает S4–S6, V1-M1–M7 или CO. Текущий приоритет P-08 сохраняется, затем готовые P-06/P-07 и остальные строки по собственным зависимостям.

## Что проверено и что требует решения

Направление Reach соответствует vision только когда соединяет наблюдение с владельцем, подтверждённым действием и проверенным результатом. Anti-vision прямо отвергает generic integration dashboard, копирующий состояние провайдера без закрытия Project operating loop. V1 помогает вернуться к проекту и принять решение; отдельный новый cockpit или конкурирующая реализация CEO этому не соответствует. Основание: [vision, anti-vision и alignment test](../../../ux/vision.md#6-anti-vision), [slice ladder](../../../architecture/iterations.md#the-slice-ladder), [предложения заканчиваются у PM](../../../architecture/work-producing-agents.md#1-co-035-answered-neither-goals-nor-nodes--observations-and-a-proposal).

Сохранённая документация намеренно оставляет S4–S6 на глубине границ до их intake: выбор crash source CO-086, каналов CO-085 и полей коллектора ещё не является решением. Настоящий результат исследования — безопасный первый вертикальный пакет и явные решения, которые нельзя выдумать. Аналогично, 147 CO ниже имеют по одному следующему действию/условию, но широкие будущие возможности не объявлены полностью спроектированными.

## Исследование по блокам

**S4: наблюдение, квоты и источники.** Cloudflare ограничивает совокупное использование пользователя/account token; чтение dashboard тоже расходует общий allowance. Для коллектора нужны общие квоты и backoff, а не лимит каждого процесса отдельно. Официально указано 1200 запросов за пять минут, отдельные endpoint limits и заголовки Retry-After/Ratelimit. Это закрывает вопрос исследования CO-014, но не его канонический статус. [Cloudflare](https://developers.cloudflare.com/fundamentals/api/reference/limits/).

В GA4 **14000 — project × property × hour**, а allowance **property × hour — 40000** для standard Core. В существующем `external-contracts.md` фраза «per-property…14000» требует уточнения при следующем касании; это не разрешение менять источник в исследовательской ветке. Использовать фактический `returnPropertyQuota` и различать quota categories, concurrency и server-error allowances. GSC имеет отдельную load quota и методные ограничения; массовое извлечение данных не равно полной выдаче всех строк. [GA4 quotas](https://developers.google.com/analytics/devguides/reporting/data/v1/quotas), [GSC limits](https://developers.google.com/webmaster-tools/limits?hl=en).

HTTP-проба создаёт новый сетевой effect/read boundary. Контракт учитывает resolved IP, redirect и DNS rebind, размер/таймаут ответа и allowlist конкретного сервиса. Обнаруженная недоступность source сохраняет last-known observation с возрастом; она не означает «исправлено». Google OAuth для native client проектировать с external browser, PKCE, literal loopback address и ограниченной жизнью callback listener. Это стандарт для нового Google connector, а не разрешение переделать existing ADR-0115 hub. [OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html), [RFC8252](https://www.rfc-editor.org/info/rfc8252/).

**S5: публикация.** Конкретные bytes, media, account и destination закрепляются в draft revision и одном grant. Ретрай не гарантирует однократность: после таймаута возможен выполненный внешней системой запрос без локального receipt. Maintainer Temporal прямо указывает необходимость upstream idempotency либо API проверки результата. Это влияет и на P-07, и на дальнейшие bounded-effect адаптеры. [Разбор maintainer](https://community.temporal.io/t/activity-external-call-idempotency/7543).

Postiz остаётся невыбранным в S5: официальный license — AGPLv3, а последние developer release notes отдельно работают с предотвращением duplicate posts. Лицензия и история исправления — основания проверить выбранные version/API/retry semantics, а не утверждать, что отдельный процесс автоматически решает все source obligations. CO-030 требует отдельного решения о границе конкретного использования. [License](https://github.com/gitroomhq/postiz-app/blob/main/LICENSE), [developer releases](https://github.com/gitroomhq/postiz-app/releases).

**S6: feedback и custdev.** Начать с одного разрешённого канала, immutable inbound id и source thread. Драфт ответа и отправка различаются; источник support finding остаётся владельцем его разрешения. Для данных клиентов заранее определить purpose, минимизацию, retention, deletion propagation и кто может видеть цитату. Guideline EDPB подтверждает, что privacy by default включает систематическую процедуру удаления; решения о применимости/основании не приняты этим исследованием. [EDPB](https://www.edpb.europa.eu/sites/default/files/consultation/edpb_guidelines_201904_dataprotection_by_design_and_by_default.pdf).

**V1: понятный контекст и честные состояния.** В исходном коде `shared/inbox.ts` намеренно исключает `readState` из NeedsYouItem; `BoardPanel.tsx` уже экспортирует AnswerForm и submitAnswer. Пакеты должны переиспользовать их и текущие launch/adoption owners. Чтение сообщения не снимает обязательство, commit ответа не доказывает доставку/возобновление, preview pack не является переданным historical pack. WCAG требует reflow, keyboard/focus и программные status сообщения; статический DOM не доказывает geometry/native screen-reader acceptance. [WCAG2.2](https://www.w3.org/TR/wcag/), [inbox.ts](../../../../apps/desktop/src/shared/inbox.ts), [BoardPanel.tsx](../../../../apps/desktop/src/renderer/src/BoardPanel.tsx).

Датированный V1 execution plan содержит старый paperclip recipe. CO-169 уже записывает переход токенов 2026-09-28; оставшееся — About/i18n hierarchy. Использовать текущие ADR-0070/--pc-* aliases и latest launch consumers, а не выполнять старый токен-переезд заново. Не повышать Product из unobserved без golden-path/time-to-decision receipt. [V1 plan](../../../ux/plans/2026-09-12-v1-execution-plan.md), [ADR-0070](../../../adr/0070-passioncode-toolkit-and-product-design-system.md).

**Горизонт runner/security.** Историческое CO-025 утверждает обход canUseTool для AskUserQuestion. Current official SDK demo использует callback, но первичные developer issues сообщают об empty answers на 0.2.63 и watchdog/control-channel failure на 0.3.233/0.3.260. Это build-specific reproduction leads; здесь они не воспроизведены в Fabric. Обязательны паспорт точного build и отрицательный контроль: timeout/empty answer никогда не превращается в согласие. [Официальный demo](https://github.com/anthropics/claude-agent-sdk-demos/blob/main/ask-user-question-previews/README.md), [issue30983](https://github.com/anthropics/claude-code/issues/30983), [issue470](https://github.com/anthropics/claude-agent-sdk-typescript/issues/470).

Electron официально требует validate senderFrame; isolated renderer не заменяет authorization main-process API. Supabase отдельно предупреждает о user-editable user_metadata и устаревших JWT claims после удаления membership. Поэтому CO-071/091/130/131 требуют allow-path и revoked-role негативных проверок, а service-role тест не доказывает работу authenticated RLS. [Electron security](https://github.com/electron/electron/blob/main/docs/tutorial/security.md), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

**Горизонт durable execution.** Temporal и Restate — кандидаты за стабильным портом, не решение внедрить второй runtime сейчас. Workflow replay требует детерминизма; LLM/API results и approvals закрепляются в истории/Activities. Schedule overlap и catchup-window — отдельные политики; нельзя взять default и получить правильное поведение публикации. Restate author тоже различает сохранённый результат и повторяемые external attempts. [Temporal determinism](https://docs.temporal.io/workflow-definition), [overlap/catchup](https://github.com/temporalio/documentation/blob/main/docs/encyclopedia/workflow/schedule.mdx), [Restate author](https://restate.dev/blog/why-we-built-restate).

**Горизонт policy/provenance.** CloudEvents даёт interoperable envelope с source+id, а не готовые tenant authorization/deduplication/effect receipts. Cedar default-deny и forbid-overrides допускают skip-on-error: diagnostics может содержать ошибку при результате Allow. CO-079 уже **resolved**: Accepted ADR-0023 закрепляет typed embedded Cedar-compatible port и преобразование relevant diagnostics в indeterminate, который не разрешает новые effects; ADR-0028 закрепляет minimum composition и schema floor. Здесь не предлагается заново выбрать engine. Открытый **CO-059** держит полное context mapping и дальнейшую интеграцию; для неё нужно доказать сохранение уже принятого stricter wrapper rule. [CloudEvents](https://github.com/cloudevents/spec/blob/main/cloudevents/spec.md), [Cedar algorithm](https://docs.cedarpolicy.com/auth/authorization.html), [Accepted ADR-0023](../../../adr/0023-policy-is-an-embedded-decision-port-that-never-grants-on-uncertainty.md), [ADR-0028](../../../adr/0028-one-effects-algebra-and-the-floor-lives-in-the-schema.md), [policy.ts](../../../../apps/desktop/src/main/policy.ts).

Ни исследование рынка/форумов, ни «эксперт сказал» не заменяют путь источник→проверка на exact installed build→receipt. Первичные треды используются как воспроизводимые failure hypotheses; здесь нет утверждения consensus.

## Сообщённые зависимости текущих работ

Родителю сразу отправлены два сигнала: build-specific question/approval semantics и Cedar skip-on-error. При convergence второй сигнал уточнён: CO-079 закрыт Accepted ADR-0023, relevant diagnostics→indeterminate уже принято; исследование проверяет сохранение этого правила при открытом CO-059 full-context mapping и не переоткрывает выбор engine. Для P-06/P-07 сохраняются дополнительные контракты: binding/goal foreign keys, append-door project authorization/RLS, TaskRun/generation-bound acknowledgment, один source finding id/revision, существующий ADR-0115 hub и правило **error/offline/stale/partial ≠ fixed**. Факт текущего schema head77 пришёл от peer и отдельно не проверялся этим исследованием: перед любой миграцией её исполнитель обязан измерить head и event catalogue и остановиться на несовпадении.

Для P-08 отдельно связаны CO-124 (upgrade path ≠ reset), CO-114/115 (self-contained ≠ reproducible/native/platform acceptance) и CO-173/175 (reread claim before repin). Сохранённые CO не превращаются в дополнительные release gates без проверки их актуального trigger/owner.
