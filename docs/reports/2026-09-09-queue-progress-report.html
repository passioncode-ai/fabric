3 · Готовые задачи — все 44

F0 — граница эстейта

  • S02.store — скоупленный стор: каждый запрос main-процесса несёт предикат эстейта (было 87 запросов без него).
  • S02.roots — грант папки принадлежит окну, которое его выдало.
  • S02.acl — у anon отозваны лишние SELECT-гранты.
  • S02 — композитная идентичность: 9 составных FK (estate_id, id); забор check-references.
  • S03.boundary — пол полномочий: четыре ранее проходивших атаки закрыты и проверяются пробами.
  • S03.effects — разрешение ≠ исполнение: у эффекта жизненный цикл, outcome_unknown — третий ответ (ADR-0050).
  • S03 — безопасный сток на входе полномочий; release резервации требует доказательства.
  • S01 — хуки над ранними return; дверь борта.

F1 — чтение и сохранность

  • M198 — ревизия = seq события, которое её установило; перестройка проекций идемпотентна (P24).
  • S14 — ReadEnvelope: чтение с расписками источников, partial не превращается в уверенный ноль.
  • S12 — зеркало объявляет, чего не держит; импорт — одна транзакция с замком эстейта.
  • M109 — каждый из 81 IPC-хендлера сверяется с ответом, который объявляет его канал.

F2 — исполнение

  • S04 — допуск задачи — отдельный акт под замком; отказ до допуска не рождает прогона.
  • S06 — блокирующее множество: неотвеченный вопрос не пускает задачу в работу.
  • S05 — трасса каждого вызова инструмента на транспорте: девять выходов, один вход (beginAttempt).
  • S15 — цикл оставляет расписку cycle.ran@1; «приложение было закрыто» отличимо от «нечего делать».
  • M103 — байты записаны ≠ инструкция принята: таблица deliveries, ack по дайджесту.
  • S10 — словарь ADR-0045: WorkflowRun / TaskRun / Iteration вместо одного «Run».

F3 — наблюдаемость агентов

  • M177 — протокол агента выводится из одного источника, не дублируется прозой.
  • M178 — heartbeat — позитивный сигнал; монотонный beat_seq; тишина перестала быть одним состоянием.
  • M179 — runtime-наблюдатель: одна находка на переход состояния, не на тик.
  • M180 — «failed» — не одно состояние: 8 видов отказа ADR-0040, certainty observed/suspected.
  • M181 — capability: декларация — supported_unverified; повышает только наблюдение.
  • M155 — обязательства протокола: REFUSED / OBSERVED / ADVICE, каждое REFUSED называет точку принуждения.
  • M188 — task_runs: run_id впервые несёт значение (0 из 2260 событий раньше); окончательность — триггером.
  • M149 — вопрос агента оператору: приоритет не задаётся клиентом, очередь не прыгается.
  • M151 — одна доска: authored-вопросы и derived-обязательства в одном ранге, без «прочитано».
  • M152.commit — ответ оператора коммитится CAS-ом по ревизии вопроса.
  • M152.continue — ответ доезжает до работы, которая ждала; recommitAnswer: false всегда.
  • M152 — агрегат вопроса не сжимается в один enum; Banner не расширялся ради одного вызова.
  • M168 — один checker перед каждой записью proposal; события — только из commands/.

F4 — первые представления

  • M191 — предпросмотр context-pack без запуска агента; тот же компилятор, что у запуска.
  • M189 — liveness виден человеку: заявление агента и наблюдение Fabric — разные строки.
  • M190 — обрезка списка говорит о себе; у цели — знаменатель, а не счётчик открытых.
  • M173 — DAG решений: обратный индекс — списки, BFS с visited; вся линия предков сохранена.
  • M185 — Inbox-модель: у обязательства нет поля «прочитано» по типу; лента и Board — две полосы.
  • M186 — «запущено» ≠ «получилось»: конфигурация / наблюдение / исход — три независимые колонки.
  • S13 — один словарь ref'ов (entityRef.ts): доска двоила префиксы (review:review:t1), lease открывала несуществующую задачу; маршрут — одно значение AppRoute, забор check-route.

F5 — ретро и менеджер (частично)

  • M182 — закрытая категория инсайта (project/agents/harness/fabric/process); исход коррекции пишется там, где случается отказ — инструмент больше не возвращает запрос как результат; случай (occurrence) ≠ упоминание; проба нашла три моих же дефекта (неидемпотентная ветка, неперестраиваемый эстейт, уроненный арм retrieved).
  • M154 — читатель ретро: находки и ловушки впервые читаются по роду; «никто не проверял источник» ≠ «источник удалён»; счётчик повторов unknown, а не «однажды»; курсор привязан к вопросу.
  • M176 — trajectory-eval до настройки manager-профиля: жёсткое нарушение не компенсируется; неполный захват — inconclusive; ожидаемые unknown совпадают точно; вердикт — не разрешение; корпус из 9 реальных дефектов этого репозитория, забор check-eval резолвит каждое имя против реестра.

F6 — поставка и команда

  • S07 — сборка опознаёт себя из артефакта (BuildManifest@1), никогда из git на рантайме; грязная сборка не равна самой себе; окно схемы — отказ (read_only / incompatible / unknown раздельно); schema_version() из базы; забор check-release.
  • S08 — один полный цикл против живого HTTP-сервиса с посаженным дефектом: исполнитель не единственный проверяющий; объём судится до результата; телеметрия исключается, не обнуляется; негативный контроль на самого судью.
  • S09 — эстейт сохраняет владельца: пол — триггер (держится против прямого SQL от service-role), ревизия membership, CAS-команда, идемпотентная по command_id; забор check-actor — ни один хендлер не берёт личность у вызывающего.

5 · Проблемы

5.1 · Найдено при подготовке отчёта: дефект скрипта очереди

Сессионный счётчик готовности ключевал строки по отображаемому имени (m152.commit), а зависимости ссылаются на якорь (m152-commit) — каждый узел с точкой в имени резолвился как «не отгружен», и его иждивенцы читались заблокированными.

Следствие: M153, M158, M183.local были готовы, но значились blocked — и прогон ушёл в F6/F7 раньше, чем добрал F5. Объявленный порядок пакетов нарушен: S07–S09 отгружены раньше хвоста F5. Сами узлы корректны; вред — порядок и простой цепочки M157 → M184 → M166 → … → M175.

Состояние: скрипт починен, но живёт в скратчпаде сессии и умрёт с ней. Правило «дотягивается ли утверждение до цели» не было применено к инструменту самой очереди. Кандидаты на действие: перенести счётчик в scripts/ репозитория как гейт и записать находку в ретро следующим прогоном (вопросы №16–17 в §7).

5.2 · Системные

  • claude-mem не пишет память — квота OpenRouter исчерпана (403, monthly limit); авто-захвата знаний сессии нет. Смягчено: ретро, реестры и карта полны и в git.
  • Продукт работает на service-role — все RLS-политики никогда не проходились приложением; полы поэтому — триггеры. Аутентификация — крупнейший незакрытый слой.
  • 61 строка верификации «never watched failing» (7,2%) — хвост стабилен, не растёт и не убывает.
  • 79 открытых carry-over строк — отдельный бэклог долгов, не пересекается с очередью.
  • Сборка невоспроизводима — toolchainDigest: null, честно объявлено в строке сборки, но не решено.
  • Русская локаль — 146/557 ключей; храповик держит долг от роста, покрытие низкое.
  • Manager/CEO-слой не тронут (M166–M175, M194) — самая большая цельная область впереди.

8 · Дисциплина, которая работала

  • Постоянные инструкции ретро R-001…R-005 применялись каждый прогон; каждый прогон штампован.
  • Чек-лист шага 0 вырос до 12 правил; правило «кто это показывает» нашло 6 корректных производных без единого читателя за одну сессию — по цене одного grep.
  • Каждая итерация: перемер карточки против HEAD → TDD → подсадки наблюдаются падающими → ci full → запись в живую карту → пересчёт реестров → коммит и пуш.
  • Новые правила, оплаченные дефектами этой сессии: фикстуру должен уметь выдать производитель; заменяя проектор — перенести каждый арм и спросить, переживёт ли он собственный реплей; утверждать то, что оператор увидит; структурный гейт читает код, а не комментарии; негативный контроль ставится и на судью; упавшая проба сообщает меньше, чем провалившаяся.
