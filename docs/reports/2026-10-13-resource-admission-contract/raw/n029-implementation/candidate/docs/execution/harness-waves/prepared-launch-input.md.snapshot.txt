# Once-prepared managed launch input

## Contract

N029 adds a concrete content producer and consumers to the existing managed launch. It does not enable resource enforcement in `index.ts`, configure a pool, activate pending migrations, start a provider or establish R1 ownership. The first supported required path is a newly admitted ordinary managed task. Required pre-admitted receipts, chain triggers and instruction overrides refuse before new admission. The shared `createAdmitExisting` door also refuses chain or missing/foreign prepared input before calling the resource adapter, covering the chain's separate earlier admission. Ordinary launches without a resource dependency retain their existing path and behavior.

`createPreparedLaunchInputs` reads actual task instruction/brief/option and project folder through the existing ScopedStore and calls the actual `compileContextPack` once. It does not accept caller-provided context text. The configured Estate must match the store's real scope, and the original scope object reference and complete scope fields are compared around reads. Replacing the exposed scope cannot hide changes to the original object captured by ScopedStore. Task/target projections are read before and after compilation. Missing rows, errors, changes, invalid modes, unsupported custom-agent/nonconnected runner targets or exceeded bounds yield no packet. Connected, ready built-in catalogue runners are the bounded target set; actual installed availability and runtime/mode checks remain at the existing PTY door.

The factory takes explicit receipt count, instruction-byte, compiler-character and timeout bounds. `index.ts` supplies 32 local receipts, 65536 instruction/brief UTF-8 bytes per field, the existing 12000-character compiler budget and a 10000 ms preparation deadline. These are content preparation bounds, not host capacity or permission defaults. Data has already crossed the existing command ingress; the prepared path adds no second trim/redaction to the instruction body. Source transport can return a larger field before the producer rejects it: the byte limit is not a network response allocation cap. The existing compiler's source-page/omission semantics remain unchanged.

An observed result carries a deeply frozen, same-producer packet containing Estate/project/task/session, trigger, target option/folder/requested mode, exact `instructionBody`, its SHA-256, the actual ContextPack and domain-separated `contentDigest`. `executionAuthorized` is false. The content digest binds identity, target, body hash, context hash, compiler revision and required-source selection policy. It is not the complete resource `inputDigest`; no N023 lease observation or N026 selected-input receipt is upgraded to held ownership. Context markdown is sanitized/formatted by its existing compiler. Exact-body identity refers to the separately retained instruction, not to its rendered excerpt inside the context pack.

Producer methods are `prepare(request)`, `owns(packet)`, `current(packet)` and `release(packet)`. Same-instance membership is an internal lifecycle check, not authentication. `current` rereads actual task/target/scope without recompiling context. It does not claim all memory sources remain current. A released/copied/foreign packet is refused. Local release deletes the packet receipt only; it cannot release a durable reservation. These checks provide cooperative currentness, not immunity to an arbitrary writer racing the final SQL call or native spawn.

One producer has one outstanding I/O operation and bounded active receipts. Timeout stops waiting while retaining occupancy until the entire operation settles. Late results create no usable packet or later reads. A pending `current` operation likewise cannot return permission after release/timeout. The actual compiler now starts its four reads through safe Promise thunks and uses the trusted internal `settleStartedReads:true` option in prepared calls to wait with `Promise.allSettled` before rethrowing any rejection. Ordinary compiler callers retain the default fail-fast `Promise.all` behavior, so a rejected source does not trap their existing degraded-context path behind a hung sibling. A failing query cannot release the outer producer slot while a sibling query remains unresolved. This bounds accumulation per producer instance, not across arbitrary independently created producers or native processes. The producer uses the monotonic process clock directly and introduces no injectable synchronous clock callback.

## Existing consumers

`createManagedLaunch` prepares before its admission callback whenever resources are required. Absence of a producer refuses. The same packet is passed to `createAdmitExisting`, the resource adapter's existing prepare callback, native preparation, PTY bundle compilation and dispatch. With a producer installed, the resource adapter checks packet ownership and identity before I/O and binds cached same-session retries to the same packet object. The low-level adapter still supports its prior standalone injected preflight contract without a producer; it cannot pass the shared required managed admission doors that now mandate one. The index remains unconfigured for actual resources.

After admission, the managed coordinator checks the receipt's task/project/session/option/instruction against the captured content and refreshes task/target currentness before begin. A known owned receipt can ask the existing `cancelUnbegun` SQL command to prove cancellation. A local mismatch itself is not proof of release. Final spawn checks run resource currentness, then prepared-input currentness, then the existing SQL validation; an asynchronous resource refresh cannot hide a task change from the later content read. Existing process-start classification, compensation, binding, readiness, permission-mode and delivery guards remain in place.

`PtyManager.open` accepts the optional internal packet, compares its actual project/task/session/runner/mode/folder and forwards it to the same BundleCompiler. The bundle checks producer membership and content integrity before minting. For a supplied packet it uses its exact context markdown and instruction body, never the legacy context callback. Existing `executionPacket` materializes and verifies both named `context` and `instruction` parts; `context.md` receives the same markdown. Required packet/journal failures escape the degraded-context catch and roll back the session credential/directory.

The existing `context.compiled@1` journal emission was extracted in `index.ts`; its metadata still describes the exact compiler output. Preparation alone does not append a launched-session event or mint a credential. Consuming a prepared bundle journals that context before spawn. The ordinary callback preserves its previous compilation and degraded-source behavior. Journal/bundle operations retain their existing lifecycle; the preparation deadline is not a new deadline for all launch operations.

Dispatch receives the packet's exact instruction BODY. The existing continuation transport later adds a run/delivery-derived header and maintains its own digest/claim/begin/write/ack boundary. N029 does not claim the pre-admission digest identifies the complete later wire bytes, and it does not replay an uncertain delivery. The packet is released locally when the managed operation ends; materialized content remains in the existing packet store under its existing lifetime.

New tests exercise actual ScopedStore and context compiler, exact UTF-8 body hashes, real bundle files and content-addressed readback, actual managed factory ordering, required shared-door refusal, separate content/full-input digests, changed receipt/target/task, task mutation during resource refresh, journal rollback, foreign/copied packets, bounded repeated timeout and compiler sibling rejection. The existing required adapter fixture now prepares real packets; former required pre-admitted-chain coverage is replaced by explicit early refusal, while the legacy managed/chain contract remains unchanged.

Original consumer source fails the unchanged selected tests for preparation-before-admission, missing-packet shared-door refusal and foreign-packet bundle refusal. Independent review also reproduced misbound/mutated ScopedStore scope and nested compiler I/O accumulation; both received production regressions. Focused tests use synthetic SQL/spawn boundaries and actual owned local bundle files. They establish no native CLI/provider, actual SQL reservation/compensation or installed resource policy acceptance. The stack-backed context-pack command is NOT_RUN in the small source overlay; its import stopped before any stack action. Context mandatory/privacy checks run offline. Exact command results and hashes belong to the N029 receipt.

## Remaining composition

A trusted resource composition must share this producer with the adapter and managed/bundle consumers, define complete selected inputs and an explicit composite input digest, supply actual ownership/run-fence semantics, complete worker observations and trusted policy/assignment, and promote pending SQL under the owning migration policy. None is fabricated here. Source wiring is available but resource activation in `index.ts` remains absent.

A later chain slice must prepare the resolved substituted brief before its separate admission, persist/bind that same digest in dispatch evidence and recover it after restart; until then required chain refuses early. Custom-agent configuration and complete runner/MCP/system-prompt dependency selection remain separate scope work. This packet covers actual context and task body, not a claim to identify every input that may influence a runner. Existing answer delivery to a running waiting worker remains a continuation, not a new prepared launch or permission to free that worker's resource slot.
