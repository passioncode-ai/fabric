# Часть Fabric в общей сверке S1–S10

**Итог: Fabric участвует в S1, S2, S4 до S6 и S8 до S10. Под каждым пользователем macOS он работает как отдельный локальный хаб и стек. Порт хаба на пользователя уже сделан (CO-505), а всё межмашинное и организационное (relay, токены организации, членство, entitlement, порты стека) открыто до организационного среза 2026-11-21.**

Источник: `main` с незакоммиченной волной CO-521 на 2026-11-06. Строки carry-over взяты из `docs/evidence/specs/2026-08-16-software-fabric-carryover.md`.

## S1. Где живёт каждый агент

**Что делает Fabric.** Под каждым пользователем macOS работает свой экземпляр: своё Electron-приложение, свой хаб на loopback и свой стек Supabase в `userData/stack`. Внутри одного пользователя Fabric один: `app.requestSingleInstanceLock()` (`apps/desktop/src/main/index.ts`). Чужие агенты Fabric видит по дескрипторам в `services/` с полем `placement: local | remote` (`apps/desktop/src/main/agentRegistry.ts`). Так облачный агент можно описать как `remote`.

**Что работает.** Порт хаба считается от uid: 47070 для uid 501, дальше по одному на пользователя (`hub.ts#userHubPort`). Тест `apps/desktop/test/hub-files.test.mjs` «CO-505: the default port is per user…».

**Чего нет.**
- Порты стека одинаковы у всех пользователей: `supabase/config.toml` (api 54321, db 54322, shadow 54320, studio 54323, smtp 54324, pooler 54329), а `bundledStack.ts#materializeStack` копирует файл без изменений. Второй пользователь на Studio стек не поднимет (CO-513, открыто).
- Нет «одной копии синглтона» между машинами. Две машины, восстановленные из одного дампа, работают как одно поместье (CO-515, открыто).
- Дескриптор, перенесённый с другой машины, не читается как «размещён в другом месте» (CO-490, открыто).
- Fabric не пишет собственный дескриптор `fabric-service` (CO-263, открыто).

**Расхождение.** ADR-0178, D8-a: хабы обеих организаций R1 держит один Fabric на Studio, каждый под своим ключом. План Studio (`docs/evidence/specs/2026-11-06-studio-spaces-gaps.md`) и CO-505 говорят другое: отдельный Fabric под каждым пользователем macOS. Новой ADR, которая бы это согласовала, нет.

**Ошибка шире CO-515.** Идентификатор поместья одинаков у каждой установки, а не только после восстановления: `supabase/seed.sql` создаёт `org1 = 00000000-0000-0000-0000-000000000001`, а `activeEstate.ts#DEFAULT_ESTATE` берёт его по умолчанию. Свежие Fabric под личным пользователем, под пользователем организации и на MacBook имеют один и тот же estate id. Строка CO-092 об этом открыта с 2026-08.

**VM участника и облака (Heroku, DigitalOcean)** как место работы Fabric: не участвует.

## S2. Как оператор говорит с агентами

- **Локальная сессия.** Работает: консоли, CEO-чат, `fabric-mcp` каждого кодового агента записывается в проект через хаб (ADR-0134).
- **SSH и Tailscale.** Не участвует. Хаб слушает только `127.0.0.1` и `[::1]` и отказывает чужому `Host` (`apps/desktop/src/main/agentSurface.ts`). Удалённого входа в хаб нет.
- **Доска между пространствами.** Доска (`com.*`) хранится в базе одного Fabric; у каждого пользователя на Studio она своя. Клиента relay в коде нет, CO-453 открыт.
- **Telegram.** В ответе `com.status` транспорт зашит как `telegram: 'off'` (`boardService.ts`); `docs/architecture/telegram-surface.md` имеет статус «design, nothing built».
- **Fabric Dashboards.** Fabric не публикует себя как сервис (CO-263). Чужие дашборды он только читает из реестра.
- **Inbox.** Fabric подключает Fabric Inbox как продукт и вызывает его через хаб (`productConnect.ts`, `hubCall.ts`, ADR-0115).

## S3. Доступ людей

**Что есть.** В схеме есть членство с ролями и дверь `change_membership` (`supabase/migrations/20260909000052_membership_authority.sql`). Но приложение работает от одного локального оператора (`identity.ts`, `LOCAL_OPERATOR_PERSON`); дверь вызывает только `seedRepair.ts`. Потока «пригласить человека» нет.

**Флаг машины.** Есть `machineTrust` со значениями `mine` и `organization` (`appSettings.ts`). На машине организации ответить на запрос доски сразу нельзя (`accessService.ts`), а решения Agent access по пересказанным словам оператора отказываются и принимаются только в окне (`relayedAccess.ts`). Тест `apps/desktop/test/relayed-access.test.mjs` (ADR-0190). Привязку агента отзывают в Settings → Agent access.

**Чего нет.** Членство в организации, роли архитектора и участника, вход по passkey: CO-130 и CO-337 открыты. Участник с доступом только к VM: не участвует.

## S4. Токены и ключи

**Что работает.** Хаб при каждом старте переписывает `hub.json` и дверной токен (0600). Учётные данные привязок хранятся как sha256 (ADR-0115). `fabric-mcp` отправляет учётные данные только хабу, названному в `hub.json`, и только пока жив его pid (`fabricMcp.ts#moved`). Секреты продуктов лежат в хранилище Observatory проекта `fabric`: запись через `vault.py put`, чтение через `use_secret.py run --vault-only`, значение идёт через FIFO (`observatoryVault.ts`). Записей в Keychain Fabric не создаёт; credential Claude Code только читает, чтобы показать квоту.

**Чего нет.** Проверки, что порт хаба слушает процесс того же uid (CO-514, открыто): хаб принимает соединения любого локального аккаунта. Токенов организации, где каждый участник выпускает свои (ADR-0178 п.4): CO-319, CO-337 и CO-422 открыты.

**Пробелы в документации.** Правило одного Mac (VES-TWO-VAULTS) в документах Fabric не встречается. Ранбук переезда относит `tokens/` к файлам, которые «пишет хаб при каждом старте» (`docs/launch/release-mac.md`), но код Fabric этот каталог не пишет. Облачный агент, которого развернул человек, Fabric видит только как дескриптор `remote` и ключей ему не выдаёт.

## S5. Общая инфраструктура проектов

Скилы, репозитории и ключи деплоя: не участвует. CI только свой (`scripts/ci.sh`). Аккаунты Claude: Fabric читает каталог Switchboard (`switchboard --json agents status`, только чтение, тайм-аут 5 с, `agentCatalogRead.ts`), группами не управляет. MCP: `fabric-mcp` каждого кодового агента сам записывается снова после перезапуска Fabric (таблица lifecycle в `AGENTS.md`); Fabric отмечает папку доверенной в состоянии Claude Code (`claudeTrust.ts`).

## S6. Связь пространств и машин

Регистрации в сервисе организаций в коде нет. Relay организации (DEC-0134): CO-453 открыт. Порты и claims: свой claim Fabric не публикует; хаб только отказывается брать порт, который заявил зарегистрированный агент (`hub.ts#checkPortUnclaimed`). DEC-0154 в коде Fabric ещё не учтён (CO-513, CO-514 ждут его тега); порты стека 54320 до 54329 нигде не заявлены. Метки хоста нет.

## S7. Облака и коммерция

Почти не участвует: код не читает ни одного entitlement (CO-516, с PLAT-137); «Запуск в облаке» и «Создать организацию» относятся к CO-337; проверки лицензий нет.

## S8. Переезд и непрерывность

**Что работает.** Ранбук переезда: что переносится, что начинается с нуля, порядок и проверки (`docs/launch/release-mac.md`, раздел «Moving Fabric to another machine or another macOS user», CO-518). Архив журнала с проверкой до записи (`backup.ts`), тест `apps/desktop/test/backup-restore.test.mjs`. Экспорт личной истории (ADR-0079).

**Чего нет.** Плановой резервной копии: архив делается только вручную. Учения по восстановлению на второй машине (CO-490). Защиты от двух живых копий одного поместья (CO-515).

**FileVault и перезагрузки.** Fabric запускается как login item с `--background` (CO-322), то есть только после входа пользователя. После перезагрузки с FileVault пользователь организации не получит работающий Fabric, пока в него не войдут; режима без графического сеанса нет.

**Потеря MacBook.** Без резервной копии поместье теряется; отзыв машины по passkey (CO-320) не сделан.

## S9. Развёртывание с нуля

Шаги: Docker (Colima, OrbStack или Docker Desktop) и Supabase CLI (Fabric сам запускает Colima, если тот установлен, `dockerLaunch.ts`); DMG; первый старт делает `supabase start`, миграции и seed (`docs/launch/release-mac.md`); хаб публикует `hub.json` на порту своего пользователя; агенты подключают `fabric-mcp` (через `passioncode doctor`); человек выбирает `machineTrust`. Повторный запуск идемпотентен: seed с охранами (`supabase/seed.sql`), `materializeStack` переписывает только своё. Нужен человек: вход в macOS, входы в Claude, Codex и GitHub, выбор `machineTrust`, шаг обновления схемы (Fabric только называет команду, `schemaReadiness.ts`). Время не измерялось. Мешают: CO-513 (второй стек на одном Mac), нет автообновления (CO-501), CO-515.

## S10. Ключи в Observatory и перенос в организацию

Секреты продуктов лежат в хранилище Observatory того пользователя, под которым работает Fabric (проект `fabric`, окружения `local`, `stage`, `prod`); привязки агентов хранятся как хэши в базе Fabric. Владелец: пользователь macOS. Механизма переноса в организацию нет: по ранбуку входы делаются заново на новой машине, а секреты берутся из хранилища Observatory, которое там есть.

## Правило изоляции (агенты организации говорят только с агентами той же организации)

Сейчас: отдельный Fabric, база и доска на каждого пользователя macOS, граница по аккаунту ОС; дверной токен в домашней папке с правами 0600; `com.directory` показывает только проекты своего поместья. Нет: метки организации у проекта внутри одного Fabric (любой проект пишет любому через `com.submit` и передачу работы, `crossProjectAssign.ts`); отказа соединениям другого аккаунта (CO-514); контекстов `org:<id>` (CO-422); правила «одна организация на проект» (ADR-0178, D8-d). Одинаковый estate id у всех установок сломает различение поместий, как только появится relay.

## Вопросы оператору

1. Что принимаем для Studio: один Fabric держит хабы обеих организаций (ADR-0178, D8-a) или отдельный Fabric под каждым пользователем macOS (CO-505, план Studio)? Нужна новая ADR, которая отменит одно из двух.
2. Расширить CO-092 до случайного estate id для каждой новой установки, с миграцией существующих?
3. Пользователь организации после перезагрузки с FileVault: держим его сеанс открытым или заводим строку на режим Fabric без графического сеанса?
4. Ставим ли `machineTrust: organization` на Fabric пользователя организации? Тогда одобрения, пересказанные из другого агента, там отказываются, и решать придётся только в окне.
5. Нужен ли временный канал доски между пространствами до relay (CO-453), или ждём срез 2026-11-21?
6. Чей каталог `tokens/` в папке хаба? Код Fabric его не пишет, а ранбук называет его хабовым.
