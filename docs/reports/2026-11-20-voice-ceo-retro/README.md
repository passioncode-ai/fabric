## Находки (каждая с доказательством выше)

1. **Разговор не сохраняется.** Реплики человека и голоса живут только в памяти окна (`voiceCall.ts`, personLine,
   transcript.delta); на диске нет ни текста, ни связи «реплика → вызов инструмента». Ретро и разбор ошибок невозможны,
   CEO не видит, что сказали голосу. Нужно: локальный приватный журнал звонка (реплики, вызовы, ответы, длительность,
   стоимость по XAI_USD_PER_MINUTE), с вырезанием секретов (privacy-filter) и сроком хранения; видимый в окне CEO.
2. **Голос запускает работу голым терминалом.** session_start принимает runner `shell` с задачей-прозой; инструкция
   голоса (`voiceInstructions`) не говорит, что шелл только для команд. Нужно: голос по умолчанию запускает агента
   проекта (claude-code), `shell` только по прямой просьбе «открой терминал» и без текста задачи. (Fabric-сторона
   «шелл не принимает прозу» уже передана сессии 8343a070.)
3. **Голос сам делает работу агента.** 12 session_input в шелл за 2 минуты: отладка руками через терминал. Нужно:
   правило в инструкции «не исполняй работу сам, делегируй агенту проекта или ask_ceo», и предел на серию вводов.
4. **Имена проектов на слух не находятся.** «DC» (dissy), «sound engine» (два проекта), «<часть имени worktree>» (worktree),
   «~» (домашняя папка как проект). Нужно: нечёткий поиск по звучанию и транслиту (кириллица/латиница,
   «Диззи», «<личный проект владельца>», «Саунд энджин»), алиасы проекта, при неоднозначности короткий выбор голосом из 2–3 вариантов,
   а не отказ; worktree находятся через основной проект.
5. **Мусор в реестре проектов.** Дубли с одинаковым именем (`fabric-agents-database` в `~/DATA` и в `~/.cache`),
   проекты-папки из `~/.cache`, worktree и временные копии (`<a worktree copy of sound-engine>`, `<probe copies>`), проект с
   папкой = домашняя. Нужно: чистка/архив и правило, что .cache и временные worktree не становятся проектами.
6. **Голос лезет в консоль CEO.** session_input в собственную консоль: отказ после «not-delivered». Нужно: голос
   знает id консоли CEO и для неё использует только ask_ceo.
7. **Ответ CEO не возвращается в голос.** ask_ceo отдаёт просьбу в консоль, но голос не может дождаться и прочитать
   ответ CEO вслух. Недостающий инструмент: `ceo_reply` (ждать и прочитать последний ответ CEO на эту просьбу).
8. **Шквал одинаковых вызовов.** session_launches 7 раз за 7 секунд с подбором имён. Нужно: подсказка в отказе
   (ближайшие имена), и один вызов поиска проектов вместо перебора.
9. **Запуск теряет первую задачу** (не голос, но тот же session_start): сессия 0d842f8b 40 минут пустая. Передано
   8343a070.
10. **Недостающие инструменты голоса** (сравнить с тем, что есть у CEO-консоли): поиск по доске и задачам, статус
    машины (диск, нагрузка), уведомление владельцу, «что изменилось с прошлого звонка» (сводка по сессиям), остановка
    своих зависших запусков, проверка, что запущенная сессия приняла задачу.
