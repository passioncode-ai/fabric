Запрос оператора 2026-09-27: довести первую версию до проверяемого релизного качества, а не остановиться на аудите. **Работа продолжается; релиз не принят.** Здесь единый вход для следующего исполнителя. [Карта модулей](modules.md) → [порядок и пакеты](development.md) → [фактические проверки](checks.md) → [Stop contract и следующая интеграция](stop.md) → [восстановление истории](recovery.md) → [допуск сборки и схемы](release-admission.md) → [private CEO conversation](ceo-conversations.md) → [draft/send service](ceo-conversation-service.md) → [trusted chat host](ceo-conversation-host.md) → [private archive and restore prerequisite](ceo-private-archive.md) → [restore authority](restore-authority.md) → [native topology proposal](provider-topology-proposal.md). [Интерактивная карта продукта](../../reports/product.html#view-r0-map) остаётся целевым дизайном, не runtime receipt.

## Что входит

Fabric — управляющий агент, с которым оператор обсуждает работу. Project сохраняет цели, решения и историю; исполнитель заменяем. В R0 входят: настройка Fabric и доступного исполнителя; выбор папки/нескольких источников одного Project; первый обзор; CEO-чат с текстом, проверенным голосовым вводом и контекстом; доска, план, работающие агенты; наблюдаемая остановка и продолжение; память/поиск; возвращение к работе и ограниченный повторяющийся цикл. Полная карта ниже не превращает эти возможности в уже готовые.

## Текущий срез

База анализа: [`eda2e5d071cfb891719e81cf6ba448327f6a7643`](https://github.com/passioncode-ai/fabric/tree/eda2e5d071cfb891719e81cf6ba448327f6a7643). Предыдущие доказательства — [E01–E16](../../audit/2026-09-26-harness/evidence.md). Проверка кода показала, что H00…H09 — план исполнения, но не вся первая версия: отдельные обязательные владельцы CEO, голоса, источников и памяти перечислены в [modules.md](modules.md). Готовность считается по capability, не по длине файла и не по количеству макетов.

Первый рабочий срез: подготовка bundle → admission → действительная доставка → ACK → наблюдаемая остановка. Следующий сквозной срез: своя папка → обзор с источниками → задача через CEO → запуск → остановка → новая сессия с проверенным контекстом → возвращение после перезапуска приложения.

**Где мы на 2026-09-27, после консолидации.** Все шаги первого среза есть в исходниках с локальными и изолированными SQL-проверками; ни один не принят на настоящем провайдере. Трек CEO-чата: хранилище, сервис, HTTP-host и TLS проверены по отдельности, но не собраны вместе и не включены. Восстановление: A0 (схема 65) влит, A1 (личный архив, ADR-0079) — следующий. Готовность по шагам и очередь пакетов — [development.md](development.md#after-consolidation--2026-09-27). Реестр проверок: 190 из 1549 строк ни разу не наблюдались падающими на подсаженном дефекте — число пересчитывает `node scripts/check-registers.mjs` ([verification](../../evidence/verification.md)).

## Передача

- Ветка Fabric: `main` — единственная рабочая линия после [консолидации 2026-09-27](../../evidence/plans/2026-09-27-branch-consolidation.md); владелец исходников — существующий `origin`. Прежние member-ветки сохранены тегами `archive/*`, незакоммиченное — `archive/wip/*`. Новая member-ветка коммитит результат у себя до передачи.
- Решения: ADR-0063/0065/0067/0069, private-content boundary ADR-0075, ADR-0077, личный архив ADR-0079 и топология Codex ADR-0081; эта карта уточняет состав и зависимости. Не создаём вторую истину о задачах, новый memory engine или отдельную базу CEO.
- Предпосылки: Node/pnpm из lockfile; для DB — изолированная тестовая БД; для native — точные CLI builds, реальная авторизация и выделенный тестовый Project. Чужие БД и глобальные настройки провайдеров не используются как fixture.
- Открыто: все строки без native receipt; CO-168 остаётся реестром незавершённой реализации, CO-169 — отдельным владельцем общего визуального слоя. Ничего не закрывается посещением экрана.
- **Общий порядок работ** — строка Now/Next [общего плана](../../evidence/backlog.md#general-development-plan); N1 там — полоса 5.
- **Точный следующий шаг этого модуля:** пакет N1 [плана до первого среза](../../evidence/plans/2026-09-27-first-slice-plan.md#n1--first-slice-on-real-providers) на настоящих аккаунтах машины: Claude — профиль claude-swap аккаунта 8 (`cswap run 8`), ход проверен; Codex — существующий вход ChatGPT, связанный с owned-профилем ссылкой (`modelAccess`), путь до модели проверен, но аккаунт Codex исчерпал лимит до 3 октября 19:15. Следующее: рецепт Claude в owned stdio и матрица HAR-R0-04 на Claude; ходы Codex — после сброса лимита. Готово: A1, E0, C0–C5, B0–B4; локальная база на схеме 67.
