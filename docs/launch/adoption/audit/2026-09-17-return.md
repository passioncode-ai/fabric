# First work and return loop — bounded static UX audit

Baseline: `bac1f67`. Read-only audit 2026-09-17. No browser and no production execution. Evidence classes: STATIC = inspected render/handler chain; TEST = bounded Node tests / pure reproduction; DESIGN GAP = missing target contract or integration, not a claim about runtime. Files reviewed: launch, assistant, concierge, operations, controller, guided; canonical SCN-040/041/042/045/052/059/060/067/090/091/093/094.

## What currently works in the prototype

- Chat opens through one launcher, preserves draft per estate/project thread, changes composer scope without navigating the main page (`assistant.mjs:7–23`, `controller.js:29–32`). Explicit task in a project uses the shared Task writer; saving does not start a Run (`controller.js:37–42`, `operations.mjs:379–388`). Unscoped write asks for destination.
- Attached references are filtered to available, nonarchived projects, copied into the submitted message, revalidated before send; attached other-project sources do not change destination (`context-items.mjs:2–8`, `assistant.mjs:17–22`).
- Board topic → detail → written outcome → done/later/reopen is an actual handler path; blank outcome is rejected. Source obligations route to their actual question/result, rather than being independently closed (`launch.mjs:32–42,84`). Admission/delivery remains separate.
- Task → Launch → context preparation / runner check → admit → Run → spawn/deliver/ack/check/stop is modeled. Unknown admission and delivery preserve identity; failed spawn, exhausted retry and stop have recovery controls (`operations.mjs:110–139,233–253`).
- Guide task uses the same Task writer; guide skips do not create missing Task/Board outcomes; duplicate archived project links to recovery (`guided.mjs:47–51`).
- Exact immutable past context versus future preview is distinguished; missing past pack never borrows current content (`operations.mjs:138`).

Validation run: `node --test scripts/test/calm-context.test.mjs scripts/test/calm-flows.test.mjs scripts/test/calm-work.test.mjs scripts/test/ceo-onboarding.test.mjs` — 21 tests, 21 pass, 0 fail. This is prototype handler/render coverage, not usability, actual providers, durability or observed product coverage.

## Findings needing individual decisions

### RET-01 — P1 — New personal Home still shows Atlas/Studio activity
- Evidence STATIC: `launch.mjs:58–68` appends fixed Atlas/Studio Live rows regardless of owned projects; `launch.mjs:18–22` correctly resets personal project/topic data but not this feed. Pure render TEST with sole personal project `own` returned `newPersonalHomeShowsAtlas:true`, `newPersonalHomeShowsStudio:true`, ownedProjects `[own]`.
- Affects SCN-059/060/090/094. First user can believe somebody else's work belongs to them; the honest empty/first-work state is lost.
- Decision A (recommended): estate-scoped observation read model, explicit sample dataset only behind “Посмотреть пример”. B: keep sample alongside empty state but label the entire sample region and disable real-work actions; inferior for first real project.
- Impact: Home feed + Pulse + Board counts + fixtures + estate filtering + generated previews. Do not patch only the two displayed names.
- Negative checks: one fresh personal project → no Atlas/Studio name, IDs, links or activity counters; archive/remove last project; switch estate while feed paused; missing source ≠ zero activity.

### RET-02 — P1 — Home resume cannot recover the exact work or a true since-last-visit delta
- Evidence STATIC: `launch.mjs:57` selects `lastProject`, then latest `launchData.events`, with Atlas fixed “3 изменения”; button always opens project overview. `launch.mjs:73` sets lastProject only when rendering launch-project. Operations has independent history and mark at `operations.mjs:34,73,198`. `controller.js:34` inserts chat messages into launch events, not operation lifecycle.
- Affects SCN-040/045/060/090/093/094. Visiting Task/Run directly, switching project, answering or completing work can produce a resume card that knows neither exact entity nor measured delta. A chat reply may replace the meaningful next step.
- Decision A (recommended): one ReturnSnapshot contract keyed estate/project/user: source cursor, seen cursor, exact continuation ref, pending operator decision, next permitted action, coverage/age, observed state. Home compact projection; Project expanded projection; CEO same snapshot. B: call existing card “Последний открытый проект” and defer promise of context return (does not deliver core launch value).
- Impact: durable read cursor and journal, Home/Project/CEO/notifications, session restore, origin routing, cache invalidation. “Continue” must not mark unrelated updates read.
- Negative checks: Task/Run direct deep link updates continuation; two projects retain distinct marks; new event after render but before leave remains unread; refresh failure keeps prior age; deleted/inaccessible target recovers without another project's substitution.

### RET-03 — P1 — Return shortcut is a count summary, not the promised return insight
- Evidence STATIC/TEST: `assistant.mjs:57` suggests “Собери изменения с прошлого визита”; `concierge.mjs:41–43` returns project purpose + total tasks + open question count and one project link. Pure test returned “Only my project: First value. В снимке 0 задач; открытых вопросов — 0.” No visit cursor/decisions/what changed/next step.
- Affects SCN-042/090/093, guide first chat. Current guide promises first value through a query unable to demonstrate it (`guided.mjs:48`).
- Decision: reuse RET-02 snapshot instead of separate NLU-specific summary. On truly first visit say no previous checkpoint, show sourced imported context or capture a first checkpoint. Never invent “changes since visit.”
- Impact: read service, CEO answer schema and source links, guide milestones, telemetry definitions.
- Negative checks: first visit, no changes, stale/partial observation, empty journal, unresolved blocker, changed decision, answer sources all in exact allowed scope.

### RET-04 — P1 — Task link correction is exposed but wired to Board-topic relinking
- Evidence STATIC: saved task card exposes “Уточнить связь” (`assistant.mjs:38`); handler `save-link` at 55 invokes controller `onRelink` (`controller.js:35`), which always calls `relinkLaunchArtifact`; that function only finds `d.topics` entry `ceo:<artifact.id>` (`launch.mjs:31`). Task path `controller.js:41` creates only operations Task.
- Pure TEST: relink of saved task proposal returned `{ok:false,error:"Исходная запись не найдена"}`. Existing tests cover references and task creation but not this callback chain.
- Affects SCN-042/045 and conversation attribution. The visible feature cannot finish its purpose for the only artifact type where it is shown.
- Decision A: explicit attribution command shared by Task and Board, typed entityRef + immutable original origin + append-only link change receipt. B: remove Task relink until supported and preserve original attribution; do not leave failing control.
- Impact: command contracts, artifact provenance, task timeline, conversation card, authorization and cross-project rejection.
- Negative checks: existing task same project succeeds; blank allowed/unlink policy explicit; foreign task refuses; same request repeat no duplicate receipt; archived project refuses write; original message origin unchanged.

### RET-05 — P1 design gap — Product run controls force operator through low-level runner stages
- Evidence STATIC: ordinary primary Run actions include “Создать процесс”, “Доставить инструкцию”, “Сверить адресную доставку”, “Подтвердить остановку”, “Checker: принять результат” (`operations.mjs:118–127`). Handlers mutate simulated process/checker facts (`244–251`). Fault injection is disclosed, but these normal source transitions still look like operator responsibilities.
- Affects SCN-052/067; contrary to user request that agents handle routine mechanics. Useful simulator, incomplete production UX contract.
- Decision A: one explicit “Начать работу” after scoped readiness, automatic process/admission/delivery/checker state machine, visible stop/retry/reconcile only when operator action required. Observations are read-only; simulator controls explicitly marked. B: expert console retains manual steps behind advanced mode, never default onboarding.
- Impact: orchestrator/admission/host observation, Run state projection, buttons and labels, permissions, integration tests. Preserve admission ≠ acknowledgement ≠ independent acceptance as data even when automation hides mechanical steps.
- Negative checks: duplicate start; uncertain delivery does not resend; unknown stop never shows stopped; checker absent/author cannot award acceptance; partial artifacts survive retry; UI offers only actions supported by current server capabilities.

### RET-06 — P2 — Deferred Board topic has no explicit return trigger
- Evidence STATIC: defer requires text then sets only status `later` (`launch.mjs:32–36,84`). Home shows only `open` (`70`); Board offers Later filter (`71`). No due date/trigger/next-review contract in topic model.
- Affects SCN-041/093. “На следующий раз” can disappear indefinitely unless user remembers to inspect a separate tab; hook lacks reliable reason to return.
- Decision A: “Следующий разбор” as default explicit trigger, optional date/event in details, resurfacing receipt and dedupe. B: rename “Отложить без напоминания” and show deferred count on return. Avoid silently scheduled reminders without user choice.
- Impact: attention read model, daily review/session boundary, scheduler optionally, Board status versus resurfacing event, notification consent.
- Negative checks: once-only resurfacing, overdue/no source, archived project, skipped review, many deferrals, clear distinction task priority vs personal attention.

### RET-07 — P2 — Shortcut/example overwrites a user's unsent draft
- Evidence STATIC: `assistant.mjs:57` assigns `t.draft` for any suggest action without retaining old text; `controller.js:46` guide examples also assign t.draft. Scope switching itself retains drafts, so this is a different loss path.
- Affects SCN-042/059. Need not ask a modal each time: recommendation insert example only into empty draft, otherwise offer append/replace with immediate Undo and retain original.
- Impact: common composer draft reducer for shortcuts, examples, voice transcript and contextual actions; ownership by scope and revision.
- Negative checks: typed draft → shortcut → Undo; switching scope during shortcut; voice draft and attachments preserved; repeated shortcut does not pile up duplicate text.

### RET-08 — P2 — Default voice example requests a compound action but executes only Board read
- Evidence STATIC: transcript at `assistant.mjs:60` = “Собери изменения с прошлого визита и вынеси вопросы на доску.” Classifier uses first regex match, Board precedes Context (`concierge.mjs:12–13,32`); TEST returns `{id:board,mode:read}`. No summary or Board write occurs.
- Affects SCN-042/093, voice introduction. Misleading first voice experience even within labeled demo.
- Decision A: first voice example one supported read intent; explicitly preview multi-intent plan later and execute typed commands with separate receipts. B: recognize compound intent and clearly state which part is unsupported, never imply completion.
- Impact: capability routing, action plan schema, tutorial examples, partial completion and retry contract.
- Negative checks: compound command partial failure; clarify missing destination; read success/write refusal; no duplicate topic on retry; transcription edits preserve original and final text attribution.

### RET-09 — P2 — Returning digest acknowledges current total, not the exact displayed boundary
- Evidence STATIC: `operations.mjs:73` renders sorted newest-first rows and uses count equality; navigation at `operations.mjs:191` and `controller.js:136` writes current history length. SCN-090 (`scenarios.md:2163–2182`) requires oldest-first and acknowledgement of exactly the visible reading, including sources arriving during view.
- Affects SCN-090. No event-stream browser reproduction claimed; static callback is susceptible if history grows between render and leave. Counts also fail on reordering/backfill.
- Decision: immutable render receipt with source head/cursor, visibility rule and monotonic acknowledgement. Preserve currently approved leaving-ack behavior, but use rendered receipt, not current length. Unify with RET-02.
- Impact: every navigation route, digest polling, active-pane visibility, background tabs, stream append/backfill, persistent marks.
- Negative checks: event appended after last render, late/backfilled event, failed head, switching task while digest hidden, double return no repeated old rows, source reordering.

### RET-10 — P2 — Session tutorial measures setup records instead of demonstrated return value
- Evidence STATIC: guide completion gate is task+topic (`guided.mjs:51`); guide progress counts project/task/topic/finished (`34`). It neither requires handling the tutorial topic nor a context switch/second visit nor actual result. Created topic at `50` instructs user to close it but completion does not depend on that.
- Affects SCN-059/060/090. User can finish the entire guide without experiencing the core promise, while tutorial itself adds a noisy attention item.
- Decision A: milestones are actual outcomes: scope known → first checkpoint/context digest saved → first useful action → leave/return comparison → real attention resolution. Task/topic records remain analytics but not activation. B: retain setup checklist labeled setup, add separate voluntary first-value path. No artificial blocker on work if skipped.
- Impact: onboarding state machine, ReturnSnapshot, analytics cohorts, tutorial Board metadata/priority, empty project path vs imported existing project path.
- Negative checks: skip never advances milestone; deleted task doesn't erase historical success but invalidates continuation; archived project suspends prompts; manual completion outside guide counts; no re-show after dismissal unless meaningful trigger.

### RET-11 — P2 — Missing conversation deep link silently falls back to current scope
- Evidence STATIC: `controller.js:30` overrides context only if matching conversation is found; otherwise it uses current scope, with no “conversation missing” state. Threads are in-memory Map (`assistant.mjs:7,14`); source links are shareable hash params (`launch.mjs:42`).
- Affects SCN-040/042/060 and durable conversation requirement. Existing empty thread can appear in place of expected source conversation after refresh or missing data.
- Decision: explicit unresolved/missing/denied source-link state that preserves requested identity and offers current scope as separate action. Durable history later uses same contract.
- Impact: route parser, conversation resolver, source citations, reload/session restoration, access revocation, snapshots.
- Negative checks: missing conversation, wrong estate, deleted project, partial history, inaccessible original, message missing within existing conversation. Never substitute another message.

## Proposed staged discovery (triggers, not arbitrary days)

1. Session A / first contact: existing-project user chooses one source, sees one sourced “what this is / current work / next choice” snapshot; new-idea user states outcome and captures first next step. Agent installation, avatar, graphs and cadence optional. Value: stop re-explaining project intent. End with a saved return checkpoint and exact continuation, not a tour completion badge.
2. Session A / first useful action: perform one meaningful action in that scope — answer a real pending question, save a task with criteria, or accept a verified imported decision. Board tutorial only as optional, explicitly educational item excluded from work counts. Explain CEO immediately beside the action, with one context-aware example. Preserve choice to keep using external agent.
3. Session B / first return or deliberate switch: compare current observation with checkpoint, show what changed, what still waits and one next action. User follows source and resumes in ≤ one overview + one action. Introduce “Attach context” only if another project's source is relevant. This is primary activation, not project-created count.
4. Session C / repeated real attention: introduce morning review / Later resurfacing after two independent useful decisions (proposed heuristic to validate, not a fact). Offer optional notification or review schedule. Preview scope, permission and one run outcome before enable. No schedule by default.
5. Session D / scaling: after second project or parallel agents, reveal portfolio, featured/order, dependency graph and read-only activity filters. Memory lineage when a source is challenged, deeper Run details when blocked, costs when choosing execution/provider. All remain discoverable in navigation/help for advanced users.

Measure hypotheses, not invented conversion targets: first sourced checkpoint, first actionable outcome, first successful return, repeated return with real delta, unresolved attention resolved, proportion needing help, wrong-scope attempt rate, time-to-source and time-to-next-action. Exclude tutorial/demo events, page views, token counts and heartbeat from value metrics. User test manually before any conversion claim.
