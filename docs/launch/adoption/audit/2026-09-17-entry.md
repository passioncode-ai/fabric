# New-user entry / creation / guided adoption audit

Date: 2026-09-17. Baseline: bac1f67. Scope: read-only source audit and bounded pure prototype handler tests; no browser, native application or deployed runtime was traversed. No repository edits. Evidence format: file:line relative to Fabric baseline; EXEC means a named pure test/probe actually ran, STATIC means code inspected, PROPOSED means product design to validate.

## Alignment and user value

Vision principles 1, 4, 5 (`docs/ux/vision.md:27` onward): durable Project; sourced state; progressive adoption before complete organisation. Foundation JTBD-01/02, ST-022/023/029/039/040 motivate entry, intent, continuation and return. Existing guided flow optimises creating Project + Task + tutorial Board. That is an inspectable setup outcome, but for the primary operator who already has several live projects the hook is recovering sourced current state and the next meaningful decision. Do not measure setup completion as demonstrated context-restoration value.

Recommended session order is trigger-based, never a forced calendar schedule:
1. First entry: choose existing work vs new idea; establish one scoped Project; inspect a small real source-backed orientation card. Existing-work card: goal / where stopped / important change / next decision with source+freshness. Idea card: intended outcome / saved next step / return checkpoint; explicitly no fabricated history.
2. First useful action, same visit if wanted: resume existing Task, record a real missing decision, or create first Task only when it is actually needed. Explain Board in the user's first real attention item, rather than injecting mandatory tutorial work into the work queue. Offer a clearly marked disposable sample if no natural item exists.
3. First return after a meaningful change: show delta since acknowledged checkpoint and remaining next action; stale/unread sources remain visible. Return is a meaningful outcome, not a streak notification.
4. Second Project or concurrent agent: introduce context switching and source attachment at the moment of need, keeping separate drafts and scopes.
5. Repeated manual activity: offer explicit routine preview, boundary, cadence, pause and independent result check. No automatic policy promotion from lesson completion.
6. Dependency/history question: expose expandable plan/decision graph. Personal avatar and historical pulse are optional identity/recognition, not prerequisites to value. Full capability catalogue remains searchable help.

No conversion uplift is claimed. Proposed measurements must be separately designed: elapsed time to first sourced orientation, successful exact task/decision navigation, return-context understanding, recovery success, explicit setup abandonment reasons. Avoid counting clicks, decorative progress or heartbeat as product outcomes.

## Findings requiring explicit decisions

### F01 P1 — Two competing creation paths and contracts (confirmed STATIC)
Sources: `controller.js:99`, `calm.mjs:23`, `workbench.mjs:100–103`, `guided.mjs:25–34`, `controller.js:198`, persona `applyPulseAction`.
Issue: same +Project intent leads to guided 4-step flow or advanced workbench; capabilities differ (repository suggestions/templates/independent draft list/reconciliation vs scan/guide). Completion lands in different home. The user must learn entry points, not just a product concept.
Decision: one draft domain and one primary entry; preserve advanced configuration as a subordinate module, route all creation affordances through the same coordinator. Preserve old deep links as aliases, not remove features.
Impact: route model, model journey links, SCN031/059, FLW18/32, SCR27, guided/workbench/controller, persona transitions, fixtures and exact route tests.
Acceptance: every create affordance yields same draft identity/schema; changing path cannot lose fields; source modes and optional configs reconcile; success same Project+receipt; previous deep links still work; keyboard/mobile entry and return verified.

### F02 P1 — Choosing idea still deduplicates against previous repository (confirmed EXEC handler probe)
Sources: `guided.mjs:42,47`, `controller.js:197`.
Repro: enter existing repo `/archived`; switch mode to idea; create. `g.repo` remains `/archived`, before repoMode none is applied the duplicate check finds archived Project and blocks creation. Output: `{mode:"idea",repo:"/archived",created:0,archive:"old"}`.
Decision: retain per-mode field drafts if useful, but derive effective source before review, duplicate check and create; idea has no repository identity. Review and command must share exactly that effective source.
Impact: source-mode draft schema + dedupe + review; canonical source identity also needed for URL/path aliases.
Acceptance: single→idea with existing/archived repo creates repo-free idea; idea→single restores optional draft but requires explicit attachment; path whitespace/alias/case/symlink identity tested at runtime resolver, no UI guess.

### F03 P1 — Native restarted draft IDs can collide and overwrite restored work (STATIC strong code finding, native DOM test not run)
Sources: `App.tsx:193,232,402–405`. `draftSeq` starts at 0, restored disk keys not used to seed it; newDraft writes `draft-1` with object spread overwrite. Existing persistence test fixture uses `tab-1`, not realistic generated `draft-1` (`onboardingDraft.persist.test.tsx:34`).
Decision: UUID draft identity or allocator collision-proof over restored/in-flight IDs; restore and create must not race. Keep project UUID identity separate.
Acceptance: restore dirty draft-1 and draft-2, click new draft twice, all old fields+project IDs unchanged; separate tabs unique; restart preserves all; no create before hydration overwrites pending disk state. Test actual shell event, not standalone counter.

### F04 P1 — No dedicated value checkpoint/return loop in current guided path (PROPOSED product gap)
Sources: `guided.mjs:34,49–51`; foundation ST039/040 and vision progressive adoption. Guide completion is Project+Task+tutorial topic, not demonstrated context recovery.
Decision: two cohort routes: existing work → sourced orientation and one next action; idea → saved intent/checkpoint. Define first value and first return evidence independently from feature lesson completion.
Impact: read adapters/source coverage, context capsule, read/ack checkpoint, attention feed, guide progression, event schema and privacy-conscious measurement. Never fabricate delta when no history or unread sources.
Acceptance: user can answer goal/current state/next decision from own source card; source link exact; unknown shown; return after one new event highlights it once only after acknowledgement; routine heartbeat alone cannot qualify.

### F05 P2 — Guide completion can mark Board learned without reading/resolving it (confirmed STATIC; existing EXEC test deliberately accepts mere IDs)
Sources: `guided.mjs:34,50,51`; `scripts/test/calm-flows.test.mjs:6` onward.
Decision: distinguish created/read/applied/skipped. Prefer first real Board outcome. If tutorial, separate learning record with `tutorial` provenance; do not include in meaningful progress metrics.
Impact: GuideProgress event/projection, Board outcome linkage, deletion/supersession/replay handling, pulse filters.
Acceptance: creating topic alone does not mark learned; navigate away/skip distinct; real resolved item can satisfy objective once; delete item doesn't delete user's Task; no fabricated production evidence or points.

### F06 P2 — Skip hides obvious exact resumption (STATIC discoverability gap)

Acceptance: skip at every step→navigate other Project→help resume restores original Estate/Project/revision/draft; archived/ACL loss safe; no repeated automatic nudge after opt-out; request to resume clears only relevant dismissal.

### F07 P2 — “Настроить позже” still creates Builder candidate with provider `later` (STATIC)
Sources: `guided.mjs:27`; `new-project.mjs:7`; `operations.mjs:355–359`.

Acceptance: defer→no provider ID later, no runnable session/binding; creation still allowed; next needed action offers setup; selecting real candidate preserves original Project and Task; authority remains explicit.

### F08 P2 — Guided chat shortcut can write draft to a different thread than currently shown (STATIC hypothesis requiring browser/controller test)

Issue: override chat scope within same route; guided chat shortcut computes assistantScope(view,state) ignoring scopeOverride, writes there, then assistantUI.render honours still-valid override. User sees old/empty draft while intended prompt exists in another thread.
Decision: one context resolver for display and all composer mutations. Explicit object shortcut either announces/pins destination or respects current scope; no silent split.
Acceptance: on guide Project A choose chat Project B/global then invoke guided example; displayed scope and draft destination agree; no overwrite other draft; cancelled speech/attachments remain scoped; send creates no wrong-project artifact.

### F09 P2 — Native retry of same Project ID doesn't validate changed create payload (STATIC contract gap)

Decision: immutable pending create command+payload fingerprint, reconcile before edited submission; user chooses explicit post-create update for new values. Do not infer from already-exists success that current fields were saved.
Acceptance: lost create response + changed name/purpose/repos yields conflict/review, not silent success; same request identical payload idempotent; partial attachments reconciliation exact; authorization rechecked. Backend/native integration required.

### F10 P2 — First conversation prompt asks for “changes since last visit” before any visit/history (STATIC UX mismatch)
