# Fabric: знакомство через полезное возвращение

Статус: **предлагаемый конечный дизайн**, 17 сентября 2026. Основание — запрос оператора и [vision](../../ux/vision.md), проверенная точка `bac1f67`. [Наблюдения](findings.json) отделены от решений. Это не сообщение о поставленных runtime-функциях и не обещание измеренного роста конверсии.

## Обещание и hook

«Добавьте один проект. Fabric поможет понять, где вы остановились и что делать дальше». Для новой идеи: «Сохраните результат, к которому идёте, и первый шаг. Здесь вы сможете продолжить». Пользователь не должен сначала построить организацию, установить всех агентов или понять термин Harness.

Предлагаемый цикл ценности: **пауза или переключение → понятный актуальный контекст → одно нужное действие → сохранённое решение/следующий шаг → более лёгкое возвращение**. Польза накапливается в проверяемой истории проекта. Аватар и пульс помогают узнавать своего Fabric, но не доказывают результат и не штрафуют за отсутствие ежедневных посещений. Не создавать поводы для возвращения там, где системе нечего сообщить.

Первый value отличается по исходным данным. У существующего проекта — верное краткое объяснение цели, состояния и ближайшего решения со ссылками на прочитанные источники. У идеи — собственная сохранённая цель, ограниченный следующий шаг и явные неизвестные. Создание Project — setup receipt. Создание Task — action receipt. **Первый успешный возврат** — отдельное наблюдение: после ухода пользователь восстанавливает направление и продолжает точную работу без повторного объяснения. Ни один из этих результатов не выводится из процента прохождения уроков.

## Весь функционал и его место

[Полная ведомость](inventory.json) сопоставляет **85 текущих target-представлений с 20 семействами**, canonical сценариями, backlog IDs и исходными статусами. Она сохраняет все идеи и aliases, но не объявляет 85 функций готовыми к запуску. Источники строк привязаны к baseline; численность проверяет `node scripts/check-adoption-plan.mjs`.

| Семейство | Польза и R0 | Когда знакомим |
|---|---|---|
| Вход, проект, источники | один проект/папка-кандидаты/идея; сохранить и возобновить | сразу, остальное по раскрытию |
| Home, поиск, возврат | доска, точный checkpoint, проекты, фактический Live | после первого проекта; повторно после паузы |
| Имя/аватар/пульс | узнаваемость и подтверждённый прогресс; AI-генерация позже | необязательное предложение после value |
| Доска, вопросы, решения | ответить, отложить с условием возврата, открыть последствия | первый реальный вопрос |
| Task/Run/результат | записать критерии, делегировать, проверить, продолжить | задача по потребности; запуск после readiness |
| Агент и manager | один допущенный preset; контекст и состояние | перед первым делегированием |
| Harness/настройки | конкретные пределы действия и источники | нужная настройка непосредственно перед действием |
| Аккаунты | выбранная identity; managed multi-account только по capability | квота/другой аккаунт; не gate входа |
| Подключения/MCP | точный внешний ресурс и разрешение | задача реально требует ресурс; широкий каталог позже |
| Циклы/workflow | узкий review preset с pause и host requirement | после полезного ручного цикла; advanced editor позже |
| Цели/план/история | направление, связи, почему пришли сюда | первый вопрос «почему» или зависимость; полное редактирование позже |
| Память/источники | происхождение факта и реально переданный контекст | сомнение/агент/проверка результата |
| Live/релизы | факт начала/завершения/проверки, среда, receipt | при фактических событиях; empty честен |
| Ретро/улучшения | повторяющиеся причины и исправление | повторный сбой или запрос пользователя |
| Совместная работа | роль и область видимости; отдельный вход приглашённого | приглашение/делегирование; no project-only promise |
| IDE | артефакт, файл, сессия; specialist panels сохранены | контекстная ссылка из результата |
| Затраты/уведомления | нужные лимиты до эффекта, полезный сигнал по opt-in | перед платным действием/по желанию |
| Хранение/восстановление | сохранить работу, обнаружить потерю/конфликт | всегда доступно; показывать при исключении |
| Архив/диагностика | вернуть объект/разобраться без подмены данных | при конкретной необходимости |
| Примеры предметных циклов | support/content/release и другие сохранённые идеи | библиотека примеров после ядра; не обязательная школа |

Near/later в каталоге — горизонт представления. Базовые admission/authority/cost checks обязательны перед соответствующим действием, даже когда расширенный экран later. Реальный голос обязателен для R0; его урок необязателен. Полный граф-редактор, широкая автономия, always-listening, AI-аватары и specialist workflows остаются в CO-166 и существующем backlog.

## Сессии — события, а не расписание обучения

Пользователь может пройти несколько фаз за один заход либо растянуть их на недели. Никакого календарного unlock; помощь следует потребности. В каждой фазе показывается один следующий рекомендуемый шаг. Поздние функции остаются доступны через поиск, помощь и прямые ссылки, если они реально поддерживаются.

| Фаза | Триггер | Видимый минимум | Действие и результат | Не показываем заранее |
|---|---|---|---|---|
| S0 · Вход | первое открытие | что получу; существующий проект или идея; продолжить черновик | выбрать источник/цель; сохранить один Project | аккаунты всех провайдеров, команда, полный workflow |
| S1 · Первое понимание | Project сохранён, наблюдения доступны или честно отсутствуют | цель, «сейчас», ближайший шаг, источники/unknown | проверить/исправить и сохранить checkpoint; сделать одно полезное действие | граф всех сущностей, длинные технические receipts |
| S2 · Возвращение | пользователь ушёл/переключился и снова открыл работу | что изменилось с показанной границы, что ждёт, продолжить | открыть точную Task/Decision, ответить на реальный вопрос | новый тур; повторная настройка проекта |
| S3 · Делегирование | хочет выполнить Task агентом | результат и критерии, кандидат, пределы и readiness | допустить ограниченный запуск; получить проверенный исход | ручные spawn/deliver/checker команды |
| S4 · Несколько контекстов | второй проект/параллельная работа | проекты и приоритет; разные состояния и черновики | A→B→A, приложить источник, scope перед отправкой | все разделы платформы одним меню |
| S5 · Повторение | полезный ручной цикл нужен снова | предложение preset, когда/где/предел/результат | сохранить paused, включить явно, проверить run, поставить на паузу | огромный DAG editor и обещание работы при закрытом desktop |
| S6 · Углубление | источник сомнителен, blocker, приглашение, расход, release | нужная детализация и возврат в исходную работу | раскрыть граф/память/историю/доступ/IDE | обязательное прохождение всей библиотеки |

### Когорты и ветвления

- **Есть один проект:** выбрать папку/репозиторий → разрешённые наблюдения → sourced orientation. Нет истории агента — не утверждать, что знаем его решения; предложить приложить доступный источник или записать checkpoint.
- **Папка с множеством проектов:** read-only scan → кандидаты с причинами частичного чтения/дубликатов → выбрать один → показать остальные как сохранённый выбор для будущего. Массовый импорт не запускает агентов и не создаёт активные циклы.
- **Новая идея без репозитория/провайдера:** название и результат → собственный следующий шаг → сохранено, не запущено. Настройка исполнителя при желании выполнить, не до первого сохранения.
- **Приглашённый:** увидеть Estate и настоящую область доступа → открыть назначенную существующую работу. Не вынуждать создавать первый проект и не выдавать Estate-wide доступ за project-private.
- **Прервал setup:** «Продолжить настройку» с точным draft/scope; новая вкладка не перезаписывает старую. После неизвестного create — reconcile, не ещё один проект.
- **Вернулся после долгой паузы:** прошлый checkpoint и свежесть; крупные изменения сгруппированы по цели/решениям, остальные раскрываются. Недоступный источник остаётся отмеченным.
- **Опытный пользователь:** может сразу найти agent/cycle/graph, пропустить предложения и возобновить помощь для выбранного проекта; skip не уменьшает полномочия.

## По клику: ключевой сквозной маршрут

1. **Добавить проект.** Один coordinator для всех входов. Back сохраняет поля, cancel read прекращает чтение, имя/цель валидируются рядом. Режим «идея» не участвует в repo dedup. Known duplicate предлагает открыть существующий; archived — точный архив/восстановление по доступу.
2. **Сохранить.** Review показывает ровно effective payload. Pending блокирует повтор этой команды; unknown предлагает сверку. Commit даёт точный Project link. Изменённый retry не смешивается со старой частично выполненной командой.
3. **Разобраться.** Одна context-card с goal/state/next. «Источники» раскрывает read status/revision/freshness; корректировка сохраняет revision пользователя. Не просить обязательную Task, если полезнее ответить на уже существующий вопрос.
4. **Обсудить с Fabric.** Правый диалог, выбранный Project над вводом. На Home общий scope. Выбор можно сменить, источник другого проекта прикрепить отдельно; write destination виден. Shortcut не стирает свой текст. Результат содержит ссылку на объект и короткое состояние эффекта.
5. **Сказать голосом.** Явный capture → stop → обработка → исправить → send. Permission/device/silence/abort/offline имеют recovery. Оригинал и поправка логируются; raw audio отдельно. Первый пример — одно действие; сложное поручение показывает поэтапный план и частичный исход.
6. **Разобрать доску.** Реальный вопрос/результат, варианты и последствия. Answer saved не равен effect accepted. Later выбирает возврат на следующий разбор/срок/без напоминания. Учебный пример по желанию в отдельной области, удаление не трогает работу.
7. **Поручить.** Task описывает результат, readiness объясняет лишь недостающее; запуск один и ограниченный. UI наблюдает механику, показывает исключения. Result verified vs failed/unverified различаются. Остановка имеет receipt, а не оптимистический success.
8. **Уйти и вернуться.** Last shown snapshot + exact continuation сохраняются. Новое событие между render/leave остаётся unread. После restart пользователь видит свои Project/Task/черновики; чужие sample events отсутствуют. Удалённый объект даёт восстановление, не другой объект вместо него.
9. **Повторять.** Успешный ручной разбор можно превратить в preset. Preview объясняет расписание/timezone/host/пределы. Save paused и Enable отдельны; пропущенный запуск честен. Уведомления отдельно согласуются и показывают только существенное изменение.

Каждый шаг обязан покрыть [универсальную матрицу состояний](contracts.md#state-and-error-rules-for-every-click) плюс свои отрицательные проверки в packet. Это спецификация полной приёмки; фактически выполненные проверки отдельно в [checks](checks.md).

## Компоновка и текст

Сохраняем согласованную Home: компактная идентичность и пульс сверху, Board и проекты в центре, небольшой возврат и Live один под другим справа. Обучение встроено в актуальный блок, не новая постоянно раскрытая колонка. В начале без данных пульс нейтральный; зелёный Live означает свежие подтверждённые наблюдения, не декоративную жизнь. Чат справа имеет один composer; technical receipts доступны рядом по раскрытию. Блокирующие причины, freshness и scope не скрываются.

Screen contract: primary action виден до длинной документации; не больше одной предлагаемой учебной карточки; source/detail/return рядом с результатом; ошибки сохраняют ввод; клавиатура и narrow layout не требуют точного hover. Уровень/стрик, если появится, не служит permission или readiness и не выводится из потраченных денег. Пример копи: «Сохранено. Исполнитель ещё не выбран»; «Источник пока не прочитан»; «Ответ записан. Ждём подтверждения действия»; «Продолжить знакомство с этим проектом».

## Конверсия в пользу: как проверять гипотезу

В пилоте по каждой когорте отдельно измерить elapsed/active time до first context checkpoint, долю верно названных goal/current state/next action, время нахождения источника, успешный возврат после паузы и долю решений с подтверждённым исходом. Знаменатель включает начавших и прервавших; причины отказа фиксируются. Повторные визиты без события и без действия не выдавать за доказанный hook.

TTV clock: start при начале конкретной своей работы, end при продемонстрированном cohort-specific value; отдельно время ожидания источника/провайдера/offline. Внутренние события `project_saved`, `checkpoint_saved`, `return_snapshot_shown`, `meaningful_action_committed`, `guide_dismissed` — предлагаемые названия, не существующая телеметрия. Payload только pseudonymous IDs, phase/capability/result/error category, без разговоров, путей файлов, raw audio или task text. Реализация consent/retention и метрик входит AD23, не hidden analytics в макете. Сначала собрать baseline; не придумывать проценты улучшения.

## Выбор для итогового review

Рекомендуем строить запуск вокруг **первого верного контекста → первого успешного возврата**, а настройку агентов/циклов преподавать по намерению пользователя. Все 34 наблюдения индивидуально разобраны в [18 решениях](findings.json); связанные изменения объединены в [25 пакетов](plan.json). Узкий сквозной checkpoint AD04–08 — первый runtime value, не ожидание завершения всех расширенных редакторов. Обязательные voice/readiness/recovery всё равно должны пройти свою приёмку перед полным R0.
