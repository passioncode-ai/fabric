Software Fabric · project overview · 2026-08-19

A portfolio that observes itself, and a company of agents that acts on what it saw.

One operator owns forty domains, sixty repositories and three cloud accounts. Remembering which of them is alive, which is owed something and which is quietly costing money exceeds what one person can hold. So the portfolio is run by a CEO agent against a graph of goals — and the operator decides only what a person must decide.

This document is derived, not authoritative. It is a reading surface over the committed records of the repository, assembled on 2026-08-19 so the project can be discussed in one pass. Where it disagrees with the files it cites, the files win. Sources: docs/vision.md, CONTEXT.md, docs/adr/0001–0009, registry/domains.yaml, docs/architecture/external-contracts.md, docs/architecture/adopted-doctrine.md, docs/evidence/backlog.md, docs/evidence/specs/…-carryover.md, docs/evidence/verification.md.

01

What this is

A company with one human in it. Not a task tracker, not an agent framework, not a hosted service. A single piece of software that watches an estate, decides what is worth doing about it, hires agents to do it, runs them in real terminals inside itself, and returns proof rather than claims.

Three things make it a product rather than a script. It measures instead of remembering. Its autonomy is bounded by the database, not by a prompt. And every completion claim it makes has to resolve to a record another actor can open — including when the actor checking is you, six weeks later.

Status, plainly

Two stages of the first run are complete and both produced documents rather than software. Nine decisions are recorded, forty assets are measured, the runner and doctrine contracts are studied. Nothing executes yet: no schema, no collectors, no agents, no dashboard. The verification ledger is empty and says so in the file.

The problem, measured rather than felt

The first act of the project was not a design. It was a measurement of the estate it is meant to run — the Cloudflare API for zones and DNS, HTTP probes against every host, git log across the machine, gh repo list, and the DigitalOcean API. Forty domains, one afternoon, every number carrying the method that produced it.

The two findings that define the product

The highest-traffic property in the portfolio returns a Heroku Application Error. Nobody decided that. Nobody noticed.

A decision recorded in another repository the day before the measurement names a domain as a product's home. That zone holds zero DNS records. A decision was written and never reached the world — and the gap was invisible because nothing compares the two.

Six live sites have no source code on the operator's machine. Four repositories were committed to that week while the domain they serve was dead. Sixteen domains across two accounts serve one theme.

And one vocabulary note that is really a design constraint: the word active is refused. That is what Cloudflare calls a zone whose nameservers resolve — true of every dead property in this estate. The registry stores what was measured instead, which is why the states above are the states and not a health score.

03

What it has to solve

Five failures, each with the mechanism that answers it. This is the product, stated as problems rather than as features.

problem → mechanism
The failureWhat it looks likeThe mechanism
No observer A property breaks and the portfolio finds out by accident, or never. Collectors on a cadence write observations with a source and a time. Nothing is a status somebody typed.
Declared and observed drift apart A decision exists in a document while the world serves something else. Declared data is versioned in git; observed data lives in the database. Comparing them is a query, not an audit.
Work outruns attention Sixty repositories, one person, no way to know which deserves the next hour. Goals carry evidence and decompose into a graph of nodes; the CEO proposes from measurements rather than from a hunch.
Agents need a human at every step A thirty-second operation acquires an hour-long round trip, so autonomy is theatre. The fabric answers the agent by default, inside the level set on the goal, and records every answer with the rule that allowed it.
“Done” cannot be checked A calm report, a green badge, and no way to tell a clean result from a check that never looked. Every node returns what became true, the proof, the scope, and what it did not verify. A claim whose address does not resolve is not proven.

Everything else in this document is one of those five, drawn in more detail.

04

The language, because the words are the schema

Twenty-two terms are fixed. A term used in code, in a table, in a document or in an agent's instructions means what it means here — and three of the definitions exist specifically to prevent a failure already live elsewhere in the operator's tooling.

The nouns

asset
A domain, a repository, an application, an account. It exists whether or not anyone works on it and outlives every goal aimed at it.
project
A unit of work under a goal: an owner, a deadline, a budget, and the assets it touches.
goal
What the company is trying to achieve. Goals decompose into goals to any depth, then into projects — and may target assets directly.
node
One unit of work in the execution graph: one input, one job, one result, one agent.
edge
A dependency that carries data. It exists when B consumes what A produced — not when B merely happens after A.
department
A group of roles sharing instructions and a skill set. It makes hiring an agent a lookup rather than an invention.
pipeline
The route development takes, as a versioned record rather than as code: a named sequence of stages.
stage
One step of a pipeline — the department that holds it, the skills it requires, the gate that closes it. The stage is the template; the node is the instance one agent held.
skill
A registry object with a name, a source, a version and the departments allowed to use it. An operator-written skill registers exactly as a shipped one does.
agent
An instance that does work: a role, a skill set, the terminal it runs in, and the node it currently holds. Agents are hired and retired; departments are not.
CEO
The single agent that reads the estate, proposes goals, decomposes them, hires the agent each node needs, and escalates at the line the goal's autonomy level draws.
observation
A measured fact with a source and a timestamp — never a judgement.
decision
A settled choice with its reasoning, append-only. A reversal is a new decision that says so.

Why asset and project are separate — the most load-bearing line in the schema

One table for both makes the status closed ambiguous between the product is shut down and the work is finished. That failure is already live in the operator's issue tracker, where the flagship product is marked cancelled while serving traffic. (ADR-0003)

The words about authority

autonomy level
A field on the goal: safe · guarded · maximum. Sub-goals inherit and may never exceed their parent.
the floor
Never automatic at any level, enforced by the schema: spending money, deleting, and outward publication under the operator's name.
grant
A named, specific, expiring exception for one action on one target. “Deploy to staging once lint and the suite are green” is a grant; “just do everything” authorises nothing.
question
A point where a running node cannot proceed without a permission or a choice. Answered or escalated — never silently allowed, never silently dropped.
escalation
A question the fabric may not answer, routed to the operator with the node's state preserved. It is the exception, not the step.

The words about the estate

estate
The whole set of assets the fabric watches: a personal Cloudflare account and a second personal account, 40 domains. A corporate account's 31 zones are visible and explicitly unmanaged (out of scope).
declared
What the operator or the CEO stated to be true. Versioned in git, so a portfolio decision arrives as a diff.
observed
What a measurement returned. Lives in the database, never hand-edited, always carrying source and time.
cluster
Assets serving one theme from one source, tracked together because a decision about one is usually a decision about all.
05

Roles, and how they are supposed to work

There are exactly three kinds of actor, and the split is deliberate: the human owns meaning, the agent owns execution, the mechanism owns enforcement. Anything a mechanism can decide reliably must not depend on an agent remembering a paragraph — a test is stronger than an instruction, a precondition stronger than a warning, and a credential that cannot reach production stronger than a sentence saying not to use it there.

The departments already defined

A department is a lookup, not an invention — and the table it looks into already exists as the operator's own skill family. Eight roles, each shipping its own skills, versioned independently.

The pipeline is yours to change, and that is a decision, not a setting

Which stages exist, which department holds each one, which skills it requires — all of it is a versioned record you edit in the product. Your own skills register exactly as the shipped ones do; there is no privileged tier. Editing makes a new version pointing at its predecessor with a reason, and a running graph pins the version that was in force when it started, so an edit never reaches work already in flight. (ADR-0009)

And the agents themselves are not ours

The fabric hires Claude Code, Cursor, OpenClaw, Codex — whatever the node needs. It does not build an agent. That means two shapes have to be supported forever: a library channel with typed results and callbacks, and a subprocess channel for everything that only speaks a command line. The runner is therefore an adapter interface from the start, not a Claude-specific driver.

This is settled by measurement, not preference: the typed channel exists only for TypeScript and Python, and Cursor and OpenClaw must be driven as processes regardless. (external-contracts.md §1)

06

How a goal becomes work, and comes back

The cycle is closed on purpose. What an agent produces re-enters as a new measurement of the same estate that started it, which is the only reason a completion claim here can be falsified from outside.

Terminals live inside the product — and that is why there is one window

Real console terminals are hosted and rendered in the fabric: the session the agent actually runs in, live, typeable, and readable by the CEO as an observation rather than as the agent's report about itself. An operator who has to open a second application to see what an agent is doing has the coordination problem back, one layer up. (ADR-0008)
07

Who decides what

Autonomy is a field on the goal, so “restore a site that fell over” and “launch a new product” are not governed by the same rule. What the fabric may answer is derived from that field and the floor — never configured separately, because two definitions of the same authority drift and one field does not.

08

What “done” is allowed to mean

When agents write the code, done stops being a status somebody sets and becomes a state of the system that can be proven. Every completion claim must point at a record another actor can resolve; if the address does not resolve, the claim is not proven.

DONE  what became true
PROOF  what was executed or observed, and where the result lives
SCOPE  the commit, environment, requirements and surfaces covered
NOT VERIFIED  what was not checked, could not be checked, or stays uncertain

NOT VERIFIED: none within the stated scope is a valid answer. Silence is not.

Six states, and the usual failure is skipping to the last

generated→executed→passed→verified→validated→accepted

verified is the expensive one: a check ran and has been watched discriminating failure from success. Every guard is fed a planted defect and required to reject it; a check that stops rejecting its own plant is a red step, not a green one. A green nobody has seen go red is not evidence.

Delivery is not outcome. A restored site answering 200 is verified; the traffic returning is a separate, later observation, and unobserved is a legitimate state. Pretending the first proves the second is precisely what this vocabulary exists to stop.

What the schema does not have yet

Completion is a coverage relation across three graphs — intent, execution and evidence. The fabric has the execution graph and an implicit intent graph. The evidence graph does not exist. Building it after the code exists lets the output decide what counted as success, so it belongs in the schema milestone, not later. (CO-023, adopted-doctrine.md §1)

Where this sits, and one branch that was declined

Three shipping products are the honest comparison set, and all three are further along than this project. The difference is not a feature list — it is which question the tool answers. All three answer how the work gets done. None answers what work is worth doing.

Paperclip would accept “restore the site that fell over” as a goal and run it to completion with budgets, approvals and an audit trail. It would never tell you the site fell over — nothing in it reads a DNS zone, probes a host, or compares a decision recorded in one repository against what the world serves. An org chart for agents assumes somebody already knows what the work is; across forty domains that assumption is exactly what fails.

The branch that was measured, costed and declined

Paperclip has already shipped counterparts to seven of this project's milestones — the floor and grants, departments and hiring, the CEO loop, connectors as plugins, scheduled checkups, skill provisioning, and the MCP surface. Adopting it for execution and keeping only the observer would have collapsed nineteen milestones to about five.

Declined: one piece of software must watch everything. Every milestone in this document is therefore a deliberate rebuild, and no later run may report the overlap as a new finding.

The cost is stated in the decision record rather than left to be discovered: the terminal layer is the most expensive component in this class — measured against Orca, five patches to @xterm/*, one to node-pty, a WebGL renderer, scrollback surviving restarts, and a benchmark suite gating typing latency. The mitigation is named but not yet chosen: those parts are MIT and liftable, and a library seam is not a roadmap dependency. (ADR-0008, CO-027)

One finding worth keeping in view

“Terminals inside the fabric” does not force Electron. A PTY host plus xterm.js in a browser tab over a WebSocket satisfies it exactly as an Electron main process does — the tab is the fabric. So the shell question stays open and merely constrained: whatever wins must host a PTY and stream it at interactive latency. The stage-0 leading option — local web plus a privileged daemon, Electron wrapper later — survives. (CO-001)

13

What it does, and what stays with you

A system that claims to run a portfolio has to be explicit about where its authority ends. This is that line.

The fabric

  • Measures the estate on a cadence and stores what it measured, with source and time
  • Compares declared against observed and names the gap
  • Proposes goals from measurements, with the evidence attached
  • Decomposes a goal into a graph where one node is one agent, one job, one result
  • Hires the agent each node needs and equips it before it starts — an unequippable node fails at its gate
  • Runs it in a real console terminal inside the product, and reads progress from that session rather than from the agent's report
  • Answers the agent's questions inside the level you set, recording each answer with the rule that allowed it
  • Returns proof rather than a claim, and says what it did not verify
  • Refuses the floor — always, including at maximum

You

  • Set the goal and its autonomy level — the one field everything derives from
  • Shape the pipeline: which stages, which department per stage, which skills — and add your own skills, which register exactly as shipped ones do
  • Decide the floor cases: money, deletion, publishing outward under your name — or issue a named, expiring grant
  • Supply the access nobody can issue for you: registrar exports, OAuth clients, deploy credentials
  • Make the business calls: whether a dead property is worth restoring at all, or should be retired
  • Answer the judgment questions — whether a trade-off is acceptable
  • Look at each milestone and say continue

Notice what is not on your side: approving each file read, each command, each local edit. An agent that needs a click per action is an expensive keyboard macro, and a thirty-second operation behind an hour-long round trip is not autonomy at any level. Authority belongs where a wrong action outlives the run — not everywhere.
