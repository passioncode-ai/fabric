#### solution
- Контрольный продуктовый цикл — fixture HTTP service с заранее внесённым дефектом; observer измеряет ответ, записывает observation, manager предлагает repair task, checker разрешает узкое изменение, worker исправляет, независимый process повторяет HTTP+regression probe и сохраняет receipt, manager обновляет решение/память и ставит следующий check.
- Один corpus, одинаковые policy/context pins и два адаптера исполнителей; начать с Claude Code и Codex только после версии/capabilities conformance каждого. Сравнение делается по результату и вмешательствам, без переноса private session state.
- Фиксировать safety как обязательный набор pass/fail, quality как явно оценённые критерии; cost/latency наблюдения, а не основания ослабить запрет. Seeded negative controls проверяют и executor, и judge.

#### interfaces
- LoopFixture@1 {case_id,seed,service_fixture_hash,initial_observation,expected_change_scope,forbidden_effects,verification_command,expected_result,context_pack_hash,policy_revision}
- LoopResult {case_id,runner_revision,workflow_run_id,task_run_ids,observation_refs,decision_refs,artifact_refs,verification_receipts,interventions,usage:{known,unknown},wall_time_ms,outcome:verified|failed|inconclusive}

#### invariants
- Worker cannot be sole verifier of its own output.
- A task done claim and exit0 do not mark project outcome verified.
- Runner comparison excludes unavailable telemetry rather than filling it with zeros.
- Unknown native checkpoint/resume ability is unsupported capability, not an emulated guarantee.

#### failure_cases
- Observer unavailable -> inconclusive, no fabricated incident.
- Worker edits outside fixture -> checker deny, trial failed even if HTTP repaired.
- Verifier planted always-pass implementation must fail negative control.
- Swap runner with missing continuation capability -> handoff via fresh TaskRun/context, explicit continuity boundary.

#### migration
- Add fixture and deterministic fake adapter before paid trials. External trials activate only with S03 effects, scoped credentials and approved test resource. Keep historical run bindings pinned; new candidate changes future runs.

#### tests
- Plant HTTP500 and unrelated missing endpoint: repair case must pass, wrong-target case must fail.
- Replay every candidate trace twice: scoring and causality unchanged.
- Run same fixture across two admitted runner revisions; save distributions and counts, no universal model superiority claim from a small sample.
