#### solution

##### entry
Предложено заменить decision или manager пытается settlement.

##### exit
Разрешённый checked change либо approval question с original/replacement/impact; current memory не меняется до принятия.

##### recipe
Pure criticality module считает компоненты по authoritative current snapshot; separate hard-floor predicate; commit повторно проверяет dependency/policy revisions.

##### preview
Original→replacement, причина изменения, влияние и действие человека. Score details раскрыты, но причина запроса видна.

##### states
no-change,eligible,requires-human,stale-assessment,declined,approved; trust is context not green permission badge.

#### interfaces

##### route
Board item=question:<approval_id> ↔ decision SCR33 original/replacement

##### canonical_id
change_proposal_id + base_decision_id/revision + assessment snapshot seq/policy revision

##### dto
DecisionChangeAssessment {original,replacement,componentValues,score,threshold,hardFloors,affectedRefs,permissionVerdict,evidenceRefs}

##### command
decisionChanges.assess is pure/read-only and returns assessment with pinned inputs. Applying a proposal is owned by M157 and its M168 checker + S06 atomic commit, with current revision/authority revalidation. M158 itself has no commitApproved writer.

##### read_policy
Assessment detail ordered original → proposed replacement → impact → hard-floor reason → score components. No data/unknown dependency count is incomplete, not zero criticality. Refresh keeps draft and invalidates stale assessment.

##### outer_envelope
Query: canonical ReadEnvelope<T>; mutation: Command<T>/CommandResult<T> from system-contract §4–5. UI lifecycle labels are local, not wire enums. New seq/epoch: decimal strings.

#### invariants
- Score never overrides person/auth floor.
- Released status/dependent count unknown → incomplete assessment, cannot auto-settle.
- Threshold comparison explicitly above per ADR; test equality separately, not accidental >= assumption.

#### failure_cases
- Dependencies change between render/approve; project weight changes; person provenance null/unknown; grant expires.
- Approved proposal targets old superseded decision → conflict, refresh before resubmit.

#### migration
- No global new opinion score stored as truth; assessment receipt carries source revision for audit.
- Provenance unknown treated conservatively, not guessed agent.

#### tests
- criticalityBoundaries: threshold-1/equal/+1, dependency cap, negative inputs rejected.
- criticalityChangedSnapshot: stale approval conflict.
- criticalityHumanFloorIndependentOfScore.
