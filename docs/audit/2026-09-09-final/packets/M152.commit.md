#### solution

##### entry
Question detail Board или approval/change detail; оператор выбирает option или вводит ответ, видит scope и затронутые задачи.

##### exit
Committed receipt с question revision, decision ref и остатком blockers; затем отдельный delivery status.

##### recipe
Одна server transaction проверяет open+expectedRevision+scope+policy, фиксирует answer и decision lineage и обновляет все blocker множества. Один command_id определяет retries. Не делать два независимых append без общей atomic boundary.

##### preview
До commit: зачем ответ, варианты/последствия, primary Submit. После: кто ответил, ответ, decision link, «продолжение готовится/не требуется».

##### states
editing/submitting/committed/conflict/rejected/retryable. Business answered не равно delivered и не значит task done.

#### interfaces

##### route
Board route + item=question:<id>; после commit сохраняется detail answered item

##### canonical_id
question_id + expected_question_seq; decision_id + answer_command_id

##### command
questions.answer({command_id,question_id,expected_seq,answer,chosen_option?,authority_ref?})

##### response
AnswerCommitReceipt {question_id,decision_ref,commit_seq,remainingBlockersByTask,continuationRequired,delivery_ref?}

##### read_policy
Question detail fixed by ID; options keep declared order, consequences do not re-sort. Draft persists on error/conflict; current question seq required. Reconnect checks command status before resubmission.

##### outer_envelope
Query: canonical ReadEnvelope<T>; mutation: Command<T>/CommandResult<T> from system-contract §4–5. UI lifecycle labels are local, not wire enums. New seq/epoch: decimal strings.

#### invariants
- Нельзя получить answered без decision при decision-producing contract или decision без committed answer.
- Human answer не требует выдуманных citations; agent settlement проходит M157/M168.
- Два open question Q1/Q2: ответ Q1 снимает только Q1.
- Нельзя выдать effect grant через текст ответа без существующего typed authority boundary.

#### failure_cases
- Double click и ответ с другого клиента → одно winning commit, loser получает current receipt/conflict.
- DB outage после client timeout → запрос command status/retry тем же ID; draft сохраняется.
- Option ID исчез в новой question revision → reject stale, не сопоставлять по label.
