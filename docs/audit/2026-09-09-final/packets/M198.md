#### solution

##### choice
Preserve v1 displayed revision semantics (initial1 + number of legacy config-changing events), but derive absolute revision from journal prefix rather than mutable projection state. Future config reference adds event_seq+snapshot_hash to remove ambiguous historical labels.

##### algorithm
- For first project.created@1 assign revision1. For legacy config events at seq S assign 1+COUNT(effective project.updated@1/project.settings.updated@1 events for this estate/project from its first valid create through S), not current row+1. A duplicate legacy create also assigns the prefix-derived absolute value, not an accidental reset. Ordered replay over existing rows converges. Orphan pre-create updates are diagnosed and not counted as effective changes. Add scoped partial index for the legacy prefix query.
- For new config commands, transaction validates expected revision and emits project.configuration.changed@2 with absolute next_revision, previous_ref and canonical snapshot_hash. Projector assigns the recorded number/snapshot, never recomputes from current mutable projection. Legacy-to-v2 cutoff per project is explicit; later legacy guarded config writes disabled.
- ConfigRef={project_id,revision,event_seq,snapshot_hash}; run pins this immutable ref. A numerical legacy revision that drifted due rebuild is retained as legacy_display_revision only, not presumed an exact snapshot identity.

##### serialization
Public config_revision is opaque Revision string through common serializer. Internal prefix-derived numeric bigint remains SQL arithmetic; no client arithmetic or unsafe Number conversion.

#### invariants
- Two rebuilds identical incl config_revision; no replay increments.
- A revision pin cannot silently retarget to another snapshot.
- S02 scope validates event project matches aggregate before new config writes.

#### failure_cases
- Existing project revision inflated by previous rebuild → canonical correction plus retained legacy label; no invented historical mapping.
- Two config updates same expected revision → onecommit, otherstale.
- Late replay event cannot increment beyond prefix-derived revision; out-of-order projection application is refused by projection cursor, full replay ordered.

#### migration
- New append-only migration replaces only per-concern projector; keep M97 dispatcher shape. Backfill canonical revisions from journal and capture before/after mapping once.
- Return config_revision to P24 snapshots; expand parity set to new config_versions when added. Validate historical persisted references before conversion; references without supporting seq/hash remain explicitly unverified.
- Existing renderer uses revision for refresh and display; preserve positive integer and add structured refs without silently changing wire type.
