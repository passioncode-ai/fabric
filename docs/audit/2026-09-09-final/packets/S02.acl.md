#### id

#### depth

#### solution
- Revoke unintended anon/PUBLIC rights on app-owned tables explicitly, instead of relying on a default-privileges statement that only governs tables created afterwards.
- Split the P21 assertion into ACL capability and RLS row visibility, because a passing grant check and an enforced policy are different claims and the log conflates them.

#### interfaces
- An append-only ACL repair migration; P21 reporting privilege and visibility separately, each with its own positive control.

#### invariants
- service role reads every app table; anon holds no SELECT privilege; an authenticated member sees their estate and not another's.
- Granting anon SELECT inside a rolled-back fixture still yields zero rows, which is what proves RLS separately.

#### tests
- Role matrix over an isolated migrated database; a temporary table per relevant owner/default set.

#### migration
- Additive revocation; required service DML is not stripped before its writer moves to typed RPC.

#### failure_cases
- A missing grant looks exactly like an empty table, which is the failure this repair exists to stop recurring.
- CLI/image drift changes the inherited default; the manifest records the measured versions rather than asserting a cause.
