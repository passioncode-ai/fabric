#### solution

##### choice
Resolve contradictory ADR grain explicitly in a NEW proposed ADR: WorkflowRun preserves0030 graph walk and existing run_id wire; TaskRun is a new canonical task_run_id for one admitted explicit task invocation. fabric_session_id/native_session_ref are separate and may span sequential TaskRuns only through a verified adapter. This deliberately narrows0042 no-new-id assumption while preserving its fresh progress per iteration and journal-projection architecture.

##### entities
- WorkflowRun pins graph declaration version, config/binding/provider/policy/engine refs, budget and cancellation context. Rendered graphs are queries; immutable graph/plan definitions and event receipts are allowed, not a second mutable visualization graph.
- Every explicit task evaluation loop pass creates fresh TaskRun after admission, with new plan/step state. A denied admission is no run. Transport retry/LLM hidden internal turn is Attempt/unknown-internal-work, not another TaskRun.
- PlanRevision immutable within TaskRun: plan_revision_id, revision_no, supersedes_plan_revision_id, reason, total_known, step definitions. StepId stable across replans only for same semantic operation; changed operation new stepId with supersedes reference.
- Step claims and verification observations independent. Plan can support parallel sibling steps/dependency DAG and nested parent steps; parent progress derived from child receipts and never a second mutable number.

##### states
- TaskRun runtime terminal once ended; result/verification evidence may arrive later as linked assessment, never rewrite terminal runtime receipt. WorkflowRun terminal state immutable; continuation new WorkflowRun with predecessor_ref.
- StepClaim planned→active|skipped; active→blocked|done|failed|skipped; blocked→active|failed|skipped; terminal claim within that plan revision not reopened. Corrected work declares new revision/step or next TaskRun. done is agent claim; verification pass/fail/not_run/unknown has separate source.
- Replan atomically activates new plan revision via expected_current_revision CAS. Old definitions and claims freeze for current-view purposes. Same-run carryover of completed step allowed only with explicit carryover_ref and unchanged inputs/operation; fresh TaskRun always resets all steps.

##### transactions
- declarePlan(scope,key,expectedPlanRevision,steps): require active admitted TaskRun/current lease, validate unique step ids, existing parent ids, no parent/dependency cycle, valid needs, bounded text/step count, all evidence/input refs scoped. Store complete immutable declaration and supersession event; no partially declared plan.
- reportPlanStep requires task_run_id from credential, exact plan revision/step, expected step revision, valid transition and current lease. Late old-run/old-plan event refused with safe trace; cannot mark successor progress. Idempotency returns original event. Verification uses separate observer-authorized recordEvidence command.
- saveExecutionSnapshot stores {execution_snapshot_id,task_run_id,plan_revision_id,step_claim_watermark,input_refs,artifact_refs,budget_counters,last_committed_seq,adapter_state_ref?}; finalize only after referenced command receipts exist. This is durable resume state, not Checkpoint gate verdict. No hidden model chain-of-thought stored. Resume reconstructs accepted plan/claims; new explicit evaluation uses new TaskRun with fresh statuses. A gate checkpoint may reference this snapshot; snapshot alone never authorizes continuation.

#### invariants
- Every explicit iteration has fresh TaskRun/steps, even reused native session; never infer internal loop counts.
- No stored visualization graph or mutable plan history; graphs are queries over immutable declarations/receipts.
- A step done does not mean verified or task done.
- run_id is not silently reinterpreted; v2 names are explicit across schema/IPC/MCP/adapters.
- Gate checkpoint verdict and durable execution snapshot are separate records: snapshot persistence is no permission to resume across an unresolved gate.

#### failure_cases
- Late step done fromrun1 arrives whilerun2active → rejected, run2unchanged.
- Concurrent replan from samebase → one active revision, other stale; old historical claims remain.
- Partial input set or unknown total → no fabricated percentage denominator.
- Adapter says native resume supported but lacks invocation mapping → no session reuse.
