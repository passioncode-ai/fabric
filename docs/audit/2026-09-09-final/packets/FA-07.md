### observed
OPERATOR_ACTOR литерал; runtime использует service-role. Последний owner защищён триггером; login/invite transport и authenticated RLS через приложение отсутствуют.

### solution
IdentityPort получает проверенный auth subject в доверенном процессе; membership revision проверяется на каждом command/read. Supabase Auth — предлагаемое минимальное решение, выбор провайдера остаётся design gate. Service-role не раздаётся клиентам; privileged backend actions имеют отдельную границу.

### steps
- Закрепить identity/session/revocation contract и миграцию literal operator к person.auth_user без смены авторства истории.
- Реализовать login return с сохранением invite и revalidation expiry/revocation; transport invite выбрать отдельно.
- Проверить read/command/MCP/file capabilities после revoke, logout и смены estate.
- Прогнать owner/member/outsider роли на disposable stack включая прямой SQL/RPC и последний owner race.
- Сохранить estate-wide visibility v1; project ACL не имитировать renderer filter.

### acceptance
- Actor нельзя передать с клиента; outsider не читает и не пишет чужой estate.
- Отзыв membership инвалидирует уже загруженные данные и grants на следующей операции.
- После login человек возвращается к тому же приглашению; revoked/expired не принимается.
