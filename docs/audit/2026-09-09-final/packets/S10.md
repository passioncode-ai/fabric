#### solution
- Две независимые правды: нормативное целевое устройство (this system-contract + domain dossiers + model JSON) и состояние реализации (code pins + probe receipts + backlog). Diagram генерируется из model JSON, а не редактируется отдельно. Per-card engineering catalog связывает каждую текущую карточку с контрактом/обоснованием/tests/files.
- Уточнить термины WorkflowRun / TaskRun / Session / CycleInvocation / ExecutionAttempt / Iteration до реализации M188 и M194. Новые предлагаемые семантики записать в новых ADR; старые записи не править. Принятие новой ADR запускает propagation CONTEXT/architecture/schema examples/UX/contracts in one change.
- Read statuses, execution statuses, decision claims и independent verification — разные типы. Запретить общий done как измерение проекта без источника. Exact event type IDs берутся из versioned registry, proposed IDs маркируются до регистрации.
- Генератор карты и checker проверяют coverage, IDs, links, meaningful edge payloads, allowed lifecycle transitions, graph cycle exceptions, source fingerprints. Семантический review всё ещё обязателен: gate не понимает правильность бизнес-решения.

#### interfaces
- SystemModel@1 {modules,entities,relations,flows,cycles,decisions,sources}; Catalog@1 {input_plan,items,execution_nodes,dependency_edges,requirements}; generated HTML never owns a domain fact.
- ImplementationEvidence {capability_id,design_status,implementation_status,verification_status,installation_status,observation_status,receipts[]}; no single averaged readiness score.

#### invariants
- All57 source cards accounted for including shipped preserve rows; do not silently reimplement shipped foundations.
- All proposed API/schema names labeled future; paths to create distinct from current evidence paths.
- Rejected/pre-admission work is not a successful or failed runtime iteration.

#### failure_cases
- Remove task from catalog -> coverage gate red.
- Edit diagram without model -> generated-output parity red.
- Unknown event claimed implemented -> source evidence check/review red.

#### migration
- Introduce target design as explicit recommended baseline; implementation retains existing wire until versioned migration. Historical audit snapshots keep dates/source commit and link forward to current target.

#### tests
- Run node scripts/check-system-model.mjs and builder --check; negative fixtures remove card, reference absent node/source and stale output -> fail.
- Review every proposed semantic reversal against ADR0030/0042/0043/0041/0018 before marking accepted; implementation agents execute specified migration not choose ontology.
