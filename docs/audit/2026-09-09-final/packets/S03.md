#### solution

##### split
S03.boundary supplies shared per-command scope/floor/revision/grant reservation. S03.effects adds actual adapter dispatch, attempts, observations and unknown reconciliation. S04/S06 require boundary, not a finished external connector.

##### states
- Grant: available → reserved(command_id) → consumed(at dispatch fence); available/reserved → revoked; expiry blocks new reservation/dispatch. Release reservation only with proof no dispatch occurred, by explicit command.
- EffectIntent: proposed → reserved → dispatching → succeeded | failed_known | outcome_unknown. reserved → cancelled_before_dispatch. outcome_unknown is unresolved, not success; reconciliation creates new evidence and resolves it. Terminal result receipts immutable.

##### transactions
- issueGrant preallocates grant UUID and appends grant.issued@2 with full scope/action/target/revision/expiry; projection built in same transaction. reserveEffect locks grant and effect command, checks DB now<expiry, revoked_at=null, project/action/target exact match, precondition/current revisions, all ceilings minimum and absolute floor; unique reservation grants at most one command. Refusal carries safe reason, never executed.
- beginEffectDispatch checks current principal fence, policy revision, grant not revoked/expired, budget and reservation; records attempt + dispatch_started and consumes grant before releasing transaction. External call occurs only after commit. A one-shot grant authorizes the logical effect; adapter retries use same effect idempotency key, not a second consumption.
- observeEffect requires trusted adapter/reconciler capability, matching attempt/provider effect ref and structured evidence; agent prose is a claim. Commit observed outcome + receipt atomically. Crash after effect but before receipt → unknown; lookup provider by same key/ref, never new key retry.
- Release and beginDispatch take the same grant/reservation lock. Release succeeds only while every recorded attempt proves not dispatched; absence of a final receipt is not proof. The old intent retains reservation/grant lineage. A subsequent command acquires a new reservation UUID; concurrent new commands have one winner under the partial unique index.

##### redaction
Replace free-text authority target with {resource_ref,operation,canonical_target_digest}; secret-bearing target input is refused, not normalized into a different permission. Human-readable why may be redacted with count receipt. Safe sink runs in Policy/command ingress, not only AgentSurface. Never persist raw OAuth/bearer/secret material in a trace.

##### tables
- grants_v2 projection: id,estate_id,project_id,action_class,floor_class,target_ref,target_digest,issued_by,issued_seq,expires_at,grant_revision,revoked_seq,status,reserved_command_id; UNIQUE(estate_id,id)
- effect_intents_v2: command_id PK,estate_id,project_id,action_class,target_ref,target_digest,policy_revision,grant_id,reservation_epoch,state,last_receipt_seq; reservation_id FK; grant_id lineage is not globally unique across released reservations
- effect_attempts: attempt_id PK,command_id,attempt_no,adapter_revision,idempotency_key,dispatch_started_seq,provider_effect_ref,status,observation_ref; UNIQUE(command_id,attempt_no); same target idempotency key across retries
- grant_reservations: reservation_id PK, estate_id, grant_id, command_id, state:'reserved'|'consumed'|'released'|'revoked', revision, release_proof_ref, acquired_seq, released_seq; immutable lineage, event-derived status. UNIQUE(grant_id) WHERE state IN ('reserved','consumed','revoked'); released reservations keep their rows. revoked grant remains unusable regardless of uniqueness.

##### commands
- GrantIssue({scopeSubject,actionClass,targetRef,expiresAt,preconditions}) → grant receipt
- EffectReserve({actionClass,targetRef,expectedPolicyRevision}) → {effectCommandId,reservationRef} | refusal
- EffectDispatch({effectCommandId,expectedEpoch}) → durable dispatch permit, no success claim
- EffectObserve({effectCommandId,attemptId,providerReceipt,outcome}) → observed receipt
- EffectReconcile({effectCommandId}) → succeeded|failed_known|still_unknown; EffectCancel → cancel_requested|cancelled_before_dispatch
- ReleaseGrantReservation({reservation_id,expected_revision,no_dispatch_proof_ref}) → canonical CommandResult<GrantReservation>. Lock reservation + grant + intent; require cancelled_before_dispatch and no possibly-dispatched attempt; append released receipt atomically. If grant expired/revoked keep it unusable; otherwise restore available. Consumed/unknown cannot release.

#### invariants
- The DB floor validates matching live grant, not merely nonnull FK.
- A permission receipt cannot produce effect.executed.
- Revocation after dispatch does not erase or mislabel an already completed external effect.
- Cooperative MCP alone remains trusted-local tier, not mandatory CLI interception/sandbox.

#### failure_cases
- Reservation expiry/revoke between reserve and begin → no dispatch.
- Timeout after provider acted → retain reservation/unknown, reconcile before replay.
- Two grant requests from distinct projects/actions with same target → only exact granted scope succeeds.

#### migration
- No historical journal rewrite. Existing grant.issued@1 lacks grant UUID and current direct row may be unjoinable: mark legacy_unverified, preserve records, do not automatically promote unspent legacy grants to v2 authority. Require explicit reissue with exact action/scope.
- Existing effect.executed@1 produced by permission path is displayed as legacy claim/unverified unless independent evidence proves completion; add classification projection, not retroactive invented receipts.
- Switch both operator and agent effect paths to shared v2 commands in same release; legacy generic writer rejects v2 guarded types; minimum compatible writer version prevents downgrade.
