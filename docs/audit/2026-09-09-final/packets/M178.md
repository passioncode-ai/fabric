#### solution

##### choice
Heartbeat is an authenticated, run-bound positive claim with server receipt time. Persist one monotonic agent sequence per task invocation/generation; old messages cannot revive old execution. Separate reported phase, observed transport/process activity and derived liveness.

##### states
- phase enum reading/working/waiting/verifying/blocked, independently receivedAt and process state. waiting_on only valid for waiting/blocked and only current scoped question/grant/continuation.
- derived liveness working/waiting/quiet/stalled/gone plus observation coverage available/unsupported/unobserved. stalled means suspicion based on gap, never proven wedged cause.
- duplicate beat returns prior receipt without refreshing last_received_at; lower beat_seq is stale; same seq with changed payload conflicts.

##### transactions
- heartbeat({beatSeq,phase,note?,waitingOn?}) takes task_run_id/fabric_session_id/role_slot_id/binding_revision/epoch from credential. Lock current run/heartbeat row, verify active invocation and current fence, validate waiting object scope/state, append agent.heartbeat@1 with receive timestamp from DB and projection update only if seq advances.
- On newly resolved waiting object, liveness cannot remain permanently waiting on old self-report; state records wait target resolved, grace starts from resolution receipt, await next beat/work observation. Policy thresholds/cadence are resolved/pinned from estate settings + runner capability; validate stall_after>=quiet_after>=expected_interval and positive bounds.

##### time
DB/server receivedAt is authority for durable ordering; client sentAt optional diagnostic only. Local watchdog uses monotonic elapsed clock and host sleep intervals to avoid wall-clock jump errors. An unsupported beat capability is declared, not silently assigned a universal 60-second fault threshold.

#### invariants
- Heartbeat cannot update ended TaskRun or a successor run sharing native session.
- waiting_on names a current object; absence does not imply no blocker.
- A phase is a claim; heartbeat receipt is a fact; neither measures task correctness.

#### failure_cases
- Late beat from old lease/taskrun → refused and safe trace.
- Client clock+1year or out-of-order seq → no liveness extension from client timestamp.
- DB unavailable → gap/unobserved, no invented durable heartbeat.

#### migration
- No current heartbeat producer; add event/projection/tool/protocol/catalog/locale in one slice. Keep SessionState legacy compatibility mapping but new consumers read separate observation state.
- M177 must supply versioned protocol and capability declaration; session.oriented@1 existing receipt name retained.
- Existing sessions without heartbeat support are legacy/unsupported, not automatically diagnosed failed.
