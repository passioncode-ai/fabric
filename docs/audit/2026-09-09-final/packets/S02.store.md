### contract

#### id
S02.store

#### depth

#### solution
- Move the estate/project predicate out of the call site: a table→scope map derived from the schema, and a client narrowed to one scope handed to every caller instead of the naked SupabaseClient. An unmapped table is refused rather than passed through.
- Give the two projections that carried no owner one — goals and question_blocks — backfilled from the authoritative parent, with NOT NULL as the assertion rather than a silent drop.

#### interfaces
- shared/scope.ts: Scope, TABLE_SCOPE, scopeFilters(table,scope), scopeOwnership(table,scope), withinScope(scope,projectId).
- main/scopedStore.ts: createScopedStore(db,scope) with select/insert/update/delete and no escape hatch; projectStore(db,parent,projectId) refuses a project outside the parent scope.

#### invariants
- Every projection read in the main process is narrowed to one estate, and to one project where the scope names one.
- A table absent from the map raises rather than returning an unnarrowed builder.
- Scope columns are written on insert, but never the row's own primary key.

#### tests
- Two-directional map/schema parity; predicate shape per scope kind; a planted question blocking a foreign task; a block row written for a task it cannot block.

#### migration
- Additive columns with parent backfill; the projector arm for goals is extracted to its own function rather than the monolith being rewritten.

#### failure_cases
- Unknown table -> UnscopedTable naming the file to edit.
- A read that lost its predicate -> the ratchet names file and line before merge.
