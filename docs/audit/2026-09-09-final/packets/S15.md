#### solution

##### choice
One CyclePort for routine, chain, hygiene, retro, letters and manual wake; each producer declares policy and receipts. A cycle invocation is orchestration, not automatically a TaskRun or fabricated task. Before UI M186 the producers already expose truthful health/outcomes.

##### states
- CycleDefinition enabled/paused/retired plus host availability observed/unobserved; independent of execution.
- Window pending → leased → running → completed|skipped_no_delta|partial|failed_known|outcome_unknown; pending/leased → cancelled_before_dispatch. completed/skipped advance watermark; partial advances only explicitly committed subwindows, unknown never advances uncertain work.
- Active invocation can waiting/backoff without burning a worker; persisted next_eligible_at and bounded attempt budget; manual wake coalesces with eligible current window.

##### transactions
- requestCycle locks cycle slot; deterministic window key dedupes manual/cadence/Board signals, merges unconsumed event range to pending. acquireCycle assigns epoch and owner host_generation under DB clock; role cycles additionally pin role_slot_id/binding_revision and current role epoch.
- Before work persist through_seq, input ids/hash, policy and definition revision. Producer command keys derive window+logical operation, not transient attempt number. After accepted command results and checkpoint persist atomically, completeWindow advances completed watermark. Late completion by previous fence refused.
- Wake-worthy event class registry ignores heartbeat/tool trace/checkpoint and self-only maintenance; consume each eligible source event once. A worker result sharing causal root is eligible; no blanket suppression of all descendants. Bound chain hop/iteration and total model/time/cost budget independently.

##### time_policy
Interval routines use UTC interval origin and coalesce_missed_once. Calendar letters use timezone + calendar day key with preserved one-per-day windows; catchup each bounded by max starts per poll. Persist DST policy: nonexistent local trigger→next valid time; ambiguous→first occurrence, one logical window. Record calculated UTC bounds and tzdb/runtime version. If policy changes, new definition revision; never reinterpret old window keys.

##### app_off
A disabled/offline host cannot produce new health receipts. Last observer timestamp and reason remain visible. No always-on claim; next launch processes explicit catch-up. Unknown crash gap cannot be labeled confirmed app closed. Diagnostic source-down overlay is separate from business success.

##### commands
- requestCycle({cycleId,triggerRef,eventThroughSeq?}) → window id/coalesced
- acquireCycle({windowId,expectedDefinitionRevision}) → lease epoch/input window
- checkpointCycle({invocationId,expectedEpoch,checkpointRef,committedCommandRefs,throughSeq}) → checkpoint receipt
- completeCycle({invocationId,expectedEpoch,outcome,completedThroughSeq}) → summary receipt

#### invariants
- Watermark advances only past durably accounted input.
- Manual/cadence/Board triggers use same admission and budgets.
- Last run started is not last successful outcome.
- Replay reconstructs receipts/epoch values, never dispatches external work.

#### failure_cases
- Two hosts acquire same window → one owner.
- Crash after command commit before checkpoint → lookup same command key and resume, no duplicate effect.
- Outdated role binding completes cycle → fence reject; successor can reconcile prior receipts but not inherit live authority blindly.

#### migration
- Adapt current routine.ran/paused@1 to legacy started/paused observations; never invent completed receipts from those rows.
- Add explicit definitions for existing routine/chain/notifier first; future producer absent reads not_configured, not healthy.
- S04 launch port reused; small CyclePort module need not wait for M186 or a model. Reference durable engine binding remains ADR0022; local profile truthful.
