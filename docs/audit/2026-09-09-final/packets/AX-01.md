### context
Table exists but runtime does not complete its lifecycle. Admission returns task_run_id and pre-spawn session; handler ignores ID, pty generates another, projector never corrects it; no runtime run.ended producer. Current renderer still starts through legacy create+spawn. Upgrade trap: commit 242eeb8 edited already-existing migration44 to emit run.started while migration49 does not replace admit_task_launch; upgrading from 0a5e932 leaves original function unless migrations are replayed manually.

### solution
Create one launch service for recorded tasks and every trigger; allocate stable command/run/session identities before spawn or append explicit session binding under epoch. Persist dispatch state/outbox. Finalize every admitted run including spawn failure, exit and restart; guard old generations. Deliver acknowledgements under run+epoch+digest.

### decomposition
- Define command/run/session/epoch DTO and migration with immutable ended constraints.
- Make creation separate from admission; migrate all operator/routine/chain callers; expose startExisting in actual task UI.
- Bind allocated identity through PTY/bundle or atomically attach actual session and run before delivery; record running/ended transitions and recover abandoned admission.
- Make transport write receipt originate at actual flush, ack receipt at authenticated agent acceptance; stable replay never inserts text twice.
- Add integration harness using fake PTY + real temporary schema and exercise renderer→IPC→launch→ack→exit; retain scenario receipts.

### acceptance_positive
- One UI start yields one task, one run, one actual session and ending receipt.

- Wrong session/old epoch/wrong digest refuses ack.
- No run for denied admission; no duplicate write after lost response; no run state rewrite after ended.
