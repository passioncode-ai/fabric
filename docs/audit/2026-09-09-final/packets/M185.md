#### solution

##### entry
Estate home inbox preview, project event strip, attention toolbar.

##### exit
Needs-you→exact Board item; Happened→source subject/receipt; Back restores lane/filter/cursor.

##### recipe
Use BoardService for needs-you and safe NotableEvent query for happened. Add operator-specific acknowledged seq/cursor/preferences only; do not clone business obligations. Dedup source command/obligation, distinguish occurrence and resolution events.

##### preview
Needs-you count/actions and a few happened items; each has project/source age/severity. Full Inbox supports filters.

##### states
loading,verified empty,partial producers,stale,reconnect,read/unread,source unavailable; no read watermark advance from new event arrival or error.

#### interfaces

##### route
#/e/:estate/inbox?lane=needs-you|happened&project=:projectId&item=:canonicalRef

##### canonical_id
Needs-you BoardItem ID; Happened journal estate+seq or canonical source-event ID

##### query
inbox.query({operator,scope,lane,filters,cursor,asOfSeq}); returned DTO sanitized before renderer

##### command
inbox.markRead({operator,visibleThroughSeq,expectedCursor}) only happened

##### dto
NotableEvent {id,kind,title,occurredAt,recordedSeq,actorRef,subjectRef,severity,sourceRefs,readState,detailSafe}

##### read_policy
Needs-you inherits Board rank; Happened recorded seq desc, filters project,event kind,time,read state. Per-operator read cursor never advanced by passive delivery/error. Complete empty distinct from uninstrumented producer.

##### outer_envelope
Query: canonical ReadEnvelope<T>; mutation: Command<T>/CommandResult<T> from system-contract §4–5. UI lifecycle labels are local, not wire enums. New seq/epoch: decimal strings.

#### invariants
- Opening/marking read never resolves obligation.
- Per-operator state cannot mark another operator read.
- Exact source inspection never exposes unredacted raw payload by default.
- No notification source implies source coverage unknown, not zero events.

#### failure_cases
- Old event replays/duplicates; two clients updating cursor; new event arrives before read request; source removed or permissions changed.

#### migration
- Settings/read-cursor schema additive and local/per-operator. Migrated history remains unread/unknown according to explicit initial policy; no arbitrary latest seq auto-read.

#### tests
- inboxReadCursorRace; inboxNeedsYouNotDismissable; inboxSubjectDeepLinks; inboxSafePayload.
