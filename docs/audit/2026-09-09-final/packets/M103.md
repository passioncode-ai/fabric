#### solution

##### choice
DeliveryPort produces persisted delivery identity and explicit milestones: process_started, transport_ready, bytes_written, adapter_accepted, agent_accepted. Only correct invocation-scoped ack moves task to running; a prompt heuristic cannot substitute. Native session reuse is available only when adapter can bind each invocation to task_run_id and fence.

##### states
- queued → waiting_ready → written_unconfirmed → accepted; waiting_ready → failed_before_write; written_unconfirmed → outcome_unknown on timeout/disconnect, not automatically resent.
- cancel_requested blocks future writes; written command requires receiver cancellation ack/observed invocation end before cancelled.
- Task attached is a relation, not confirmation. agent_accepted is an agent claim received by Fabric, not proof of understanding or success.

##### transactions
- Create delivery_id and instruction_digest/inputRef atomically with TaskRun launch outbox. Structured adapter receives envelope with task_run_id,delivery_id,run fence,protocol_revision and input_ref. Ack must match all and come through that run-scoped credential; duplicate same ack returns original receipt, different digest/recipient refuses.
- Reuse live native session only after previous TaskRun terminal and old credential fenced; new invocation gets new delivery_id/TaskRun/credential. Crash retry of queued delivery safe only before write proven; unknown write requires lookup/ack or operator inspection.
- Legacy PTY preserves bracketed-paste encoding, but silence/deadline is only a readiness hint. After one write return unconfirmed and expose inspect/explicit resend new-intent action. Do not queue a second prompt automatically on timeout; pending deliveries cannot overwrite each other.

##### continuation
An answered question resolves a task-addressed continuation. If original TaskRun is active and adapter supports addressed resume, deliver within that invocation; if it ended, S04 admits a new TaskRun pinned to resolution input. Never deliver to selected/latest terminal.

##### commands
- fabric_task_accept({deliveryId,inputDigest,protocolRevision}) → accepted receipt; task/run taken from scope
- DeliveryPort.send({deliveryId,taskRunId}) → queued|written_unconfirmed|accepted|unknown|refused
- DeliveryPort.lookup({deliveryId}) → versioned observed milestone snapshot

#### invariants
- No bytes-written event without writer result; no agent-accepted event without matching acknowledgement.
- Slow startup/timeout never silently changes target or doubles prompt.
- Provider-native session id never authorizes delivery to another TaskRun.

#### failure_cases
- No output until deadline → policy explicit legacy write once/unconfirmed or required structured mode waits, never accepted.
- Malformed ack and old-session late ack → refusal, current task untouched.
- Early process exit before write → failed_before_write; after write → unknown delivery with observed exit.

#### migration
- Keep asOnePaste and existing terminal methods for manual terminal use, route managed task delivery through DeliveryPort.
- Add capability flags structured_ready/task_ack/invocation_reuse separately; default legacy adapters false.
- Existing attached sessions read delivery=legacy_unconfirmed unless evidence exists. No retrospective acknowledgement from transcript or nonempty output.
