#### solution

##### choice
Introduce startExistingTask; createTask and admitTaskLaunch are separate commands. Routine may create its own task once per unique cycle window, chain must launch the existing follower. Resolve actual runner through scoped binding before quota/admission. TaskRun is created after admission as an explicit logical invocation, never because a button was pressed or an unrelated predecessor completed.

##### states
- AdmissionReceipt: refused or admitted; refused has no TaskRun.
- TaskRun: admitted → launching → active → ending → ended; admitted/launching → ended(failed_start/cancelled_before_launch); active → ending(cancel_requested) → ended only on invocation/process evidence. ended is immutable. Outcome unknown is retained as uncertainty, not inferred success.
- Task Board status stays backlog/review until agent acceptance; attached/launching is an execution indicator. On ack, task enters running; structured completed result submits review, never auto-done. Legacy delivery-unconfirmed displays live process beside unchanged task state.

##### transactions
- admitTaskLaunch(scope, key, task, expected_task_rev, trigger): under estate lock validate scope, nonterminal task, allowed explicit transition, all open blockers, pinned graph links/needs, runner capability/profile, current role_slot_id/binding_revision/epoch, fresh provider/account quota snapshot, total budget reservation and no active TaskRun. Allocate task_run_id/run_ordinal, task lease/fence and launch outbox; append admitted and return same receipt on duplicates.
- Join must group ALL incoming follows edges for follower; require each relevant predecessor terminal accepted result plus every named required output. Store chosen predecessor TaskRun/result/artifact refs in launch input lockfile. A failed/cancelled predecessor blocks with one durable eligibility-state reason, not one event every tick. Ambiguous duplicate names across parents must be explicit qualified input keys, not last-object-write wins.
- linkTasks validates scope and DAG under SAME transaction lock as append; graph traversal excludes mere provenance spawned links from dependency cycle topology unless their contract declares execution dependence. Opposite edges racing serialize; unknown/RPC error refuses. Pin graph version/as-of input; later edits affect future WorkflowRuns or explicit replans, never an already pinned execution invisibly.
- Local runner dispatch occurs after outbox receipt. Mark launch_attempt before invoking adapter. Crash between marker and physical launch leaves unknown; discover by stable task_run_id/supervisor receipt. Without authoritative lookup, do not automatically spawn again; explicit retry after reconciliation creates a new TaskRun/key linked to predecessor.

##### quota
QuotaSnapshot includes provider/account/binding revision, observedAt/expiresAt, completeness, validated numeric windows, source and limits. HTTP200 {} is unknown. Unattended admission requires a policy-approved complete source or an explicitly configured alternative capped budget profile; manual attendance relaxes advisory quota only with recorded override, never scope/floor/capability. Reserve Fabric budgets atomically; vendor account activity outside Fabric means quota is a sampled admission signal, not a guarantee of global spend.

#### invariants
- One logical launch key yields one TaskRun, one default active invocation per task.
- A task run ordinal increments only after committed admission; retries of transport do not consume a number.
- Native session reuse requires per-invocation mapping/ack/trace; CLI without this capability launches a fresh PTY.
- No port declares durable profile merely because dispatch is persisted.

#### failure_cases
- Process starts but journal response lost → discover same TaskRun; no createTask fallback.
- Runner binding belongs another project, quota sampled for another account, stale config → no admission.
- Dependency edited after pin → current TaskRun uses pinned inputs or explicit pause/replan, not silent mixed graph.

#### migration
- Add v2 task_runs/command/outbox projections and RPC first, migrate main IPC/research/routine/chain entrypoints to one port together, then disable direct guarded task launch events through generic append.
- Retain @1 task.started/session.attached semantics and build legacy history separately. Preallocate new task_run_id before adapter call, keep old session_id unchanged. A structured adapter can attach multiple sequential TaskRuns to one native session; legacy mapper cannot infer unseen iterations.
- Keep old Task.status enum; add execution indicators/DTO fields so launching does not pretend running. M103 supplies acceptance protocol; temporary legacy mode explicitly unconfirmed.
