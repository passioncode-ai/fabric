#### solution

##### entry
Agent tile, project task card, Task SCR32.

##### exit
Expand current plan, select attempt/revision, open full run history in SCR40 project DID task scope; blocker→Board question, checkpoint→evidence.

##### recipe
RunStatusReader consumes M188 snapshot and M178 observations; same DTO everywhere. Count done/declared steps in selected plan revision; skipped/failed counts separate. Support parallel active steps. Live updates preserve user selected old run/revision until explicitly switch to latest.

##### preview
Task title, Run N (no invented total), claimed done/total, current active path(s), blocker, age of contact, independent result if exists.

##### states
no-plan,declared,working/waiting/quiet/stalled/gone with evidence,partial,replanning,disconnected,reconnecting,old-revision,admission-denied without Run; admitted spawn-failure inside TaskRun,unverified result.

#### interfaces

##### route
Inline preview; #/e/:estate/p/:project/graphs/project-history?task=:taskId&run=:taskRunId&revision=:planRevision

##### canonical_id
Stable task_run_id and plan revision from target M188/S10; no UI-derived iteration from output

##### query
runs.status({scope,task_id,run_key?,plan_revision?}) → ReadEnvelope<RunStatusView>

##### dto
{taskRef,runRef,ordinal,selectedRevision,steps[],counts:{done,total,skipped,failed},claims:{phase,reportedAt},observations:{process,lastContact,detectors},blockers[],verificationRefs,availableActions}

##### read_policy
Steps declared order with dependency outline; run history ordinal/recorded seq, revision history declaration seq. Selected historical revision remains pinned. Empty plan is no declaration; stale observation and connection state separate from step status.

##### outer_envelope
Query: canonical ReadEnvelope<T>; mutation: Command<T>/CommandResult<T> from system-contract §4–5. UI lifecycle labels are local, not wire enums. New seq/epoch: decimal strings.

#### invariants
- done claim != verified outcome; no average of confidence/progress.
- Full denominator tied to declared revision, not tasks remaining.
- No plan ≠ 0%; unknown total iterations → Run3, not3/3.
- Replanning creates new revision, no rewrite of old completed steps.
- Each admitted execution iteration has its own complete plan with fresh step statuses. Plan revisions within a run preserve history; no inherited done status from previous TaskRun.

#### failure_cases
- Slow read A arrives after runB; two active paths; heartbeat fresh+tool hung; no adapter capability; retired plan steps; late old session reports.

#### migration
- Preview lightweight shell can land behind capability but not count shipped until M188/M178 data; old stage claim remains distinct.

#### tests
- runWidgetAllStatuses; runWidgetOldRevisionPreserved; runWidgetLateResponseDropped; runWidgetClaimVsObservation; keyboard disclosure.
- runWidgetNewIterationFreshFullPlan: previous done steps stay historical, current plan resets.
