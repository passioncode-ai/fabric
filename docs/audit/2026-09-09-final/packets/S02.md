#### solution

##### choice
Main derives Scope from registered webContents/window project selection or validated AgentSurface credential. A caller-provided estate/project is a requested object selector, never authority. Introduce scoped repository interfaces so schedulers cannot receive naked SupabaseClient. Keep local operator identity explicit; do not claim this completes authentication/team roles.

##### transactions
- For every command, re-read parent project/task/agent/session/repo membership under one scoped transaction; compare estate and project on all related IDs. Add composite identities UNIQUE(estate_id,id), UNIQUE(estate_id,project_id,id) where required and composite FK on v2 relationships. No UUID-shaped binding is admitted solely because it exists.
- Local trusted main can supply system actor only from hardcoded scheduler capability, not renderer input. Task/result writers check execution lease+binding revision inside guarded RPC. Read queries always carry estate predicate, plus project predicate for project scope; no array of foreign IDs assembled by unscoped preliminary query.

##### filesystem
Per-window/per-project RootGrantSet, not global union. resolve(scope,root_ref,relative_path) resolves actual parent/target and enforces boundary at each operation. Native folder selection grants only that window/context; no widening other windows or agents. Existing realpath check protects static symlink escape but not an attacker replacing path components concurrently. Trusted-local profile may retain this stated limit; untrusted-repo profile requires dirfd/handle-relative no-follow opens or sandbox, and stays unadmitted until race fixture passes.
