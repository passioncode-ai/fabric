#### solution

##### choice
Observer runs outside agent and independently of the PTY dispatch event queue. Use a dedicated worker event loop for main-loop responsiveness/monotonic host sampling; process identity includes PID+birth/start fingerprint+host_generation. Its bounded spool remains able to report DB/main-loop unavailability; no perpetual daemon is introduced.

##### detectors
- Orientation unconfirmed: no successful/recorded protocol delivery within grace. Existing session.oriented@1 is only request-side evidence; append may fail while rules are delivered and may precede response completion. Classify unconfirmed, not skill-failed.
- Agent signal gap with host and transport known healthy → stalled_suspected; recent valid heartbeat plus long silence → quiet/working, not fault.
- Observed invocation/process exit → runtime ended. Exit0 does not prove task result success. PID reuse must not resurrect task invocation.
- Host suspend/resume/main-loop-unresponsive or DB outage → observation gap on host/source; suppress agent-specific blame until observer reacquires fresh evidence.

##### transactions
- Condition occurrence key {task_run_id,detector_kind,condition_generation}; transition healthy→suspected appends one finding. Repeated unchanged sample updates observation age without creating duplicate Board obligation. recovery appends resolution receipt to same occurrence.
- On restart, reconcile only runs owned by this host generation and expired leases. Query provider/supervisor by task_run_id; positive alive matching fingerprint may reattach under explicit supported profile. No evidence → outcome_unknown/recovery_required; do not mark all running tasks cancelled merely because app restarted. Remote/other-host runs untouched.

##### limits
Worker shares app lifetime; if whole app is dead no online observer exists. Show last_observed_at on next launch. An independent hosted monitor would be a new placement/profile, not implied by this worker.

#### invariants
- Observer does not infer failure from absence if its own source is unavailable.
- Condition dedupe key stable through restart; repeated polling does not spam Board.
- Run terminal state never fabricated from output silence or startup.

#### failure_cases
- Main eventloop stalled but worker responsive → host_loop_unresponsive, not agent_wedged.
- DB outage while process alive → data_source_unavailable and gap, task still not classified success/failure.
- Host dies, PID reused by another process → mismatched fingerprint, no reattach.

#### migration
- Replace bulk startup-abandon logic only for v2 runs, retain v1 historical meaning as legacy unknown view; startup feature gates prevent mixed owner assumptions.
- Use canonical session.oriented event and introduce explicit protocol-delivered receipt if adapter can prove it. Do not rename old event bytes.
- Health Board obligation reader shares runtime_conditions occurrence id, not a new independent notification record.
