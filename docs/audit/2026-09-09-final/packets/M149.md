#### solution

##### entry
Агент из выполняемой task вызывает ask; человек видит карточку через estate top5/project top10/full Board и из блокирующей task.

##### exit
Получен question_id+accepted_seq либо типизированный отказ; check возвращает состояние вопроса и delivery отдельно. Ответ проверяется по ID, не поиск похожего текста.

##### recipe
Общий QuestionService проверяет actor scope и каждую blocked task; нормализует about, topic и options, сохраняет один вопрос по command idempotency key. Add ask/check adapters в AgentSurface и preload, DTO в shared. Источник задаёт request, сервис формирует авторитетные estate/actor поля.

##### preview
Вопрос, автор, project/task, что остановлено, адресат и одно действие открыть; полные последствия вариантов в question detail.

##### states
open/answered/withdrawn/stale — business state. submitting/accepted/rejected/retryable — command transport. Вопрос без blocks допустим; task ladder не меняется на blocked.

#### interfaces

##### route
#/e/:estate/p/:project/board?item=:boardItemId

##### canonical_id
question UUID; board item key question:<id>; command_id отдельно

##### commands
- fabric_question_ask({command_id,task_id?,about?,topic?,text,why_blocked?,options:[{id,label,consequence}],blocks:task_id[],recipient_ref?})
- fabric_question_check({question_id,after_seq?})

##### response
QuestionReceipt {question_id,accepted_seq,status,decision_ref?,delivery_ref?,problem?}; recipient actor/role только после проверки membership

##### query
questions.get(scope,id); blocks содержат canonical task refs; asOfSeq+coverage из общего ReadResult

##### read_policy
Questions are authored commands, not a sortable collection. Their previews inherit Board rank/scope; check(id) returns current revision. Source timeout is retryable, never answered/empty. Reconnect repeats same command/check ID.

##### outer_envelope
Query: canonical ReadEnvelope<T>; mutation: Command<T>/CommandResult<T> from system-contract §4–5. UI lifecycle labels are local, not wire enums. New seq/epoch: decimal strings.

#### invariants
- Client не назначает себе priority, estate или author; server выводит их из authenticated actor.
- Все options имеют уникальные стабильные IDs; chosen_option далее обязан принадлежать именно этой revision.
- Один retry одного command не порождает новый вопрос; второй вопрос с похожим текстом не дедуплицируется без семантического решения.
- Не раскрывать чужую question через check; отсутствие прав и отсутствие записи обрабатываются без leakage.

#### failure_cases
- Cross-project blocks или recipient → rejection до append.
- Потерян response после commit → повтор command возвращает прежний receipt.
- Question уже answered/withdrawn → check не возвращает obsolete open.
- Process передаётся topic=process при kind=decision; kind=process отвергается, priority использует существующий decision weight.

#### migration
- Additive event schema для recipient/correlation и idempotency; legacy null остаётся неопределённым адресатом, не назначается молча operator.
- Согласовать M184 producer: kind=decision + topic=process; добавить topic как отдельное typed поле. Не расширять QuestionKind/priority weights только ради темы.

- questionScopeIsolation: own positive control и foreign estate/project/question.
- questionCheckCurrentRevision: answer/withdrawal race.
