# The commercial unit is an Estate subscription with managed continuity and agent credits

- **Status:** Accepted — internal product architecture; do not propagate to public
  open-source narrative surfaces
- **Consequences / affects:** internal entitlement, usage, memory/sync and product
  packaging design; `docs/evidence/backlog.md`
- **Source:** operator, 2026-08-29 — resolves CO-075

The primary commercial unit is a **subscription attached to an Estate**. It is neither a
seat nor a single agent/run transaction.

The subscription combines two value pools:

1. **Managed continuity:** cloud memory and synchronization that let the same Estate
   continue across devices and let several authorized participants share coordinated
   state — including agent-sync-like task/decision continuity. This is governed Estate
   state with provenance and access control, not an undifferentiated model transcript.
2. **Platform agent capacity:** an included pool of credits consumed by providers/agents
   supplied and funded through PassionCode.ai. Credits are an entitlement/capacity unit;
   they do not replace the Estate's durable usage and cost ledger.

Seats, active projects, retained storage, run counts, third-party providers and
marketplace transactions may become limits, add-ons or separate settlement dimensions,
but they are not the primary unit around which the product is explained.

This decision does not set tier names, prices, credit conversion, overage rules, BYOK
treatment, marketplace payouts or tax/refund policy. Those remain later private product
decisions. Public Fabric/open-source documentation continues to describe capabilities,
contracts and self-operated paths without reproducing this packaging decision.
