# The public category is the shift from vibe coding to passion coding

- **Status:** Accepted
- **Extends:** ADR-0010 and ADR-0018; it changes neither the Project model nor the
  PassionCode.ai/Fabric boundary
- **Consequences / affects:** `README.md`, `docs/vision.md`, `docs/ux/vision.md`,
  `docs/ux/foundation.md`, `docs/ux/scenarios.md`, `docs/ux/flows.md`,
  `docs/ux/screens.md`, `docs/brand/`, `docs/public/organization-profile.md`, public
  repository READMEs and `passioncode.ai`
- **Source:** operator direction, 2026-09-03

The public narrative has one category transition and one primary positioning line:

> **From vibe coding to passion coding.**
>
> **PassionCode.ai — The agent-agnostic operating system for AI-native teams.**

“Vibe coding” names the useful first step: a person directs coding agents through
prompts, chats and tasks. It becomes an operating problem when that person has to
coordinate many agents across many projects and keep the purpose, authority, state and
proof of each handoff in their head.

“Passion coding” moves the control point up one level. The person operates **Projects**:
each Project keeps its purpose, accountable team, roles, Routines, authority, work,
Evidence and feedback loop together. A Project may begin as an idea at zero, an existing
repository, or a running product; its operating model can become progressively more
explicit and automated as it moves toward one and beyond.

The short reframe is:

> **Stop managing agents one by one. Start operating projects.**

This is not a promise that people disappear or that every Project runs without
supervision. People remain accountable. Agents and Providers remain bounded and
replaceable. The durable unit is the Project and its operating history, not a particular
chat, model, process or vendor.

The previous slogan, “Where people and agents run the business together,” remains an
approved secondary line. It must not replace the primary positioning in the opening
hierarchy.

Public surfaces must distinguish current implementation from product direction. The
category thesis describes the product model; capability claims still resolve to
`docs/brand/facts.md` and must state when they are design rather than shipped software.
