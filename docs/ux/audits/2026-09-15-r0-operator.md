# UX Audit — R0 operator — 2026-09-15

- **Scope:** feature:R0-launch; reachability, flow conformance, information hierarchy, CEO/input/settings.
- **Depth:** deep в пределах выбранного launch-среза; не повторный аудит всех 94 сценариев desktop.
- **Method:** два read-only code-trace пакета + независимый проход основного агента в браузере. STATIC, EXECUTABLE HELPER, BROWSER PROTOTYPE и PRODUCT RUNTIME разделены.
- **Base version:** [192cdcc29a9145d930bc696a9658f95987bceeb7](https://github.com/passioncode-ai/fabric/tree/192cdcc29a9145d930bc696a9658f95987bceeb7), wiki v63. Источники и line references ниже относятся к этой ревизии, а не к будущим исправлениям.
- **Request:** [OF-01…OF-12](../../launch/operator-first.md), включая новое обязательное требование голосового ввода.

## Summary

**REFINE.** Результат первой версии пока нельзя считать полностью достижимым через согласованный UI. Есть полезные подробности, локальные действия и формы, но приоритетная оболочка не везде передаёт правильный объект/область и не всегда показывает результат того, что только что сделал человек. Без исправления этого минимилистичная композиция не снимет нагрузку.

Наиболее существенное: (1) область CEO не соответствует Home/agent; (2) новые проекты, предложения CEO и статусы расходятся между двумя моделями состояния; (3) ссылки часто теряют ID вопроса/релиза; (4) нет полного пути голос→журнал→задача→timeline; (5) базовые настройки спрятаны за переходом в прежнюю оболочку. Сначала общий контракт, затем целый критический путь и сокращение шума.

Знаменатель аудита — **30 перечисленных ниже возможностей**, не число кнопок и не процент готовности продукта. **20 PARTIAL / 4 FAIL / 6 BLOCKED / 0 end-to-end PASS**. BLOCKED означает отсутствие достаточной проверки, а не найденный дефект. PASS отдельных static-критериев указан внутри строки и не повышает весь путь. Все product-runtime outcomes в этом проходе **BLOCKED: desktop не запускался**. Figma frames, полная WCAG-проверка и пользовательская понятность не проверялись.

## Browser receipts

Один временный localhost docs-only server, source baseline выше; только синтетические данные. Никаких настоящих задач, агентов, микрофона или модели не запускали. Стартовый viewport 1280×720. Дата 2026-09-15. Слова в кавычках — наблюдённый UI прототипа.

- **B01:** `#view-launch-home` → launcher «Открыть CEO — Atlas»; экран «Моё пространство / Fabric», composer «Сообщение для Atlas». Отправка «Собери утренний обзор по всем проектам и вынеси вопросы на доску» → предложение с основанием «Разговор Atlas». Несоответствие воспроизведено.
- **B02:** в B01 «Добавить на доску» → «CEO-1 · Записано в примере». Escape → app-nav «Доска»: только исходные три темы, нового поручения нет. Нажатие «Закрыть» по видимому тексту первоначально не нашло кнопку: её accessible name «Закрыть CEO»; это ошибка локатора аудита, не дефект продукта. Escape сработал.
- **B03:** первая тема Q-12 → «Итог разбора»: «Выбран адресный пакет контекста с решениями и источниками» → сохранить. Актуальных тем стало 2; Agent/IDE всё ещё «Ждёт вас», «Нужно ваше решение». **Не утверждаем**, что итог обязан автоматически разрешать run: отсутствует явный следующий путь к исходному обязательству. Project recap также продолжает говорить об открытом вопросе.
- **B04:** app-nav Fabric → Atlas → «Пульс и следующий обзор» → route `#view-launch-pulse?project=atlas`, heading «ВСЕ ПРОЕКТЫ». В этой карточке project scope потерян.
- **B05 / visual judgment:** Home 1280×720 после B03. Цветной профиль остаётся узнаваемым. Внутри product canvas приветствие/три числа/облик занимают верхний большой блок, а актуальная доска только начинается ниже него. Внешний report chrome занимает отдельную область и **не считается дефектом production UI**. Предлагаем компактный профиль и summary-first, сохраняя первоначальный порядок профиль→доска→проекты. На Pulse B04 история активности предшествует текущим исключениям. Это оценка иерархии, не измерение времени реакции или WCAG.
- **H01 / executable helper:** `assistantScope` вызван для launch-home(scope=estate, project=atlas) и launch-agent(task=T-12); вернул atlas и task=null. Контроль legacy estate/task возвращает estate/T-12. Подтверждает branch omission, не подменяет B01.
- **S01 / static absence:** поиск `getUserMedia|MediaRecorder|SpeechRecognition|microphone` по `apps/desktop/src` и `scripts/product` не обнаружил voice capture path; совпадения слова voice в других документах обозначают также бренд/outbound. Не делаем вывод об отсутствии кода в неосмотренных внешних providers.

## Cross-batch

**Clean после сведения:** оба статических пакета независимо нашли ScopeRef/CEO mismatch; это OF01, а не два дефекта. B01/B02/B04 подтверждают конкретные пути. «Итог» не повышен до grant: OF05 описывает отсутствующий переход, а не предлагает автоматически запускать работу после заметки. У manual agent/routine есть static runtime paths, поэтому они PARTIAL, а не «не реализовано». Отсутствие backend execution receipt в этом проходе остаётся BLOCKED, не FAIL всей системы. C16 hierarchy не засчитана как слом сценария; там остаётся BLOCKED для непроверенного интерактивного исхода. Rich graph остаётся R1; C18 проверяет доступность контекста, не расширяет R0 до graph editor.

Дополнительный review плана исправил пять расхождений до публикации: heuristic C16 отделён от scenario failure; локальные read-controls не названы всем чтением; console-first сохранён для IDE; голос имеет integration gate текстового command path; OX-12 явно требует P1–P5/L01–L06 runtime receipts. Проверка контрактов также уточнила владельца retention и отдельное включение цикла.

## Scope and limits

Не переаудированы все ветви 94 SCN, authentication/инсталлятор, реальные CLI capabilities, schema privileges, production deployment desktop, Figma и пользовательское исследование. Сценарные глобальные Last audit/status/Product не повышены: этот отчёт проверяет перечисленные launch-пути и новые требования, а не весь scenario contract. Следующий OX-02 обновляет цепочку scenarios→flows→screens для новых требований и отдельную voice-сцену; OX-12 приносит полные runtime receipts.

## Verdict

**REFINE** приоритетную оболочку как единый продукт, сохранив визуальное направление. Успех следующей итерации — полный путь «выбрал проект → поручил → увидел задачу → агент спросил → ответил → увидел результат → ушёл → вернулся», с одинаковыми адресами и статусами.
