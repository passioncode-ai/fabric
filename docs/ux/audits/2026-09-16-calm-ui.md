Дата: 2026-09-16. Объект — текущий интерактивный target design, не весь production runtime. [Решения и следующий пакет](../../launch/calm-ui.md) · [Интерактивная карта](../../reports/product.html#view-launch-design).

## Метод и границы

Маршрут прочитан из AGENTS.md и docs/AGENT_SYNC.md: сценарии → композиция → строки → renderer → браузер → Git/wiki. Toolkit и design pack измерены на машине; shortlist сообщает 528 callable для активного host claude, а не перечень гарантий Codex. ux-audit применён с двумя независимыми проверками: конфигурация и рабочие действия. Их исправления и регрессионные тесты включены в эту итерацию.

Вся модель содержит 85 представлений, 63 canonical screen records; target-каталог шире обязательного R0. Просмотрены общая навигация, состояние, доступность ссылок и адаптивность всех представлений. Глубокая функциональная проверка выполнена для изменённых путей; все операции во всех сочетаниях данных не объявляются пройденными. Нужна отдельная runtime/accessibility/pilot приёмка.

## Открытые вопросы и критерии следующей приёмки

Все хорошие идеи сохранены в CO-166 и предшествующих планах. Остались durable journal и snapshots содержимого приложений, native discovery/voice, реальный command adapter, scope/ACL invalidation при позднем ответе, приёмка R0 на реальных рабочих проектах и формальный screen-reader/keyboard audit. Это не закрытые findings production.

Pilot должен измерить время возврата к правильному следующему действию, ошибочный выбор проекта, необходимость раскрыть технические подробности для обычного решения, долю повторных вводов и восстановление после сбоя. Численных результатов pilot пока нет. Задача — подтвердить, что меньше видимых элементов действительно уменьшает нагрузку, а не прячет работу.
