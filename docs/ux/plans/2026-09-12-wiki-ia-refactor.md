# Wiki IA refactor — рабочее пространство по намерению читателя — 2026-09-12

- **Sources:** операторский бриф 2026-09-12 (paraphrased: the wiki is too complex and needs rebuilding,
  especially the mockups — open and click them, see previews, the plan and backlog, the
  screen map and the architecture, with sound navigation); `workspace/` (хост, ADR-0048/0055);
  `workspace/docs/ux/scenarios.md`; записанный паттерн «оператор многократно
  спрашивает, как открыть дашборд».
- **Goal:** от намерения («посмотреть макет», «где план») до предмета — ≤2 клика; макет
  находится глазами по превью и открывается кликабельным; гиганты-отчёты перестают быть
  входами и становятся глубиной.

## 1. Проблема, измеренная

Входами сайта были ЧЕТЫРЕ снапшот-гиганта: `product.html` 3.7 МБ (все 72 вьюхи внутри
собственного роутера), `system.html` 1.9 МБ, `map.html` 0.7 МБ, `completeness.html`
0.9 МБ — плюс библиотека на ~600 файлов. Найти макет значило открыть 3.7 МБ и крутить
пикеры; найти план — читать доску на 840 строк; статус экрана — таблицу внутри отчёта.
Навигация называла ФАЙЛЫ («Продукт», «Система»), не намерения.

## 2. Решение: разделы по намерению, гиганты — глубина

**Новая панель разделов (одно определение, `lib/navigation.mjs#NAV`):**
Обзор · **Макеты** · **Экраны** · **План** · **Архитектура** · Библиотека.
`sectionOf(path)` — один резолвер принадлежности: прототип помечается как «Макеты»,
system/map — как «Архитектура», и читатель ВНУТРИ гиганта видит, через какую дверь
вошёл.

**Четыре новые хост-страницы** (рендер из снапшота, никакой второй правды):

| Страница | Что отвечает | Данные |
|---|---|---|
| `/mockups` | галерея 72 вьюх с НАСТОЯЩИМИ кадрами прототипа; фильтр по горизонту, поиск; клик открывает прототип на этой вьюхе (`#view-<id>`) кликабельным | `product-model.json` + `docs/reports/previews/` |
| `/screens` | карта всех SCR со статусом реестра словом (построено/спроектировано), «Макет» и «Запись» у каждого | `product-model.json` (`registry_evidence.status_claim`) |
| `/plan` | вехи V1 со статусами, очередь оснований F0…F7, входы в план/пакеты/дизайн/merge-лог | `docs/reports/plan.json` — проекция ДОСКИ |
| `/architecture` | четыре входа: модель системы, карта дизайна, документы, решения | снапшот |

**Обзор** переработан: герой ведёт в галерею; шесть карточек-намерений вместо четырёх
карточек-файлов.

## 3. Честность превью и проекций — два новых родительских генератора

- `scripts/build-mockup-previews.mjs` — 72 кадра из САМОГО прототипа (file://,
  собственный hash-роутер, `#product-screen`), Chrome через
  `FABRIC_PLAYWRIGHT_MODULE`/`FABRIC_CHROME` (контракт browser.mjs); dsf 0.5 → 475px
  JPEG, 1.1 МБ на все. Манифест пиннит sha256 прототипа и модели; `--check` в
  `ci.sh fast` краснеет при расхождении БЕЗ браузера — превью не могут протухнуть
  молча, и не перестраиваются, когда прототип не менялся.
- `scripts/build-plan-projection.mjs` — `plan.json` из доски одним парсером
  (`lib/markdown-table.mjs`, FA-05); `--check` — байтовая парность. Страница плана
  ничего не утверждает сама.

Оба гейта наблюдались красными на подсадках (byte в prototype → «previews stale»;
правка строки проекции → «plan projection stale»).

## 4. Пограничные кейсы (в сценариях вики SCN-006..008)

вьюха без превью → подписанный плейсхолдер, не битый `<img>`; снимок без модели/
проекции → «не входит в этот снимок» + путь к порядку обновления; пустой поиск →
явное состояние со сбросом; экран без вьюхи → «без макета» словом; статус вне словаря
→ рендер словом как есть, без выдумывания; фильтр живёт в адресе (закладка/шеринг
восстанавливают список — правило библиотеки).

## 5. Что осталось (named, not implied)

- Гиганты сами по себе не перестроены: оглавления-входы ВНУТРИ system/map — отдельная
  итерация (кандидат: генерируемые TOC-страницы).
- Превью статичны кадром «default»-состояния; кадры остальных 6 состояний — кандидат
  для карточки-веера позже.
- `/plan` показывает вехи V1 и батчи; полный рендер строк батчей — по запросу, доска
  остаётся в одном клике.
