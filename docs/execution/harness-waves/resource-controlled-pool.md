# Controlled ordinary managed pool

## Contract

N035 is source preparation, not production activation. The concrete factory owns an exclusive N034 writer, actual N028 assignments, N029 prepared inputs, declaration-first N031 intents, R1/R2 adapter, N032 units and the existing managed launcher. It calls the actual PTY entry; no second native launcher or index/default wiring is added. Sources: `apps/desktop/src/main/resourceControlledPool.ts`, `resourcePoolRegistry.ts`, `resourceWorkerInventory.ts`, `resourceManagedUnit.ts`, `pty.ts`. Focused checks: `apps/desktop/test/resource-controlled-pool.test.mjs` (18 focused checks passed on the frozen candidate; exact hashes and logs travel with N035 evidence).

`createControlledManagedPool(config,deps)` constructs one fixed ordinary-required creation domain and returns only `launch`, `snapshot`, `close`. App `getPath(userData)`, host identity, store, SQL transport, authority/guard, tracking, stopping, dispatch and preflight are trusted composition inputs. Root is checked canonical and bound throughout; an injected app object does not prove an arbitrary caller chose the production installation root. Production composition must supply the actual canonical app/runtime inputs. This does not prove universal exclusion of other programs, legacy or unmanaged launches on that host or named pool.

## Durable domain

Provision and reopen are explicit, different lifecycle operations. Provision is a trusted lifecycle action, never autonomous proof that an empty directory was never used. Controlled genesis differs from generic genesis. Its constructor requires a private actual-factory capability; exported readback/issue/bind/consume functions recognize private WeakMap objects and have no public mint. Neither a caller-selected marker nor a copied object upgrades an existing generic ledger.

Each writer epoch stores the full normalized host policy plus exact validated coverage bytes, linked into the canonical head. Every retained unit links to that epoch and its invocation, policy binding revision and coverage digest. The coverage manifest is validated audit provenance, not an independent execution measurement of the file named by its source hash. Actual module composition and private writer ownership define the controlled creation path. Registry locations remain stable across invocations and policies; epochs and declarations are bounded and never retired here.

N031 constructs the exact canonical intent bytes and directly appends their declaration through the captured actual writer before writing or acknowledging the intent event. If later event creation, durability or currentness fails, the declaration remains. It counts a conservative unretired logical unit, not proof of a running process. Historical declarations do not need old task membership or live N031 handles; supplemental event loss does not decrease occupancy, but prevents operating that handle.

Completeness assumes trusted intact storage and exclusive use of this creation domain. Loss/rollback of BOTH ledger and its external anchor can erase history even while stop-host identity survives; no external monotonic authority detects that. Missing ledger with intact anchor, surplus/partial files, corrupt chains, unknown versions, unclean writer lock and exceeded bounds refuse. There is no lock stealing or automatic reset.

## Native boundary

After actual admission attachment, the private factory issues a one-use ticket bound to the owned prepared packet, exact admission receipt, intent and actual PTY manager. PTY binds the exact native token once. After all asynchronous currentness checks and the final existing SQL check, PTY synchronously consumes that same ticket immediately before spawn, with no intervening await. Closing, poison, copied/foreign tokens, redirection and reuse refuse. Existing noncontrolled callers have no ticket and retain their behavior.

Actual raw task body/context remain the N029 packet throughout bundle/dispatch. Trusted preflight receives independently refreshed N028 identity and a conservative registry inventory, not mutable producer handles. It must still supply actual ownership/fence/full-input authority; N028 attribution and N026 selected bytes are not R1 held or complete dependency selection. Sampled refreshes are not atomic validation across every await.

## Conservative inventory and handoff

The factory feeds the actual N022 sampler all retained declarations, including orphaned, historical and possibly alive units. `complete:true` is internal worker-set coverage for this closed creation domain, never all host processes or actual liveness. Physical CPU/memory/disk sampling still sees other host workloads. `snapshot` is observation with `executionAuthorized:false`, not permission to reserve or launch. No process exit, signal, missing PID or provider uncertainty retires a unit.

Every failed/refused/unknown/timed-out/busy factory operation permanently poisons the invocation, including snapshot failure and successful spawn with uncertain delivery. Exact retries cannot clear poison. A poisoned factory cannot create more work or cleanly seal; unresolved I/O and writer ownership remain retained. This deliberately reduces availability.

`close` revokes tickets/new calls synchronously, waits for its actual creation promise with a deadline, checks permanent poison, then delegates to N034 sealing with its own retained-I/O deadline. There is no outer seal timer allowing late continuation to start a seal. A drain timeout prevents subsequent seal initiation. An uncertain syscall acknowledgement after a safely written seal may mean the lock was already removed; unknown close is not proof the lock still exists. No clean result is returned without the N034 receipt. This drains creation/registry work, not all continuing PTY/journal/provider callbacks.
