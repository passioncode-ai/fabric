# Coherent resource pool accounting

## Contract

N027 is an internal observation producer. Its pending SQL and TypeScript reader grant no execution, ownership, reservation or future admission authority. The active migration chain and native runtime remain unchanged. It complements [the publisher](resource-pool-publisher.md#contract), preserving that publisher's exact eight-field `read_resource_pool` response.

`createResourcePoolAccountingReader` takes a fixed trusted full host policy, independent trusted host ID, expected configuration generation, explicit maximum roots (1–1024), timeout (1–30000 ms), RPC client and optional epoch clock. It validates and freezes a copy of the policy with `readResourceHostPolicy`. Its `bindingRevision` uses the same `policy-sha256-v1:` plus canonical full-policy digest as N025; the policy's human revision is not the SQL binding revision. Configuration generations must be safe positive integers. The reader never configures a pool or refreshes its expectations after a mismatch.

The new service-only RPC is `read_resource_pool_accounting(p_host text,p_pool text,p_revision text,p_configuration_generation bigint,p_max_roots bigint)`. One `STABLE` SQL statement materializes the scoped pool, a bounded set of held root reservations and their numeric sums under one MVCC snapshot. It takes no row/advisory locks. Child reservations are already allocated inside their root envelope and are excluded. Released rows are excluded. Roots from every Estate sharing the host/pool are counted. A complete empty set legitimately sums to zero; missing or truncated readings do not.

The response is either `{state:'unknown'|'refused',reason}` or an observed object with exactly `state,hostId,poolId,bindingRevision,configurationGeneration,capacity,maxAgeMs,observed,observedAtMs,reserved,rootCount,snapshotAtMs`. Arguments, missing pools, missing/stale/future readings, changed policy/generation, the root bound, unsafe aggregate numbers and capacity excess have explicit outcomes. Sums use PostgreSQL `numeric` before safe-integer checks; JavaScript independently validates every axis and adds through `BigInt`. No uncertain quantity becomes zero. The client returns only allowlisted reasons, never raw transport errors.

`observedAtMs` is the observation timestamp floored to epoch milliseconds. `snapshotAtMs` is the statement timestamp floored to milliseconds; it does not refresh observation age. Flooring retains the conservative earlier instant when PostgreSQL has finer precision. The client requires observation ≤ snapshot ≤ local completion clock and rejects clock rollback from its pre-RPC reading. SQL and trusted client clocks must share an epoch domain; skew can conservatively refuse. Pool timestamps, generation, observation and aggregate belong to the same SQL snapshot, not sequential client reads.

An observed client result contains an immutable `snapshot`, domain-separated `snapshotId`, `overlapCredit:'none-conservative'` and `executionAuthorized:false`. Unknown/refused results contain `reason` and `executionAuthorized:false`. No overlap credit means charging observed usage plus reservations conservatively. It is not a measurement that observed/reserved overlap equals zero. This API deliberately does not manufacture R1's measured `reservedObserved`, ownership proof, parent allocation evidence or ready `ResourceContext`. Future composition must preserve observation age and bind the SQL digest revision, generation, selected inputs and independently established ownership.

## Resource bounds

The RPC selects at most `maxRoots+1` candidates before aggregation. Exceeding the bound returns unknown without claiming a complete sum. `resource_reservations_accounting_roots(host_id,pool_id,reservation_id) WHERE state='held' AND parent_id IS NULL` supports this root-only scan. These are logical materialization bounds, not a guarantee about physical index pages, dead tuples, planner work, elapsed database time or table growth. Deployment statement/resource limits remain a separate obligation.

Each long-lived reader permits one outstanding RPC. A timeout returns unknown but retains that slot until the underlying request settles, and late evidence is discarded. Repeated calls cannot pile up pending RPCs in that instance. Independent instances/processes are not globally bounded by this module. Ordinary native rejected Promises accidentally returned by the synchronous clock are consumed and refused; exotic Promise subclasses or arbitrary hostile DI objects are outside the trusted injection contract. The service role remains the trusted machine kernel across hosts/pools; exact predicates provide data scope, not a new per-host authentication system.

## Verification

Focused command: `node --experimental-strip-types --test apps/desktop/test/resource-pool-accounting.test.mjs`. Tests use the production reader, covering exact policy/generation/digest, immutable snapshots, missing and hostile fields, stale/future/fractional times, conservative arithmetic, capacity/overflow, empty roots, scoped RPC arguments, repeated timeout retention, late settlement and rejected asynchronous clocks. The clock-rollback regression was independently reproduced against the original candidate and then added to this suite.

`apps/desktop/test/resource-pool-accounting-db.test.mjs` is prepared for the existing owned PostgreSQL runner after pending107 is applied. It uses actual admission and cancellation RPCs for two Estates, a nested child and released roots; actual role denials; bounded roots; wrong identity/generation; epoch floor; and production reader readback. Explicit owner-only corruption fixtures test overflow and an atomic paired-update race. Those mutations test reader boundaries, not legitimate admission behavior. The paired-update probe is timing-dependent and cannot prove exhaustive interleavings; the single-statement STABLE implementation supplies the snapshot guarantee. It requires the runner's isolated database URL and Unix socket. It creates no cluster and touches no active database itself. Actual SQL execution is **NOT_RUN in the initial N027 candidate** pending the root's shared heavy slot and disk headroom.

No native host, active DDL, timer, automatic worker inventory, complete task input closure, nested-parent proof, launch composition or all-runner enforcement acceptance follows from these tests. Promotion and runtime composition remain separate source-owned tasks.
