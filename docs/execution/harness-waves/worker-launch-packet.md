## Scope and actual consumer

One unit is one newly admitted ordinary resource-required managed task execution through createManagedLaunch → index prepare → PtyManager.open. Operator/routine/answer use this path; required chain, supplied admission, instruction override and custom/unprepared targets retain N029 refusal. Shells, free terminals, legacy managed launches, external CLI enrollments, backendLaunch and other invocations are outside this logical pool. Physical memory/disk/CPU observations still cover the measured host/volume and include other work; pool ceilings are not host totals and this exclusion gives no physical capacity credit.

The concrete adapter is resourceManagedUnit.ts, constructed from actual N031 intent manager, actual N028 assignment manager, actual PtyManager, a scoped store and the existing host invocation identity. It consumes opaque handles created by those producers. It does not accept caller-supplied process facts, a counts array, ended callback or complete boolean. It emits observation/evidence only, never R1 held ownership or spawn authority.

The existing consumer targets are managedLaunch.ts:66–110 and index.ts:3176–3224. index currently configures no required resource adapter. Wire a trusted optional managed-unit dependency at these existing factories without changing absent-resource behavior. Required composition must refuse a missing/mismatched unit dependency before admission; this is an internal source contract, not a renderer toggle or an activated policy. No second launcher.

## Minimal API and ordering

1. N031 register(assignmentHandle, adapterId), then readIntent(intentHandle), reads actual N028 identity and actual retained bytes. N031 runId is the agent-sync mapping id, not SQL task_run_id. Keep both names explicit. Its unitId is assignment.attemptId. Compare estate/project/task/session/attempt, actual host/boot, pool, human policy revision and full bindingRevision. Human policy label alone cannot identify N025 policy. Intent failure/timeout blocks the required path and retains any ambiguous intent; no guessed cleanup.
2. After actual resource admission, append an immutable admission attachment linking intent digest, exact SQL task_run_id/run ordinal/session, reservation id/fence, prepared contentDigest and full resource inputDigest. Obtain these from the exact owned adapter receipt, never derive them from the N028 mapping. Require durable readback before begin. If this fails, invoke existing cancelUnbegun; an unavailable reply leaves intent and reservation unresolved.
3. createManagedLaunch keeps begin_task_run_launch as one-shot spawn permission. Adapter prepares an opaque native-unit permit only after durable attachment; beforeSpawn refreshes intent/assignment first, then existing resource currentness, prepared currentness and finally validate_task_run_launch. PtyManager retains its existing no-await interval between final guard and synchronous spawn (pty.ts:493–523). No disk append or other await is inserted after that guard.
4. PtyManager.open receives the permit only from the trusted required factory. Mint a private native-unit handle immediately after this.spawn returns, bound to the exact LiveSession object and host invocation. Preserve it if process capture/journal/setup later fails. The handle cannot be forged by copying {sessionId,pid}, and replacement/dismissed sessions fail lookup. At pty.ts:601 capture, use the existing processBoundary.capture result; never reconstruct an OwnedProcess from a journalled pid. An actual capture failure is unknown, not never-spawned.
5. resourceManagedUnit.observe(handle) calls actual ptys.observeOwnedUnit(nativeHandle), which checks private session identity before/after the existing observeProcess sampling and returns exact process identity + root/tree state. Persist native binding as a new immutable lifecycle event after capture. If binding-write reply is lost, read/reconcile that event and keep busy until underlying I/O settles. No replay of spawn. Failure after spawn enters existing ProcessLaunchFailure/stop path and retains unit.
6. Native exit is a request to inspect, not retirement. Reconcile using actual scoped operational run_stop_commands / run_launch_compensations and task_runs; scope metadata already classifies these (shared/scope.ts:136–137). Exact receipt identity, verified sequence, process identity digest, host/boot, outcome and basis must match the retained unit. A fabricated onState/onExit object does not satisfy this readback.

Suggested adapter surface: prepareIntent(assignmentHandle, preparedPacket), attachAdmission(unitHandle, ownedReceipt), current(unitHandle), observe(unitHandle), reconcileRetirement(unitHandle). No public markActive/markEnded. The first operation consumes the actual N028 handle; the native binding operation is private to the concrete PtyManager collaborator. Exact TypeScript names can follow N031 freeze; no generic infrastructure port substitutes for these real consumers.

## Retirement proof and current limits

Observed retirement requires the existing managed Stop path to have recorded stopped/basis observed for this exact run/session and process reference: root exit + terminal.closed receipt + process tree quiescence + independent provider quiescence + revocation/transcript evidence (nativeStopRuntime.ts:133–154; managedStop.ts:135–167). Read the operational row, not raw run.ended or terminal.closed journal claims. Never-spawned retirement requires exact operational compensation joined to task_runs.ended_seq, or the existing verified stopped/basis never_spawned command. Existing pending107 cancel/release RPCs remain the reservation authority (lines263–310); a local intent event cannot free SQL capacity. Prefer retaining the logical unit until reservation release also readbacks successfully, a conservative extra condition.

Current index.ts:1205–1206 explicitly omits provider observation. Therefore connected runner exits cannot produce a positive observed retirement in this slice. Darwin/Linux have owned-group observations, with escaped descendant uncertainty sticky; Windows group capture is unsupported and remains unknown. Even on POSIX, processBoundary explicitly is not a sandbox against previously unobserved escaped work. No detached/provider proof is inferred from an empty group, a PID lookup, success exit code, empty PTY map, timeout or app restart.

Restart/foreign invocation: read retained intents, report unresolved; do not attach by PID or recreate opaque native handles from stored numbers. A separately verified existing operational Stop/compensation receipt can retire an exact durable identity; otherwise recovery needs a later process/provider ownership mechanism. A consumed begin with unknown spawn outcome never retries automatically.

## Completeness and bounds

N031 always complete:false. Distinguish complete conservative logical occupancy from complete knowledge of process liveness. With actual exclusive entry coverage and an intact complete registry, every unretired durable intent counts one slot: pending before spawn, known active, possibly active, unknown after exit, and an earlier boot that has not been authoritatively retired. Missing provider proof blocks retirement, but does not by itself make that conservative set incomplete. The knownActive subset remains a separate observation, never the whole denominator. This is a logical-unit upper bound, not a count of OS processes or an assertion each retained unit is alive.

A positive complete inventory requires: (a) actual source-enforced/provisioned registry scope for this exact host/pool, with every admitted member path obtaining durable intent before native permission; (b) an exclusive controlled writer domain, with no unaccounted alternate invocation using the same pool; (c) a bounded complete snapshot under the same registry lock or verified revision, including all unretired lifecycle chains/tombstones; (d) valid record provenance and no corruption, overflow, omitted pages or unresolved insert identity. Count an ambiguous append conservatively if exact durable readback proves its unit; otherwise return unknown because set completeness is unavailable. An unknown retirement never removes an id.

Prior boot/foreign invocation is not inherently disqualifying if its intact records are validated within the same proven registry coverage; count it without adopting its process ownership. Unproven provenance or alternate writer coverage is disqualifying. A current stale task assignment prevents launch but need not erase a previously established durable unit from the charged set. Multiple retries of the same unit still count once. Policy change must not drop older unretired units in the same logical pool.

An actual bounded source implementation could create an exclusive pool-domain/coverage record before the first allowed launch, hold a pool writer ownership mechanism while allowing launches, and serialize the complete inventory snapshot with append/retirement. This record is evidence of implemented entry coverage, never proof merely because a manifest says complete. Crash/restart must retain old units and refuse a new writer until its coverage/recovery is proved. A simple exclusive file that cannot be safely recovered may conservatively block a restart; PID-based lock stealing is not a substitute. Existing N031 intent registration, an empty PtyManager map, installed adapters and N028 manifests do not implement this coverage protocol. Thus the first N032 active-binding slice remains complete:false, while a subsequent concrete coverage slice can expose all unretired unit ids to N022 as conservative worker occupancy. It must label that accounting meaning explicitly. No automatic complete:true from knownActive alone.

Bound max retained units/events/bytes and scan pages explicitly. Keep one outstanding operation per unit plus bounded global outstanding count; timeout revokes follow-on work but holds occupancy until every started dependency settles. Same-unit methods share the slot. Different bounded units can progress independently. Nested operations use the same permit, never acquire a second slot. Avoid unconditional allSettled changes to legacy components: retention is opt-in for this producer, preserving N029 lesson.

## Required focused negatives

- Intent append fails, loses reply or hangs: zero spawn; repeated calls retain bounded I/O and no new intent. Same attempt retry cannot create another unit.
- Exact SQL admission attachment differs in task/project/session/run/reservation/fence/content/input digest: zero begin/spawn. Agent-sync run id cannot substitute SQL run id.
- Final guard stale after async intent/readback: zero spawn; nothing awaits after final SQL permission before synchronous spawn.
- Spawn returns then capture/journal/attachment fails, or immediate exit precedes bind: retained unit, no false never-spawned compensation, no instruction replay.
- Foreign/copy native handles, session replacement, reused pid, changed process start/group/boot: unknown; no active attribution or retirement.
- Root exit with live descendant, escaped descendant, unknown process identity, missing provider proof, SIGTERM/SIGKILL acknowledgement, forged callback stopped, raw ended journal: no retirement.
- Exact operational never-spawned compensation and fully matched synthetic operational Stop receipt retire once; wrong seq/run/host/boot/provider reference refuse. Actual SQL conformance later uses root's one heavy slot.
- With proven coverage, a durable uncertain/unbound intent remains charged even with an empty local process registry; missing coverage keeps complete:false. Corrupt record, page overflow, unproven foreign provenance and untracked in-pool launch cannot report complete inventory. Fully validated prior-boot records remain charged rather than being silently excluded.
- Legacy ordinary launches remain unchanged; required chain/admitted/override remain refused before reservation. Physical sample totals are never reduced by logical exclusions.
