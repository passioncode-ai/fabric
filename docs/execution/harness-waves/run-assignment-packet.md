# Proposed bounded Fabric assignment-to-agent-sync correlation producer

DESIGN ONLY. Source: Fabric `193b0e1e3b7c6eb3622bf57a1a825f5832d1c19e`, plus reviewed N026 `resourceInputSnapshot.ts` SHA256 `0db51b7184489b8bb1c41fdfb6122f65cf047bae105289fd73b18884c9ece5b6`. No implementation, lease acquisition, installed change or launch is claimed. This packet is local and does not depend on COM.

## Decision and finite scope

Build one internal `resourceRunAssignment.ts`, one narrow Python readback helper if needed, focused tests and its contract document. One explicitly configured installation, repository and project lane; root attempts only; exact selected paths; one manager process. No generic policy language, launcher, lease scheduler, global identity service or new database schema. N027 remains independent.

The result is a **correlation receipt**, always `executionAuthorized:false`, `ownership:'unproven'`. It supplies N026's trusted assignment/identity reader and N023's exact target from independently read local configuration, Fabric task membership, installed identity derivation and actual remote lease evidence. It never returns R1 `held`.

ADR0152 already permits internal preflight and evidence producers. A new Fabric-owned ADR is needed only before treating cooperative snapshots as a supported ownership guarantee, selecting enforceable isolation instead, or defining new attempt-fence authority. Do not hide that decision in this producer. An attempt UUID here is an identity, not a fence.

## Concrete construction and API

A kernel-only constructor receives an approved lane configuration: exact estate/project, canonical repository root and remote, fixed selection-manifest path and expected SHA256, key-to-scope mapping revision, pinned agent-sync executable/script identity, owned storage root and finite limits. These are source-owned configuration, never renderer/task fields. It performs real bounded file reads: validate manifest bytes/digest, exact paths and N026-compatible bounds. The manifest names the approved task lane and scope; task-authored touches cannot broaden it.

`allocate({taskId, sessionId})` accepts those two IDs only from trusted main composition. It independently reads the exact task/project using the existing estate-scoped database client, validates project/lane/root, mints an attempt UUID and a short random key, and persists the full copied assignment before returning an opaque in-process handle. It refuses changed identity/selection on the same session. Missing policy or unreadable membership stays unknown. It does not ask a callback whether the caller's supplied object is valid.

`readIdentity(handle)` rereads persisted assignment and current task/project membership, verifies immutable lane/manifest binding and handle provenance, then emits only `{estateId,projectId,taskId,sessionId,attemptId}` for N026. It accepts no expected identity argument. The task/project read establishes membership; it is not subject authorization, which remains the existing admission/guard's job.

`allocate` includes installed-function readback before returning its handle; `readAgentSyncIdentity(handle)` below describes an internal implementation step, not an extra public method. It runs a bounded owned child adapter over the exact hash-pinned installed script's `_rid_from`, `_session_key`, `run_id` definitions. Use a Python AST extraction limited to those named definitions plus necessary audited stdlib globals; evaluate their actual bodies with an explicit `AGENT_SYNC_RUN_ID`, minimal environment and owned scratch root. Source hash is checked before extraction; unsupported version/hash, unexpected AST/dependencies, missing explicit env, output excess, timeout or rejection refuses. No module `main`, `Sync`, config loading, vault or foreign marker path executes. Verify returned identity against the registered key and persisted collision registry, and bind the script hash into the receipt. This is **installed-function readback**, not a claim of whole-CLI/native execution. No maintained reimplementation of `_rid_from` replaces that readback. A full CLI readback may be a later separately authorized integration check.

`observeLease(handle, expectedTip)` constructs the N023 reader from the stored approved remote, actual derived run ID, configured key and repository name; it makes the real read. The exact expected tip must come from an explicitly recorded authorized acquisition/readback step, not an arbitrary task argument. First creation may record an observed tip as *unattributed observation*; matching labels alone never proves that this assignment acquired the lease. No acquire/renew/release is performed by this module. Changed tip, expiry, unknown transport or mismatched repository/key remain unknown/refused; renewal needs a newly recorded observation, never silent acceptance of a different tip.

`childEnvironment(handle, sanitizedBase)` returns a fresh environment object whose final `AGENT_SYNC_RUN_ID` equals the persisted key, ignoring any parent value. It accepts only a live opaque handle; no JSON receipt can authorize this operation. Actual PTY wiring is a later narrow composition change: apply this final override **after** descriptor/bundle env at [pty.ts](https://github.com/passioncode-ai/fabric/blob/193b0e1e3b7c6eb3622bf57a1a825f5832d1c19e/apps/desktop/src/main/pty.ts#L515), preserving secret stripping, and verify the requested session matches the handle. Merely exporting this method does not claim the child received it.

No SQL run ID is fabricated before admission. Future composition must bind the returned exact SQL task/run/session/ordinal to the assignment and its actual prepared context/instruction. [managedLaunch.ts](https://github.com/passioncode-ai/fabric/blob/193b0e1e3b7c6eb3622bf57a1a825f5832d1c19e/apps/desktop/src/main/managedLaunch.ts#L132) can dispatch a chain override; that text and [sessionBundle.ts](https://github.com/passioncode-ai/fabric/blob/193b0e1e3b7c6eb3622bf57a1a825f5832d1c19e/apps/desktop/src/main/sessionBundle.ts#L194) actual context bytes remain separate prerequisites.

## Storage and collision policy

Use an explicitly owned app-data directory, e.g. `<userData>/resource-run-assignments/v1`, with0700 directory and0600 **immutable mapping files**, named by validated derived run ID. No journal, database, secondary indexes or project/plugin writes. Before allocation take one exclusive allocation lock (`O_CREAT|O_EXCL`, no-follow), bounded-read the retained records to detect duplicate session/key/run IDs, then exclusive-create the one new record, write bounded canonical bytes and fsync file/directory before returning a handle. A single manager serializes requests; a second manager cannot allocate under the held lock. Delete only this operation's own verified lock after actual I/O settles. No existing record is overwritten. A partial record, fsync failure or crash leaves evidence unresolved, never reusable. Bound total records/bytes and refuse at the cap. No compaction, record deletion, expired-ID reuse or stale-lock stealing in this packet. Lock collision or incomplete/corrupt record blocks allocation; restart reports unknown until explicit owned recovery.

Generate lowercase alphanumeric keys of length12 so actual installed derivation avoids truncation. Persist and enforce both key and actual derived run-ID uniqueness across **all retained mappings**, including closed ones. A collision refuses that allocation (bounded explicit retry, if chosen, has a fixed small cap); never adopt a preexisting mapping or lease because labels match. Randomness lowers collision probability but is not the correctness check. Known local parent mappings are excluded. This guarantees local registry nonreuse, not global uniqueness against another machine or a self-reported hostile writer.

Lifecycle domain: each manager belongs to one Fabric **app invocation**, identified separately from the stable installation ID; this is not an OS boot identifier. Record installation and invocation IDs alongside the Fabric identity. Handles exist only in that invocation and cannot be deserialized. Crash/restart reloads records only as unresolved historical assignments. No live handle, current lease or permission is restored from disk alone. Refresh task membership, installed derivation and exact lease observation before any new correlation receipt; missing evidence stays unknown. Preserve unresolved entries and IDs. This is sufficient for the producer; automatic crash-lock recovery and reuse are deferred rather than guessed. A stranded lock is an explicit owned recovery condition, not a license to delete another process's state.

Raw selection paths/configuration remain local; exported receipts include bounded identifiers, digests, script hash, lease tip/times and reason codes, not credential values or source bytes. The key is non-secret identity correlation and must not be treated as a bearer credential.

Public surface is limited to `allocate`, `readIdentity`, `observeLease` and `childEnvironment`; source readback and storage are private implementation. The storage/lock writes described here are future owned mapping files authorized by composition, not permission to mutate installed tooling or another project.

## Acceptance required for this finite packet

1. Real owned configuration/task fixture: changed manifest, foreign estate/project/task, reused session with different scope, malformed paths and absent membership cannot allocate. Persisted exact identity feeds N026; modifying the caller object afterward cannot change it.
2. Execute the actual pinned installed-function bodies in owned scratch: short and long derivation controls, changed script hash, malformed output, absent explicit override and accidental fallback refuse. Prove no project `.agent-sync`/config/notes or foreign filesystem writes occur. No full CLI acceptance claimed.
3. Deterministic collision plant returns an already-used short key/run ID for a different attempt: refusal, no record overwrite or existing-owner adoption. Concurrent allocation and second-manager tests show one durable owner. Failed fsync, partial immutable record, size cap and lock conflict return unknown/refused.
4. Reload records after simulated crash: prior mapping is historical, no live handle/held result; unknown lease or missing task remains unknown. Retained IDs are not reused. No stale lock auto-removal.
5. Real owned Git authority fixture through N023: foreign owner, matching label without attributed acquisition, changed key/repo/tip, expiration and denied transport never become held. No production lease is acquired.
6. Environment fixture with parent/descriptor/bundle conflicting keys: final kernel patch chooses only the mapped child key; another session's handle refuses. Native spawn NOT_RUN until actual PTY composition.
7. One outstanding I/O/subprocess slot per reader or manager operation retained through actual settlement; repeated timeouts cannot accumulate children. Late success never approves the old call, ordinary rejected clocks are consumed, scratch cleanup is bounded. Dependencies may differ by operation; do not wrap all proof in a caller-supplied boolean.
