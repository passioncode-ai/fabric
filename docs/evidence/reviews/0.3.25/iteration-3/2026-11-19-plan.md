# Fabric 0.3.25 release review, iteration 3: plan

Level plan, candidate 6da674bdc092ed36a34521198dd0f5d472d0d531, baseline 53e8c3e2, reviewer model anthropic/claude-sonnet-5.5, read-only.

## Verdict

No blocking finding in the material shown. The candidate does what the owner asked:
- The popup is redesigned, and the CEO button carries the character's face with a state ring.
- The voice is male by default and male or female per character, in Settings and in the first run, with a sample.
- The call is a panel in the chat, and its last ten calls are kept.
- Stop and Restart work and have real tests, in the main process and in the popup.
- The composer has a `tools` slot for another session's record button.

The existing call keeps `MAX_CALL_MS`, `IDLE_CALL_MS`, `CONNECT_DEADLINE_MS`, the generation guards, the `VoiceKeyForm` key flow and `ASK_CEO_TOOL`. The only change to the session is `voice`, from `eve` to the character's voice.

**Previous findings:**
- PL-13 is fixed. `stopDoorId` is now stored, and `personStopEnded` and `onExit` match on it, so a console stopped while still opening ends the person-stop marker. Test ER-10 covers it.
- PL-14 is fixed. SCN-187 and the CHANGELOG now say the hold lasts "for as long as Fabric runs".
- PL-15 is mostly fixed. An ended call no longer shows the live block, and the `ceo-call-hangup` class is gone from the registry. A narrow leftover remains (see PL-15 below).
- PL-3, PL-5 and PL-11 are carried, narrowed, as non-blocking.

**New:** one very narrow edge in the door counter (PL-16). It does not block.

**Not run:** I ran no test, no built app and no xAI call. Everything rests on reading the diff and the changed files.

## Checked and fine

- **PL-13 fixed:**
  - `stopDoorId` is set in `personStopping`.
  - `onExit` handles `held && id === stopDoorId && id !== sessionId`.
  - `personStopEnded` ends the marker through `stopDoorId`.
  - Test ER-10 opens a console while a door stop is in flight, and a later `send` is answered.
- **PL-14 fixed:** SCN-187 says "for as long as Fabric runs; a restart of Fabric starts the CEO with its window". The CHANGELOG says "(for as long as Fabric runs)".
- **Stop and Restart:**
  - `held` is honoured in `ensure`, `onExit`, `onOutput`, `fallBack`, `startFallback` and `restart`.
  - `status()` reports `stopped`.
  - A stop that leaves the console running releases the hold and answers `still-running`.
  - `stop()` waits for a start and a pending fallback in flight. `start()` stops a console opened while held, and `ER-9` covers a stop that fails there.
  - A message or a person's restart waits for the person-stop marker before clearing the hold.
  - The main-process tests ER-1, ER-2, ER-3, ER-6 to ER-10 and the base stop tests simulate the pty order where the exit callback runs before the stop resolves.
  - `CeoPopup.test.tsx` covers Stop, the stopped text, Start (which calls `restart`, the person's restart), the failed-stop message and the call the home card asked for.
  - The tool `fabric_ceo_session_stop` still refuses the CEO's own console, and its wording points to the popup.
  - `ceoAgentStop` and `ceoAgentTakeCall` are added to the window policy and to `CEO_USES`.
- **Existing call:**
  - The timeouts and generation guards are unchanged, and the protocol tests are intact with a `levelOf` test added.
  - `ER-12` (the unhandled-rejection catch on `receive`) is a safe change.
  - The key flow still goes through `VoiceKeyForm` and `setVoiceKey`, now with a catch on a thrown IPC error.
  - `ASK_CEO_TOOL` is still in the tools.
  - `mute` and `levels` are optional on `CallAudio`.
  - `autoplayPolicy: 'no-user-gesture-required'` is set for the CEO window only.
- **Call as a panel, history kept:**
  - Live lines and the text field show only under `call.active`.
  - `keep` writes outside the state updater, caps a call at 40000 characters and ten records, and dedupes by id.
  - An ended call shows its reason and its record, and nothing before the first call.
  - `CallLauncher` opens the popup with `{ call: true }`. The popup takes the ask once through `takeCall`, and the ask is dropped when the window closes.
  - The reduced-motion CSS is gated.
  - The no-key path shows the key form, and its test is real.
- **Voice:**
  - No stored voice reads as male. An unknown voice is dropped and the look is kept.
  - The mapping uses only xAI's five built-in voices, and the tests check it against the measured pitch groups.
  - The picker uses native radios. The sample button is hidden without a key, and a refused sample is said while the choice still works.
  - The first-run step shows only when `voiceReady` is true, and Settings always shows the choice.
  - `voiceReady` and `voiceSample` are `MAIN_ONLY`.
- **Sample path:**
  - A whitelist check precedes the cache filename, so there is no path traversal.
  - The key goes only in the request header, and the test checks it is not leaked.
  - Cache files are written 0600 in a 0700 folder, by temp file and rename.
  - The "under a cent" claim holds: about 90 characters at USD 15 per million is about USD 0.0014.
- **Docs:**
  - The CHANGELOG, ADR-0197 amendment 2, SCN-184, SCN-186, SCN-187, the scenarios index, external-contracts, the CO-597 and CO-601 rows and the ledger dispositions agree with the code I could see.
  - No em dashes appear in the sample texts, and the test checks this.
- **Not checked:**
  - `persona()`, `PersonaProvider`, `usePersona`, `useFabricName`, `FabricAvatar` and the persona save path in main are not in the material.
  - The CSS tokens were not confirmed by me; the ledger says they are in `tokens.app.css`.
  - The i18n key `ceoAgent.state.idle` and the policy test body beyond `CEO_USES` were not seen.
  - No live xAI call or built-app walk was seen, apart from the design-map note that one was done.
