# Fabric 0.3.25 release review, iteration 3: data

Level data, candidate 6da674bdc092ed36a34521198dd0f5d472d0d531, baseline 53e8c3e2, reviewer model anthropic/claude-sonnet-5.5, read-only.

## Verdict

No blocking data or storage findings. Nothing in the candidate loses data, leaks a credential, breaks something that worked in 0.3.24, or leaves a shipped claim false, as far as the diff and the full files show. I ran no tests or builds.

Status of the previous iteration's findings:

- **DA-7 is fixed.**
  - `useVoiceCall#keep` now keeps at most 40 000 characters of lines per call, dropping the oldest first. Ten calls then stay near 400 000 characters, well under the localStorage quota.
  - The filter is sound: the budget only decreases, so once a line overflows, every older line is dropped too.
  - The 2000-character line cap and the 200-line cap are still in place.
- **DA-6 is partly fixed.** Parts (a) and (b) are fixed:
  - The tmp name is now `.${name}.${randomUUID()}.tmp`, so two writes cannot share one.
  - A `try/finally` with `rmSync(tmp, { force: true })` removes the tmp file after any failure, and after a successful rename it is a no-op.
  - Part (c), no check that the cached bytes are audio, is still open (see the table).

## Findings

| Id | Severity | Finding | Evidence | Suggested fix |
|---|---|---|---|---|
| DA-6 (c, left) | Non-blocking | A 200 answer from xAI with a non-audio body is cached as `<voice>-<lang>-v1.mp3` and served on every «Послушать». The renderer's decode failure only shows "unavailable" and does not delete the file. The only guard is the zero-bytes check. | `ceoVoice.ts#voiceSample`: only `bytes.length === 0` is refused before `deps.cache.write`; `VoicePicker.tsx#listen` catch sets `unavailable` and nothing else | Before caching, check the first bytes (`ID3`, or an MP3 frame sync, `0xFF` followed by a byte with the top three bits set). Otherwise return a failure and do not write. |

## Checked and fine

- **`validatePersona`:**
  - `voice` is optional, and only `male` or `female` are kept.
  - A bad value (string, number, null, array) drops only the voice and keeps the look; the tests cover these.
  - The result is built as `{seed, style}` plus `name` and `voice` only when present.
- **Old files read as male:**
  - `voiceGenderOf` returns male for a missing or unknown voice.
  - `xaiVoiceOf` falls back to the default style for an unknown style and always returns one of the five built-in ids.
  - `PERSONA_VOICES` is frozen, and the test asserts every mapped id is built in and has the measured gender.
  - The mapping matches the changelog, ADR-0197 amendment 2 and external-contracts.
- **Realtime call voice:**
  - The `ceoAgentVoice` handler uses `xaiVoiceOf(persona().persona)` instead of the fixed `eve`.
  - It returns the token and session fields only, never the xAI key.
- **Sample cache names:**
  - The voice is checked against the five built-in ids before any path is built, so `../../etc` gives `unknown-voice` (tested).
  - The name is `${voice}-${ru|en}-v1.mp3`, with the language normalised and an explicit version.
- **Sample cache modes:**
  - The folder is created 0700 and files are written 0600.
  - A file is written beside the target and renamed into place (DA-3 and DA-4 of the earlier iteration stay fixed).
  - The cache sits under `userData/ceo-voice/samples`, outside the CEO agent's folder.
  - A read or write failure does not block playback.
- **xAI TTS request shape:**
  - `POST https://api.x.ai/v1/tts`, JSON body `{text, voice_id, language}`, `authorization: Bearer`, `content-type: application/json`, 20 s timeout.
  - The reply is base64 MP3, and zero bytes is a failure.
  - The key is the person's own or the vault slot, and is held only for the request.
  - The sample text is under 90 characters in both languages, so the "under a cent" claim holds at USD 15 per million characters.
- **Credential hygiene:**
  - Failure details carry a reason code, an HTTP status or the error class name only. The test asserts the refused result does not contain the key.
  - The handler logs `reason` and `detail.slice(0, 200)` and returns only `reason` to the renderer.
  - `ceoAgentVoiceReady` returns `{ ready: boolean }` only.
  - Nothing in localStorage holds a key or token. The call records hold lines, time and price.
  - `VoiceKeyForm` clears its field after a save, and a thrown save is turned into `unwritable`.
- **IPC policy:**
  - `ceoAgentVoiceReady` and `ceoAgentVoiceSample` are `MAIN_ONLY`; their callers (`PersonaScreen`, `FirstRun`) are main-window screens.
  - `ceoAgentStop` and `ceoAgentTakeCall` are `MAIN_AND_CEO`, and `CEO_USES` in `ipc-window-policy.test.mjs` lists both. This is broader than needed, and CO-601 item 6 records it.
  - Key reading and clearing stay main-only, `ceoAgentVoice` stays CEO-only, and the preload and `FabricApi` add the same channels.
- **Handler arguments:**
  - The `voiceSample` handler coerces a non-string voice to `''`, which gives `unknown-voice`.
  - `open` accepts `{call: true}` only when strictly `true` and clamps the draft to 8000 characters.
  - `ceoCallWanted` lives in memory, is taken once, and is cleared when the CEO window closes.
  - `autoplayPolicy: 'no-user-gesture-required'` is set only on the CEO window, which keeps `sandbox: true`.
- **localStorage and sessionStorage in the CEO window:**
  - Only `fabric.ceo.calls` and `fabric.ceo.voiceMuted` are used, and there is no `sessionStorage`.
  - Every access is in try/catch.
  - `readKept()` validates each record and each line and treats an unreadable store as empty history. The test covers null, `{id:2}`, a bad `who` and broken JSON.
  - `keep()` writes outside a state updater, so a call kept while the window closes is still stored.
  - A repeated end of the same call is deduplicated by id.
  - A failed write (quota) still shows the call in the window.
- **Held and stopped state:** held state is in memory only. It is not written to `persona.json`, `ceo.json` or the call store, so after a Fabric restart the CEO starts with its window as in 0.3.24, which matches the changelog and SCN-187.
- **Shipped claims checked against the code:** a look saved before this reads as male; a sample is fetched once per voice and language; the last ten calls are kept on this computer; the first-run voice step is offered only when `voiceReady === true`.

Not checked:

- I did not run tests, a build or the packaged app.
- I could not see `persona()` in `index.ts`, or the main-side code that writes `persona.json`. I could not confirm the saved file goes through `validatePersona` and keeps `voice`.
- I could not see the variant buttons' `setDraft` in `PersonaScreen`, so whether a variant click keeps `voice` is unconfirmed. The ledger says it spreads the draft.
- I could not confirm that `randomUUID` is imported in `index.ts`. The diff's import line adds `mkdirSync`, `renameSync`, `rmSync` and `writeFileSync` but not `randomUUID`. It is probably already imported, and a type check would catch it.
- I could not confirm whether the CEO window and the main window share one localStorage origin. If they do, the changelog and ADR phrase "the CEO window's own storage" is loose, but the keys are prefixed and nothing collides.
- I could not see the key store's own folder handling for `ceo-voice`.
- I did not verify live that xAI accepts `language: "ru"` or `"en"` or that `/v1/tts` returns MP3 by default. CO-601 item 4 says real samples have not been heard.

Status of iteration 2:
- **DA-3 is fixed.** The `voiceSample` cache `write` in `index.ts` now calls `mkdirSync(samples, { recursive: true, mode: 0o700 })`, and the files keep `0o600`. A `ceo-voice` folder that already exists keeps whatever mode its creator gave it. I could not see the key store's own mkdir.
- **DA-4 is fixed for the crash case.** `write` now writes `.<name>.<pid>.tmp` and then `renameSync`s it into place, so a cut-off write no longer leaves a half-file under the real name. Two small leftovers are in DA-6.
- **DA-5 is rightly left.** Each kept line is now cut at 2000 characters (`CeoCall.tsx`, `onLine`: `text.slice(0, 2000)`), and the history is capped at 10 calls of 200 lines. A control to clear the kept calls is ruled to CO-601 item 5. The changelog and SCN-184 say the calls are kept on this computer. No key or token enters these records. One quota point is in DA-7.

## Findings

| Id | Severity | Finding | Evidence | Suggested fix |
|---|---|---|---|---|
| DA-6 | Non-blocking | Three small leftovers in the sample cache. (a) If `writeFileSync` or `renameSync` throws, the `.tmp` file stays in `samples` and is never removed. (b) The tmp name has only the pid in it, so two writes of the same voice and language in one process would share one tmp file. (c) The bytes are cached without any check that they are audio. | DA-7 | Non-blocking | The kept-call history can fill the origin's `localStorage` quota. The worst case is 10 calls × 200 lines × 2000 characters, about 4 million characters, against a quota of about 5 million.
