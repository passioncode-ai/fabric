# Fabric 0.3.25 release review, iteration 3: errors

Level errors, candidate 6da674bdc092ed36a34521198dd0f5d472d0d531, baseline 53e8c3e2, reviewer model anthropic/claude-sonnet-5.5, read-only.

## Verdict

**No blocking finding. The candidate may ship from the errors level.** All four findings of the previous iteration are fixed or rightly left.

- ER-10 and ER-11 are fixed. A stop of a console still opening now settles its own marker, and a second stop door no longer releases the first door's hold.
- ER-12 and ER-13 are fixed. The audio event handler now catches rejections, and the voice-key save has a catch.
- The remaining findings are rare or low-impact, so none is blocking. No credential leak, cache path traversal, audio context left open, or regression from 0.3.24 is shown.
- I did not run the build or tests.

## Checked and fixed or rightly left

- **ER-10 (fixed).** `personStopping()` now records `stopDoorId` for an opening id, and `onExit` handles `held && id === stopDoorId && id !== sessionId` by ending the marker. `personStopEnded()` accepts `stopDoorId`, clears it and ends the marker. A start still in flight stops the opened console because it sees `held`. A later message is answered, which the ER-10 test shows.
- **ER-11 (fixed for two doors on a current console).** `personStopping()` counts doors, and `personStopEnded()` settles only when the count reaches zero and `doorHold` is true. The popup's `stop()` clears `doorHold`, so a door cannot release it. ER-14 above covers the one counting hole left.
- **ER-12 (fixed).** `socket.onmessage` now calls `receive(...).catch(() => undefined)`. An invalid base64 audio delta is dropped instead of becoming an unhandled rejection.
- **ER-13 (fixed).** `VoiceKeyForm.save` catches a rejected `setVoiceKey` and shows the «Не получилось сохранить ключ» wording.
- **Stop races named in the scope.**
  - Stop during start: `stopNow()` awaits `starting` and `pendingFallback`, and `start()` stops a console opened while `held`. A console that will not stop stays tracked and the stop answers `still-running`.
  - Stop then fallback: `fallBack()` and `startFallback()` check `held`, a deferred fallback is dropped, and `onOutput` ignores output while held.
  - Send while stopping: `send()` waits for `personStop` and `stopping` before clearing `held`.
  - Stopped CEO restarting by itself: `ensure()` returns the status while held, so the popup's opening no longer starts it. The only revivals are «Запустить», «Перезапустить» and a message, as the changelog says.
- **Stop that fails.** A stop that leaves the console running releases `held`, and the popup says so.
- **`voiceSample`.**
  - The voice is checked against a five-id allowlist and the locale is normalised to `en` or `ru` before the cache name is built. `../../etc` is refused before any cache or vault access.
  - The cache write goes through a temp file and a rename with 0700 and 0600 modes. The sample folder is the voice's own, never the CEO's.
  - The key appears only in the Authorization header. Errors carry a reason, an error name or an HTTP status, and the renderer receives only a reason code. `voiceReady` returns a boolean only.
- **`VoicePicker`.** The listen generation closes stale contexts. `AudioContext` is created inside the try, and the catch closes it on decode or start failure. `playing.current` is set only after a successful `start()`. Stop and unmount call `silence()`, which closes the context.
- **`useVoiceCall`, `voiceCall` and `browserAudio`.**
  - A second start is refused while a call is active.
  - Hang-up during minting, socket opening or microphone opening is guarded by generations.
  - `browserAudio.stop()` interrupts playback, disconnects the processor, stops the tracks and closes the context. This also covers a failed `getUserMedia`, because `end('microphone')` calls `audio.stop()`.
  - Mute drops later audio and interrupts what is playing. Output levels are cleared on interrupt, and input readings expire after 0.3 s.
  - The kept-calls reader validates each record and drops the bad ones. Writes are caught, lines are cut at 2000 characters, and storage is capped at 40 000 characters per call.
- **Call ask.** `ceoCallWanted` is taken once and dropped when the CEO window closes. `takeCall` in the popup has a catch.

## Could not check

- **Voice tools.** Whether a voice tool or the CEO's tool operations call `agent.send` or `ensure` in a way that would revive a stopped CEO. `ceoTools.ts` is shown only in a one-line diff.
- **`stopRuntime` and exit timing.** The internals of `stopRuntime.stop` and the pty exit-callback timing. The tests call `onExit` synchronously before `personStopEnded`, and a real later exit is not exercised.
- **Imports.** Whether `randomUUID` was already imported in `index.ts`, since the diff does not show it.
- **Live behaviour.** The vault and key-store internals, live xAI responses, and real microphone, `AudioContext`, CSP and autoplay behaviour. Generated reports were omitted.

# Run one (candidate bb5f406587d06de3fe70be9dad130b644dc72846)

## Fabric 0.3.25 release review, iteration 3: errors
Level errors, candidate bb5f406587d06de3fe70be9dad130b644dc72846, baseline 53e8c3e2, reviewer model moonshotai/kimi-k3.1-pro, read-only.

## Verdict

**Block release.** ER-7, ER-8 and ER-9 are fixed on their tested paths, and ER-4 and ER-6 have their intended fixes. Two external-stop gaps remain: a stop during opening can leave every later revival waiting forever, and a second stop door can release the first door's hold, allowing an early-end fallback after the person's stop. These leave SCN-187 and the changelog stop contract false. No credential leak, cache path traversal or remaining VoicePicker context leak is shown.

## Findings

## Checked and fine

- ER-7 is fixed for `stop()`: the person-stop marker covers the whole of `stopNow()`, including its initial awaits, and `send()` and a person's `restart()` wait before clearing `held`. The supplied ER-7 test revives the CEO after the stop.
- ER-8 is fixed for an installed `sessionId`: the external door begins the marker, the held exit is consumed without fallback, and the message waits. ER-9 is also fixed: a console opened while held is stopped, a console left running is installed and retried by `stopNow()`, and `still-running` is returned with the console tracked. ER-10 and ER-11 above are the remaining external-door gaps.
- ER-4 is fixed. `playing.current` is installed only after a successful `node.start()`, and the catch closes the local context on decode, connection or playback-start failure. ER-5's generation checks still close stale decoded contexts, supersede older listens and invalidate work on unmount.
- ER-6 is fixed for a single registered external stop. Both index stop paths use `try/finally`, and a stop that leaves the console running releases the hold. ER-11 covers the unregistered second-door case.
- The ordinary held paths remain guarded: `ensure()` does not start a held CEO, `fallBack()` and `startFallback()` check `held`, a deferred fallback is dropped, output is ignored while held, and a held exit does not trigger early-end fallback. `stopConsole()` retains the plain-then-forced stop and the `still-running` outcome.
- `voiceSample()` allowlists the five voice ids before constructing cache names and normalizes the locale to `en` or `ru`. The supplied `../../etc` test is refused before cache or vault access. The renderer cannot traverse the sample cache through the shown input.
- The xAI key is used only in the sample request's Authorization header. Sample errors expose a reason, error name or HTTP status, the renderer receives no detail or key, and `voiceReady` returns only a boolean. Cache reads become misses, writes are caught, empty audio is refused, and the fetch has a 20-second timeout.
- `useVoiceCall` still prevents a second active start. Session refusal, socket construction failure, microphone rejection and hang-up during token minting, socket opening or microphone opening are handled by `createCall`'s generation checks.
- `browserAudio.stop()` interrupts playback, disconnects the processor, stops microphone tracks and closes its context. Muting interrupts current playback and drops later audio while transcripts continue. Output levels are cleared on interruption, input readings expire, and `levelOf()` implements the tested RMS scaling and cap.
- I did not run the build, tests or packaged app, and generated reports were omitted. The internals of `stopRuntime`, `openWithFallback`, pty exit timing, the vault and key store, live xAI responses, and actual microphone, AudioContext, CSP and autoplay behavior could not be verified. In particular, the supplied external-stop tests place `onExit` before `personStopEnded`; a later exit could not be checked.
