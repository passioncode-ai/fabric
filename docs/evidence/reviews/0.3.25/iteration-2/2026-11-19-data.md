# Fabric 0.3.25 release review, iteration 2: data

Level data, candidate 938f4b16e3a2adcb94f6ab6570ed66e81a56c79a, baseline 53e8c3e2, reviewer model anthropic/claude-sonnet-5.5, read-only.

## Verdict

No blocking data or storage findings. Both iteration 1 findings are fixed. Three new non-blocking robustness points are listed below. The persona voice migration, sample cache naming, credential handling, storage separation, new IPC rules and the xAI TTS request shape match the supplied contracts, as far as the diff and the full files show.

Status of iteration 1:
- **DA-1 is fixed.** `readKept()` now filters every restored record through `isRecord`/`isLine`. It checks id, finite at/ms/usd, and that lines is an array of lines with a valid `who` and a string `text`. A non-array or unreadable store gives an empty history.
- **DA-2 is fixed.** `CEO_USES` in `ipc-window-policy.test.mjs` now lists `ceoAgentStop` and `ceoAgentTakeCall`, matching `CHANNEL_RULES` (`MAIN_AND_CEO`). I did not run the test.

## Findings

| Id | Severity | Finding | Evidence | Suggested fix |
|---|---|---|---|---|
| DA-3 | Non-blocking | The sample cache directory is created with the default mode, not owner-only. Files are `0o600`, but `mkdirSync(samples, { recursive: true })` creates `userData/ceo-voice` and `ceo-voice/samples` with the process umask (usually 0755). `ceo-voice` is also the folder that holds the person's xAI key file. If the sample cache creates it first, the key's folder is world-listable. The key file's own mode and encryption could not be seen. | `apps/desktop/src/main/index.ts`, `voiceSample` handler, `cache.write`: `mkdirSync(samples, { recursive: true }); writeFileSync(..., { mode: 0o600 })` | Pass `{ recursive: true, mode: 0o700 }` to `mkdirSync`. |
| DA-4 | Non-blocking | A truncated or corrupt cache file is never refetched. The cache write is a plain `writeFileSync`, not a temp file plus rename. `voiceSample` returns any non-empty kept file without checking it. A write cut short by a crash leaves a non-empty partial MP3 that is served on every «Послушать». The renderer then fails to decode it and shows "The sample did not load" forever for that voice and language. The "empty file is refetched" rule covers only zero bytes. | `apps/desktop/src/main/ceoVoice.ts`, `voiceSample` (`kept && kept.length > 0`); `index.ts` cache `write`; `VoicePicker.tsx` `listen` catch path sets `unavailable` | Write to `name.tmp` then rename. Optionally delete the cached file when decode fails, so the next press refetches. |
| DA-5 | Non-blocking | Call transcripts are now persisted in plain text, with no way to clear them. `keep()` stores up to 10 calls of up to 200 lines each in the CEO window's `localStorage` (`fabric.ceo.calls`). The line text is whatever was said, including the CEO reading session screens aloud. The size of one line is not bounded, and no «Очистить историю» control is in the diff. ## Checked and fine

- **`validatePersona`:** `voice` is optional. Only `male` or `female` is kept, and any other value (string, number, null, array) drops the voice, not the look. The tests cover the old file without `voice`, valid values and bad values.
- **Voice mapping:** `voiceGenderOf` reads missing or unknown values as male. `xaiVoiceOf` falls back to the default style for an unknown style. The mapping (orbit rex/eve, spark sal/ara, wave leo/eve) matches the changelog, ADR amendment 2 and `external-contracts.md#xai-voices`.
- **Persona saves:** `PersonaScreen.tsx` and `start/FirstRun.tsx` keep an optional name and add `voice` only when the draft has one. Both initialise the draft from the stored persona, so an existing voice is not lost on save as far as shown.
- **Realtime call voice:** it uses `xaiVoiceOf(persona().persona)` in place of the fixed `eve`. `ceoAgentVoice` stays CEO-only and returns the session fields without the xAI key.
- **Sample cache names:** the voice is checked against the five built-in ids before any path is built. The file name is `${voice}-${ru|en}-v1.mp3`. A path-traversal argument such as `../../etc` is rejected with `unknown-voice` (the test covers it). Language is normalised and the version is explicit. Samples are cached per voice and language. Cache read and write failures do not block playback, and the write failure is swallowed.
- **TTS request shape:** `POST https://api.x.ai/v1/tts` with a JSON body of `text`, `voice_id`, `language`. The key goes only in the `authorization` header and is held for the request. The key comes from the person's own key or the vault slot. A 20 s timeout applies, the MP3 bytes are returned as base64, and a zero-byte answer is a failure.
- **Credential hygiene:** failure details carry a reason code, HTTP status or error class only. The test asserts that a refused result does not contain the key. `ceoAgentVoiceReady` returns `{ ready: boolean }` and drops the vault value. The IPC handler logs only `reason` and `detail.slice(0, 200)`, and returns only `reason` to the renderer.
- **IPC policy for new channels:**
  - `ceoAgentStop` and `ceoAgentTakeCall` are `MAIN_AND_CEO`.
  - `ceoAgentVoiceReady` and `ceoAgentVoiceSample` are `MAIN_ONLY`. Their callers (`PersonaScreen`, `FirstRun`) are main-window screens, so the policy matches usage.
  - Key reading and clearing stay main-only, and `ceoAgentVoice` stays CEO-only.
  - The preload and `FabricApi` types add the same channels.
- **Handler argument checks:** the `voiceSample` handler coerces a non-string voice to `''`, which is refused as `unknown-voice`. The `open` handler accepts `{ call: true }` only when it is strictly `true`.
- **Call-request flag:** `ceoCallWanted` lives in memory and is taken once. It is cleared when the CEO window closes, so a stale request cannot start a later call.
- **Stored preference and state:** the mute preference is a boolean string in `localStorage`, read and written inside try/catch. The CEO's held (stopped) state is in memory only and is not written into `persona.json` or the call store. After an app restart the CEO is not held, and the first use starts it.
- **Sample directory location:** the samples are under `userData/ceo-voice/samples`, not the CEO agent's own folder, and only audio bytes are cached.

Not checked:
- No tests, build or packaged app were run.
- The main-side `persona.json` read/write code and its file mode were not in the material. I could not confirm that the writer keeps `voice` (it should, if it goes through `validatePersona`), or that `persona()` in `index.ts` returns that validated value.
- `PersonaProvider` is now mounted in the CEO window. I could not see which IPC channels the persona provider uses, or whether they are allowed for the CEO window kind (`EVERY_WINDOW` was not shown). If they are main-only, the CEO head and button would show the default face instead of the chosen character.
- I could not confirm whether the CEO window shares a storage origin with the main window, so `localStorage` isolation is unverified. Keys are prefixed `fabric.ceo.`.
- I did not verify live that xAI accepts `language: "ru"` or `"en"`, or that the `/v1/tts` default response is MP3. CO-601 item 4 also notes that real samples have not been heard.
- I did not check the permissions of an existing `ceo-voice` directory, or whether the key store sets its own folder mode.
