# Fabric 0.3.25 release review, iteration 2: errors
Level errors, candidate 938f4b16e3a2adcb94f6ab6570ed66e81a56c79a, baseline 53e8c3e2, reviewer model moonshotai/kimi-k3.1-pro, read-only.

## Verdict

**Block release.** The basic ER-1, ER-2 and ER-3 paths are fixed, but three remaining stop races can acknowledge a stop while an opened console is still running, or let a message during a stop miss its revival and trigger an early-end fallback. Those paths leave SCN-187 and the changelog stop contract false. ER-4 and ER-6 remain only partly fixed and are non-blocking. No credential leak or cache path traversal is shown.

## Findings

| Id | Severity | Finding | Evidence | Suggested fix |
|---|---|---|---|---|
| ER-7 | BLOCKING | `send()` does not wait for the whole person's stop. `stop()` sets `held` and then awaits an in-flight start or fallback before it creates `stopping`. A message arriving in that window finds no `stopping`, clears `held` and shares or starts a session; `stop()` subsequently sets `held = true` again and stops that session. The message can be reported delivered, or fail as not delivered, while the CEO finishes stopped instead of being revived by the message. A person's restart can lose to the same reasserted hold. | `apps/desktop/src/main/ceoAgent.ts#stop` the awaits before `stopping` is assigned and the second `held = true`; `#send` the conditional `await stopping` followed by `held = false`; `#ensure` | Represent the entire stop, including its initial awaits, with one promise or epoch, and serialize `send()` and the person's `restart()` behind it before either clears the hold. |
| ER-8 | BLOCKING | A message during a console-window or History stop still has the original ER-2 race. `personStopping()` only sets `held`; it does not register anything that `send()` awaits. `send()` therefore clears the hold while the external stop is running, and the stop-induced exit is then handled as an ordinary or early exit. Inside `EARLY_END_MS` this starts `ended-at-start` fallback and can set the stopped runner aside; otherwise the CEO is left ended rather than revived by the message. | `apps/desktop/src/main/index.ts#registerIpc` session-stop and `terminal.end` paths; `apps/desktop/src/main/ceoAgent.ts#personStopping`, `#send`, `#onExit`, `#startFallback` | Register the external stop's promise with the agent and have `send()` await it before clearing `held`, so that stop's exit is always consumed while the hold is still active. |
| ER-9 | BLOCKING | A stop during start can return success and discard a console that is still running. In `start()`'s `held` branch, the newly opened id is never installed in `sessionId`; after `stopConsole()` returns, its running state is not checked. `stop()` later reads only the old or null `sessionId` and can return `{ ok: true }` with state `stopped`. If both stop attempts failed, the new console remains live and untracked, contrary to the claim that such a stop says `still-running`. | `apps/desktop/src/main/ceoAgent.ts#start` the `if (held)` branch and `finally { opening.clear() }`; `#stopConsole` its possible `still-running` outcome; `#stop` the later `const id = sessionId` and success return | Track the opened id and apply the normal stop path's running-state check and outcome to it, returning `still-running` with an accurate status instead of discarding a live console. |
| ER-4 | non-blocking | ER-4 is not completely fixed for a playback-start failure. `playing.current` is assigned before `node.start()`. If that call throws, the catch sees that the current context is the same context and deliberately skips closing it, leaving the failed listen's context open and its stale node referenced until another listen or unmount. Decode and connection failures are now closed correctly. | `apps/desktop/src/renderer/src/ceo/VoicePicker.tsx#listen` the assignments around `playing.current`, `node.start()` and the catch's `playing.current?.ctx !== ctx` condition | Install `playing.current` only after a successful `node.start()`, and on every failure clear any matching reference and close the local context. |
| ER-6 | non-blocking | ER-6 is fixed only when `stopRuntime.stop()` returns normally. Both external stop paths call `personStopEnded()` after the await without `finally`. If the stop rejects while leaving the console running, the hold remains latched: output stays ignored and a later exit is consumed as the person's exit instead of allowing normal fallback. | `apps/desktop/src/main/index.ts#registerIpc` session-stop and `terminal.end` paths; `apps/desktop/src/main/ceoAgent.ts#personStopping`, `#personStopEnded`, `#onOutput`, `#onExit` | Wrap each external stop in `try/finally` and always call `personStopEnded(id)`, releasing the hold only when the console is still running. |

## Checked and fine

- ER-1's ordinary path is fixed: `stop()` awaits the in-flight start, `start()` stops what it opened while held, and `personStopping()` recognizes ids in `opening`. The supplied ER-1 test covers the successful stop. ER-9 covers its remaining failure path.
- Once `stop()` has actually assigned `stopping`, ER-2 is fixed: `send()` awaits it before clearing `held`. ER-3's deferred fallback is also invalidated on a hold, with additional `held` guards in `fallBack()`, `startFallback()` and its completion handler. The supplied tests cover these narrower paths, not ER-7 or ER-8.
- ER-5 is fixed. Voice-sample listens have generations, stale decodes close their contexts, a new listen supersedes an older one, and unmount invalidates pending work and closes current playback. The remaining start-failure leak is ER-4 above.
- `voiceSample()` allowlists the five voice ids before constructing the cache filename and normalizes the locale to `en` or `ru`. The supplied `../../etc` test is refused before cache or vault access, so the shown renderer input cannot traverse the sample cache.
- The xAI key is used only for the sample request's Authorization header. Sample errors contain an error name, reason or HTTP status, the ops record receives bounded detail, and `voiceReady` returns only a boolean. No key is written to the sample cache or returned to the renderer.
- Sample cache read failures become misses, write failures are caught, and empty audio is refused. Request failures and renderer base64 or decoding failures reach `VoicePicker.listen()`'s catch rather than becoming an unhandled renderer rejection.
- `useVoiceCall` still prevents a second start while its current call is connecting, listening or speaking. Session refusal, socket construction failure and microphone rejection are handled inside `createCall`; the generation checks cover hang-up during token minting, socket opening and microphone opening.
- `browserAudio.stop()` interrupts queued playback, disconnects the processor, stops microphone tracks and closes its context. Muting interrupts current playback and drops later audio while transcripts continue. Output levels are cleared on interruption, input readings expire, and `levelOf()` implements the tested RMS scaling and cap.
- I did not run the build, tests or packaged app, and generated reports were omitted. The internals of `stopRuntime`, `openWithFallback`, pty exit timing, the vault and key store, real xAI responses, and actual microphone, AudioContext, CSP and autoplay behavior could not be verified from the supplied material.
