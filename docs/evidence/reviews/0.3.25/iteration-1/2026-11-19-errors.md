# Fabric 0.3.25 release review, iteration 1: errors
Level errors, candidate 91d952ded1cfe6bdd46b6ae288927471037875aa, baseline 53e8c3e2, reviewer model moonshotai/kimi-k3.1-pro, read-only.

## Verdict

**Block release.** Three CEO stop races can start a console after a successful stop or prevent a message from reviving a stopped CEO. That leaves the new SCN-187 and changelog stop contract false in those paths. The remaining findings are non-blocking. No credential leak or cache path traversal is shown.

## Findings

| Id | Severity | Finding | Evidence | Suggested fix |
|---|---|---|---|---|
| ER-1 | BLOCKING | A stop during an in-flight start is acknowledged without stopping that start. `stop()` captures the old or null `sessionId`, sets `held` and returns `ok`; `start()` later unconditionally installs its session and sets `state = 'running'`, so the CEO runs after the successful stop. A console-window stop during open is also missed because `personStopping()` checks only `sessionId`, although `opening` already identifies the CEO console. | `apps/desktop/src/main/ceoAgent.ts#stop`, `#start`, `#personStopping`, `#isCeo` | Serialize stop with in-flight starts and stops, re-read the session id, recognize `opening` ids, and make `start()` stop or discard its console if `held` when open returns. |
| ER-2 | BLOCKING | Sending while the person's stop is still running clears `held` before the stop-induced exit arrives. Inside `EARLY_END_MS`, `onExit()` then starts an `ended-at-start` fallback and sets the stopped runner aside instead of treating the exit as the person's. A subsequent send can start the wrong runner, or fail with `all-set-aside` and `not-running` when no other runner is available, contrary to the claim that a message starts the CEO again. | `apps/desktop/src/main/ceoAgent.ts#send` clears `held` before `ensure()` awaits `stopping`; `#onExit`, `#startFallback`, `#fallBack` | In `send()`, await the active stop before clearing `held`, so its exit is always consumed as the person's exit before the message starts a session. |
| ER-3 | BLOCKING | A deferred fallback survives a successful stop. The fallback completion handler runs `startFallback(next)` whenever `sessionId` is non-null, without checking `held`; `stop()` leaves both `sessionId` and `runner` intact. `fallBack()` then sets that runner aside before `restart()` notices `held`. With the previous runner already set aside, a later message can find every runner set aside and fail to revive the CEO. | `apps/desktop/src/main/ceoAgent.ts#startFallback` completion handler, `#fallBack`, `#restart`, `#stop` | Invalidate deferred fallback work on the person's stop and check `held` before setting a runner aside, restarting, or retyping lines. |
| ER-4 | non-blocking | A failed voice-sample decode or node setup leaks its `AudioContext`. The context is created before `await decodeAudioData()`, but is not stored in `playing.current` until decoding and setup succeed; the catch only changes the displayed error. Repeated bad samples therefore leave contexts open. | `apps/desktop/src/renderer/src/ceo/VoicePicker.tsx#listen` | Keep the context in a local variable visible to the catch and close it on every decode, connection, or start failure. |
| ER-5 | non-blocking | Sample listens are not serialized or cancelled. While one request is loading, the other gender remains enabled and the first becomes enabled again when the second changes `hearing`. Multiple late resolutions can play simultaneously and overwrite `playing.current`, leaving earlier contexts untracked. A pending request can also start playback after the picker has unmounted. | `apps/desktop/src/renderer/src/ceo/VoicePicker.tsx#listen`, `#silence`, the listen button's `disabled` condition and unmount effect | Add a listen generation and mounted check after every await, close stale contexts instead of playing them, and cancel or supersede all pending listens on a new listen or unmount. |
| ER-6 | non-blocking | An external stop failure leaves `held` latched. Both index stop paths call `personStopping()` before awaiting `stopRuntime.stop()`, but no outcome path clears the hold if that stop throws or leaves the console running. Unlike `stop()`'s `still-running` handling, output remains ignored and a later exit cannot trigger the normal fallback. | `apps/desktop/src/main/index.ts#registerIpc` session-stop and `terminal.end` paths; `apps/desktop/src/main/ceoAgent.ts#personStopping`, `#onOutput`, `#onExit` | Clear and broadcast the hold when an external stop fails or leaves the session running, while retaining a stopping marker to classify the exit race. |

## Checked and fine

- `voiceSample()` allowlists the five voice ids before constructing the cache filename and normalizes the locale to `en` or `ru`. The supplied `../../etc` test is refused before any cache or vault access, so the shown renderer input cannot traverse the sample cache.
- The xAI key is used only for the request's Authorization header. Sample errors contain an error name, reason, or HTTP status, and the ops record receives only that bounded detail. `voiceReady` returns only a boolean. No key is written to the sample cache or returned to the renderer.
- Sample cache read failures become cache misses, cache write failures are caught, and an empty audio response is refused. Other request or decoding rejections reach `VoicePicker.listen()`'s catch rather than becoming an unhandled renderer rejection.
- `browserAudio.stop()` interrupts queued playback, disconnects the processor, stops microphone tracks, and closes its audio context. The existing generation checks and tests cover hang-up during token minting, socket opening, and microphone opening.
- Muting interrupts current playback and drops subsequent audio while transcripts continue. Output-level entries are cleared on interruption, input readings expire, and `levelOf()` implements the tested RMS scaling and cap.
- `useVoiceCall` prevents a second start while its current call is connecting, listening, or speaking. Session refusal, socket construction failure, and microphone rejection are handled inside `createCall`.
- The supplied tests cover ordinary stop, stop from another door, still-running stop, voice-sample caching and refusal, and call teardown races. They do not cover the races in ER-1 through ER-3 or the audio lifecycle failures in ER-4 and ER-5.
- Not checked dynamically: I did not run the build, tests, or packaged app. Generated reports were omitted. The internals of `stopRuntime`, pty exit timing, the vault and key store, real xAI responses, and actual microphone, CSP, and autoplay behavior could not be verified from the supplied material.
