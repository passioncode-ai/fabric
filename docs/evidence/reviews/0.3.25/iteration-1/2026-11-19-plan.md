# Fabric 0.3.25 release review, iteration 1: plan

Level plan, candidate 91d952ded1cfe6bdd46b6ae288927471037875aa, baseline 53e8c3e2, reviewer model anthropic/claude-sonnet-5.5, read-only.

## Verdict

No blocking finding in the material shown. The plan does what the owner asked, and the existing call keeps its limits, key form and `ask_ceo` tool.

- **Done:** popup redesign, CEO button with the character's face, male default voice per character with a sample in Your Fabric and in onboarding, call as a panel in the chat, and Stop/Restart with a real main-process regression test.
- **Not run:** I could not run any test, the built app, or the xAI TTS call, so everything below rests on reading the diff.
- **Partial:** two of the asks are only partly delivered. Call history lives only as long as the CEO window (PL-1), and the composer slot is a prop that neither the popup nor the home card passes through (PL-5).
- **Confirm before ship:** PL-2 and PL-3 need a check, because they decide whether a test fails or the chosen character is ignored in the CEO window.

## Checked and fine

- **Stop/Restart in the main process:**
  - `held` is honoured in `ensure`, `onExit` and `onOutput`. Writing to the CEO or a person's restart clears it.
  - `fallBack` cannot restart a held CEO.
  - The main-process test simulates the pty's exit-before-resolve order. It checks no second `open`, no set-aside, a stopped `ensure`, Start bringing it back, a stop from the console's own window, and the `still-running` answer.
- **Stop/Restart in the popup:** `CeoPopup.test.tsx` covers stop, "stopped", Start and the failed-stop message. The i18n keys (`ceoAgent.problem.*`, `stopped`, `stopFailed`, `restartShort`) exist in both ru and en and match `CeoProblem`.
- **Existing call:**
  - `MAX_CALL_MS`, `IDLE_CALL_MS`, `CONNECT_DEADLINE_MS` and the generation guards are unchanged, and the old protocol tests remain.
  - The key flow still goes through `VoiceKeyForm` and `setVoiceKey`.
  - `ASK_CEO_TOOL` is still in the session tools.
  - Only `voice` changed, from fixed `eve` to the character's voice.
- **Voice mapping:**
  - A look saved without `voice` reads as male. An unknown `voice` is dropped and the look kept.
  - The mapping uses only xAI's five built-in voices, with pitch-based gender documented in `external-contracts.md`.
  - The `persona.test.ts` "measured pitch" assertion only restates the table, so it is a weak test, not a wrong one.
- **Sample path:**
  - `voiceSample` checks the voice against a whitelist before building the cache filename, so there is no path traversal; the test covers `../../etc`.
  - The key goes in the request header only. Errors return reason and HTTP status, and the test checks the key does not appear.
  - The cache is per voice and language with 0600 files.
  - `VoicePicker.test.tsx` covers default male, per-character voice choice, no-key (no sample button), a refused sample and playing.
- **Onboarding:** the voice step appears only when `voiceReady` is true, as the owner specified. Settings always shows the choice.
- **Reduced motion:** the meter bars rest and the ring animations sit inside `prefers-reduced-motion: no-preference`.
- **Docs:** ADR-0197 amendment 2, SCN-186, SCN-187, the scenarios index and the changelog agree with the code. The changelog states the male default, the stop behaviour and the measured gender.
- **Not checked:** I ran no tests, did not run the built app, and did not see `persona()`, `PersonaProvider`, `usePersona`, the home composer's render site, `openCeoWindow`'s close behaviour or `ceoVault`.
