# Fabric 0.3.25 release review, iteration 1: ux

Level ux, candidate 91d952ded1cfe6bdd46b6ae288927471037875aa, baseline 53e8c3e2, reviewer model anthropic/claude-sonnet-5.5, read-only.

## Verdict

No blocking findings. The stop works as the owner asked and the call is a panel in the chat. The voice picker and the face on the button are in, and the CHANGELOG, SCN-182/184/186/187 and ADR amendment 2 largely match the code shown. Twelve non-blocking findings remain, mostly accessibility, one overclaim about call history, and CSS tokens I could not confirm. I did not run the code, the tests or the built app; everything below comes from the diff and the listed files.

## Checked and fine

- **Em dash:** none (U+2014) in the new ru and en strings, `sampleText`, the CHANGELOG entries, or SCN-184/186/187 text in the diff. The test asserts `sampleText` has none. I could not grep the untouched parts of the files.
- **ru/en parity:** every new key appears in both files (`ceoAgent.stop`, `stopping`, `start`, `stopped`, `stopFailed`, `restartShort`, `state.stopped`, the call, voice, tone and sample-failed keys, `problem.*`). All five tone keys match the five xAI voices in `PERSONA_VOICES`. All four `CeoProblem` codes have wording, which replaces the raw code the failed banner showed in 0.3.24.
- **States:**
  - connecting, listening, speaking, ended and failed each have a label, a meter colour and a panel border.
  - After a refused key the panel offers the key form, and `reset` returns it to idle.
  - Stopped, stop-failed and still-running are worded and covered by `CeoPopup.test.tsx`.
- **Stop and start behaviour:**
  - `held` is set by `stop()` and `personStopping`, and cleared by a send or a person's restart.
  - `ensure()` and `onExit` honour it, so no fallback fires and a reopened window does not start the CEO.
  - `status()` reports `stopped`. The unit tests cover stop, the other door, and a stop that leaves the console running.
- **Call from the home card:** `takeCall` is taken once, the broadcast reaches an already open window, and the mount path covers a fresh one. `start()` refuses a second call while one is active. The voice channel is `CEO_ONLY`, matching the call living in the popup.
- **Reduced motion in CSS:** the starting ring and the connecting meter are inside `@media (prefers-reduced-motion: no-preference)`, with matching first and last frames. Under reduced motion the meter bars hold their shape and the phase colour carries the state.
- **Keyboard and roles, otherwise:**
  - Native `<details>` and `<summary>` for past calls, a labelled call section, a labelled «Сказать текстом» input, and a checkbox for the voice switch.
  - Focus rings on the floating button and the voice controls.
  - The call button keeps one DOM node across its two states, so focus survives.
  - The call lines list is `aria-live="polite"`. `role="status"` is on the stopped notice and on the sample-failed message.
- **Voice sample:** an unknown voice id is refused before any request, so a crafted id cannot reach the cache path. The key is held only inside the main-process request, and a failed sample never blocks saving the choice. The first run shows the picker only when `voiceReady` is true.
- **Claims versus code:**
  - The CHANGELOG items hold: the character's face on the button with the ring states, male default, the character mapping (orbit, spark, wave to Rex/Eve, Sal/Ara, Leo/Eve), legacy looks read as male, and the stop details.
  - SCN-186 and SCN-187 steps match the code. The SCN-187 telemetry names `ceo.agent.held` and `ceo.agent.stopped` are both recorded.
  - ADR amendment 2 matches `persona.ts`, `ceoVoice.ts` and `ceoAgent.ts`.
  - The ceoTools refusal text now says "stops or restarts".
