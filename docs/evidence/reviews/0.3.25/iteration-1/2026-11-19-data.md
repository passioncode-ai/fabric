# Fabric 0.3.25 release review, iteration 1: data
Level data, candidate 91d952ded1cfe6bdd46b6ae288927471037875aa, baseline 53e8c3e2, reviewer model moonshotai/kimi-k3.1-pro, read-only.

## Verdict

No blocking data or storage findings. The persona voice migration, sample cache, credential handling, storage separation, and xAI TTS request shape match the supplied contracts. Two non-blocking robustness and test-consistency issues remain.

## Findings

| Id | Severity | Finding | Evidence | Suggested fix |
|---|---|---|---|---|
| DA-1 | Non-blocking | Restored call history is only checked for being an array. Valid JSON containing null or malformed records can throw during rendering, for example when reading `r.id` or formatting `r.usd`, despite the comment that an unreadable store must never break the window. | `apps/desktop/src/renderer/src/ceo/CeoCall.tsx`, `readKept()` and `CallPanel` history rendering | Validate each restored record and its lines, discard invalid entries, and fall back to an empty history when validation fails. |
| DA-2 | Non-blocking | The CEO policy-test fixture omits `ceoAgentTakeCall`, although the runtime policy grants that channel to the CEO window and the popup invokes it. The fixture therefore no longer describes the shipped CEO IPC surface and may fail an exact allowlist assertion. | `apps/desktop/src/shared/ipcWindowPolicy.ts`, `CHANNEL_RULES.ceoAgentTakeCall`; `apps/desktop/test/ipc-window-policy.test.mjs`, `CEO_USES`; `apps/desktop/src/renderer/src/ceo/CeoPopup.tsx`, `takeAsks` | Add `ceoAgentTakeCall` to `CEO_USES` and run the IPC window-policy test. |

## Checked and fine

- `validatePersona` keeps `voice` optional, accepts only `male` or `female`, and drops unknown values without rejecting the persona. `voiceGenderOf` reads missing or unknown values as male, and `xaiVoiceOf` also falls back safely for an unknown style.
- Both persona save paths preserve a selected voice while retaining the existing optional-name behavior: `PersonaScreen.tsx` and `start/FirstRun.tsx`.
- The realtime call now obtains its voice through `xaiVoiceOf(persona().persona)`, replacing the fixed `eve` voice. The character mappings match the changelog and external-contract documentation.
- Sample cache names are constrained to an allowlisted voice, normalized `en` or `ru` language, and explicit version, for example `rex-ru-v1.mp3`. Unknown voices are rejected before any cache path is read or written, preventing path traversal through the IPC argument.
- Sample audio is written with mode `0o600`; cache-write failure does not prevent playback. Empty cache files are refetched, and samples are cached separately per voice and language.
- The sample cache is under `userData/ceo-voice/samples`, not the CEO agent's own folder. Only audio bytes are cached, not the xAI key.
- The TTS request matches the supplied contract: `POST https://api.x.ai/v1/tts` with JSON containing `text`, `voice_id`, and `language`; the key is used only in the authorization header. The documented default MP3 response is decoded as audio by the renderer.
- Failure details returned and logged by the sample handler contain reason codes, HTTP status, or error class, not the credential. `ceoAgentVoiceReady` returns only a boolean and drops the vault value.
- Call history is confined to CEO-window `sessionStorage`, capped at ten records and 200 lines per call, with storage reads and writes guarded. The mute preference is only a boolean in `localStorage`. Neither storage area contains the xAI key or ephemeral voice token.
- New IPC channels have explicit rules: stop and take-call are available to main and CEO windows, voice remains CEO-only, and key reading and clearing remain main-only. Sample and readiness calls return no secret.
- The CEO stop state is held in memory rather than persisted as part of the persona or call stores; messages and person-initiated restarts clear the hold as specified.

Not checked: no tests or packaged application were run; the actual `persona.json` read/write implementation and its file mode were not included; existing sample-directory permissions, atomicity of cache writes, live xAI acceptance of the request, and real storage behavior in the packaged CEO window could not be verified from the supplied material.
