## Checked and sound
- Project scoping of the board search: `project_tasks`, `task_notes` and `work_claims` are read through the session's project-scoped store (`scopedStore.ts#select` applies `estate_id` and `project_id`, `scope.ts:116,148,150`). No other project's tasks, notes or claims can be read. Every column read exists (`moved_at`, `brief_*`, `started_at not null`, `agent`, `released_how`, `author_kind`). The operator's notes were already readable by agents through `fabric_work_list` (`workTools.ts:325`), so this opens no new exposure.
- The board part uses the session's own reader door: `board.list(this.boardCaller(scope), ...)` reads `board_list_reader` with `p_reader: caller.projectId` (`boardService.ts:759-760`). It reads only threads the project takes part in, marks nothing read, and binds cursors to the reader and filter. The directory part is `com.directory` for the same caller. Another project's text reaches the answer only as messages in threads this project takes part in, which `com.list` already shows.
- The answer echoes the query, and `searched`/`not_searched` are lower-cased words of that same query, which `checkReference` (`assertAgentReference`) has already admitted. The query is at most 300 characters, at most 12 words are searched, each document is read to 6 000 characters, each word to 64, and a snippet is 240 characters. `query`, `notSearched` and the ids are computed linearly (`allQueryWords`, `compoundsOf`).
- The window ladder costs at most 15 `com.list` pages (one day, 6 hours and 1 hour, 5 pages each; the widening path takes fewer) plus 5 directory pages. The run-one fixes hold. DA-8/UX-12: a failed wider read keeps the whole narrower window and says «another window could not be read», and `allFailed` does not count a kept window as failed (`:251`). ER-13: the 1-hour failure is fixed, but see DA-11 for the 6-hour case. `board_window_days` is rounded.
- DA-5 (released claims capped), DA-7 (`board_narrowed`, no «wider days» when narrowed), UX-5 (`holder_unknown`, `holders`), UX-11/DA-9/DO-19 (the query cut in its own order, an id counting as one; probe output matches the test `['mikes','novembers','co-571']`) all hold on the candidate.
- `work.swept@1`: `found` is built from `ABANDONED_KINDS`, so the new `request-no-folder` kind passes ingress (`commandIngress.ts:205-213`). `capped` is still an enumeration of `SWEEP_CAPS`. Migration 124 adds no SQL-side shape check. The only issue is the meaning of the `threads` value (DA-10).

An inbox item to a project with no folder stays skipped (`:1061-1062`; test DA-6 passes). `toOperatorMarks('no-folder')` reaches the sweep through `index.ts:3109`, and the sweep shows `request-no-folder` only while the request is not settled.
