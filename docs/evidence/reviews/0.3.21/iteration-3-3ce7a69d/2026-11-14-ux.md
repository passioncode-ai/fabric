| UX-14 | non-blocking | ER-13 (V3-7) is fixed only for the 1-hour step. When one day does not fit and the 6-hour read then fails, the day's 500 messages already read are dropped. Add a test where the 6-hour read throws. |
| UX-15 | non-blocking | `board_narrowed` says "the board was read for the last N hour(s) only" even when that window was not read whole. In that case only its oldest 5 pages are kept. The newest messages of the window, which an agent searching "who works on what now" needs most, are the ones left out. `capped: ["board"]` is present, but the one sentence that explains the board's coverage claims the whole window. | UX-16 | non-blocking | A query word joined by `-`, `_`, `.` or `/` is searched only as an id, with no Russian or English forms and no parts. Natural hyphenated words ("sign-in", "on-demand", «мини-приложение», «Telegram-бот») therefore find nothing, even when a document says the same thing in another case or without the hyphen. Since ER-12 an id no longer matches by its first word, so `Board/Rail` and `telegram-бот` lost the matches they had at `7b5a7205`. The agent then reads "the searched words were not found". The tool description names ids only by examples (`CO-571`, `fabric_work_list`, `boardDispatchRun.ts`). Spec §2 says a text's ids are read "beside their parts", which holds for documents but not for the query. | `apps/desktop/src/shared/boardSearch.ts:141-157` (a run of 2+ words becomes one id with the terms `[id]`); `:199-202` (ER-12: an id never matches a shorter word); probe 4; `apps/desktop/src/main/workTools.ts:402`; `docs/evidence/specs/2026-11-14-board-search.md` §2, first bullet | Search a query id's parts too, at a lower weight, as documents already index them.
