## Checked and sound
- ER-15 (fixed): `compoundsOf` pushes each tail after `/` (`boardSearch.ts:101-107`). `frequency`'s id rule (`:213`) matches a longer term only where it goes on with a separator. `'-_./'.includes('')` is true, but that branch is reached only for `t === term`, which the exact read at `:201-202` has already returned. Test «ER-15 (run two)» passes, and `CO-571` does not find a longer CO number that begins with it.
- Cost of the tails: quadratic in path depth, bounded by `TEXT_MAX` 6000. The worst I measured on 2 500 documents is 2.85 s (`ab/` x2000), against 1.24 s before and the spec §3a's 8.5 s cold bound. Realistic prose with paths takes 1.10 s against 1.03 s. V8 string slices keep the heap at about 76 MB for 500 worst-case documents. Not a finding.
  - A single-word tail also counts that word twice: `terms('see docs/board')` gives `board` twice. The ranking effect measured 0.224 against 0.221, which is negligible.
- ER-17 (fixed): `touchWords` cuts at the first dot followed by a Latin letter (`:292`). `fabric-0.3.21-mac.json` keeps its version, `index.test.ts` reads as `index`, and the test passes.
- ER-18, DA-10 (fixed): the sweep and the dispatcher each handle the two thread caps correctly.
  - `readBoardRequests` adds `threads` for either cap (`abandonedSweepRun.ts:791`).
  - The dispatcher logs only the open read's cap (`boardDispatchWiring.ts:394`). A request missing from `states` falls back to the follower (`:500`), so the newest read's cap loses no state there.
  - `readRequestThreadIds` marks a cap only on the last page that still has `more` (`boardThreadIds.ts:38-39`).
- ER-19, UX-14, UX-15 (fixed for `days` of 2 and more), shown by probe B and the run-two test:
  - When the 1-hour read fails after an incomplete 6-hour read, the 6-hour rows are kept with window 0.25, and `board_narrowed` says «only its oldest messages» and «another window could not be read».
  - A widening read that fails keeps the whole window (`:115`).
  - `allFailed` treats a board window that was read as a part read (`:259`).
- DA-12 (fixed): `liveClaims` answers `{claims, capped}` from `readWork`'s `capped` (`workTools.ts:423`, `workRead.ts:171`).
  - Probe D: held hits keep `held_by` and get no `holder_unknown`, unheld hits get `holder_unknown`, `capped` names «live claims», and `holders` says «whole».
  - Probe E: the uncapped object form behaves like the array form.
  - A failed `readWork` (tasks or sources unread) throws and lands in `degraded` as `claims`.
- UX-17 (fixed): the note with hits names the words past the cap (`:291`), and the tool description names `not_searched` (`workTools.ts:402`).
- `BoardScreen.tsx:499-514`: a question with no `why` shows no why block and keeps the holds line. The fold state is keyed by the row's ref. The moved `.lp-decide-holds` rule sits after «adaptations to the app window» (`launch.css:536-537`).
- `handlerIsProduct` (`productConnect.ts:190-197`): on macOS it requires the exact bundle name. On Windows and Linux it checks that the squashed handler name contains the product name, so a quoted registry command line still passes and Electron still fails.
- `boardDispatchRun.ts:1061-1062`: an inbox item with no folder stays `skip` (`skipped-no-folder`) and is never given to the operator.
- `boardDispatchRun.ts:750-786`: `resolveProject` caches the canonical id, proposes the alias once per process without awaiting it, logs a failed proposal, and throws on a real ambiguity.
- `folderResolver.ts` CO-573 (10): a failed remote read reads as no remote.
- The ruled UX-16 (hyphenated query words searched as ids, CO-578) is not re-reported. ER-20 is the slash case, which UX-16 does not name.
