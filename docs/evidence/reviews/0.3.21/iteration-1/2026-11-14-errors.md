## Checked and sound
- Tokenizer and stemmer on odd input: empty, punctuation only, emoji, the stop words of both languages, `ё`/`Ё`, NFKC ligatures, `NaN` and negative limits, and regex-like queries. None throws, and each returns `[]` where nothing matches (probe1). Query length is bounded at 300 by zod (`workTools.ts`). `days` and `limit` are integers with bounds, so `new Date(NaN)` cannot be reached.
- Each read stands alone: a thrown read, a `failed` read and a `{error}` refusal are each named in `degraded` while the other parts answer. Every part failing gives the "not nothing matches" note (except ER-4). The `board_list` refusal shape `{error:{code,message}}` matches `boardService.ts` `refusal`.
- Board window narrowing is bounded: at most 3 windows of `BOARD_PAGES` calls, even with a cursor that never ends. It reads with `unread` false, so the search marks nothing read. The tool writes nothing.
- The message fields `searchBoard` reads (`id`, `thread`, `kind`, `sender.project`, `at`, `body.text`, `request.{id,target,capability,state}`) match `board_message_json`.
- The store scopes `project_tasks`, `task_notes` and `work_claims` to the session's project (`shared/scope.ts:116,148,150`), so the search and `similar_work` never read another project's tasks or claims. The PostgREST `.or(moved_at.gte.<ISO>,...)` value has no `,` or `)` and so parses as one value; this is unverified against a live stack, which this review may not start.
- `similar_work` cannot throw after the claim is written. `ClaimView.task.title` is always a string, touches default to `[]`, and `settled.touches ?? []`. The only throwing read after the write, `readWork`, existed before this release.
- `isWorkCall`: the keep-alive is an MCP `ping` (`fabricMcp.ts:623-640`) and fabric-mcp sends no `tools/call` of its own (`:565-567`). Batches are refused before `touched` (`agentSurface.ts:1050`). A console merged with a held session uses `outputAt`, and a session that just started counts as working.
- The no-folder path: the dispatcher waits `NO_FOLDER_TO_OPERATOR_MS` from submission, only while the switch is on. It never rewrites an earlier record as "three runs", the in-memory set is pruned when the request leaves the board, and the request heals when the folder returns.
- `resolveProjectForFolder`: `gitCommonDir` resolves null on any git error (`folderResolver.ts:43-44`), and `remoteOf(...).catch(() => null)` now covers an `originOf` that throws (`agentSyncLeases.ts:65-73`). A git that cannot be started no longer refuses enrollment.
- `runStateOf`: an exit with no code is read as `crashed`. Its only effect is the `crash` reason of the next hand-over (`boardDispatchRun.ts:644`); it adds no empty-run count.
- The launch-failure log is said once per change, and the error of a program that cannot be started now carries its system code (`boardDispatchWiring.ts:144`).
- `readRequestThreadIds` throws on a page that does not answer, reads each thread once, and sets `capped` at either bound. The board door supports `openOnly` (`shared/commsRead.ts:101`).
- `normaliseAsk` recommended option: option indexes stay aligned (no option is filtered out before the mapping), and an unknown recommended id, several recommended options or none are refused with how to fix it.
