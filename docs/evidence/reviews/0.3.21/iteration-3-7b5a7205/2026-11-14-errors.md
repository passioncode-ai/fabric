## Checked and sound
- ER-8's test cases hold (`index.ts`, `main.ts`, `README.md` link nothing, test «ER-8 ...» passes). The finding above concerns names outside them.
- ER-9: `queryWords` cuts at `QUERY_WORDS` after compounds and duplicates; the test «reads a document to TEXT_MAX, a word to WORD_MAX and a query to QUERY_WORDS words» passes. camelCase words carry several terms each, but within the 300-character query I measured no stall beyond the recorded range (p2, p3).
- ER-1 still fixed: `compoundsOf` is linear. A word cut at `WORD_MAX` never forms a false compound: `end` comes from the cut length, so the next word's start never equals `end + 1` while the run continues. NFKC expansion is re-cut by `wordsOf` on the same string `compoundsOf` indexes.
- The per-term prefix memo (`Indexed.seen`) lives per call: each `rankDocs` call builds fresh `Indexed` objects, so no stale memo crosses calls or queries.
- `similarClaims`: own claims and the same task are left out; `total` is computed on the capped query; lapsed and structurally `related` claims are filtered by the caller (`workTools.ts:588-594`).
- `readBoard`: at most 15 sequential pages; a refusal and a throw are both named in `degraded`; a whole window already kept survives a later failure; a sync throw in the door is caught (the call sits inside the `try`). `days` arrives as an integer 1 to 90 (zod), so the `since` dates are always valid. `allFailed` needs no document and every wanted part degraded. `holder_unknown` and `holders` appear only when the live claims failed.
- `handlerIsProduct`: macOS stays exact (`Fabric Inbox.app`, trailing slashes stripped). On Windows, `path.win32.basename` takes both separators. The substring match accepts versioned AppImages and refuses `electron`, `electron.exe` and `Electron.app`. An empty `app` would accept any handler (`''.includes`), but `app` is the constant `'Fabric Inbox'` (`productConnect.ts:82`), so it is unreachable. On Windows the vault check refuses before the handler check (`begin`), as CO-570's row says.
- `boardDispatchRun.ts`: an inbox item to a project with no folder stays `skipped-no-folder` (DA-6). A no-folder request never rewrites its earlier record. `noFolder` and `pastDue` are exclusive. Both are pruned when a request leaves the read and rebuilt from the next pass after a restart. A request reaching a settled state, getting a folder or the switch turning off leaves `noFolder` on its next decision. In `toOperator()` a record's reason can override `no-folder` only for a request that already had a `to-operator` record, which `continue`s before the decision, so the two never meet. The alias is proposed once per process and never awaited; both outcomes are logged.
- `decideDispatch`: the no-folder hand-over comes after the grace, the empty-runs and the switch checks, and only for a `candidate` request. A no-folder request leaves «На проверке» once its deadline is within `LAUNCH_MARGIN_MS`; it expires on the board then, which is acceptable.
- `abandonedSweep.ts`: `request-no-folder` is in `ABANDONED_KINDS`, `KINDS_OF.requests`, `SUBJECT`, `UNTITLED` and both i18n files. It is exclusive with `request-unmoved` and `request-to-operator` (an if/else chain) and is not an agent-only kind.
- `runStateOf`: an `exited` end with no numeric code reads `crashed`. `run`: a spawn error says «could not be started: <code>» (an `error` event after a failed Windows `kill` would be worded the same, Windows only, unverified). The launch-failure log is said once per change.
- `isWorkCall` counts only `tools/call` (a batch counts when any message is one). fabric-mcp's keep-alive is an MCP `ping` (`fabricMcp.ts:637-640`), and the proxy calls tools only for the agent. The adapter's hooks fire per turn, not while idle. The enrolled side therefore cannot look busy by itself.
- `sessionLiveForDispatch`: index passes `workAt` as a number or null, never undefined, so an enrolled session is judged by its tool calls and its start. A Fabric console that is also enrolled is judged by its output.
- `readRequestThreadIds`: the open filter `openOnly` is accepted by the operator door (`commsOperatorRead.ts:185`) and the database function (migration `20261021000120`). A page that does not answer throws, in the sweep and in the dispatcher alike.
