## Findings
| ID | Severity | What | Evidence | Proposed fix |
|---|---|---|---|---|
| DA-8 | non-blocking | When a wider board window fails after a narrower one was read whole, the answer says two false things at once. `board_narrowed` says the board «did not fit», but it was refused. The note says «Nothing could be read, so nothing was searched», but one day of the board was read and searched; it was empty. The causes: `readBoard` returns the kept window on a failure (`:112`); the DA-7 sentence assumes size is the only reason a window narrows (`:268`); and `allFailed` counts the board as failed because it is in `degraded` while `docs` is empty (`:248`). An agent is told both that the board was read for a day and that nothing was read. | `narrow-fail.mjs` output above; `boardSearchRead.ts:112, 248, 268, 273-274` | Have `readBoard` return its cause (did not fit, or failed) and word `board_narrowed` by it, for example «the read for N days failed; the last M day(s) were read». Count a part as failed in `allFailed` only when no window was kept. Add the case to `board-search-read.test.mjs`. |
| DA-9 | non-blocking | The tool's input description says «the first 12 searchable words are searched» (ER-9). `queryWords` puts ids first, then the plain words, and cuts at 12. So with 12 plain words and an id later in the query, the id is searched and the 12th plain word is not. The 12-word bound holds; «the first» does not. | `workTools.ts:404`; `boardSearch.ts:142-147`; `qorder.mjs`: `limas` (12th word) 0 hits, `CO-571` (13th) 1 hit | Say «12 searchable words, ids first» in the tool description and in spec §3a (`2026-11-14-board-search.md:91`), or keep query order when cutting. |
