## Checked and sound
- **V3-73 is fixed.** The surface test's list names `fabric_board_search`, stays sorted, and matches every session tool registered in `src/main` (static check above). I could not run the suite itself without a stack.
- **Run four's rulings to CO-578 hold as non-blocking.**
  - ER-23 and DA-14: the regression is real on this candidate, but it happens at the title level.
    - Generic words in titles linked claims before the tails existed too (`Update README` vs `README typo`).
    - The spec applies its «links nothing» rule to touched names, and those still link nothing (`touchWords`, the fourth probe pair).
    - The proposed fix is right: drop a query tail whose name is generic, and keep one that still carries a folder.
  - ER-24, UX-23 and DO-35 concern comments only; no behaviour depends on them.
  - UX-21, UX-22 and DO-36 concern reporting and wording. Neither `matched` nor the description changes what is read.
- **The `readBoard` ladder.** I traced every branch:
  - A failed first read answers `windowDays: null`, with `board` named in `degraded`.
  - A failed wider read keeps the window that was read whole, with `failedPast`.
  - When one day does not fit, the read narrows to 6 hours, then 1 hour.
  - A failed narrower read keeps the wider read's partial rows and adds `board` to `capped`.
  - When the last hour does not fit, the read is `capped` with `windowDays` at 1/24.
  - `partial` only ever holds the one-day read's rows.
  - The two `board_narrowed` forms are mutually exclusive (`>=` vs `<`), and each one's wording matches its path.
- **`allFailed`.** It is true only when no document was read and every wanted part is degraded.
  - A board window read whole before a wider read failed counts as read.
  - `kinds: ['notes']` still answers notes when the tasks read fails; their titles are empty.
- **`liveClaims` and `holder_unknown`.**
  - `workTools.ts:423` always returns `{claims, capped}`, and `searchBoard` handles both shapes.
  - A capped or failed claims read sets `holder_unknown` on task hits nobody holds, and adds the `holders` note.
  - The scoped store filters `work_claims`, `task_notes` and `project_tasks` by estate and project (`scope.ts#scopeFilters`).
- **Board doors.** `boardList` and `boardDirectory` are always wired together (`agentSurface.ts:3239-3240`), so a session never searches projects without a board door. A door that throws is caught and named in `degraded`.
- **Query parsing.**
  - `allQueryWords` and `compoundsOf` use the same join rule. On both sides, a word cut at `WORD_MAX` cannot join the next word.
  - `frequency`'s id rule never reaches `'-_./'.includes('')`, which is always true, because an equal term returns from the exact lookup first.
  - `queryCut`, `searchableWords` and `rankDocs` all read `allQueryWords`, so `searched` and `not_searched` match what was ranked.
- **Touches.** Stored touches pass through `normaliseTouch` (backslashes become slashes, `workTools.ts:547`). So `touchWords` reads a Windows path as one name, not as several words.
- **Cost.** Tails stay bounded at 8 per path on both the query and document sides. Deep or 140-segment query paths cost the same as plain words at the read bounds (perf probe above).
- **`boardThreadIds`.**
  - `capped` and `recentCapped` are set only when a read stops at its last page with more to read.
  - The sweep adds `threads` for either one (`abandonedSweepRun.ts:791`).
  - The dispatcher reads only `capped` (`boardDispatchWiring.ts:30`), as ER-14 and ER-18 ruled.
- **Unchanged since run four, read for regressions only:**
  - `boardDispatchRun.ts#resolveProject`: `aliasProposed` proposes once per process, is never awaited, and logs failures.
  - The inbox no-folder skip (`boardDispatchRun.ts:1061-1062`).
  - `productConnect.ts#handlerIsProduct`.
