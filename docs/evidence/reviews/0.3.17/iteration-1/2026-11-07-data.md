## Findings
| ID | Severity | What | Evidence | Proposed fix |
|---|---|---|---|---|
| DA-1 | blocking | CO-315 adds a seventh key, `boardDigest`, to every archive manifest. The private-history path requires exactly six keys, both in code and in SQL. Result: exporting private history (`exportHistory`) is refused `invalid_archive` and the partial folder is removed, and no archive taken by 0.3.17 can be imported as private history (a 0.3.16 build refuses it too). This worked in 0.3.16, so a shipped capability is now broken. The comment `archive.ts:330` ("The manifest itself is unchanged: its six keys are a contract…") is now false. | `main/backup.ts:156`; `main/ceoPrivateArchive.ts:49,55,194`; `main/privateHistory.ts:99-104`; SQL `20260927000066_ceo_private_archive.sql:68,144`; Probes 1 and 2 above; `test/private-history-native-db.test.mjs:67-68` | Keep `manifest.json` at its six keys. Record the board digest outside the manifest, for example a `board.sha256` sidecar, or a flag in a separate file whose absence means "from before board history". `verify` reads that for the missing-file refusal. Add a unit test that runs `take()` and then `preflightOrdinaryArchive()` on its output, and run the full-tier private-history DB test before release. |
| DA-2 | non-blocking | Records held before bootstrap are stamped when they are flushed, not when they happened. `ops.record` takes `at = now()` at write time, and the ops digest's `observe` counts them in the flush hour. The CO-508 start record keeps its line but carries the wrong time. All held records also share the correlation id `pre-bootstrap`. | `main/opsSink.ts:36,68`; `main/ops.ts:377` | Capture `at` when the record is held and pass it through to `record` (an optional `at` in the input). |
| DA-3 | non-blocking | `isDispatchRecord` drops any record that fails its check, and the next `save` rewrites the file without it, so the drop is permanent. A dropped record that was still `starting` or `running` loses its "never a second run" guard. The drop is counted in the log, but which request lost its record is not named. | `main/boardDispatchWiring.ts:214-215`; `main/boardDispatchRun.ts` (`isDispatchRecord`) | Name the `requestId` of each dropped record in `board.dispatch.records-unread` when it is a string, so a possible second run can be traced. |
| DA-4 | non-blocking | The operator's mandate, including `instruction` (up to 500 characters), goes verbatim and unredacted into the Observatory workflow checkpoint's `constraints`. The relayed-access path redacts the same kind of text before it goes into the journal. | `main/boardDispatchRun.ts:288`; compare `main/accessService.ts:61` | Run the mandate's `instruction` through `redact` before it goes into the packet, or rely on Observatory's own redaction and say so in the spec. |
| DA-5 | non-blocking | An agent's `fabric_project_folder_detach` writes the same removal tombstone as the person's «Убрать». After that, the agent's own re-attach is refused `detached` with the text "the person detached this folder". Separately, if the History act fails after the detach, the detach stands with no undo entry. | `main/agentFolders.ts:101-103` and the `SAYS.detached` text; `index.ts` `readRepoRemovals` reads `project_repo_removals` | Word the refusal by who detached the folder. Write the act in the same step as the detach, or log a failed act with its repo id. |
| DA-6 | non-blocking | The digest prune deletes by the current clock's month. A clock set far forward removes every `hourly-*` and `daily-*` file. They are derived counts, but they are the only copy. | `main/opsDigestRun.ts:216-222` | Prune relative to the newest file's month, or skip pruning when "now" is later than the newest record by more than a margin. |
| DA-7 | non-blocking | `schemaStep.ts` is not wired into the app yet. These matter once it is. `dump-incomplete` returns the file for "the caller" to remove, but no caller exists. A second step in the same second with the same version truncates the earlier dump (`createWriteStream` default flag `w`), leaving its receipt mismatched. If the dump file stream errors, the `written` promise can reject with no handler. Modes are correct: the dump and receipt are 0600, and a new folder is 0700. The receipt holds counts and a digest only, no rows. | `main/schemaStep.ts:112,127,131,158` | When it is wired: remove the file on `dump-incomplete`, open the dump with flag `wx` (or a stamp with milliseconds), and attach a `catch` to `written`. |
