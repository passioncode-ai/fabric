| ER-1 | blocking | The new macOS netstat fallback (CO-532) takes the hub end's pid from the process name, and that name is chosen by whoever holds the port. `serverEndPidsFromNetstat` splits the row on whitespace and takes the first field after the state that ends in `:<digits>`. The `process:pid` column holds the executable's name, which may contain spaces and colons. A process of another account named `x:<pid> y` therefore gets `<pid>` read as its pid. That pid can be any process of the victim account (its fabric-mcp, its Fabric), and `ps -o uid=` then reports the victim's own uid, so the verdict is "own". This path is reached exactly when another account holds the hub's end, because lsof never shows another account's sockets. ## Verdict
Blocking findings: 2

ER-1 is a security hole in the newest part of the credential check. On a Mac with several accounts, another account can name its executable so that the netstat fallback reads the victim's own pid. The check then calls the hub's end "own" in the very race it exists for. Probe B shows the parse taking a pid chosen through the name. ER-2 makes a release-note claim false. The restore the window offers ignores the board file's digest, so a lost board file is still restored silently, as in 0.3.16. Every iteration-1 ER fix holds in code and in its test (ER-1, ER-2, ER-4, ER-5), and every ruling has a row except ER-12's text (ER-3 above). The dispatcher, the mandate reader, the opsSink hold, `callDoor` and the manager port showed no new defect at this level. All 263 targeted tests pass, and none is load-dependent.
