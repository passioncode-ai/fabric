## Not findings

- **The heal's start after a quit.** With iteration 2's fix no start follows a quit raised during the stop (probe H). The watch's heal start is `startStackOnce`, which assigns `starting` in the same synchronous turn as the spawn (`main/env.ts:197-223`), so a quit during it kills it. The launch path's heal start is `startStack`, which itself refuses once `stopRequested` is set.
- **A stack left stopped after a quit during the heal.** Correct and recorded: the heal's ops line says the stack it stopped is not started again, and the next launch starts it with its volumes.
- **`stoppedByHeal` after a failed heal start.** Turns `absent` into `stopped`, which the next try starts (V2-1 row). A `supabase stop` the operator runs by hand while the flag stands is also started again; it ends at the first start that runs (iteration 2 named the same residual).
- **The sweep's release race.** `releaseLapsedClaim` acts on claims read at the start of the sweep (`Promise.all` of four reads, the board read the slowest) and re-reads only `released_at`; a session that re-signs inside that window loses an expired claim it could have kept. The window is seconds, the claim must have been seen lapsed in two sweeps three minutes apart and either be past its expiry or this process's, and the agent can claim again. Accepted as designed.
- **The sweep never writes into a terminal.** Unchanged since iteration 2 (`AbandonedSweepDeps` has no write dependency; `main/abandonedSweepRun.ts:58-80`).
- **Swept items and the notifier.** `attentionKey` uses the finding's own key (`shared/attention.ts:380-384`), stable across sweeps, so a lasting finding is told once; a finding that leaves and comes back is told again, as every attention item is.
- **The hub's decision and mandate.** A malformed one is refused `decision-invalid` before anything is sent (`main/hubTools.ts` handler); the args hash covers both (`main/hubCall.ts`, `argsHash`); the callee's three operator refusals pass through `boundedProductOutput` and their key is forgotten on the callee's word that nothing ran (C3.5); the ops log keeps `action` or `task`, `at` and `source`, as the plan's OA-6 sentence says (`docs/evidence/plans/2026-10-26-release-0313-plan.md:155`).
- **`folder_unread`.** Refused before admission with its own words; no caller reads the code (`grep -rn folder_unread apps/desktop/src` finds only `managedLaunch.ts:78`).
- **`dockerContextHost`.** Reads two JSON files under the given `HOME` or `DOCKER_CONFIG`, never executes anything, and an unreadable file falls back to the platform default. An `ssh://` context falls back to the default socket and reads as Docker away, which the start's own Docker wait then handles.
- **Ingress of the receipt.** `capped` and `unread` are closed enumerations matching the sweep's own names (V2-27 row).

## Summary

5 new findings, 0 blocking (ER-1 to ER-5, all minor; ER-5 text only).

All non-database tests of the changed surface pass (13 node files, 14 vitest files with 292 tests) and both type checks pass; the database-backed tests were not run.
