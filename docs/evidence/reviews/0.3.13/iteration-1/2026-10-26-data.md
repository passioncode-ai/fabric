## Not findings

- **The schema step is shaped like the chain.** Every projector the migration adds or replaces (`apply_estate_and_projects`, `apply_project_repo_kind`, `apply_withdrawn_answer_chain`, `apply_question_resolution`, `apply_project_profile`, `apply_projection_times`, `apply_comms_reply_delivery`, `apply_projections`) and every helper (`refuse_held_folder`, `board_epoch_age_limit`, `board_reply_recipient`, `board_responder_live`) is revoked from `public`, `anon`, `authenticated` and `service_role` in the file (lines 178, 221, 242, 335, 365, 420, 457, 897-899, 976); the replaced board commands keep their grants (`create or replace` with the same signature). The dispatcher differs from 123's by exactly five lines; the archive function by exactly `'97'::jsonb`, and the TypeScript side admits 97 (`ceoPrivateArchive.ts:25`). The ledger hash matches; `schemaContract.json` is 97..97.
- **`work.swept@1` at the database.** Its `event_types` row has `projects = false` (no projector names it, line 926-928); its feed sentence exists in both locales (`en.ts:1386`, `ru.ts:2268`); its payload is counts and fixed names only, no title, body, path or session id. Its only defect is DA-1's door and DA-2's cadence.
- **`project_activity` is a read, not a hole.** A `security_invoker` view (the caller's RLS on `projects` and `journal` applies), `anon` revoked, writes revoked from `authenticated` and `service_role`, select granted; it is in `scope.ts` (estate and project) and `NOT_MIRRORED`. It is served by the new partial index `journal_by_project (estate_id, project_id, seq desc)`, and replaces `readHome`'s read of the estate's newest 3 000 events, which lost «Тихо уже» for a quiet project past that window.
- **`project_relations` is projector-only now** (0.3.12 DA-7): insert, update, delete, truncate, references and trigger revoked from `service_role`, select kept (line 436-437); the main process only selects it (`index.ts:1883`, `:1947`).
- **The business rule agrees on both sides.** The projector (an agent names a business only while none is set and no person ever wrote one; a person's value, or clearing, is the person's) matches `main/projectOnboarding.ts#agentProfilePayload`; the upgrade nulls `business` and replays every `project.profiled@1` in order, the only event that writes it, so no other writer's value is lost.
- **The repository dedup and the attach arm agree.** The upgrade keeps the row of each `(estate, path)` first by `attached_at, id`, the replay keeps the first attach by `seq`; the journal is serialised per estate by `append_event`'s advisory lock and `attached_at` is the event's time, so both pick the same row. Because `rebuild_estate_projections` replays over the existing rows, deleting a holder whose own attach comes later is what lets an in-place rebuild of a moved or re-attached folder replay without raising. The live door (`refuse_held_folder`, under the estate lock, line 291) keeps the refusal the index used to give.
- **`apply_projection_times`' backfill passes the ended-run trigger**: `task_run_is_terminal` refuses only state, outcome and `ended_seq` changes, not `created_at` (`20260909000049_task_runs.sql:51-66`).
- **The board reads.** `board_list` and `board_get` use `participants @> array[p_reader]` (same meaning as `= any`, `p_reader` is checked not null); `board_list_reader`'s unread is delivered-and-not-marked, the same count `board_status` keeps; the three waiting reads share `board_responder_live`; `board_tick` changes only its age test. `more` on a bulk read mark is `true` or absent in `board_read_ack_many` (migration 120) and in the zod receipt.
- **Nothing new leaves the machine.** The hub forwards an operator's decision and mandate to the callee as `_meta` (by the contract, DEC-0121, DEC-0125); the ops log keeps only their action, task, time, source ids and chain length (`hubAuthority.ts#operatorRecord`), identifiers by schema, no free text. The sweep writes no ops line with a title or body.
- **Redaction.** `authorization-field` and `yaml-credential` are anchored, need both quotes or a token-shaped value (16 or more token characters with a digit), skip an already redacted value and a scheme word; by reading, they over-redact a quoted YAML value of a credential-named key (`password: "required"`), the safe direction. They apply to what is stored from now on; nothing stored is rewritten.
- **`acts.history` filters** are the ones `actQueryOf` already accepted; the text filter is escaped before `ilike` (`actLog.ts:46`). The Агенты roster composes existing reads and adds none (`launch/agentRoster.ts` header).
- **The upgrade from 95.** Migrations 123 and 124 apply in order; 124's revoke on `project_relations` and its business replay need 123's table and columns, which precede it; the replay loops find no `project.profiled@1` at 95. Only the runbook's wording is missing (DA-7).
- **The first `--history` run that exited 1** was not reproduced in four reruns; its output was not kept. This checkout is a worktree sharing the main repository's object store, which other sessions were writing at the time; recorded here as an observation, not a finding.
