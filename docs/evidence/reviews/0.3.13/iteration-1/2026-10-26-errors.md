## Not findings

- **The terminal write's other gates.** The write is refused when the terminal printed or took input since the read (`beforeWrite` compares `terminalActivity` with the read's value; a terminal Fabric no longer runs reads `NaN` and is never equal), when the app is quitting, and when the queue saw no fresh output; a refusal by the gate un-tells the finding so it stays eligible. Correct as far as it goes; ER-2 is about what the gate cannot see.
- **SW-8 release.** A lapsed claim is released only on the second consecutive sweep with a readable claims list; a failed runs read releases nothing (`held = null`); `releaseLapsedClaim` reads the claim back and moves the task to backlog only when that claim moved it (`returnClaimedTaskToBacklog`); a thrown release is logged and retried. A claim from before a restart waits for its `expires_at`. After a crash, an agent that re-enrolled under a new session loses a claim it still works on once it expires; that is the spec's decided B1, and the project's sessions are told ("Take the task if it is yours to continue").
- **Blind reads.** A failed claims, tasks or terminals read leaves no task called unclaimed and no terminal called stalled; a failed read keeps its kinds' last telling and last findings (SW-5, SW-9); a capped claims read calls no task unclaimed and is said in the receipt.
- **One sweep at a time.** `inFlight` skips a pass that falls due during a sweep; every database call has the client's 15 s deadline (`main/dbDeadline.ts`), so a hung read cannot hold `inFlight` for good. The cycle has no overlap guard of its own (pre-existing); the sweep's guard makes overlapping cycles harmless for it.
- **Nudges.** Taken only after the board read in `fabric_work_list` and after the beat is journalled in `fabric_heartbeat`, so a failing answer loses none; bounded at 50 per session and per project; dropped when their finding is gone unless the finding's read failed.
- **Board read.** A door that answers `ok: false` throws (never "nothing waits"); pages and threads are bounded and the cut is named in `capped`.
- **Docker context.** `dockerContextHost` reads only the environment handed in, returns null for the default context or anything unreadable, and an unknown endpoint scheme falls back to the platform socket; the ping stays bounded at 2 s (`docker-ping` tests, 9).
- **Hub decision and mandate.** A malformed one is refused `decision-invalid` before anything is sent or remembered; the args hash includes both, so a resend that adds one is not answered from a key remembered without it, and a key left `outcome-unknown` still refuses it; the three operator refusals pass only after `boundedProductOutput` (a bound breach falls back to the fixed product-error text, logged); the operations log keeps when and where, never the words (`operatorRecord`); `hub-call-authority` holds the zod schemas to the pinned schemas under ajv (10 tests).
- **Attach claims and folder locks.** The claim is taken synchronously, expires after 60 s if never released, and is released when the first instruction settles or at once when there is none; task launches never attach. The folder lock drops a holder the moment its process is not running and is refused for a plain shell only.
- **The nightly gate.** Checked by hand for both clock-change nights with a three-hour start delay: 2026-10-24 21:00 UTC summer cron reads +0200 six hours earlier and runs, the 22:00 winter cron skips; 2026-10-25 the reverse; 2027-03-27 and 28 likewise. The gate job runs only on `schedule`, so the script's usage error cannot fail a push run; `process.argv[1]` is absolute, so the `import.meta.url` check holds. Schedule runs are no longer cancelled; a second cron run waits for the first and then skips.
- **The migration's corrections.** The duplicate-folder merge deletes only projection rows (no foreign key references `project_repos`; the journal keeps every attach) and recomputes the primary and the project's folder before the unique index; the projector's attach arm never raises, so a replay cannot fail, and `refuse_held_folder` keeps the live refusal at the door before any lock. The withdrawn-chain recursion uses `union` and stops on a cycle and at `seq < e.seq`. The business replay clears and re-applies in journal order, the operator's own writes carrying actor kind `person` (`main/identity.ts`). `work.swept@1` has its `event_types` row and feed sentences in both locales; `prepareEventPayload` answers `not_covered` for it, so the receipt is not refused at ingress.
- **Settings «Сохранено».** Shown only when the main process answered `saved` (a refused or unanswered write says its reason at the foot, as in 0.3.12), and for Claude Code's inbound switch only when the file read back matches the choice.
- **TO-1 (an operator's approval relayed between agents).** A policy decision of the operator (DEC-0126, the operator's rule of 2026-10-26), bounded in the rule's text to a relay from the operator's own Projects or machine carrying all four parts; not a code failure path, so not judged here.

## Summary

8 findings: 2 blocking (ER-1, ER-2), 6 minor (ER-3 to ER-8).

- **ER-1 (blocking):** with the installed Supabase CLI (2.114.0 exits 0 on an already running stack) the runtime watch never runs the half-up heal, so the CO-428 incident while Fabric runs leaves the stack down until a restart, retried and recorded as `started` forever; under the opposite CLI behaviour the launch heal is the dead one. AGENTS.md says both run.
- **ER-2 (blocking, security):** the sweep's `terminal-stalled` line ends in Enter and its conditions (running task, no beat and no terminal activity for 15 minutes) match a session waiting on a permission prompt; in `ask` mode that Enter approves the pending tool call without the person, and repeats every 30 minutes.

All changed tests that need no database pass (13 node files, 20 vitest files with 364 tests, 3 script files); both type checks pass. The database-backed tests of the schema step were not run (they need a disposable stack, which this review was not to touch).
