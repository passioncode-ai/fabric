## Not findings

- **fabric-mcp Retry-After (CO-314).** `boundedRetryMs` falls back to 60 s only for a non-number or NaN, clamps Infinity and huge values to 300 s and a past date or negative to the 1 s floor (`main/fabricMcp.ts`); `retryAfterMs` accepts seconds or the RFC 9110 date form only. The fabric-mcp suite passes (70 tests). A past date waits 1 s, but the hub states a new wait on every refusal, so this is no storm.
- **The wall and upper-case ids.** Participants are lower-cased before the wall compares them with the projects' ids (`main/boardService.ts:485`), so `ABC...` cannot slip past where `abc...` is walled.
- **The wall opens when the projects cannot be read.** Deliberate (BoardDeps comment, spec W2-5 reason), logged as `board.project-facts-read`; the read is capped at 2 000 active projects (`main/agentSurface.ts:461`). ER-2 is about a value the agent controls, not this.
- **Kept-out on `board.respond` (CO-347).** Checked before any prompt; a kept-out file that cannot be read keeps no one out by recorded decision (`test/kept-out.test.mjs:100`). The access lanes cannot deadlock: `request` runs on the agent lane and awaits `decide` and `revokeBinding` on the operator lane, and no operator-lane function awaits the agent lane.
- **Session windows per binding (CO-346).** `boundedCallBucket` is bounded (prunes past 4 096 bindings whose window ended); `hub-surface.test.mjs:246` covers the cap.
- **Re-recorded orientation (CO-399).** The hash leaves out the date sentence (`shared/protocol.ts#protocolHash`), so it changes only with the rules, language or trust; a failed append restores the previous hash.
- **Machine trust read.** A throwing settings read is logged and reads as not trusted; an unreadable file reads as null in `main/index.ts` (the `machineTrust` dependency).
- **Stack notice countdown and detached windows (CO-374).** The countdown runs from the view's arrival and clamps at 0; while the stack is down the watch publishes on every read, so a 0 does not stand long. `stackHealth` and `stackHealthChanged` are `EVERY_WINDOW`, and `broadcast` sends by the same rules (`main/index.ts:576-580`); the bridge guard returns nothing on an older preload.
- **Capped reads (CO-310, CO-405).** `readWork` and `readWhereWork` name `claims`, `leases`, `projects`; `readHome` adds `stages`; HomeWork says them (`launch/HomeWork.tsx:28-30`). A project's board filters claims, leases, review, running, done, queue and cancelled in the query. A failed cancelled read is said in its column (`main/workRead.ts#readTaskBoard`).
- **`tasks.detail` blockers.** A failed read leaves `blockedBy` out (not `[]`) and logs `tasks.detail-blockers-unreadable`, so the page never says «nothing blocks it» from a failed read.
- **Revoke act's name (CO-353).** The name read is wrapped, logged on failure and leaves the act unnamed; the revocation proceeds.
- **Settings writes said on the screen (CO-313).** `App.tsx` catches the bridge's rejection and returns the reason, so `SettingsScreen#change` cannot reject; the refusal is pinned at the foot with `role="alert"`.
- **Comms marks (CO-312) and the feed's short flag (CO-405).** `boundedMarks` drops unlisted threads only when the head list is whole, then keeps the highest seqs; `short` is set only when the best window never reached seq 0.
- **The wiki sync's stale lock (CO-390).** It runs in the dedicated worktree (`scripts/install-workspace-sync.sh:21,68`) with the machine-wide publication lock held, and removes only `index.lock`/`HEAD.lock` older than 110 minutes; `tellPerson` passes the text as `$1`, not through the shell; bounded-run tests pass (20).
- **Fabric readiness.** A buffer overflow is reported as a failure with its reason, not as the 2-minute timeout (probe E).
- **The redaction of headers as pairs and `x-...-key`.** `redactPayload` redacts `{ name: 'Authorization', value }` and keeps `idempotency_key` (probe output: `idempotency_key: "k"` kept).
- **Remembered Board filters.** `validateSettings` reads a malformed value as no filter; the project id and agent id are shape-checked (`shared/appSettings.ts#boardFilters`); a filter id that left the project list is dropped (`KanbanBoard.tsx:55`).
