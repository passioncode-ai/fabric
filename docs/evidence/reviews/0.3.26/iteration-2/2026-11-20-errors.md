## Verdict

**Releasable at the errors level. No blocking finding.**

The three iteration-1 blockers hold at the candidate:
- **ER-1:** `ceo-agent.test.mjs` parses, and 54 of 54 tests pass.
- **ER-2:** the vitest files that failed now pass.
- **ER-3:** a Fabric console is excluded by its pid and its parent chain, and `close` refuses it.

I re-ran every named test at the exact candidate, from a `git archive 30552b73` copy in the session scratchpad. This was needed because another session started editing the worktree during the review (see the receipt).

The new surface leaves six non-blocking findings:
- **ER-12:** two continues of one session can run at once. There is no per-session in-flight guard, and a console Fabric has just resumed is invisible to `resumeEnded` for about 2 s.
- **ER-13:** board runs that Fabric started through Switchboard are listed as «вне Fabric», so Close or Continue signals them directly.
- **ER-14:** when `ps` fails, the acts fail open for Claude Code processes nested under a console.
- **ER-15:** the Switchboard rows cache is untested, and it handles a failed read inconsistently.
- **ER-16:** the CEO's transcript read that ER-8 named still reads the whole file.
- **ER-17:** `readTail` ignores `bytesRead`.

The vendored contract files are byte-equal to fabric-agent-contract 4c978495, apart from the allowed lines, and removing `deepLinkRules` is safe.

## Checked and fine

- **A link to a session that runs in Fabric's own console.**
  - `openLink`'s `consoleOf` maps the console's own id, and the runner id the journal recorded, to the console, compared in lower case: `parseFabricLink` lowercases `session`, and console ids come from `randomUUID`.
  - When the journal does not name the runner id yet (the first 2 s, or after `/clear` until the next 5 min look), the banner appears. The press then finds the process owned (`find()` returns null), and `resumeEnded`'s `runningClaudeIds` contains the id from its session file, so the answer is `still-running` and nothing is signalled.
  - A failed journal read is logged, and the link still routes.
- **`resumeEnded` for a session that no longer runs.**
  - It refuses a running id first.
  - `findTranscript` requires `^[0-9a-f-]{36}$`.
  - The transcript roots (`~/.claude` and Switchboard's runtimes, 200 homes) are the same set as `claudeConfigDirs`. So a transcript it finds always belongs to a home whose running sessions it also reads, and there is no gap with Switchboard-only rows.
  - `path.resolve(file,'..','..','..')` gives the right home for both root shapes.
  - The folder comes from `transcriptCwd(readHead(file, 256 KiB))`, which takes the first absolute `cwd` and skips a cut last line, and it must belong to a Fabric project.
  - `resumeInFabric` passes the id as an argv element (`--resume`, id), so there is no shell.
  - A throw is caught in `machineSessions.continueInFabric` and recorded.
- **`continueInFabric` for a session that is running.** `projectFor` is asked before the signal, and its failure or null leaves the session running (UX-1 test passes). The wait is bounded at 10 s; a process that does not end is reported, never killed. A failure after the stop says `stopped-not-continued` with the resume command.
- **Pid reuse in `ownedBy`.** `runningPids` lists only `running` sessions. A pty's root is Fabric's child and is not reaped (so its pid cannot be reused) before the exit handler clears `running`. The parent walk stops at pid 1 and after 32 hops. `processParents` runs `/bin/ps` by absolute path through `execFile`, with no shell, a 3 s timeout and a 4 MB buffer; `ps` has no children, so the SIGTERM at the timeout is enough. `runningPids` falls back to `pty.pid` until the process identity is captured.
- **A slow Switchboard.** No listing waits more than 3 s for rows. The rows are read-only for acts, because Switchboard-only rows have `pid: 0` and no act button. `list()` always settles: file-system reads, a journal read, a 3 s `ps` and a rows wait of at most 3 s. So the new in-flight flags in both pollers cannot stick.
- **Vendored contract.**
  - `secretShape.ts` differs from `fabric-agent-contract@4c978495:src/secret-shape.ts` only in the two vendoring header lines and the region's `docs:` line.
  - `fabricLinks.ts` differs only in the header lines, the region's `docs:` line and the import path `./secretShape.ts` (twice). It also drops the `findings.js` import and `deepLinkRules` with its doc comment, as the header says.
  - Nothing under `apps` or `scripts` imports `deepLinkRules` (`git grep` finds only the header comment). `folder-attribution/` keeps its own `secret-shape.js` copy, which these files do not affect.
- **`sessionLaunches.ts#ensureDir`.** The rejection handler resets `ready` asynchronously, and no concurrent writer can install a second promise before it runs. The DA-9 test passes.
- **`scripts/ci.sh`.**
  - The `node --check` loop sits in the fast tier's "pure tests" step, under `set -euo pipefail`, so a file that does not parse fails the run.
  - The three files added to the named loop exist and pass.
  - `check-test-chains.mjs` (no unnamed test files) is unaffected.
- **`ceoTools.ts`.** Removing `machine` from the launches tool output (DA-10) changes only the tool's answer. The record type keeps the field for the journal.
- **IPC.** Session ids are checked by `sessionArg` (`/^[0-9a-f-]{36}$/i`) before any act. Every non-`ok` outcome is recorded as a failure in the operations log (DA-11).
