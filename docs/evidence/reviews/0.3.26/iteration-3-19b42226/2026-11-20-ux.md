# Fabric 0.3.26 release review, iteration 3: ux
Level ux, candidate 19b422264b26d1dbed6b380574978d2f9cc0d25f, baseline 53e8c3e2, reviewer Claude Opus 5.5 (1M context), read-only.

## Verdict

**Not releasable as it stands: 1 blocking finding (UX-42) and 5 non-blocking ones.**

- All five run-three ux findings are dealt with. UX-37, UX-38, UX-40 and UX-41 are fixed and hold at the candidate; UX-39 is ruled as CO-604 (32), which is present. The focused tests pass: 34 in the three ask, panel and queue files, 24 in `linkRoute`, 15 in `session-resume`.
- The UX-41 fix and the run-three UX-33 fix both offer «Продолжить в Fabric» for a session that only Switchboard names and that no process runs. On this machine that press fails for every row it is offered on.
- Measured now: Switchboard lists 4 sessions as `needs_you / ready_to_continue`. All 4 transcripts are in Switchboard's `homes/<uuid>/projects/…` folder. Fabric looks for transcripts only in `~/.claude` and Switchboard's `runtimes/` folder (`ceoTools.ts#defaultTranscriptRoots`). So `resumeEnded` answers `gone` for all 4.
- That makes three shipped claims false where they apply: SCN-166's «one no process runs is continued from its history», SCN-142's equivalent, and the CHANGELOG line «one no process runs can be continued from its history». The ask also promises «Fabric продолжит её из истории» before the press, and the press then refuses.

## Checked and fine

- **The queue in `App.tsx`.**
  - The reducer `launch/continueQueue.ts` replaces the refs. A press in flight is never replaced.
  - Another session's link waits behind a press, and the newest one wins. A link for the same session is ignored.
  - `done` shows what waited. A link that replaces an idle ask drops what waited. A stale `busy` report changes nothing.
  - The ask says the waiting link (`links.continue.queued`).
  - `latest` ref: the answer calls the newest render's callbacks (ER-26 test).
- **Read-only state.** No primary press. The way out is «Закрыть». The sentence names the folder and contains no id.
- **Ended Switchboard row in the ask.** It is named by folder and agent and said as ended; the press is enabled. A `gone` answer says `goneHome`, not «не найдена на этом компьютере».
- **Агенты panel.**
  - Close stays only on rows whose process Fabric knows.
  - Continue is not offered on a running Switchboard-only row.
  - The counts line is unchanged.
- **Main.** `rowsChanged` clears the 20 s cache after close and continue. The rest of the cache staleness is already CO-604 (19).
- **Strings.**
  - The new ru and en keys pair up: `links.continue.close`, `goneHome`, `whichEnded`, and the changed `viaSwitchboard`.
  - The Russian reads naturally («ничего с ней отсюда не делает»).
  - No session id reaches the screen.
  - The added lines of `53e8c3e2..19b42226` contain U+2014 0 times in each of `ru.ts`, `en.ts`, `CHANGELOG.md`, `scenarios.md` and the spec.
- **SCN-166, CHANGELOG and spec row 8.** They now say that an ended Switchboard-only session can be continued and a running one is not acted on. This matches the code paths, apart from the outcome measured in UX-42.
