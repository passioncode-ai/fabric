## Checked and fine

- **What a Switchboard-only session now shows.**
  - `links.continue.viaSwitchboard` and `links.continue.whichEnded` take the folder's basename. The full `cwd` appears only when the basename is null.
  - The agent is shown through `runnerLabel`. The session id and the transcript path are never shown.
  - The app is shown only as `appName(from)`, said as the link's own claim.
  - `links.continue.queued` names neither the waiting link's id nor its app.
  - The queued link is held in the `continueQueue` reducer, and its `from` reaches the screen only when it becomes the ask.
- **Continuing an ended Switchboard row from the panel.**
  - It goes through `continueOnce`, then `resumeEnded`.
  - `runningClaudeIds` refuses a session that is still running.
  - `findTranscript` looks only under `~/.claude` and Switchboard's `runtimes/*`, and checks the id against `^[0-9a-f-]{36}$`.
  - The folder comes from the transcript's own `cwd`, read from at most 256 KB, and the folder's project is found before anything starts.
  - The operations-log record carries the session id, the outcome and the console id. It carries no `from` and no turns.
  - The panel offers no continue for a live Switchboard row (`s.source === 'claude' || !s.live`). This matches CO-604 (25).
- **`rowsChanged` (`index.ts:4851`).** It only resets the cached rows' age so the next listing runs Switchboard again. Nothing new is read, stored or sent.
- **Redaction of another session's turns.** It is unchanged. `turns: redactedTurns` stays wired (`index.ts:4815`), and `ceoTools.ts` is untouched since run three.
- **Stand fixtures and screenshots.**
  - `apps/desktop/stand/fixtures.ts` and `docs/evidence/reviews/0.3.26/shots/` are unchanged since `5d549a8d`.
  - The fixtures use only `/Users/example`, synthetic ids (`aaaaaaaa-0000-4000-8000-00000000000N`, `s1`, `p1`) and "Example Co".

  - The `/private/tmp/claude-501/…` scratch paths name a uid folder, not a person.
