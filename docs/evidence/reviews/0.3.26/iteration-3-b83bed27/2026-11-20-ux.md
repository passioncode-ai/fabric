# Fabric 0.3.26 release review, iteration 3: ux
Level ux, candidate b83bed27ec8fe80ada818372290fd78d18b66a57, baseline 53e8c3e2, reviewer Claude Opus 5.5 (1M context), read-only.

## Verdict

**Not releasable as it stands: 1 blocking finding and 4 non-blocking ones.**

- The fix for UX-33 holds for the case it names. An ended Switchboard-only row (`live: false`) now reads «Сейчас она не идёт: Fabric продолжит её из истории», and the press is enabled. The test for it passes.
- The fix did not keep the second half of run two's suggestion: «Keep the half-done retry enabled». The ask now hides its only press whenever `elsewhere` holds, and that includes after a half-done refusal.
- Right after Fabric stops a session, the re-read is usually served from main's 20 s cache of Switchboard rows. That cache still carries the stopped process's pid. So a session Fabric just stopped comes back as a running Switchboard-only row.
- At that point the ask says, side by side, «…продолжите её там, где она идёт. Сессия: …, идёт.» and «Сессия остановлена… «Продолжить из истории» откроет её в консоли». No such button is on screen (UX-37).
- This keeps SCN-142's «half done and offers «Продолжить из истории»» false on the path most people take: pressing within about 20 s of the ask opening. The fix is one condition.
- All other run-two fixes hold, two of them only partly; the gaps are new non-blocking findings. The four focused test files pass (47 and 15 tests).

## Checked and fine

- **The `live` semantics match Switchboard 0.7.125.** Running and waiting rows carry `pid` (7 rows: `pid:92154`, `pid:3805`, and so on). Every `needs_you` and `ended` row has none. So the `live` split in `list()` reads the source correctly.
- **The queued-link flow in `App.tsx`.** A link that arrives while a press is in flight queues behind it, unless it is the same session (guarded). A link that replaces the ask clears the queue. `onDone` shows what was queued. A non-continue link closes an idle ask, as before.
- **Strings.**
  - The new and changed ru and en keys match each other: `links.continue.queued`, `links.continue.from`.
  - No added line in `ru.ts`, `en.ts`, `CHANGELOG.md` or `docs/ux/scenarios.md` contains U+2014 (counted on `git diff 53e8c3e2..b83bed27`: 0, 0, 0, 0).
  - No session id appears on screen in the ask or the panel.
- **Scenario and docs wording.**
  - SCN-142's amendment now says that a running session is named by its folder, agent and state, that an ended one is said as ended, and that a link names itself. It also says that a running Switchboard-only session is read-only and an ended one is continued from its history. This matches the code, except for the half-done claim (UX-37).
  - The CHANGELOG and spec row 8 match the same wording.
  - The SCN-166 and SCN-182 amendments are unchanged and still match the code.
- **Carry-over rows.**
  - CO-604 (31), the App-level test for ER-23, is present.
  - CO-603 (5) now gives Fabric's half to this repository's release session.
  - CO-604 (19) records the 20 s cache's staleness on a failed read. UX-37 is a different effect of the same cache, on a successful read.
- **Main-side origin.** `linkOriginOf` and `continueOrigin` are pure, exported and tested. The journal reasons are unchanged in wording from run two.
