## Checked and fine

- **The grammar of `from` (`linkOriginOf`, `continueOrigin`).**
  - A non-object or `null` becomes `undefined`, which counts as a screen press.
  - An object whose `from` is missing or outside the grammar becomes `{}`, which is a link with no app.
  - Only a `from` that passes `AGENT_ID` (lowercase, at most about 95 characters, `[a-z0-9.-]`) reaches the launch journal reason.
  - The operations log records for `agents.machine-continue` carry no `from` at all (`machineSessions.ts:230,252-256`).
- **What the ask shows (`ContinueSessionAsk.tsx`).**
  - The app is shown by its product name, or else as the raw id that passed the grammar. It is now said as the link's own claim.
  - The folder is shown by its basename; the full path appears only when the basename is null.
  - The agent is shown through `runnerLabel`, and the state by its key.
  - The session id is never shown.
  - A running session seen only through Switchboard now offers no continue button, only the way out (UX-36).
  - An ended one seen only through Switchboard is continued from its local transcript through `resumeEnded`. `resumeEnded` finds the transcript only under the local roots and refuses with `gone`, `unreadable` or `no-project` otherwise. A live local process is caught earlier by `find`.
  - The new queued line, `links.continue.queued`, says that another link waits, without its id or app.
- **App-level queue (`App.tsx`).** The queued link is now React state, and its `from` reaches the screen only through `appName` when it is shown.
- **Redaction of another session's turns.** This is unchanged since run two. `redactedTurns` (`ceoTools.ts:210`) is wired at `index.ts:4815` and in the CEO's read at `ceoTools.ts:335`. The test that a key across the cut leaves nothing passes.
