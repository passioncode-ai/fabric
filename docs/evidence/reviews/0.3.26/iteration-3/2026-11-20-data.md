## Verdict

Nothing blocks the release at the data level.

The run-four data finding DA-26 is fixed and the fix holds. The earlier data rulings are still in CO-604.

The main change since run four is UX-42: Fabric now also reads Switchboard's per-account Claude homes (`homes/`), beside `~/.claude` and `runtimes/`. Here is what that change does, and does not do:

- **Which sessions appear.** Sessions launched under other Switchboard accounts of the same person now appear on Агенты and in the CEO's session listing.
- **What can be done with them.** Their last turns can be read, and an ended one can be continued from its transcript.
- **Redaction.** Every path that reads their turns, for the panel and for the CEO's model, goes through `redactedTurns`.
- **Other OS users.** Nothing of another OS user is read. Every root sits under the current user's own home. On this machine all 52 homes are Claude homes, owned by the same user, with mode 700.

There are two new findings, both non-blocking:

- **DA-27.** Three code comments still say only `~/.claude` and `runtimes/` are read.
- **DA-28.** The ledger's run-four paragraph is a copy of run three's, so it is a false record.

## Checked and fine

- **The new roots.**
  - `switchboardHomeRoots(home)` returns `<home>/Library/Application Support/ai.passioncode.fabric-switchboard/{runtimes,homes}`.
  - `claudeConfigDirs` lists at most 200 children of each root, with a read error swallowed per root.
  - `defaultTranscriptRoots` is `~/.claude` plus those two roots.
  - The base of every path is `homedir()`, so another OS user's home is never a root.
  - `liveClaudeSessions` accepts only `<config>/sessions/<pid>.json` with a UUID `sessionId` and an absolute `cwd`.
  - On this machine:
    - Every one of the 52 `homes/*` entries is a Claude home: it has `.claude.json`, and neither its `projects` nor its `sessions` folder is a symlink.
    - The `homes` folder belongs to the current user.
    - There are no Codex or Kimi homes under it.
- **What reaches the panel and the CEO.**
  - The panel's read gets its turns from `turns: redactedTurns` (`index.ts:4824`).
  - The CEO's `read` returns `redactedTurns(text)` on a tail read capped by `READ_TAIL_BYTES`.
  - `findTranscript` checks the id against `^[0-9a-f-]{36}$` before it touches the disk.
  - The CHANGELOG discloses both paths: lines 19-28 say sessions under another Claude home are listed and read redacted, and lines 123-124 say the CEO's reads go to its model, and to xAI during a call.
  - The `folder` the CEO receives (Claude's encoded project folder name) and the cwd values in `machine_sessions_on_disk` follow the same pattern as before, now from more homes. The panel still shows the full cwd only when its basename is null.
- **Continue.**
  - `resumeEnded` resolves the home as the transcript's grandparent folder and passes it as `CLAUDE_CONFIG_DIR`. The new test asserts that this is the account home.
  - The operations-log records are unchanged. They carry the session id, pid, outcome, console and, where they did before, the folder. They carry no turns and no `from`.
- **The new ask strings.**
