## Checked and fine

- **`switchboardHomeRoots` and `claudeConfigDirs` (UX-42):**
  - Each root is read with its own `try` and capped at 200 entries, so at most 401 config folders.
  - A missing root is skipped. A home that disappears after it is listed is skipped by `liveClaudeSessions` (`readdir` in a `try`) and by `findTranscript` (`readdirSync` in a `try`).
  - `readdir` does not recurse, so a symlinked home cannot loop. A home that links to `~/.claude` is deduplicated by pid and by id.
  - On this machine the `homes` folder holds 52 real folders, each with a `sessions` folder, and no files or symlinks.
- **No main-thread block worth naming.** Timed with the real `findTranscript` and `defaultTranscriptRoots` (scratch `time.mjs`), a miss across about 1 100 project folders takes 5 to 22 ms. `claudeConfigDirs` plus `liveClaudeSessions` take 11 ms for 59 folders and 15 live sessions. CO-604 (17) still covers the synchronous walk, which is now wider.
- **`defaultTranscriptRoots(home)`:** the order is `~/.claude`, then `runtimes`, then `homes`. `path.resolve(file, '..', '..', '..')` gives the account home, so `resumeInFabric` sets `CLAUDE_CONFIG_DIR` to the home the session ran in, and to nothing for `~/.claude`.
- **`resumeEnded`:**
  - It refuses with `not-outside` before it touches the transcript.
  - `unreadable` covers a head with no `cwd`.
  - A transcript deleted between the lookup and the read rejects. `continueOnce` catches that and records it, and the screen says it as a failure.
  - It signals nothing.
- **No act on the wrong process.**
  - Sessions in account homes are now `source: 'claude'`. Every signal still goes through `find` (live files, excluding Fabric's own by journal and by process tree), `unknown-owner` when the process table is unread, and `stillNames`.
  - `continuing` serialises a close and a continue of the same session.
  - Sessions a board dispatch started that now show from account homes are covered by the existing ruling CO-604 (18).
- **`ContinueSessionAsk`:**
  - The `first` ref is per session instance, since App keys the ask by session; a repeat link for the same session keeps the same instance.
  - `whichStopped` falls back to `''` when no row was ever read.
  - A press after `resumedSince` clears `refused`, so the state returns to a plain continue.
  - The reducer and the `latest` ref from run four are unchanged.
- **The edited test «a stopped session that did not reach a console is half done»** now makes its second read return no row. That matches main: the process is dead before `stopped-not-continued` is answered.
- **ER-30 bounds:** concurrent reads are bounded by person-driven acts multiplied by the 30 s deadline plus one retry (`switchboardSessions.ts` `withOneRetry`). `rowsChanged` runs on every outcome through `finally`.
