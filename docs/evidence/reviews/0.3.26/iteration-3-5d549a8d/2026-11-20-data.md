The other run-one findings are settled:

- DA-22 and DA-23 are ruled into CO-604 as items (28) and (27).

There is one new non-blocking finding, DA-24: the main-side fix of DA-19 has no test that would turn red if it were reverted.

## Checked and fine

- **How `from` is checked.** One grammar is used everywhere: the contract's `AGENT_ID`, `/^[a-z][a-z0-9-]{1,62}(\.[a-z][a-z0-9-]{0,31})?$/`. It is applied in the renderer (`appName`), in the IPC handler and in `linkReason`.
  - A `null` or a string in place of the link object becomes `undefined`, which counts as a screen press.
  - An array becomes a link with no `from`.
  - Only a value that passes the grammar reaches the journal reason. The journal reads the reason back clipped to 1000 characters (`sessionLaunches.ts:91`). Older readers map an unknown `via` through `oneOf`.
- **What the ask shows.**
  - The folder is shown by its basename; the full path appears only when the basename is null.
  - The agent is shown through `runnerLabel`.
  - The state is shown by key.
  - The app is shown by its product name, or else as the raw id that passed the grammar.
  - The session id is never shown, as the test asserts.
  - A session seen only through Switchboard shows `viaSwitchboard`, and its button is disabled.
  - A refusal code is translated. Its raw text reaches the tooltip, and appears under the line in Агенты only when Fabric has no sentence for it (UX-28).
- **Redaction of other sessions' turns.** This is unchanged since run one. `redactedTurns` redacts the whole text before cutting it to 700 characters, and is wired at `index.ts:4819` and at the CEO's `read` (`ceoTools.ts:335`).
- **Stand fixtures** (`apps/desktop/stand/fixtures.ts`). They use only `/Users/example/...` paths, synthetic session UUIDs (`aaaaaaaa-0000-4000-8000-00000000000N`), the neutral names support-desk and atlas, and machine `stand`. There are no private names.
- **Screenshots.** `docs/evidence/reviews/0.3.26/shots/` is unchanged since iteration 2.
- **Re-rendered previews.** There are 89 JPEGs plus `previews.json`, whose only change is the source hash. A `strings` scan of every changed preview for home paths, the operator's handle, the e-mail address and UUIDs found nothing. I viewed `agents.jpg` and `estate-agents.jpg`; they show only demo data (Atlas, Orbit).
- **Committed review reports and docs.** A grep of every changed non-preview file for home paths, the operator's e-mail address and key or PEM shapes found nothing. `node scripts/check-private.mjs` printed «PASS: no private data in the tracked files».
- **CO-603 (10) and CO-604 (23) to (30)** are present. CO-604 says that the rulings of the last run are written in the ledger and added on main after the tag (PL-24).
- **Tests run.**
  - `node --test test/session-resume.test.mjs`: 14 of 14 pass.
  - `vitest run` on `ContinueSessionAsk.test.tsx` and `MachineSessions.test.tsx`: 21 of 21 pass.
