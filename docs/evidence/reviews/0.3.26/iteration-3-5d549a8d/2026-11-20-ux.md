# Fabric 0.3.26 release review, iteration 3: ux
Level ux, candidate 5d549a8dc93396a096fef8998e37d50fe3aa0a2a, baseline 53e8c3e2, reviewer Claude Opus 5.5 (1M context), read-only.

## Verdict

**Not releasable as it stands: 1 blocking finding and 3 non-blocking ones.**

- The blocker is UX-33, and it comes from run one's fix for UX-30. The continue ask now refuses every session that only Switchboard lists, including sessions whose process has ended.
- Switchboard's «нужны вы» group holds exactly those ended sessions, marked `why: ready_to_continue`, `acts: continue`. On this computer there are 4 of them right now, and each has its transcript in a Switchboard runtime that `resumeEnded` reads.
- So a `fabric://session/continue` link for one of them shows a greyed-out «Продолжить в Fabric» with a false sentence («продолжите её там, где она идёт»).
- The same overreach breaks the iteration-2 UX-18 half-done retry for Switchboard-launched sessions. After Fabric stops such a session, it re-reads as a Switchboard-only row, and «Продолжить из истории» is greyed out.
- That makes two shipped claims false: SCN-142 says «one that ended is continued from its transcript» and that a half-done session «offers «Продолжить из истории»»; the CHANGELOG makes the same claim about ended sessions.
- The fix is one condition and a test. Every other run-one finding holds or is ruled into CO-604. All four focused test files pass.
