## Checked and fine

- **No act can hit the wrong process.**
  - The rename from `from` to `link` leaves `find`, `unknown-owner`, `stillNames`, the `continuing` single flight and `close`'s `busy` unchanged.
  - An owned session still goes to `resumeEnded`, which answers `not-outside`.
  - The IPC handler still guards the id with `sessionArg`.
  - A malformed `link` (null, string, array) becomes `undefined` (a screen press) or `{}` (a link). In both cases, only an `AGENT_ID`-valid `from` reaches the journal reason, so no free text is written.
- **No busy flag stuck on another session.** `onBusy` writes `continueAsk.session` from the ask instance's own render. The ask is keyed by session, so the instance is one session's. Every settle path of `go` calls `onBusy(false)`: ok, refusal and rejection. The promise's closures run even after an unmount, so `continueBusy` is reset in every case. One limit: a `machineContinue` call that never settles would leave busy set. That was already so in iteration 2 (Cancel disabled while busy).
- **Re-read after an answer.** `reads` triggers a fresh `machineSessions()` read. The previous read's `alive` flag stops a late answer from overwriting it, and `about` keeps its last value until the new read lands, so the button does not flicker to disabled. A rejected `machineContinue` does not re-read. That is harmless: nothing was signalled.
- **`appName`.** It returns null outside the grammar and the product name for our ids. The `name.instance` form maps by its first segment.
- **The stand fixture.** `terminal.launch` returns a full launch record for any id. `agents.machineSessions` holds two rows that cover the long-folder grid case and the Switchboard-only case.
- **`readTail`, `redactedTurns` and the CEO `read` tool.** They are unchanged since run one. The large-transcript test gap is ruled as CO-604 (29).
- **Typecheck.** `tsc --noEmit -p tsconfig.node.json` and `-p tsconfig.web.json` both exit 0.
