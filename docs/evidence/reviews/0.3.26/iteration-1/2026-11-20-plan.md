# Fabric 0.3.26 release review, iteration 1: plan

Level plan, candidate 314c956660b35a25b4b71e3ba97cbd8b548914a4, baseline 53e8c3e2, reviewer Claude Opus 5.5 (1M context), read-only.

## Verdict

**Not ready to release. 3 blocking findings, 10 non-blocking.**

What works: the release puts the right work in one release. The CEO card goes back to the right, Fabric reads Switchboard's `sessions --rows`, and the launch journal, the fast session end and the unpublished 0.3.25 all ship together. The decision to fold 0.3.25 into 0.3.26 follows the release gate: no code may change after `verifiedCommit`, and 886e555e changed code after 6da674bd. The plan also sets up three new iterations instead of reusing 0.3.25's.

Three problems block the release:

1. **"One machine, one count" is claimed but not done.** The CHANGELOG and the commit message say Fabric now matches Fabric Dashboards. The spec's own measurements show the counts still differ.
2. **Deferred work is not in the carry-over ledger.** None of the spec's §4 deferrals has a ledger row, two have no id at all, and one points at the wrong row.
3. **CO-601 is due now and is not handled.** It falls due at 0.3.26 and still lacks nine findings that 0.3.25's iteration 3 ruled into it.

Missing an hour from now, a tester would also find the Dashboards and Fabric numbers different. They would see no message when Switchboard does not answer. And they would see no change in the body of the project page.

## Checked and fine

- Folding 0.3.25 into 0.3.26 follows the gate rule. 886e555e is a code change after `verifiedCommit` 6da674bd, so 0.3.25 could not be released. No `v0.3.25` tag exists locally or on origin. The spec plans three new iterations, and the draft 0.3.26 ledger (untracked, written by the release session) says 0.3.25's iterations are not reused.
- The baseline is an ancestor of the candidate. Both side branches (session-launch-journal, session-end-fast) start at the baseline. No commit in the range touches anything a release forbids.
- The CHANGELOG has a single `## Unreleased` section with no `## 0.3.25` heading. Its intro ("prepared and never published") does not trip `changelogProblem`, which rejects only "unreleased" and "not released" (`scripts/lib/release-mac.mjs`, around line 86).
- The CEO card ask (spec row 1) is addressed in the right place: the top row now spans both columns, measured at three window widths. SCN-182 is amended to match.
- The operator's words are quoted with dates and sessions in the spec, and each is traceable to a row or a §4 item, except as noted in PL-2 and PL-9.
- The new list's degraded paths are tested: Switchboard answering `null` and throwing both fall back to the files (`session-resume.test.mjs`). Sessions only Switchboard names are read-only, and closing one is refused with "gone".
- The fast session end keeps a task run's TERM-only stop and its receipts. It applies only on the person's press (per the 7477c14b message and SCN amendment).
- The design map and the merge log both carry the iteration in the same change, so the map stamp is refreshed.
