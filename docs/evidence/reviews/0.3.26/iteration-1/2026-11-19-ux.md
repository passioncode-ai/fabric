## Findings

| ID | Severity | Finding | Evidence | Fix |
|---|---|---|---|---|
| UX-1 | blocking | A spoken name that fits several services opens the wrong one, and the code's own rule "a local one beats an online one, at the same score" is not implemented: ties fall to alphabetical order of the name. On this machine's real registry «открой [name]» opens `[name]-[name].cloud` (the organisation's cloud copy, name "[name] [name]" sorts first), «frame» / «[name]» opens `[name].cloud` (the organisation copy) before `[name].default`, «[name]» opens `[name].[name]`, «[name]» opens the Community Bot out of four tied [name] dashboards. The owner asked for his dashboard and gets another organisation's, silently (only `also_matched` hints). | ceoTools.ts:721 (comment) vs ceoTools.ts:722 (sort: score, showcase, `name.localeCompare`; `placement` never read); ceoTools.ts:737 (`found[0]` opened without a tie check); replay: `[name] => [name]-[name].cloud [6], [name].default [6]`, `frame => [name].cloud [3], [name].default [3], …`, `[name] => [name].default [3], [name]-data-agent.default [3], [name].default [3], …` | Add the promised tie-breaks (local before remote, then the `.default` instance and the operator's own before an organisation copy); when two or more different products remain tied at the top score, refuse with the candidates (`several dashboards fit «…»: …`) so the CEO asks, instead of opening one. Add a test with a local and a cloud copy of one product. |
| UX-2 | blocking | A weak match opens a dashboard: one word found only in a summary (score 1), or a filler word, is enough, and a Russian transliteration of a Latin name never matches. Replay on real names: «аналитику» opens World Pulse (its summary starts «Аналитик мира»), not the Analytics agent; «Фрейм агент» opens the [name] showcase (matched on «агент», «фрейм» does not reach "frame"); «дашборд Ани» opens Ania's showcase instead of Ania (the word «дашборд» adds a summary point to the showcase only). In a Russian voice call the transcript of an English product name is often Cyrillic, so the owner hears «открыл World Pulse» for «открой аналитику». «Аню», «Аня», «Growth», «Киру» do resolve correctly. | ceoTools.ts:711-720 (any word scores; summary words count 1; no minimum; no stop words); ceoTools.ts:735-737 (opens whenever `found.length`); replay: `аналитику => world-pulse.default [1]`, `Фрейм агент => studio-showcase.ania-agent-[name] [3], studio-showcase.[name] [3], …`, `дашборд Ани => studio-showcase.ania-agent-[name] [4], ania-agent-[name].default [3]`, `Гроус =>` (nothing) | Open only when the best hit matches on the key or name (score at least 3 per meaningful word); drop filler words («дашборд», «агент», «открой», «покажи», "dashboard", "agent"); for a summary-only or no match, refuse with the closest names so the CEO asks. Say in the tool description that names are matched as written (Latin product names in Latin), so the voice model passes «Growth», not «Гроус». |
| UX-3 | non-blocking | Until the owner grants Accessibility, `fabric_ceo_windows` reports Fabric Dashboards as closed even when it is open: `bounds()` answers `null` for "not allowed" and for every error, and the tool turns `null` into `open: false`. The CEO will say "Fabric Dashboards is not open" to the owner. | ceoWindows.ts:137-139 (`!d.trusted(false)` and catch both return null); ceoTools.ts:537-539 (`b ? {open: true…} : {open: false}`) | Return a reason with the null (`not_allowed`, `not_running`, `unknown`) and answer `{ open: null, why: 'macOS has not let Fabric read other apps\' windows yet' }` when it is not known, never `false`. |
| UX-4 | non-blocking | The first move of Fabric Dashboards' window, the one that raises macOS's Automation question, ends in a raw failure, not in the friendly Automation step the code and the test promise. `osascript` waits on macOS's question (the Apple Event timeout is two minutes), but `runOsascript` kills it at 8 s, so the error is Node's `Command failed: /usr/bin/osascript -e tell application "System Events" …`; the -1712/-1743 test never matches, and the reason handed to the CEO (and possibly read aloud) carries the AppleScript text. The test injects `(-1712)` directly, which the real port cannot produce first. Separately, the comment says "the move waits for their answer" for the Accessibility prompt, but `isTrustedAccessibilityClient(true)` returns at once. | ceoWindows.ts:124-126 (`timeout: 8000`, message from `err.message`); ceoWindows.ts:151-153; ceoWindows.ts:143; test/ceo-windows.test.mjs:223-226; scratch check: `{"m":"Command failed: /usr/bin/osascript -e delay 3\n","killed":true}` | Treat `err.killed` (timeout) as the consent case: answer the Automation step ("macOS is asking to let Fabric control System Events; allow it, then ask again"), never the script text; cap any raw detail to the ops log. Fix the comment. Add a test where the injected osascript rejects like a killed child. |
| UX-5 | non-blocking | «Открой Аню на весь экран» when Fabric Dashboards is not running: the link starts the app, the move runs after a fixed 1.2 s, and System Events answers that the process does not exist yet; the owner hears "macOS did not move Fabric Dashboards' window: System Events got an error: Can't get process …". The dashboard opened, the full screen did not, with a technical reason. | ceoTools.ts:746-753 (`await sleep(1200)` then one `arrange`); ceoWindows.ts:153 (raw reason) | Before placing, wait for the process and its window (poll `bounds()` up to a few seconds), then place; if still absent, say "the dashboard opened; its window was not ready to move, ask again". |
| UX-6 | non-blocking | The voice call now sends `anyOf` in function parameters for the first time (`display` is integer or string in `session_window_layout` and `session_dashboard_open`). xAI's realtime voice API documents JSON-schema tools but no keyword list; if `session.update` refuses the schema, the call loses every tool, the old session tools included, which worked before. Not verified on a live call. | ceoTools.ts:116-117, 120, 140 (`z.union([number, enum])`); ceoTools.ts:807-813 (`ceoVoiceTools` sends `z.toJSONSchema` as is); generated: `session_window_layout … UNION`, `session_dashboard_open … UNION PATTERN`, no older tool has either | Verify with one real `session.update` before release, or flatten `display` to a string enum (`"1"…"8"`, `primary`, `other`, `current`) for the voice tools; `pickDisplay` already accepts digit strings. |
| UX-7 | non-blocking | «Консоль Fabric справа» puts Fabric's main window on the right, not the console of the project named Fabric: the words `fabric`, `main`, `ceo`, `dashboards` are taken as Fabric's own windows before any project lookup, and the owner works on the Fabric project itself. Natural Russian forms are partly missing (`'фабрик'` is listed, «фабрика»/«фабрику» and «Fabric Dashboards» are not, so they fall to the project lookup). | ceoTools.ts:580-582 | Match the reserved words only when nothing else is named (or require `main`/`ceo`/`dashboards` exactly), and resolve «X console» / a project name first; cover the Russian case forms; note in the parameter description that a project named like a reserved word is named by its id. |
| UX-8 | non-blocking | A layout saved "as the windows stand" leaves out Fabric Dashboards' window, though the owner's layouts are consoles plus a dashboard («console left, dashboard right»); restoring «рабочая» then moves the consoles and not the dashboard. A layout saved from `place` without a named screen keeps no screen, so on two monitors it restores on whatever screen each window happens to be on. | ceoTools.ts:676-691 (snapshot from `w.list()` only, Fabric's windows); ceoTools.ts:667-670 (`display` kept only when named) | Include the dashboards window in the snapshot when its bounds are readable; store the resolved screen number of every placement at save time. |
| UX-9 | non-blocking | "Windows with no area share the screen without covering one another" is not true when some windows on that screen have an explicit area or when more than four are named: «A слева, B и C» gives B left and C right, B covering A; a fifth window repeats the grid. The voice model reads this promise from the tool description. | ceoTools.ts:112 (description); ceoTools.ts:613-615 (auto areas ignore the explicit ones); windowLayout.ts:57-58 | Fit the area-less windows into what the explicit ones leave, or soften the description ("share the screen; with an area named beside them they may overlap"). |
