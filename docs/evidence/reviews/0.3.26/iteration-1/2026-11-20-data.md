# Fabric 0.3.26 release review, iteration 1: data

Level data, candidate 314c956660b35a25b4b71e3ba97cbd8b548914a4, baseline 53e8c3e2, reviewer Claude Opus 5.5 (1M context), read-only.

## Verdict

No blocking findings at the data level. The launch journal, the voice sample cache and the CEO call history are bounded and owner-only, they hold no argument list, environment or token, and every new IPC channel is main-window only. There are 11 non-blocking findings. The four that matter most:

- **DA-1:** the «Сессии вне Fabric» read sends transcript text to the renderer without redaction. The CEO's read of the same transcripts does redact.
- **DA-4:** for a few seconds after a Fabric console starts, and for up to 5 min after a `/clear`, Fabric shows its own console as an outside session. Closing it from there sends a plain SIGTERM, and the journal records the end as `crashed`.
- **DA-5:** a crash can leave a stale session file. If its pid is later reused, «Закрыть» can SIGTERM an unrelated process. Not observed on this machine.
- **DA-7:** a quit within about 2 s of a console's start can drop that launch from the journal.

The rest are rows for the board.

## Checked and fine

- **Journal permissions.** The `launches` folder is created 0700 and the month files 0600. The test asserts both modes (`test/session-launches.test.mjs:38-39`), and the test file passes 12 of 12. `test/session-resume.test.mjs` passes 7 of 7.
- **What the journal keeps.**
  - `program` is the runner's program name only (`pty.ts:521`, `option.program`), never its arguments.
  - The environment handed to the sink is used only to find `CLAUDE_CONFIG_DIR` and is never written.
  - `reason` is redacted and cut to 1 000 characters.
  - The parser caps every field (400, 1 000 or 4 000 characters) and rejects unknown events.
  - A torn line is skipped, an end written before its opening still folds, and `chainOf` stops at 10 steps and never loops.
- **Retention.** 13 months. `prune` removes only names matching `launches-YYYY-MM.jsonl`. Writes go through one serial queue, so lines never interleave.
- **Voice sample cache.**
  - The voice comes from an allowlist of 5 built-in voices and the language is from settings, so the file name is fixed and cannot traverse a path.
  - The cache is at most 10 files, written in an owner-only folder (0700, files 0600) under `ceo-voice/samples`, outside the CEO's own folder.
  - Each file is written beside its final name and then renamed, and the temporary file is always removed.
  - The xAI key never leaves the main process. `voiceReady` answers a boolean only.
- **CEO call history.** It lives in the CEO window's localStorage: at most 10 calls of 40 000 characters each, re-validated when read. Tool lines keep only the tool's name or xAI's error message.
- **IPC.**
  - Every new channel (`agentsMachine*`, `projectsResumeLast`, `terminalLaunch`, `terminalRecent`, `ceoAgentVoiceReady`, `ceoAgentVoiceSample`) is `MAIN_ONLY`; `ceoAgentStop` and `ceoAgentTakeCall` are `MAIN_AND_CEO` (`shared/ipcWindowPolicy.ts`).
  - Session ids are checked against the UUID shape (`sessionArg`), and `findTranscript` builds only the fixed name `<uuid>.jsonl`, so no path can be traversed. `terminalLaunch` limits its id to 128 characters.
- **Whose files are read.** Only this OS user's Claude homes (`~/.claude` and Switchboard's runtimes), at most 200 homes and 200 sessions, each with a UUID id and an absolute folder. Switchboard rows are capped per field (`parseMachineRows`), and a row whose session is gone is not listed.
- **«Продолжить последнюю».** It reads directory listings and at most the first 256 KB of a transcript, and returns only a session id (`main/projectResume.ts`).
- **New operations-log lines.** They carry ids, pids, folders, counts and errors cut to 200 characters. No transcript text and no token is logged.
- **Persona voice.** The new field is optional and backward compatible; an unknown value reads as male and never costs the look (`shared/persona.ts#validatePersona`).
- **Database.** There are no `supabase` changes or migrations in the diff.
- **Switchboard output.** It is capped at 16 MB per call, and only reads are retried.
