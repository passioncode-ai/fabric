# Fabric 0.3.26 release review, iteration 3: plan
Level plan, candidate 4ba9fd6214dd80526eeba127b5c2fcb0a962647c, baseline 53e8c3e2, reviewer Claude Opus 5.5 (1M context), read-only.

## Verdict

**Not ready to release on this candidate. 1 blocking finding (PL-23), 4 non-blocking (PL-24 to PL-27).**

Hosted CI on this candidate failed: `ci.yml` run 44681000417, `ci.sh fast`, 24 of 26 browser suites pass. Two suites fail on the new 0.3.26 UI:

- **`layout-stress`:** the grids `.rail-pick`, `.ag-machine` and `.ag-machine-turns` grow past a 600 px column (2878, 2878 and 2500 px).
- **`screens-stand`:** the stand is not given the new calls `terminal.launch` and `agents.machineSessions`.

No earlier run of a 0.3.26 candidate reached the browser suites (314c9566 stopped at ELIFECYCLE, 30552b73 at SP-2), so this run was the first time they ran. The fix touches CSS or the test stand, and neither file may change after `verifiedCommit`. So 4ba9fd62 cannot be `verifiedCommit`: the release guard would refuse the tag, because its commit would differ from 4ba9fd62 only in metadata and CI would stay red. Iteration 3 has to run again (a "run two", as in 0.3.21 and 0.3.24) on a fix candidate.

The plan itself is sound:

- Every ask the operator made on 2026-11-20 either shipped or is recorded with an owner (spec §2a and §4, CO-601, CO-603, CO-604, P-12, P-27).
- Every iteration-2 plan finding holds.
- The receipts for iterations 1 and 2 are valid.
- The doc, register, plan and SP-2 gates all pass in the hosted run.
