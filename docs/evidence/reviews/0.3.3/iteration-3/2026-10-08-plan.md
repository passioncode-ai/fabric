- `verifiedCandidateProblem` (real git: ancestry, diff set, package comparison, candidate chain) → `null`

The addition: `scripts/ci.sh fast`, which item 1 of *Release close* requires, does **not** pass on that commit. `check-design-map.mjs` exits 1 with "Changed iteration reuses the committed top entry: add a NEW top changelog entry". The release commit changes map sources, so it also has to add a new top `#changelog` entry to `docs/reports/map.html`, with a `#` review link, and run `--refresh`. With that added, `check-design-map` exits 0 and the release functions still return clear. `docs/reports/map.html` and `docs/MERGES.md` are both admitted after `verifiedCommit` (`scripts/lib/release-mac.mjs#verifiedCandidateProblem`, metadata set). The 0.3.2 release commit `c3543227` touched both. See PL-1.

**2. Is anything still required in a file that is not allowed? No, under two conditions.** No backlog, carry-over, runbook or code change has to happen before the tag. Each such finding below (PL-7, PL-8) can land in the close commit after the tag, as 0.3.2's close `1190e261` did. A fourth candidate becomes necessary only in these cases:

- (a) **The operator declines the REQ-08 reading.** Then the remaining English in the main process becomes a code change (PL-3). Ask for that answer before the release commit is cut.
- (b) **Claude Code or Codex updates before `ci.sh fast` runs on the release commit.** `check-provider-capability.mjs` then fails, and the re-pin edits `apps/desktop/src/shared/providerCapabilityMatrix.ts`, which is not admitted (PL-9). Today it is `claude-code 2.1.295` and `codex-cli 0.161.0`, both matching.
