### Fresh pass

- `revealSection` (`LaunchShell.tsx:25–67`): no leak. Every exit path calls `done()`, which removes all four listeners: the anchor missing past the deadline, the person moving, and the settle window ending. The listeners are `once` and not capture, so the removal matches. Overlapping calls each own their listeners, and the first pointer or key event stops all of them.
- The `tasks.start` keyed queue with the setup guard: the guard and the walk run before the queue, so a refused setup never holds the queue. Two same-id starts serialise, and the second gets `running` once the first has bound. No defect found. One untested corner, not reachable from today's UI: a retry with the fallback option re-walks and can throw "exhausted" before the plan would have brought a running session forward. No window passes `taskId` together with `fallback-order`.
- `explainError` codes: every `task-refused:*` code main throws (`not-an-id`, `read-failed`, `other-project`, `setup-needs-surface`) has en and ru strings. `readback-failed` is now never thrown (the string is dead, which is harmless). The setup guard's created-agent read error is an English sentence (`index.ts:1643`), inside CO-225's named remainder.
- Silent catches added since v0.3.2 (all `+…catch` lines in `git diff v0.3.2..HEAD -- apps/desktop/src`): the only ones that hide something the person was promised are `AgentPaths.tsx#abandon` (ER-3) and `adapterSkills.ts#json` (ER-8). The others are named on screen, sent to `ops.failed`, or documented fallbacks.
