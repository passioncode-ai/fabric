### UX-17 (non-blocking): the folded rail's view switch is clipped

What is wrong. `rail.css` at `max-width:900px` sets `.rail-view{grid-template-columns:1fr}` with
`.rail-view button{font-size:10px;height:22px;overflow:hidden;text-overflow:ellipsis}`. In a 64 px rail the first button
shows «Проек…» and the second «Агенты» (`scratch-ux/shots/home-ru-w900-light.png`). The control is usable (the second word
is whole, and the first is recognisable from the dots below it) but it reads as a defect. The mockup has no folded state,
so this is not a parity break and 0.3.14 had the same fold, hence non-blocking.

Fix. Show signs only at that width (a dot and a person glyph with `aria-label` and `title`), or shorten the label with a
dedicated short string. Not needed for the release.

### UX-18 (non-blocking): no selected row on the console screen

What is wrong. In `after-console-light.png` the rail's agent list has no highlighted row for the session that is open;
the mockup (`mockup-console.png`) highlights «Claude Code · Fabric». On the agent page the selected row is highlighted
(`agent-ru-w1000-light.png`). The console route is the one place where the person loses the "you are here" mark. The
committed console shot is from a fixture, so the same may be a harness artefact (the route is opened by a tab, not by the
rail). I could not verify in the real app; hence non-blocking and flagged for a look.

Fix. If real: mark the rail row of the open console's agent the same way the agent page does.
