### UX-1 (blocking): the status word on rail agent rows is gone

What is wrong. 0.3.14 wrote the word for every status in the left column, «Работает» included (CHANGELOG 0.3.14 lines
76 and 79: «the word is always written, «Работает» included»; «The left column, «В работе» and the agent's screen give a
session the same word»). The README of this release says the opposite of what the code does: "How conflicts are decided:
v2 and later reviews win over the mockup ... (back/forward/home, the status word and shape on agent rows, the console
icon, the «Цель» line). They stay". Rail gap 16 itself marks the row "Operator's choice". The candidate chose the
mockup: `LaunchShell.tsx#LaunchShell` renders `{status !== 'working' && <span className="rail-word"> · …</span>}`, so the
four working rows in the shot carry only a dot, while the same agent on Главная («Работает») and on its page
(«работает») carries the word. R-19 (v2 line 105) says "a status colour with a word". The change is written into
`docs/ux/scenarios.md` as an amendment, but CHANGELOG 0.3.15 (the text a person reads on update) never mentions it,
and no operator decision is cited. It is a regression of a 0.3.14 behaviour the brief names, against the README's own
rule.

Evidence. `apps/desktop/src/renderer/src/launch/LaunchShell.tsx` (agents list, `rail-agent-line`);
`docs/reports/2026-10-27-mockup-parity/README.md` "How conflicts are decided"; `gaps/2026-10-27-rail.md` row 16;
`CHANGELOG.md` 0.3.14 lines 76 to 79 against `## 0.3.15`; `scenarios.md` amendment line.

Fix. Keep the word for every status in the rail, in the quiet 11 px type already used (it costs one short word on a
line that has room only for the branch, see UX-7, so show it after the branch only when it fits, or shorten to the
dot's accessible name plus the word on hover); or, if the mockup is to win here, record the operator's decision with
date and words in the README and CHANGELOG 0.3.15 and change the README conflict rule so it does not say the opposite.

### UX-2: false "no project is at work" while the reading is unread

`projectsAtWork` receives `pulses: null` while `work.home` has not answered (or failed) and keeps only pinned, waiting,
live-terminal and on-screen projects; with none of those, `noneAtWork` is true and the rail prints «Сейчас ни один
проект не в работе.» over a list hidden behind «Все проекты · N» (probe A). On a failed read the same sentence stays
until the next success. A claim of absence made from not having read is the pattern the rest of the release avoids
(numbers show a dash placeholder with a reason). Fix: when `props.pulses === null` show the reading line (`rail.projects.reading`) or
the full list, and say «quiet» only after a successful reading. Evidence: `LaunchShell.tsx` (`noneAtWork`),
`railProjects.ts#projectsAtWork`.

### UX-3: rhythm shows "not read" while it is only loading

`useRhythm` starts as `{ rhythm: null, problem: null }` and `HomeRhythm` receives that object as `rhythm`, so
`rhythmOf` takes the "main answered, nothing in it" branch: totals read «решения и результаты не прочитаны» and every bar
is the hatched unknown (probe D). That is the state of every window start for the length of one IPC read, and of a
failed read too, with no word that distinguishes loading from failure (`title={why}` only on hover). Fix: pass
`undefined`-like "loading" so the totals line shows the reading wording (or nothing) until the first answer, and keep
«не прочитаны» for `problem !== null`. Evidence: `HomeParts.tsx#useRhythm`, `rhythmOf`, `launch.home.rhythm.totalsUnread`.

### UX-4: one project, two names

The release goal is "one name every screen prints" (`projectDisplayName` header, rail gap 15). The rail row, the top
bar (`App.tsx#placeTitle` through `projectNameOf`), Главная and the console titles use the display name, but the
project page's own heading is `<h1>{project.name}</h1>` (`ProjectHome.tsx` line 1313), the stored slug. A person who
presses «Research Agent» in the rail lands on a page titled `research-agent` under a top bar that says «Research
Agent». The rail row's hover shows the slug, so the two are at least reachable, but the heading is the first thing
read. Fix: print `projectDisplayName(project)` in the h1 with the slug as its `title`, or show the slug as a small
line beneath.

### UX-5: raw ids in visible text

`EstateHome.tsx#nameOfProject` falls back to `projectDisplayName({ id, name: id })`, which returns the id when the
project is not in `projects` or in `displayNames` (the display names are read for `status = 'active'` only,
`main/projectNames.ts#readNow`). `HomeBoard` then prefers `nameOf(item.projectId)` over the board's own
`item.projectName` (`NeedsYouCard`), so a question of an archived project, or any question while the project list is
still unread, loses a correct name and shows a UUID; `HomeBoardWaiting` does the same for both ends (probe C prints the
UUID). Also, a request with no target prints «Без проекта не взял · …», which reads as "no project did not take it".
Fix: `nameOfProject` returns null for an unknown id and the callers fall back to the board's name (or to
`launch.home.agents.noProject`); for a null target say «ещё никто не взял».

### UX-6: grammar, and the shots are not this build

`launch.home.inWork.agentsQuiet` is «молчат: {count}» for every count; the probe prints «молчат: 1». Russian needs
«молчит: 1» (the mockup says «молчит: 1»). Worse for the evidence: both `after-home-light.png` and
`after-home-dark.png` show «молчит: 1», which this code cannot produce, so the shots filed as "the candidate's renderer"
were taken with different copy (or a different build). Fix: plural form keys (`one`, `few`, `many`) as the strip's
`launch.home.stats.working.*` does, and retake the shots from the candidate bundle.

### UX-7: rail agent rows

From `after-agent-dark.png` (crop in `scratch-ux/rail-crop2.png`): the console button next to a row that Fabric holds
is visibly wider than the dashed "elsewhere" one (about 34 px against 24 px, `.rail-console` says 24 px; the global
`button` padding wins) and its glyph «›_» sits low and right instead of centred. The button takes width from the name,
so «Claude Code · Copylot», «· Dashboards», «· Observatory» are cut to «Claude Code · Cop…», «· Dash…», «· Obser…» and
the agents are told apart only by those letters (the mockup rail shows the full names); with the status word the branch
is cut too («fix/se… · Простаивает»). The css for `.rail-console` is unchanged from 0.3.14, so this is old, but it is
what the rows now look like next to the mockup and it hides the one fact the rows exist to show. Fix: `padding:0` and
`line-height:1` on `.rail-console`, put the console button on the branch line, and let the name wrap to two lines or
shrink the runner to a short form («Claude · Dashboards»).

### UX-8: narrow windows

`.estate-home .lh-home` becomes one column at `max-width:1100px` (`launch.css` line 777) with the side column last in
the DOM, so «Нужны вы» and «Запросы без ответа» sit below every project card, the one block that asks something of the
person. A laptop window with half a screen is under 1100 px. The agent page does the same at 1000 px (`.as-cols`,
line 1031): «Открыть сессию» is below the whole task list. Fix: at the narrow breakpoint place the side column between
the strip and «В работе» (grid areas), or collapse «Нужны вы» into a summary line with a count that jumps to it.

### UX-9: humanised slugs

`humaniseSlug` capitalises every word: `ssheleg-personal-os` becomes «Ssheleg Personal Os», `fabric-mcp` «Fabric Mcp»,
`sms-activate-app-website` «Sms Activate App Website», `telegram-dev` is fine. The comment calls them "a guess", but
`derived` is not used by any screen to mark it, and for a project with no service descriptor this guess is now the name
on the rail, top bar, Главная, board cards and console tabs. Fix: keep short all-caps words (≤3 letters that are known
acronyms: AI, OS, MCP, SMS, API, UI) upper-case, or show the slug itself when no descriptor matched (the rail's hover
already does) and mark derived names in a subtle way.

### UX-10: smaller copy and consistency points

- The console header shows `StateChip` with `session.state` wording («РАБОТАЕТ», uppercase, blue, `after-console-dark.png`),
  while the agent page and the rail say «работает» in a green pill. One agent, two words in two colours one press apart.
  Use `agentStatus` there, as the other screens do (ER-18).
- `heldFor` (new, `duration.ts`) returns the em dash character (U+2014) for an unparsable date, and `agentScreen.held` /
  `launch.home.inWork.held` would print "holding it" followed by that dash. Rare, but the house rule forbids an em dash in text a person reads;
  hide the clause instead.
- `xp.assignLater` is a fixed date in a string («в релизе от 5 ноября», «in the 5 November release»); the disabled
  «Поручить агенту …» button and its hint are present and correct today, but the sentence goes false on 5 November
  and needs a removal task.

## 0.3.14 behaviours checked and kept

Back, forward and the home button (`Rail.test` line 271, `App.tsx` `goTo` for the new «← Главная» and the console's
«← runner · project»); the status shape and word on «В работе» rows and on the agent page; the console icon beside a row
(present, UX-7 for its look); the «Цель» line with its by-person marker and «Открыть цель»; «Поручить агенту …»
disabled with its hint «в релизе от 5 ноября» (`CrossProjectConsole.tsx`); «Открыть сессию» only opens the console
when pressed; empty, reading, failed and capped states of the agent page and the home are all said in words (tests
green). Both themes: all new css uses defined tokens in both palettes; the light and dark shots agree.

## Verdict

Blocking findings open: UX-1 (rail drops the status word «Работает», against the README's own conflict rule and
CHANGELOG 0.3.14, undisclosed in CHANGELOG 0.3.15). UX-2 to UX-10 are non-blocking.
