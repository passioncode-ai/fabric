### DA-11 (non-blocking) turn window shorter than the task-work window
`apps/desktop/src/main/agentWork.ts#withWork` reads `session.turn.observed@1` with `gte occurred_at now - AT_WORK_MS` (15 min), while `shared/agentWork.ts#workOf` accepts any `recent` signal within `TASK_WORK_MS` (60 min) for an agent holding a task. For the turn signal the 60 min rule is unreachable. An agent whose claim is older than an hour, doing a long build with its last finished turn 20 min ago and no working heartbeat, reads not at work, drops out of the card into «Подключены, без дела», and its task shows as an orphan line.
Fix: read turns for `TASK_WORK_MS` (the 500-row bound then needs a per-session check, or read the newest turn per session with a bounded query), keep `AT_WORK_MS` for the bare "fresh" test.

### DA-12 (non-blocking) the carry window for released claims
`shared/agentIdentity.ts` carries a released claim if `released_how` is `session-ended` or `lapsed` within `CARRY_CLAIM_MS` (2 h), but also requires `taskBy.get(work_id).status === 'running'`. `main/workRelease.ts#returnClaimedTaskToBacklog` moves the task to backlog on every release but done, and the sweep repairs a leftover running task within minutes (`abandonedSweepRun`). So in practice only open claims (`released_at` null) of earlier session ids are carried; the 2 h branch holds for at most the minutes between release and the sweep, and is only exercised by the fixture. Data is not wrong (nothing false is shown), but the CHANGELOG/comment promise of 2 h is stronger than the behaviour.
Fix: state the real window in the comment and CHANGELOG, or drop the released branch; if the intent is 2 h, the task's backlog return must be ignored by the carry (read the task status from the claim's release).

### DA-13 (non-blocking) stale agents without a task are uncounted
`groupInWork` counts `connectedIdle` only for `!stale`, `agentsQuiet` only for stale-with-task (via `onWorkRow`), and `withWorkSignals` leaves stale ones out of `atWork`. A stale agent that holds nothing appears in no number on Главная. The numbers add up as printed, but live total minus printed buckets is not zero, and 0.3.14 counted them. Acceptable if intended (silent, no task), but say so: a hover on the idle line or a line in the CHANGELOG.

### DA-14 (non-blocking) `operator` actor kind
`main/workRhythm.ts` filters decisions with `actor->>kind in ('person','operator')`, and `shared/workRhythm.ts#isPersonDecision` repeats it. `packages/journal/src/index.ts` defines `ActorKind = 'person' | 'agent' | 'system'`. The extra value costs nothing now, but a future writer using `operator` would be silently counted; the board responders' `operator` is a different field. Fix: use `person` only, or add a comment naming the source of `operator`.
