### PL-5 (non-blocking): the plan to release is not recorded

The ledger `docs/evidence/plans/2026-10-27-release-0315-verification.md` says «three independent iterations» in its title and refers to 0.3.14's protocol, and records the target 2026-10-29 and the rollout. It does not say that iteration 3 closes with a version bump (`apps/desktop/package.json`, `CHANGELOG.md` heading "(unreleased)") written together with `docs/launch/release-gate.json` at the release commit, nor what the gate file must then name (version 0.3.15, this ledger, the verified commit, the receipts of iterations 1 to 3, the release metadata). `release-gate.json` is still the 0.3.14 file (`"version": "0.3.14"`, `verifiedCommit 39c82b7b`). Row P-30 says "in progress, target 2026-10-29 (MD-16), branch `feat/mockup-parity`" and links only the README: no link to the ledger, no mention of the three iterations or of the gate. `grep -n -i "release-gate\|bump" docs/evidence/plans/2026-10-27-release-0315-verification.md docs/evidence/backlog.md` prints nothing for this release.
Why it matters: the plan is coherent (three iterations, bump at the release commit, 2026-10-29) only in this brief; a later agent resuming after a compaction has no recorded step order, and an un-bumped gate is the failure the 0.3.14 release process was built to prevent.
Fix: add a «Release» section to the ledger (iteration 2 and 3 candidates are never rebased; the release commit bumps `package.json`, `CHANGELOG.md` heading and `release-gate.json` in one change, verified by the release gate script; tag after green checks; the rollout holds the broker target first) and link the ledger from P-30; say in P-30 that the bump is the release commit's.
