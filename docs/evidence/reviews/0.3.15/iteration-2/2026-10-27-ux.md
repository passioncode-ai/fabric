### UX-11 (blocking): the hero collapses just above the 1100 px breakpoint

What is wrong. `launch.css` sets `.estate-home .lh-hero{grid-template-columns:auto minmax(0,1fr) minmax(260px,360px)}`
inside a two-column page (`minmax(0,1fr) 300px`, gap 24 px) and restacks only at `max-width:1100px`. With the 216 px
rail, a window 1101 px wide gives the left column 513 px, the hero 513 px, and after the face (72 px), two gaps (48 px),
the padding (48 px) and the rhythm's 260 to 360 px, the words column gets nothing. Measured in WebKit with the
candidate's own stylesheets: words column 0 px at 1101, 82 px at 1200, 162 px at 1280 (readable, two lines), 322 px at 1440.
At 1110 and 1120 px the screenshot shows «ВАШ FABRIC · CEO», «Fabric» and the greeting broken into one character per
line down the whole card (`scratch-ux/hero-1120.png`, `row-1110.png`); at 1200 px the greeting wraps to four short lines
(`row-1200.png`). A window of 1101 to about 1180 px is an ordinary state (a dragged window, a half-width window on a
large display); the main window has no minimum width (`main/index.ts#createWindow` sets 1440 by 900 and nothing else).
The 0.3.14 home had no such state, so this is a regression on the screen the release exists to fix. The shots are at
1440 px and the iteration-1 review looked below 1100 and 1000 only, so it was not seen.

Evidence. `apps/desktop/src/renderer/src/launch/launch.css` (the `.estate-home .lh-hero` rule and its
`@media(max-width:1100px)`), `.estate-home .lh-home` grid; probe `scratch-ux/run.mjs` output above.

Fix. Restack the hero earlier (for example `@media(max-width:1260px)` for the hero's grid only, rhythm under the words),
or give the words a floor (`grid-template-columns:auto minmax(180px,1fr) minmax(220px,360px)` and move the rhythm under
them when the card is narrower than the sum). Add a CSS-level or Playwright check at 1101, 1200 and 1280 px.

### UX-12 (blocking): one agent, two answers about «works»

What is wrong. CHANGELOG 0.3.15 says «Работает» means at work and that an agent that only stays connected is counted
apart in «Подключены, без дела», so the strip's number is the cards' less the quiet ones (home gap D3, the operator's
complaint about «37 агентов работают»). Главная and the rail's agent list follow it (`onWorkRow`). But
`launch/agentRoster.ts#composeRoster` still decides `state = ... l.stale ? 'quiet' : 'working'` for every live agent and
never reads `atWork`, and `shared/sessionStatus.ts#agentStatus` takes only `stale`. So an agent with `stale:false,
atWork:false` is listed on Агенты under «Работают сейчас» (probe prints `state: working, group: working`) and its page
says «работает» in a green pill, in the same app where Главная says «Подключены, без дела: 1» and the strip does not
count it. The group's count on Агенты is the 37 the operator objected to. The CHANGELOG sentence does not limit itself
to Главная and the left column.

Evidence. `agentRoster.ts#composeRoster` line `const state: AgentState = held?.state === 'ended' ? 'ended' : ... l.stale ?
'quiet' : 'working'`; `sessionStatus.ts#agentStatus`; `shared/homeProjects.ts#onWorkRow`; `CHANGELOG.md` 0.3.15 second
bullet; probe `scratch-ux/roster.test.mts`.

Fix. Treat `atWork === false` (judged, not at work, not holding a task) as a connected-only state in the roster (the
«Простаивают» group, word «подключён, без дела» or «простаивает») and pass `atWork` into `agentStatus`, so every screen
that prints a status or counts «работают» uses the one definition. Add a roster test and an agent-page test for it.
If the operator wants Агенты to list raw sign-of-life, say so in CHANGELOG and name the group differently.

### UX-13: the cross-project panel prints slugs

`CrossProjectConsole.tsx` builds the project select with `{p.name}`, the buttons with `chosen.name` («xp.open»,
«xp.assign»), the folded line with `chosen.name` and the wall and home notes with `wall.name` and `chosen.name`. The rows
come from `window.fabric.projects.list()`, which carries `displayName`, so a person who sees «Research Agent» in the rail
and on the page picks `research-agent` in this panel. The release goal is one name on every screen. Fix: print
`projectDisplayName(p)` for these (keep the slug for the agent's instruction text). Evidence: `CrossProjectConsole.tsx`
(`projects.rows.map((p) => <option ...>{p.name}</option>)`).

### UX-14: narrow-window order

(a) `.as-side{order:-1}` at `max-width:1000px` puts the whole right column (session card with its big button, then
«Вопросы этого агента») before `.as-main`, which holds «Сейчас» and «Задачи». The CHANGELOG says the session card comes
before the tasks; in fact it also comes before what the agent is doing now, so the page's first answer is pushed below
about 250 px of session facts. Putting the questions first is defensible, the facts are not. (b) At `max-width:1100px`
the home uses `display:contents` and `order` to put «Нужны вы» after the strip; the DOM order is still main column then
side column, so keyboard and screen-reader order differ from the visual one (focus lands on every project card's links
before the questions). Fix: for (a) order side items individually (`.as-questions` first, `.as-session` after
«Сейчас»); for (b) reorder in the DOM (render the side column between the strip and «В работе» at narrow widths with a
wrapper, or accept and note it in the spec).

### UX-15: the shots do not show the main row

`after-home-dark.png` and `after-home-light.png` print «Цель не названа» on every agent row of a project at work, no
project line under the project name (the mockup has one), and «Запросов между проектов... : 1. Самый старый ждёт 2 ч.»
instead of the request line. These come from fixtures with `goal: null` and no profile summary or request list. The
mockup's row leads with the task's title; the candidate's shot never shows that line, so the parity of the most
important row is not evidenced by the shots, and a reader comparing the two sees a regression. Fix: retake the shots
with a fixture that has a task title, a goal, a summary and a request list, and keep both; or say in the README which
elements the fixture omits. The code itself handles those states (`HomeInWork.tsx#AgentRow`, `HomeBoardWaiting.tsx`).

### UX-16: visible placeholders

`duration.ts#since` still answers `'(dash)'` for an unparsable time and the new rows print it: «(dash) назад»
(`launch.home.inWork.heard`), «Dashboards не взял · (dash)» (`boardWaiting.untaken`), «молчит (dash)». `AgentPage.tsx#atWords`
answers `'?'` for an unparsable time, printed as «взял ?», and by the house rule the em dash is not allowed in text a
person reads. The first iteration fixed `heldFor` only. The doc comment of `heldFor` still says «Unknown: «(dash)».» Fix:
hide the clause (as `heldFor` does) or say «время не записано»; keep a test per caller. These are rare data states.

## Checks that found nothing

- Light and dark: the added css uses defined tokens only; the light shots show readable status pills and gold buttons.
- States read in the code: reading, failed with retry, empty, capped and stale are said in words on the rail, Главная,
  «В работе», the board request list and the agent page; the rail's «Все проекты» is hidden until the home reading
  answers.
- Rail rows with long names end in «…» and keep the status word; below 900 px the rail folds to signs and its console
  buttons are hidden, as in 0.3.14.

## Verdict

Blocking findings open: UX-11 (hero unreadable at about 1101 to 1180 px), UX-12 (Агенты and the agent page still call a
connected-only agent «работает», against the release's own definition). UX-13 to UX-16 are non-blocking.
