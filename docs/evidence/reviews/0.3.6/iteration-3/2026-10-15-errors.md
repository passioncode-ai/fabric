| ID | Blocking? | Finding | Evidence | Suggested fix |
|---|---|---|---|---|
| ER-1 | No | **A failed reload of a project's tasks is invisible once tasks were read once.** The iteration-2 fix (V2-14) shows the failure only when `path === null`. `loadTasks` keeps the previous `tasks` and sets `tasksProblem`; `ProjectWay` then renders the old way (done, in work, next) as current and says nothing, and `ProjectBoardGlance` likewise. The failure goes only to the global `onError`. | `renderer/launch/ProjectWay.tsx:44-46` (`problem` read only inside the `path === null` branch); `renderer/ProjectHome.tsx:238-247` (`setTasks` skipped on throw, `setTasksProblem` set) | Render `FailureNote` above the steps whenever `problem` is set, and say the list below is the last one read. |
| ER-2 | No | **Comms read marks are unbounded but the settings file refuses more than 4096.** `onCommsRead` merges every mark ever written (`{...settings.commsReadThrough, ...marks}`), never pruned. The board's heads read is capped at 5000 threads, so "mark all read" on an estate with more than 4096 threads writes a patch that `settingsPatch` refuses ("not a value the settings file can hold: commsReadThrough"): the screen shows "not saved" on every read and the unread badge never clears. A hand-edited or grown file over the bound reads back as `{}` (everything unread). | `renderer/App.tsx:445-455`; `shared/appSettings.ts:25,131-136` (bound 4096), `:39-42` (patch refused); `main/commsOperatorRead.ts` heads `p_limit: 5000` | Keep marks only for threads the heads read still lists (prune on write), or raise the bound above the heads cap; say "too many threads" instead of the generic not-saved. |
| ER-3 | No | **Favourite toggle, replace and move have no rejection handler.** V2-13 fixed only `favourites.list()`. The three writes still end in `.then(...)` under `void`; an IPC rejection (the move handler throws on a bad argument) is an unhandled rejection and the pin stays as it was with no message. `move` was rewritten in this release (`rest` now `[]`). | `renderer/EstateHome.tsx:214-221` (move), `:258-265` (toggle), `:439-442` (replace); `main/favourites.ts:79-80` (throws) | Add the same `.catch` into `setPinProblem` that `list()` got. |
| ER-4 | No | **The lease-fetch scratch monitor turns any filesystem error into a refusal.** `scratchWithinBudget` throws on every error, including `ENOENT` when git renames or removes a temp file between `opendir`/`lstat`; the `.catch` marks `violated` and SIGKILLs git, so a legitimate fetch fails as `scratch_limit`. The same function caps scratch at 1024 entries, which a loose-object fetch can reach. Part of the harness wave behind its flag, so it cannot fail a 0.3.6 user today. | `main/gitLeaseSnapshot.ts:80-92`, `:111-114`, `:122` | Treat `ENOENT` as "already gone" and keep the walk; keep the symlink and size limits as the refusals; record which limit fired. |
| ER-5 | No | **After a failed home read the lanes keep showing the last view as current, while the stat strip goes to «—».** The strip nulls its numbers (`known = v && !problem`), but «Who is doing what» and «Agents at work» render `v` unchanged: rows, "silent" marks and ages (`since()` against `Date.now()`) keep moving while the data is frozen. The failure note is above them, and the CHANGELOG says "keeps the last reading on screen", so this is stated; the two halves still disagree. | `renderer/launch/HomeWork.tsx:49-52` vs `:105-112`, `:152-176`; `CHANGELOG.md` "The home says who is doing what" | Dim the lanes after a failed read, or stamp them "as of <readAt>". |
