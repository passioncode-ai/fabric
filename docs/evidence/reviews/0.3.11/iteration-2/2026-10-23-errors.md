## Not findings

- `newestPosts` terminates on every board: at most `PASSES` x `PAGES` = 50 `list` calls, a page whose `lastSeq` does not advance ends the window (`more = reply.more && reply.lastSeq > cursor`), and a failed page returns null, which the feed says. Measured: 30 calls on the oscillating probe, 10 on a 2e9 journal.
- A page whose `lastSeq` does not advance, and a board that says `more` forever with no messages, make `newestPosts` return the window's oldest page or `[]`. Neither can come from the shipped door: `board_list_operator` answers `last_seq = max(seq)` of the page it returns and `more` only when it held a row past the limit, and a window of 125 or fewer journal numbers holds at most 125 posts, so it cannot overflow 5 pages. Theoretical; not a 0.3.11 defect.
- A journal larger than 2000 x 4^9 numbers with very few posts returns only the newest posts inside the last window (probe: 1 of 2). This is the stated 10-pass bound, and the newest post is right.
- An empty board (`heads` ok with no threads) gives `lastSeq` 0 and an empty feed, which is the board's true answer; `heads` failing gives «unavailable» with «Try again» (tested).
- `heads` capped at 5000 does not hide the newest number: the door orders heads by `last_seq desc`.
- The feed sorts by `at`; `board_message_json` writes `at` in one fixed UTC format with milliseconds, so string order is time order.
- Unmount: the feed's interval is cleared and its read marked dead; the kanban and `useHome` guard with `alive`.
- `IPC.workBoard` accepts a 36-character `[0-9a-f-]` string; a string that passes the pattern and is not a UUID fails the read with a database error, said by the kanban. The renderer only sends project ids from Postgres. A refused id falls back to the estate read, and the kanban filters by `projectId` on the client too.
- The «Закончили» soft read: an error makes `doneRows` empty and sets `doneUnread`; a null `data` without error is an empty list, which is the database's answer.
- `PROTOCOL_VERSION` 2: no reader compares the literal; `protocol.test.ts` checks it is digits and is what `buildProtocol` serves.
- The rail focus move acts only when focus was in `.rail`, finds the visible `main`, falls back to `main` itself without a heading, and returns when there is neither. ⌘K and a typed field keep their focus.
- The agents heading's `nowrap` sits inside `.lh-agents`, whose columns are 265 px, 300 px or full width (`launch.css` `.lh-layout`), wider than «Агенты в работе 10»; its buttons wrap.
- HomeWork: an agent with neither console nor project is a row, not a button, on the Agents place; on the home it opens «Все агенты» (`onAll`), which is a place to go.
- The `needs` route: the home passes the row's `ref`, `App` keys `BoardScreen` on `needs`, and a ref the board no longer holds is BoardScreen's existing «not on the board» path.
