## Not findings

- **Schema and upgrade.** No file under `supabase/` changed since `v0.3.10`; 95 migrations; the operator's database answers `schema_version()` 95; `check-migration-order.mjs` passes. 0.3.11 writes no new table, column, row type or journal event type, so 0.3.10 reads everything 0.3.11 writes to the database and back; the upgrade and the rollback are the bundle alone, as `release-mac.md` says.
- **Persisted state.** The only new persisted field is `settings.json` `agentLanguage` (rollback behaviour documented, V1-25). The new route field `needs` lives in `AppRoute`, which is not persisted (tabs persist `TabRef` of kind project or draft only). No new `localStore` file or userData file in the diff.
- **Event types and feed sentences.** No new journal event type; the only append path touched is the existing `session.oriented@1`. The 7 new i18n keys are interface strings with identical sets in `en.ts` and `ru.ts`; no `event.*` sentence is needed.
- **Analytics and the operations log.** No analytics event added or changed (`git diff v0.3.10..HEAD -- apps/desktop/src` has no `analytics` or `track(` line outside a test stub). The op `agentSurface.working-language-read` now notes "the rules name no language", matching the behaviour; `check-ops.mjs` passes.
- **`work:board` contract.** Preload sends `projectId ?? null`; the handler accepts only a 36-character UUID string, else reads estate-wide; the window policy is `MAIN_ONLY`; `check-ipc-contract.mjs` passes. A malformed id cannot reach the query.
- **The queue by `seq`.** `project_tasks.seq` is the journal seq of the task's creation and never updated (no `update project_tasks` sets it), so "newest filed first" holds; its sort over 82 rows is a sequential scan, the index question CO-398 already holds.
- **Comms page read cost per call.** Each `board_list_operator` page is an index scan on `(estate_id, seq)`, 0.45 ms for 101 rows on the operator's board; the cost question is how many pages, not the page (DA-2, DA-3).
- **The soft done read.** `readHome` reads `finished.error` without throwing; «Закончили» carries `doneUnread`, the kanban's done column carries `unread`, every other read still throws through `must`, so the home never says "nothing" for a read that failed.
- **Tool descriptions.** The four descriptions carry "or the person's own, when it names none"; the `\'` escapes from `5a1b6eea` are JavaScript string escapes and serve a plain apostrophe; tool count unchanged (`check-surface-tools.mjs`).
