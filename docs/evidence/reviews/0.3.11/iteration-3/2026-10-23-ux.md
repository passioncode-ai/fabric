## Not findings

- The release's focused vitest files pass (241 tests) and the shell browser suite passes (107 checks); iteration 2's new tests (CommsFeed «never starts a read while one runs», commsNewest «a quiet newest stretch over a busy one») pass.
- No em dash in any i18n string or CHANGELOG line added in this release; the three em dash lines in the `scenarios.md` diff are pre-existing Coverage text re-emitted, and one is removed.
- Every en key added since v0.3.10 has a ru value; the kind «просьба» now matches the filter «Только просьбы».
- The Board's kanban on the default window does not scroll sideways (`kanban ru.scrollW 0`); an unread column says «?» and the board's words, never 0.
- SCN-176 and SCN-177 are drafts with `Coverage: none yet` and name CO-403 and CO-404; nothing in the candidate claims them, and the CHANGELOG puts them in 0.3.12.
- Агенты's hidden heading is not a missing visible title: the top bar's `h1` names the place.
- A capped kanban column on a project's own board cannot be empty (the project's board filters in the query, V1-2), so «все задачи проекта на его собственной доске» is not shown there in practice; my probe that forced it is not a reachable state.
- The ru string `launch.comms.pollFailed` carries an em dash (U+2014, between «перестала отвечать» and «показано»), but it is in v0.3.10 too, not added by this release.
