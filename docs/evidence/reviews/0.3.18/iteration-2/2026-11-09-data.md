## Findings
| ID | Severity | What | Evidence | Proposed fix |
|---|---|---|---|---|
| DA-9 | **blocking** | The DA-2 fix writes a receipt field the journal refuses. `acceptedByDefault` is not in the ingress rules for `work.swept@1`, which refuse any unknown field, so every receipt carrying it fails with `unknown_field` and is only logged as `work.sweep-receipt`. This is worse than iteration 1: a sweep that told an agent or released a claim AND accepted a review now loses its whole receipt (at 8503abbb it was written without the count), and the count is lost for good, since the next sweep finds those tasks already `done` and accepts 0. The first sweeps after the update, when old reviews are closed in bulk, are exactly the ones whose receipts go. The DA-2 test asserts the in-memory receipt and never runs `prepareEventPayload` on it, unlike its neighbours; `AGENTS.md` (Lifecycle, the sweep row) states the receipt carries `acceptedByDefault`, which is false at the candidate. | `shared/commandIngress.ts#EVENT_FIELDS` (`'work.swept@1'`, no `acceptedByDefault`); `main/commandIngressAdapters.ts#createPreparedJournal` (`rejected` throws); `main/index.ts:1015`, `:3090`; `main/abandonedSweepRun.ts:480-491` (receipt built, refusal only logged; `lastReadState` kept, count not); the scratch run above (`rejected`, `unknown_field`); `test/abandoned-sweep-run.test.mjs` "DA-2 (0.3.18 review)" (no `prepareEventPayload`, compare `:239`, `:932`) | Add `acceptedByDefault: optional(integer(1))` to `EVENT_FIELDS['work.swept@1']`; assert `prepareEventPayload('work.swept@1', w.receipts[0]).state === 'prepared'` in the DA-2 test and in `shared/commandIngress.test.ts`'s fixture; name the count in `shared/protocolObligations.ts` evidence. No migration is needed (the database stores the payload as given). |
| DA-10 | non-blocking | DA-8's quiet log writes a false recovery. `sayIfChanged(null)` is also reached when no read happened: `selectIn` answers `failed: null` without a request when the id list is empty, so opening an agent with no tasks while `task_sources` is failing writes `outcome: ok, recovered: true`, and returning to an agent with tasks writes the failure again; the log then shows recoveries that did not occur. | `main/workRead.ts#sayIfChanged`, `#readSessionTasks` (`selectIn('task_sources', ..., [...ids, ...launchedIds])`); `main/scopedStore.ts#selectIn` (`if (!values.length) return { rows: [], failed: null }`) | Call `sayIfChanged` only when the id list is non-empty (a read actually ran). |
| DA-11 | non-blocking (low) | launchd's losing copy now starts once a minute (exit 75, `ThrottleInterval` 60) for as long as a copy the person opened holds the lock, which is the normal state right after the update (registering the service with `RunAtLoad` starts launchd's copy at once). Each loser runs `editorRecovery.sweep()` at module top level, before the single-instance check, and that removes every `*.tmp` in the shared `editor-recovery` folder, including the primary's own `<file>.<pid>.tmp` between its `writeFileSync` and `renameSync`. The window is microseconds, but it is now periodic; a hit makes that keystroke's `keep` throw on rename. | `main/index.ts:1790-1791` (top-level sweep) versus `:5838` (`requestSingleInstanceLock`); `main/editorRecovery.ts#createEditorRecovery` (`keep`: tmp then rename; `sweep`: removes `*.tmp`); `build/launchd/ai.passioncode.desktop.board.plist` (`KeepAlive SuccessfulExit false`, `ThrottleInterval 60`); `shared/loginItem.ts#secondInstanceExitCode` | Run the sweep only in the primary (after `isPrimary`, e.g. in `app.whenReady`), or remove only `.tmp` files whose pid is not alive or that are older than a minute. |
