| ER-13 | blocking | The signal fix (B1, PL-3, ER-5) does not work: a SIGTERM, SIGHUP or SIGINT is still held while the board's service is on. `index.ts` registers its listeners at module top level; Electron 44 installs its own shutdown signal handler after the main module runs, which replaces them, so a signal reaches Fabric only as Electron's plain `app.quit()`, `signalled` stays false, `holds` is true and the quit hides instead of ending. The lifecycle broker's stop and restart, `launchctl bootout` and `kill` therefore wait for SIGKILL: no drain, PTY sessions killed, the open digest hour lost. `AGENTS.md` Lifecycle and `CHANGELOG.md:36` say a signal always ends Fabric, and the test that should prove it models a listener that never fires. | `index.ts:645-649`; probe above (CJS and ESM: `held`, listener silent; registered inside `whenReady`: exit 0); `quit.test.mjs:356-369` | Register the listeners inside `app.whenReady()` (a signal before ready reaches Electron's quit, which `ready()` false already lets end). Add a real-Electron test: the quit fixture with a hold that is true unless a signal was seen, SIGTERM after ready, assert exit 0 within the bound; watch it fail on the current code. Then N6 (c) on the signed build. |
| ER-14 | non-blocking | launchd's losing copy now starts every minute for as long as another Fabric holds the lock, and with the held Quit that is the whole session.
