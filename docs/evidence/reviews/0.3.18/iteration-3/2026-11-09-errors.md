| ER-18 | non-blocking | The restart question can be a free-standing message box, the shape the startup-failure dialog was fixed away from. On macOS a person can close every window (the process stays, the menu bar stays) and choose «Перезапустить Fabric» with live consoles: no window is focused and `mainWindow` is gone, so the box has no parent. While it is open `app.exit` cannot end the process (probe), so a signal (the broker's stop, `launchctl`, `kill`) or a logout during the question is ended only by the 15 s outside reaper's SIGKILL: no clean exit, past LC-01's 10 s, and under launchd a kill is restarted, which undoes UX-18's exit 0. | `index.ts:686-687` (`parent ? … : await dialog.showMessageBox(ask)`); parentless box probe (alive after `app.exit(0)`); fixture mode `dialog-orphan` ("exit 3" printed, alive at 20 s); `fixtures/quit-app/main.mjs:55-56` (the repository's own note on this shape) | Never ask without a window: show or create the main window first and attach the question to it as a sheet (as the startup-failure dialog does); add the fixture case "restart question with no window, SIGTERM ends 0". |
| ER-19 | non-blocking (low) | The next start records a false reason. `applyLoginItem` writes "launchd did not start the board …; Fabric was opened by its id instead" for any note, but the helper also writes `waited` when Fabric outlived 30 s and kickstart then worked (launchd did start it), and `open <code>` when the fallback failed too (Fabric was not opened; this start came from a later login or open). | `index.ts:805-806`; `loginItem.ts:144` (`echo waited`), `:146` (`open $rc`) | Build the note from the lines: `waited` alone is a slow quit, `kickstart N` with no `open` line is the fallback, `open N` says nothing restarted it; test each. |
| ER-20 | non-blocking (low) | ER-15 residue: a helper that fails to spawn still leaves Fabric down. The synchronous `catch` that sets the relaunch fallback is the rare path. | `restartFabric.ts:62-73`; `index.ts:698-701` | Quit only after the child's `spawn` event (or arm `app.relaunch` in the `error` handler before the quit completes); test with a command that does not exist. |
| ER-21 | non-blocking (low) | The fallback `open -b ai.passioncode.desktop` lets LaunchServices pick among every registered copy with that id. | ER-22 | non-blocking (overlaps PL-18, PL-17; for CO-549) | UX-18's exit 0 covers only launchd's own copy. The Lifecycle row's "a signal … always end[s] it" is true of the process only. | `index.ts:633`; `loginItem.ts:79-81` (`secondInstanceExitCode`); plist `KeepAlive {SuccessfulExit: false}`, `ThrottleInterval 60`; `AGENTS.md` Lifecycle row ("takes the board over when the other copy ends") | Measure in N6 with the broker hold (PL-17); either have a signalled non-launchd copy also stop launchd's job for the session, or say in the Lifecycle row and runbook that stopping a non-launchd copy hands the board to launchd within a minute. |
