| ER-2 | blocking | The quit hold does not depend on launchd keeping the service. `holds` reads only the stored switch, so where registration failed (ER-1 `not-found`), waits for the person (`requires-approval`, the person denied Fabric in Login Items) or does not exist (macOS 12, no SMAppService; no `minimumSystemVersion` is set), the person's Quit closes the windows and hides the Dock icon forever, and nothing restarts the process after a crash. With ER-1 this is every macOS install: Quit no longer quits (a 0.3.17 regression). `quitHolds`' own doc says "True only where launchd keeps the service". | `index.ts:606-609`; `loginItem.ts:37-45`; `loginItemState` maps `not-found` and `not-registered` to `off`, `requires-approval` to `needs-approval` (`loginItem.ts:58-69`) but the hold never reads it; `loginItem.test.ts` `quitHolds` cases have no system status | Pass the system status into `quitHolds` and hold only when `readLoginItem().system === 'on'` (read at quit time, a throw reads as not held). | ER-3 | blocking | The 0.3.17 `mainAppService` login item is removed whether or not the agent service registered. On the upgrade path with ER-1 (or `requires-approval`), every 0.3.17 user loses launch at login (CO-322) and gets nothing in its place; the design says it is removed "once the service is registered". | `index.ts:715-718`: `setLoginItemSettings(item)` then the unconditional legacy removal; the status check after it only logs (`index.ts:720-722`) | Read the agent service's status first and remove the legacy item only when it is `on`; record the legacy item kept otherwise. | ER-4 | blocking | A startup failure past the runtime's ready point can no longer be quit. `ready()` is true once `ptys` and `stopRuntime` exist (set at `index.ts:1485`, `1541`, inside `bootstrap`); a later throw in `bootstrap`, `registerIpc` or `startStackWatch` reaches `explainAndQuit`, whose Quit button calls `app.quit()`, which `holds` now cancels: the dialog's window closes, the Dock icon goes, and a broken process stays alive holding the single-instance lock and the hub port, so neither launchd (no exit) nor a new open (it becomes the secondary and shows the broken one) brings the board back until logout. Before the ready point the same Quit exits with code 1, which `KeepAlive {SuccessfulExit: false}` restarts in 10 s with a new failure dialog, every time the person quits. | `index.ts:597` (`ready`), `index.ts:6223-6228` (`app.quit(); process.exitCode = 1`), `quit.ts:140-150`; plist `KeepAlive` (8c7e5469) | Never hold a quit while startup has not finished or failed (`holds` false when `!windowReady` or `startupBroken !== null`). For a failed start under the service, exit with code 0 after recording the failure (or unregister until the next manual open), so launchd does not loop on a broken start; test both. |
| ER-5 | non-blocking | SIGTERM is held too. Electron turns SIGTERM into `app.quit()` and `before-quit` (the repository's own real-Electron test proves the path), so while the switch is on a SIGTERM from launchd (`launchctl bootout` when the service is unregistered, `kickstart -k`), from the machine's lifecycle broker or from `kill` is cancelled: no drain runs, and launchd or the broker escalates to SIGKILL, ending PTY sessions without the 8 s drain and losing the open digest hour. LC-01's "SIGTERM ends it within 10 s" no longer holds and no test covers it. Turning the switch off likely ends a launchd-started Fabric at once (bootout sends SIGTERM after the setting is written, so the hold reads off), against the design's "the running process stays until the next quit"; not shown on a packaged build (N6 not done). | `quit.test.mjs:290-310` (SIGTERM reaches `shutdown`); `index.ts:606-609`; settings written before `applyLoginItem` (`index.ts:5227-5232`); design "Turning the switch off" | Install a SIGTERM handler that marks the quit as a system end (like `systemEnding`) so a signal always ends the process within LC-01's deadline; prove the switch-off path on the packaged build (N6) and fix the design or the code to agree. |
| ER-6 | non-blocking | The crash restart covers only an instance launchd started.
