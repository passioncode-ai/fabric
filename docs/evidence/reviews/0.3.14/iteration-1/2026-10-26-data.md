## Not findings

- **No migration and no new event type.** `git diff --stat c05c30ef..HEAD -- supabase` printed nothing; the release appends only existing types: `task.moved@1` (releases, the sweep's repair), `work.released@1`, `work.swept@1`, `session.turn.observed@1`. The CHANGELOG's «schema 98, no migration» holds.
- **`work.swept@1` passes ingress with the new kinds and reads.** `commandIngress.ts` builds `found` from `ABANDONED_KINDS` and `unread` from `SWEEP_READS`, both now carrying `work-unclaimed`, `brief-missing`, `turns`, `briefs` (`abandonedSweep.ts:23`, `:35`); `abandoned-sweep-run.test.mjs:788` prepares a receipt with the new kind. Counts and enumerated read names only, no title, body or id.
- **Rebuild gives the same task states.** Every 0.3.14 state change is a journalled `task.moved@1`; the projector's arm sets `status = payload.to` unconditionally (`apply_operating_surfaces`, `20260927000061_managed_task_launch.sql`) and `apply_move_provenance` takes `moved_by_kind`/`moved_at` from the event's actor and time (`20260908000033_projector_scope.sql`). The runtime judgements (`taskHeldElsewhere`, `doneLeftRunning`) only decide whether to append; a replay re-applies the same events in `seq` order.
- **Scope of the new reads.** `work:session` is `MAIN_ONLY` (`ipcWindowPolicy.ts`), validates a UUID, and reads through the estate-scoped store (`index.ts:848`); `work_claims`, `project_tasks`, `journal`, `questions`, `leases` are `ESTATE_AND_PROJECT` in `shared/scope.ts`. Whoami's `waiting` reads through the session's project store and the project's own reader door, which `board_list_reader` limits to threads the project takes part in.
- **What leaves the process.** `waiting.board_requests.items` carry up to 120 characters of requests addressed to the session's own project, in threads it takes part in: the same text the session reads with `com.get`. Questions are its project's own. Nudges carry a kind, a fixed sentence and a task or request id, never a title or a body (`abandonedSweep.ts#nudgeText`, `#nudgeOf`). No secret path found.
- **Indexes for the session tasks read.** `work_claims_owner (owner_session)` (`20261011000095_work_claims.sql:73`) and `project_tasks_session (session_id)` (`20260831000004_tasks.sql:25`) serve `readSessionTasks`; both reads are bounded (200 claims, 100 launched) and say `capped`.
- **Agent-only reminders stay out of «На проверке».** `latest.findings` is filtered by `AGENT_ONLY_KINDS` (`abandonedSweepRun.ts`, the `latest = {...}` block).
- **`taskHeldElsewhere`'s "another open claim" can never be true** because `work_claims_one_live` is unique on `(estate_id, work_id) where released_at is null`; harmless, the lease half carries the check.
- **The operator's own running task returned to backlog when a claim ends** is a recorded decision in the plan («Decisions the implementers took»), not a defect.
