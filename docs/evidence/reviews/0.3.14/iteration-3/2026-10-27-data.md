## Not findings (checked)

- **No migration in this release.** `git diff --stat c05c30ef..0b633afe -- supabase` prints nothing; the CHANGELOG's «No schema change ... schema 98» (`CHANGELOG.md:12`) holds. Every new read uses existing columns: `work_claims.owner_session`, `released_at` (`20261011000095_work_claims.sql:45`, `:55`), `session_heartbeats.phase`, `last_received_at`, `waiting_kind` (`20260909000040_agent_heartbeat.sql:24-26`), `project_tasks.moved_by` (`20260905000019_move_provenance.sql:20`).
- **The single-claim rule matches the data.** One live claim per task is unique in the schema (`work_claims_one_live`, `20261011000095_work_claims.sql:70`); `spawnParentOf` deduplicates by `work_id` and keeps only this project's claims, and the agent surface's store is already project-scoped (`agentSurface.ts:1141`, `scope.ts:150`, `:220`), so a parent can never be another project's task, and `link_tasks` refuses a cross-project link anyway (`20260910000053_link_tasks_command.sql:51-54`).
- **The done repair's provenance test is sound.** `isReleaseStep` compares `project_tasks.moved_by` (the projector's `actor->>'id'`, `20260905000019_move_provenance.sql:68`) with the claim's `owner_session`; an agent's move carries `{kind: 'agent', id: scope.sessionId}` (`agentSurface.ts:2946`, `workTools.ts:575`). Probe Q6: own step within 60 s repaired, another session's move or one after 61 s left alone, no move since repaired. `moveDoneLeftRunningToReview` asks the holders again before the move (`workRelease.ts:147-152`) and appends the existing `task.moved@1` with `{task_id, from, to, note}` as `work-sweep`.
- **`selectIn`'s new `order` keeps the scope.** Probe Q4: each chunk carries `estate_id` and `project_id` filters, then `in`, `order claimed_at desc`, `limit 1000`; a refused chunk is still `failed`, never a shorter list (`scopedStore.ts:93-99`). Its only caller with `order` is the sweep (`abandonedSweepRun.ts:538`).
- **`work.swept@1` is unchanged by the fixes**: `unclaimedSessions` lives in the sweep's memory and the home view only (`abandonedSweepRun.ts`, `latest`), not in the receipt.
- **Nothing private leaves its project.** `fabric_task_create`'s new fields are a task id of the same project and a fixed English sentence (`spawnParent.ts:19-31`); the heartbeat read omits `note_safe`; the cross-project console's words reach another project only within one business or where none is recorded, the same wall the board keeps.
