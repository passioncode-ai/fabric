## Not findings

- **No migration.** `git diff --stat c05c30ef..HEAD -- supabase` printed nothing; the CHANGELOG's «schema 98» holds. Every new read uses existing columns: `goals.title`, `project_tasks.goal_id`, `origin_kind` (`20260905000016_operating_surfaces.sql:51`, `:53`), `task_links` (`:107-116`).
- **The sweep's repair events replay.** `moveDoneLeftRunningToReview` and `moveReleasedLeftRunningToBacklog` append existing `task.moved@1` with `{task_id, from, to, note}` and actor `{kind: system, id: work-sweep}` (`workRelease.ts`); the projector sets `status` from `to` and `moved_by_kind` from the actor with no check constraint on the kind (`20260905000019_move_provenance.sql:21`, `:69`); each move is read back, and `taskHeldElsewhere` is asked fresh with an empty claim id, so any open claim or live or unresolved lease stops it.
- **Scope of the new reads.** `goals`, `task_links`, `journal` are `ESTATE_AND_PROJECT` (`shared/scope.ts:104`, `:106`, `:147`) and read through the estate-scoped store; `link_tasks` refuses cross-project links (`20260910000053_link_tasks_command.sql:51-54`), so a card's aim from a goal cannot come from another project.
- **Indexes.** The goal walk is served by `task_links`' primary key (leading `task_id`); `goals` by its primary key; the attached read by `journal_by_session_id` (measured).
- **Branch names stay in the window.** `withBranches` is composed only into IPC `work:home` (`index.ts:5183`), served to the renderer; no agent tool returns the home view; git runs through the hardened runner (`gitRun.ts`, config-driven programs off, transports refused), and a failure is null with nothing logged.
- **`latest.unclaimed` is never a false 0.** It is null whenever `work-unclaimed` is blind (a failed claims, terminals or turns read, or a capped claims or turns read) (`abandonedSweepRun.ts`, `latest = {…}`).
- **The receipt still passes ingress** with `turns` in `capped` (`commandIngress.ts:203` builds from `SWEEP_CAPS`).
- **`fabric_whoami`'s `waiting` reaches only the session's own project's text** (requests addressed to it in threads it takes part in, its own questions), as iteration 1 found; the new `window_days` and deadline change no scope.
- **«Сдано сегодня»'s semantics** match `projectAnalytics.ts` (moves `to: review` and closes with `outcome: done`, each task once; `task.closed@1` payload `task_id`, `outcome`, `index.ts:1938`).
