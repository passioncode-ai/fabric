# Fabric 0.3.27 release review, iteration 3: ux
Level ux, candidate 777e96f49c90770f25c21803d46b34c6074ff922, baseline 44cd80ca, reviewer claude-opus-5-5, read-only. HEAD before/after 777e96f49c90770f25c21803d46b34c6074ff922/777e96f49c90770f25c21803d46b34c6074ff922, dirty files before/after 0/0.

## Verdict
**Not ready. 3 blocking findings, 8 non-blocking.**

I wrote probes P1 to P7 in the session scratchpad and ran them against the checkout. For comparison I extracted f10fa4b8 and 44cd80ca there with `git archive`. Nothing was written in the checkout.

**The run-seven ux fixes hold.**
- **UX-60 holds.** While the CEO is `starting`, `ceo_reply` answers `state: starting` and says "tell the owner it waits; call ceo_reply again in a while; do not ask again". It no longer says "start it" (`main/ceoVoiceTools.ts#createVoiceTools`, `ceoState` is wired to `agent.status().state` in `main/index.ts`; test «run seven: while the CEO starts or switches runners…»).
- **UX-61 holds.** After a broken-off write, the transcript is still read. An answer comes back as `answered`, with the doubt in `note`. `unknown` is said only when no answer shows by the deadline (`ceoReply` read loop; test «run six: … a broken-off write as unknown»).
- **UX-62 holds.** The person's stop drops the lines a lost console owed and keeps the person's own waiting lines (`main/ceoAgent.ts#stopNow`; test «run seven: … the person's stop drops owed lines»).

**What works in the new code.**
- The board tools answer read-only, and a failed read is said as unread.
- The window placement keeps the window on a display that still exists.
- The CEO head is one row, and its signs keep their names for hover and screen readers.
- The console line copies ids without showing them.
- The dictation tail is in the CEO brief and in the voice instructions.

**Checks.**
- **Tests on the candidate all pass:**
  - `ceo-agent` 79/79
  - `voice-retro` 40/40
  - `voice-board` 6/6
  - `delivery-queue` 11/11 (`node --experimental-strip-types --test`)
  - vitest `src/renderer/src/ceo`, `SessionMetaLine.test.tsx`, `sessionMeta.test.ts`, `windowPlacement.test.ts`: 10 files, 81/81.
- **Em dashes:** the added lines under `apps` hold 50. In the files of this level (i18n, the voice instructions, voiceBoard, ceoAddress, sessionMeta, SessionMetaLine, the ceo folder, ceoTools, knowledgeTools) all 7 are in `#region … — docs:` markers. That is the code convention, so none is text a person reads.
- **Not checkable offline:** whether xAI accepts `audio.input.transcription.keyterms` in `session.update` (`renderer/src/ceo/voiceCall.ts#sessionUpdate`). Check it in one live call before the release.

**Blocking, one line each.**
- **UX-63:** «SEO» and «CEO» still reach a project through `session_start` and `knowledge_search`, which is the owner's order of tonight broken.
- **UX-64:** `board_task` cannot open a task by the 8-character id that `board_tasks` and `board_task` themselves hand out.
- **UX-65:** a new folder whose path begins another project's folder is refused with the false words "belongs to the project X". At f10fa4b8 it became a project.
