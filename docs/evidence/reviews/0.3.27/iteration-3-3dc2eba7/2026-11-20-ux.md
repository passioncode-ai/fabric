# Fabric 0.3.27 release review, iteration 3: ux
Level ux, candidate 3dc2eba711b3ee9a799ecf8559b0256c6d56e71c, baseline 44cd80ca, reviewer claude-opus-5-5, read-only. HEAD before/after 3dc2eba711b3ee9a799ecf8559b0256c6d56e71c/3dc2eba711b3ee9a799ecf8559b0256c6d56e71c, dirty files before/after 0/0.

## Verdict
**Not ready. 3 blocking findings, 4 non-blocking.**

What works:
- **Iteration-2 ux fixes.** I ran the real `createCeoOperations` and `findProject` from scratchpad probes. Nothing was written in the checkout.
  - **UX-15 holds for `start` and `alias`.** «task runner», «retro» and «board ux» all refuse with where to go, and nothing opens. `alias` refuses a worktree name with `understood_as`.
  - **UX-16 holds.** «sound engine» lists sound-engine alone, with `copies_hidden`.
  - **UX-17 holds.** A `tool_result` row no longer opens the answer window (test, and I read `assistantSince`).
  - **UX-18 holds, except one wording.** `session_task` now gives `next` for pending, written_unconfirmed and not_delivered. See UX-31.
  - **UX-19 holds for a running console and for no console.** It does not hold for an ended one (UX-27).
  - **UX-21 holds for `understood_as`.** An exact folder no longer gets one. The same change broke folder listing (UX-25).
  - **UX-22 holds.** The `session_id` description and the resume refusal now name both doors.
  - **UX-23 holds.** Admission only realpaths the folder (`startChoices.ts#admitRepoPaths`), and `admittedNow` skips the check for that call.
  - UX-20 and UX-24 are ruled to CO-605 and their wording matches it.
- **Iteration-1 fixes.** UX-1, UX-3, UX-6, UX-9, UX-10 and UX-13 still hold. I checked them with probes or through their tests, which pass. «Фабрик» answers `understood_as: fabric`.
- **Voice instructions.** Russian and English say the same thing, including the PL-13 alias line. No em dash appears in the lines added since the baseline (grep is empty, region markers aside).
- **Tests on the candidate:** voice-retro 32/32, ceo-agent 56/56, console-open 11/11, delivery-queue 6/6, ipc-window-policy 16/16, and `voiceCall.test.ts` (vitest) 13/13. `agent-surface.test.mjs` refuses to run without a disposable stack, by design. I did not count it.

Blocking:
- **UX-25.** `session_projects` / `fabric_ceo_projects` with an absolute folder that holds several projects now answers an empty list. 0.3.26 listed them.
- **UX-26.** `session_projects`, which both the voice and the CEO are told to call first, answers a worktree's name with the main project and no mark. The next `session_start` with that name opens in the main folder. This is UX-15's harm on the prescribed path.
- **UX-27.** For an ended console in a worktree, the UX-19 refusal says «an agent works in that folder… continue it with session_resume». Resume then starts a fresh agent in the project's main folder, told to «continue where it stopped».
