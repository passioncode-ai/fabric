## Verdict
**Not ready. 2 blocking findings, 4 non-blocking.**

### Iteration 2 errors fixes I checked

**Hold:**
- **ER-15.** `assistantSince` now opens the answer window only on a user row that carries text. A `tool_result` row no longer opens it. The test «UX-15, UX-17, UX-21» covers it.
- **ER-18.** In the scrollback, `\x1b[nC` becomes n spaces (at most 200), and CSI sequences with `:` or `<=>` parameters are removed. console-open's cursor-move fixture covers it.
- **ER-19.** A worktree named by its folder's last part now carries a `worktree` mark, and `start` refuses it. My probe got «…/fabric-0327-review belongs to the project fabric … nothing was started».
- **ER-20.**
  - After the extra Enter there is a second look. With no turn, the answer is `written_unconfirmed` / `no_turn_after_enter`.
  - `written_unconfirmed` is now logged at warn, with the last 15 screen lines redacted.
  - The time budget is unchanged: the paste path is now 30 + 30 + 3 + 3 s, the same worst case as the plain second look, still under `FIRST_TASK_WAIT_MS`.
- **ER-21.** Forgetting a name that was never kept is now refused in `ceoTools.ts#alias`, and `ceoProjectAliases.ts#remove` writes nothing.
- **ER-22.**
  - `closeOrphans` reads only the last 8 KB of each file (`tailOf`). It reads the whole file only when there is no `end` row in that tail.
  - `begin` prunes down to `KEEP_CALLS - 1` before it writes, so at most 200 files remain. The DA-4 test asserts 200.
  - Pruning, listing and orphan closing touch only files named like calls that are real files, never links (`callFiles`).

**Hold in part:**
- **ER-14.** The exact-folder half holds: `~/myapp`, `…/fabric` with a registered worktree below it, and `…/mono` are all found again (my probe `it2/p1.mjs`, re-run on this candidate). The subfolder half does not hold: see ER-24.
- **ER-16.** An ended CEO console now reads as not running (`index.ts`, `ceoLastActivity` checks `running`). The echo window is measured from the wrong moment: see ER-25.
- **ER-17.** The transcript path is looked up again every 20 s. But the runner session id it uses only changes when the launch journal records it, and that check runs every 5 minutes: see ER-26.

**New code from iteration 2 that reads correct:**
- **`redactPayload` of voice answers.** I probed it: ids, SHAs and folders pass unchanged. No voice-tool answer has a key the credential-name rule would hide. The null-prototype result survives the IPC copy.
- **`cleanKeys`.** Keys are redacted like values.
- **Keep-aside of an unreadable aliases file.** It is renamed aside before any write, never overwritten.
- **`projects` copy rule.** A copy whose name starts with a listed project's name gives way to that project.
- **`admittedNow`.** A folder the same start just admitted is treated as its project's own folder.
- **`session_task` next steps.** The next steps are filled in for every state except delivered.

**Blocking findings:**
- **ER-23.** A one-word project name that 0.3.26 resolved correctly now resolves to whichever project has a worktree whose folder name ends in that word. This breaks a 0.3.26 path.
- **ER-24.** A subfolder of a project that sits right under home, or that holds another registered project, is admitted as a new project, and a session starts there with ok. That makes the CHANGELOG line «a folder inside a project … is refused with where to go» false.
