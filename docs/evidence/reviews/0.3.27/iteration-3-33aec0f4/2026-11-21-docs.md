| DO-85 | Blocking | **A CEO the person stopped is started again after Fabric restarts.** The CHANGELOG, the AGENTS.md row «The CEO's board reading» and ADR-0197 Amendment 5 §2 promise that a stopped CEO stays stopped. But the stop is the in-memory flag `held`, which starts `false` in every process and is never written to disk (`ceo.json` keeps only `projectId`). After any restart (a login with «Служба доски», «Перезапустить Fabric», or the Quit the update installer asks for), the next minute's tick runs `ceoBoardKeeper.ts#wake`. If any `ceo.task` request of the last 30 days is still queued, wake calls `ensure`, and `ensure` starts the console. Before 0.3.27, nothing started a stopped CEO at a restart: only the person's window or message did. The owner's stop was his own explicit wish of 2026-11-19. | `apps/desktop/src/main/ceoAgent.ts:121` (`let held = false`), `ceoAgent.ts:358` (the meta written: `{ projectId }` only), `ceoAgent.ts#ensure` (`if (held) return status()`). `main/index.ts` `ceoBoardTick` (`else await ceoBoard.wake(view.requests)`). `main/ceoBoardKeeper.ts#wake`. `test/ceo-board-keeper.test.mjs` has no case for a held CEO or for a restart. | Keep the person's stop on disk (for example `held: true` in `ceo.json`, cleared by the person's start, restart or message) and test a restart.
