# Fabric 0.3.27 release review, iteration 3: data
Level data, candidate 755687ab0b438a67c0ce26a6d448e3d5150ae8a1, baseline 44cd80ca, reviewer Claude Opus 5.5, read-only. HEAD before/after 755687ab/755687ab, dirty files before/after 0/0.

## Verdict
**Not ready. 1 blocking finding, 3 non-blocking.**

What works:
- **File modes hold on a fresh install, now that every message is written to disk first.** `send` calls `saveAttachments([])` before the queue is saved, even with no files. That call creates `inbox/` with `recursive, mode 0o700`, so the CEO's folder gets 0700 before `saveQueue` runs its own `mkdirSync` (which has no mode). Probe on a folder that did not exist, umask 022, first message text only, printed `rootMode 700, inboxMode 700, pendingMode 600`.
- **What stays on disk after a delivered message.** While the message is being typed, `pending.json` holds its text: `[{"line":"secret plan for Q3",...}]`. Once it is written, `pending.json` holds only `[]`. The folder holds `AGENTS.md, CLAUDE.md, ceo.json, inbox, pending.json` and nothing else. The ops records carry `chars` and `reason`, never the text.
- **The write is atomic.** It writes `pending.json.tmp` with mode 0600 and then renames it. The temp file is created fresh each time, so it is always 0600.
- **The prune removes only its own files.** It matches `^pending\.json\.corrupt-\d+$` only. In a probe it left `pending.json.tmp`, `pending.json.corrupt-1-notes`, `pending.json.corrupt-abc` and `notes.corrupt-1` alone.
- **DA-39 holds.** Both kinds of wrong shape are kept aside and recorded:
  - A file that is not a list is recorded as `why: not-a-list, kept_aside: true`.
  - A list with bad entries is recorded as `why: invalid-entries, invalid: 1`. The whole original file is kept aside, so the bad entry survives in that copy.
- **DA-40 holds.** A full queue is refused at the top of `send`, before any file is saved. The test "a full queue refuses before saving any file" passes.
- **DA-41 holds.** Every message now goes through one queue, and a second caller waits for the drain already running (`draining` is now a Promise). The test "two sends that overlap are typed in the order they were sent" passes.
- **DA-38 holds in part.** The record now says `kept_aside: true | false`. The bound of three files is applied. The 30-day limit is not applied (DA-42).
- **No change since run five** in `calls/` (`ceoVoiceJournal.ts`), `project-aliases.json` or the transcript read. The voice's `voiceAskedAt.text` (200 characters) is kept in memory only.
- **The changed and neighbouring tests pass:**
  - `ceo-agent`: 70 of 70
  - `voice-retro`: 37 of 37
  - `delivery-queue`: 11 of 11
  - `claude-transcript`: 3 of 3
  - `console-open`: 14 of 14

Blocking:
- DA-42: AGENTS.md now says kept-aside queue files are "kept 30 days". The age check runs only when another file is kept aside, so one broken file keeps the owner's words with no time limit.
