# Fabric 0.3.27 release review, iteration 1: errors
Level errors, candidate f6990a9aaed3f243d65a40be601e5b519b9af30d, baseline 44cd80ca, reviewer claude-opus-5-5, read-only. HEAD before/after f6990a9aaed3f243d65a40be601e5b519b9af30d/f6990a9aaed3f243d65a40be601e5b519b9af30d, dirty files before/after 0/0.

## Verdict
**Not ready. 1 blocking finding, 12 non-blocking.**

**What works:**
- **Delivery queue busy path.** It never writes without fresh output. It never takes the busy path for an item with a write gate. A busy timer armed for a head that was replaced is dropped. Close clears it. A busy flush with nothing new re-arms every `settleMs` (400 ms) instead of spinning.
- **First instruction.** The second readiness wait and the 10-minute `outcomes` cleanup are bounded. The worst case (30 s + 30 s + 3 s) fits under `FIRST_TASK_WAIT_MS` (70 s).
- **`ceo_reply`.** It always ends by its `until` deadline, at most 60 s: a missing transcript falls back to the screen, and a CEO that never goes quiet answers `still_working`. The voice call does not idle-end during a pending tool (`voiceCall.ts`: `pending.size === 0`). `MAX_CALL_MS` still ends the call.
- **Enrollment of existing projects is unchanged.** The scratch check runs only after the exact, ancestor, worktree and remote matches (`sessionEnroll.ts#resolveAgentFolder`).
- **`backoffFor`.** It grows for the scratch message. The message prefix matches `SCRATCH_FOLDER_MESSAGE`.
- **`hub.unknown-credential`.** It writes only a 12-character digest. The User-Agent is cleaned to ASCII and cut to 80 characters. The rate map is bounded at 256.
- **Per-session maps.** `voiceRefusals` is keyed by tool name, so it is bounded.
- **Tests.**
  - `voice-retro`: 14/14 pass.
  - `console-open`: 9/9 pass.
  - `delivery-queue`: 5/5 pass.
  - `ceo-agent`: 56/56 pass.
  - `session-enroll`: 48/48 pass.
  - `voiceCall.test.ts` (vitest): 13/13 pass.
  - `agent-surface.test.mjs` needs the disposable database stack, so it was not run (the brief forbids the database). Its new unknown-credential checks are not verified here.

**Blocking finding:**
- **ER-1.** `findProject` resolves an unregistered absolute folder anywhere under home to a project that has no repository. It does this when any launch in the journal, or any open console, ran in the home folder. `fabric_ceo_session_start` then starts an agent with the task in the home folder, under the wrong project, and answers ok. In 0.3.26 the same call admitted the folder as a new project.
