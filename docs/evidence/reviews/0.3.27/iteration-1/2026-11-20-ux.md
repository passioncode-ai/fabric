# Fabric 0.3.27 release review, iteration 1: ux
Level ux, candidate f6990a9aaed3f243d65a40be601e5b519b9af30d, baseline 44cd80ca, reviewer claude-opus-5-5, read-only. HEAD before/after f6990a9aaed3f243d65a40be601e5b519b9af30d/f6990a9aaed3f243d65a40be601e5b519b9af30d, dirty files before/after 0/0.

## Verdict
**Not ready. 3 blocking findings, 11 non-blocking.**

What works:
- The voice instructions now tell the voice to delegate: work goes to the project's agent with the task in words, a shell opens only when the owner asks, and the CEO's own console is reached through ask_ceo and ceo_reply. The Russian and English texts say the same thing and have no em dash.
- A task in words for runner shell is refused before anything starts.
- The retro's measured names resolve: «Диззи», «DC», «ПлейСинг», «Саунд энджин», «фабрик», «свитчборд», «обсерватория».
- A cache copy gives way to the real project. The call journal is kept, private and redacted.
- Tests on the candidate: `voice-retro.test.mjs` 14/14, `ceo-agent.test.mjs` 56/56, `console-open.test.mjs` 9/9, `delivery-queue.test.mjs` 5/5, `voiceCall.test.ts` 13/13. Not run: `agent-surface.test.mjs`, which needs a disposable database stack; the brief forbids that.

Blocking:
- UX-1: a name the lookup "hears" now starts a session with its task in the wrong project, where 0.3.26 refused. Reproduced: «SEO» starts in `ceo`.
- UX-2: an absolute worktree folder, or a folder inside a project, now starts the session in the project's main checkout instead of the folder that was named.
- UX-3: two projects with the same name (`research-agent` today) cannot be chosen. The refusal's `next` sends the voice into the repeated-refusal loop that finding 8 was meant to end.
