| DO-58 | Blocking | **A limit while the queue writes the next line loses the line the limit was for, and types the newer one twice.** `drainOnce` removes the line it typed with `queued.shift()`, which removes whatever is first in the queue. When B's write ends `written`, `shift()` removes A, not B. Then B is typed again on the next runner, and A is never typed. B's send also answers «queued», `not-delivered`, though B was written. This makes three things false: CHANGELOG bullet 2 («typed again on the next runner, once»), SCN-189 (alt path and «Errors & recovery»: «puts it back at the head of the queue for the next runner, once»), and AGENTS.md's CEO console row («the person's undelivered messages typed again»). The `fallBack` comment («the next runner gets them in the order they were sent») is false too. The case is real: a second message is written into a working Claude Code after 3 s, while the answer to the first can show the limit. Run six's code lost B in the same race, so the gap is not new in kind, but the wrong-entry `shift()` is new. | `apps/desktop/src/main/ceoAgent.ts#drainOnce` (`queued.shift()`, line 244). `#fallBack` (`queued.unshift(...)`, line 607).
