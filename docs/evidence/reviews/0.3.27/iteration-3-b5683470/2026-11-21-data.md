# Fabric 0.3.27 release review, iteration 3: data
Level data, candidate b5683470db10e0356217c709bd1a37e0cea71d94, baseline 44cd80ca, reviewer Claude Opus 5.5, read-only. HEAD before/after b5683470/b5683470, dirty files before/after 0/0.

## Verdict
**Not ready. 1 blocking finding, 6 non-blocking.**

What works:
- **The queue file is private and written safely.** `ceo/pending.json` is written to a temp file and then renamed into place, with mode 0600, inside the 0700 `ceo` folder. The probe measured the mode as `600`.
- **The operations log keeps no message text.** `ceo.agent.queued` and `ceo.agent.queue-delivered` record only counts, `chars` and `waited_s`.
- **A message has a size limit.** `ceoLine` caps the text at 8000 characters and the attachments at 10 paths.
- **The transcript reader keeps nothing.** It finds the file under the session's folder name, which matched 43 of 43 Fabric consoles on this Mac. It reads at most the first 2 MB, returns only true, false or null, and stores nothing.
- **The transcript cannot point outside its folder.** The runner's session id is checked as a UUID when it is read (`sessionLaunches.ts#claudeSessionOf`).
- **The changed tests pass:**
  - `claude-transcript`: 2 of 2
  - `ceo-agent`: 58 of 58
  - `delivery-queue`: 10 of 10
  - `console-open`: 14 of 14

Blocking:
- **DA-31.** A new message the console takes at once is typed before older messages still in the queue. SCN-189's claim that waiting messages go "in the order they were sent" is false.
