# Fabric 0.3.27 release review, iteration 3: ux
Level ux, candidate b5683470db10e0356217c709bd1a37e0cea71d94, baseline 44cd80ca, reviewer claude-opus-5-5, read-only. HEAD before/after b5683470db10e0356217c709bd1a37e0cea71d94/b5683470db10e0356217c709bd1a37e0cea71d94, dirty files before/after 0/0.

## Verdict
**Not ready. 3 blocking findings, 5 non-blocking.**

**What works.**
- The first-task fix does what CHANGELOG `## 0.3.27` says, on the fixtures given. With the prompt test set, nothing is written before the footer shows, even when the console is busy. A transcript with no turn retypes the task once, and an unknown transcript never retypes.
- Fabric's own resume opens a fresh console with a new Claude Code id (`ceoTools.ts#resume`). So an old transcript cannot make a dropped task read as taken.
- The composer's new wording has no em dash, and the box is cleared. Run three's ux fixes are untouched by this diff.
- Tests on the candidate: `ceo-agent` 58/58, `console-open` 14/14, `delivery-queue` 10/10, `claude-transcript` 2/2 (`node --experimental-strip-types --test`), and `CeoComposer.test.tsx` 5/5 (vitest). All pass.

**Blocking, one line each.**
- **UX-41.** A CEO that failed to start, or has every runner set aside, is now described as "busy", and the window says the message "will go by itself". Nothing restarts the CEO, and the popup head says «не запустился» at the same moment.
- **UX-42.** A new message the console takes at once jumps ahead of older queued ones. SCN-189 says "in the order they were sent" and is marked implemented.
- **UX-43.** A queued message with an attachment is typed without the extra Enter. In Claude Code it then sits in the CEO's input box, which is the case the owner reported (pasting by hand).
