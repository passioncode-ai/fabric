## Verdict
**Not ready. 1 blocking finding, 4 non-blocking.**

What works:
- **Run one's ux fixes.** I checked each one by calling the real `createCeoOperations` and `findProject` from scratchpad probes. Nothing was written in the checkout.
  - **UX-25 holds.** `projects {query:'/d'}` lists every project under `/d` and adds `why: "too-broad"`. `start {project:'/d'}` is refused with the next step.
  - **UX-26 holds as written.** `projects {query:'task runner'}` marks the match with `worktree`, `understood_as` and a `next`. This same change opens UX-32.
  - **UX-27 holds.** Resuming an ended worktree console is refused with where it would open. The start refusal now says "has ended" instead of "an agent works". See UX-33 and UX-35.
  - **UX-28 and ER-23 hold.** `start {project:'review'}` starts `code-review-bot`, not fabric.
  - **UX-29 holds.** `start {project:'copy a'}` opens the registered copy in its own folder.
  - **UX-30 holds in part.** The exact name now comes first and is named in `exact`. Nothing tells the voice what `exact` means (UX-34).
  - **UX-31 holds.** Both descriptions say "each but delivered and resubmitted". `session_task` names `unknown`.
- **Earlier ux fixes still hold:** UX-1, UX-2, UX-3, UX-9, UX-15, UX-19 and UX-21, through their tests and my probes.
- **Wording.** No i18n string changed in this run. The added lines contain no em dash (`grep -c` gives 0). The Russian and English voice instructions are unchanged and still say the same thing.
- **Tests on the candidate:**
  - `voice-retro` 33/33, `ceo-agent` 56/56, `console-open` 11/11, `ipc-window-policy` 16/16, `delivery-queue` 6/6.
  - `voiceCall.test.ts` (vitest) 13/13.

Blocking:
- **UX-32.** UX-26's new `understood_as` on a worktree match triggers the voice's own alias rule. After one "yes" from the owner, the worktree's name is kept as an alias of the main project. From then on that word starts work in the main folder with no question. That is UX-15's harm again.
