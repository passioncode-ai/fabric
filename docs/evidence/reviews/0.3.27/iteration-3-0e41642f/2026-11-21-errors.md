**Run ten's fixes at this level hold in the ordinary case:**
- **ER-87 holds when nothing overlaps.** `stopNow` and `personStopping` write `heldByPerson: true` to `ceo.json`. A new agent on the same folder reads it back. `wake` returns `'held'` and starts nothing. Probe case 3: same run `stopped`; after a restart `heldByPerson true`.
- **ER-88 holds.** A held or stopped CEO returns `'held'` and logs nothing. A failed CEO returns `'failed'`. A wake is now logged by the state the start reached (`reached`, `from`), not by the attempt.

**Blocking, one line:**
- **ER-93.** A stop pressed while the first start since Fabric opened is still looking up its project is lost from disk. That start then writes `ceo.json` without the hold, so after the next restart a waiting `ceo.task` starts the CEO the person stopped.

| ER-93 | Blocking | **The stop and a start race on `ceo.json`, and the start wins.** `start()` writes the meta as `{ projectId }` with no hold, right after `await deps.ensureProject(...)`.
