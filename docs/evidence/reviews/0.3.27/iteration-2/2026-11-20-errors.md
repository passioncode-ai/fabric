## Verdict
**Not ready. 1 blocking finding, 8 non-blocking.**

### Iteration 1 errors fixes I checked

**Hold:**
- **ER-1.** `ceoTools.ts#workFolders` keeps only worktree copies, so a launch in home no longer claims home. Test «UX-5, ER-1» covers it.
- **ER-2.** `closeLeft` ends a left call with its measured length. `closeOrphans` closes leftover calls at start. Test «DA-3, ER-2, ER-4» covers both.
- **ER-3.** The size cap now counts `Buffer.byteLength`. Test «DA-1, DA-2» uses Cyrillic lines.
- **ER-4.** The call id is read before the tool's await. `voiceAskedAt` is kept per call. A late `ask_ceo` from an earlier call cannot overwrite a newer call's ask: both go through the CEO console's one FIFO queue, so the earlier one resolves first.
- **ER-8.** By voice a start waits 8 s (`VOICE_FIRST_TASK_WAIT_MS`), then answers `pending`. Test UX-6 measured 8.0 s.
- **ER-10.** `sessionEnroll.ts#resolveAgentFolder` checks for a scratch folder before the remote attach. Test «DA-7, ER-10» covers it.
- **ER-11.** Old call files are pruned at every `begin`.
- **ER-12.** `recap` reads project names, and `voiceInputs` drops consoles that ended.
- **ER-13.** A leave is skipped when logging unknown credentials, and the map now evicts the least recently used entry.
- **DO-6.** `quietOnly` reaches the queue: `pty.ts#deliverWhenReady` passes its options to `enqueue`. The worst case is 30 + 30 + 3 + 3 = 66 s, under the 70 s `FIRST_TASK_WAIT_MS`.

**Hold in part:**
- **ER-5.** The transcript path is now cached, but the cache goes stale (ER-17).
- **ER-6.** «not running» is said when the CEO has no console. The screen-fallback test does not hold (ER-16).
- **ER-7.** The new escape-stripping drops the spaces from a hint drawn with cursor moves (ER-18).
- **ER-9.** It holds for a folder that is not registered. For a folder that is itself a registered project, the new rule created ER-14.

### Blocking finding
- **ER-14.** The CEO can no longer find a project by its own folder in two cases: the project sits right under home (`~/myapp`), or any other project is registered inside it, even a worktree copy. 0.3.26 found it. A start by that folder now tries to admit it as a new project and is refused «held-by-other». A subfolder of such a project is admitted as a new project nested inside it. That makes the CHANGELOG line «a folder inside a project … is refused with where to go» false for these projects.
