## Iteration 1 findings checked

- DA-1: fixed. `windows` sends an editor's `path.basename` only and drops `title` for console and editor windows (ceoTools.ts `windows`, `file: ... path.basename(x.subject)`, `title: x.kind === 'main' || x.kind === 'ceo' ? x.title : undefined`); a test covers it ("DA-1, DA-5").
- DA-2: fixed. `layoutName` refuses `__proto__`, `constructor`, `prototype` and the Object method names (windowLayout.ts `RESERVED`); `parseLayouts` and `boundLayouts` build `Object.create(null)`; `restore` looks up with `Object.hasOwn`; a stored name must equal its own `layoutName` to be read.
- DA-3: fixed, with a residue in DA-9. The write is `localState.ts#atomicWrite` (temp 0600, fsync, rename, dir fsync; index.ts `layouts.write`); saves run one after another on the `saving` chain and re-read the file just before writing (ceoTools.ts `windowLayout`, `saving.then`); a read failure other than ENOENT and a file over the bound are logged.
- DA-4: fixed. Each placement is rebuilt from checked fields (`placementOf`: window and area from the lists, display 1..8 / primary / other, ids `^[A-Za-z0-9-]{1,128}$`, a session placement needs one id), `saved_at` kept only when it parses as a date, at most 12 placements and 50 layouts (oldest dropped), a file over 256 KiB not read. Probe: the worst case the tool itself can write (50 layouts x 12 placements with 128-character ids, Cyrillic names) is 253 903 bytes, under the 262 144 bound; a realistic one with UUIDs is 141 892.
- DA-5: fixed. A failed save answers `the layout could not be kept (<code>)`, the message stays in the record (cut to 200); a failed move answers only the AppleScript error number; a failed link open answers a constant; the `windows` listing's `why` strings are constants; a timeout is `OsascriptTimeout` and never carries the script.
