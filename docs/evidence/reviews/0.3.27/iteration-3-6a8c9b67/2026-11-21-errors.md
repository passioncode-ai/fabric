## Verdict

**What works.** The four test files the brief allows are green:

Each command was `node --experimental-strip-types --test apps/desktop/test/<file>.test.mjs`, and each exited 0.

**Run four's errors fixes:**
- **ER-38 holds** for a fallback after a line is queued and before it is typed.
- **ER-39 holds.** A stopped or ended CEO is said as `not-running`.
- **ER-40 holds on the plain path.** An unknown write answers `delivery-unknown`, is not queued, and is delivered once. The 10 s doubling backoff is there, capped at 5 min. The race in ER-49 is the exception.
- **ER-41 holds.** A broken file is moved aside as `pending.json.corrupt-<time>` and recorded.
- **ER-42 holds.** 50 is the bound at send and at load, and a cut is recorded.
- **ER-43 holds for messages already waiting.** A send while a drain runs (`draining` true) is typed by that drain, in order (probe P6: `Q1,Q2`, nothing left).
- **ER-44 and ER-45 hold.** `hasPersonTurn` returns false for meta-only lines, for tool results alone and for a cut last line. It returns true for `queue-operation` enqueue and for a person's string.

**Blocking:**
- **ER-46.** When messages are already waiting, a new send never starts the CEO and never clears the person's stop. A stopped or ended CEO with waiting messages is not asked back by writing to it, and the voice is told the line "is typed as soon as" the console takes it, but nothing starts the console.
- **ER-47.** A queued line that the drain types into a console which then answers with a limit is lost: the fallback retypes only direct lines. A direct line in the same case is retyped on the next runner.
