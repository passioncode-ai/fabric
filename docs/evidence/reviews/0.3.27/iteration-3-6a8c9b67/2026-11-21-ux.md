# Fabric 0.3.27 release review, iteration 3: ux
Level ux, candidate 6a8c9b6730d257bf75e296ab217366bf2a19f5a8, baseline 44cd80ca, reviewer claude-opus-5-5, read-only. HEAD before/after 6a8c9b6730d257bf75e296ab217366bf2a19f5a8/6a8c9b6730d257bf75e296ab217366bf2a19f5a8, dirty files before/after 0/0.

## Verdict
**Not ready. 1 blocking finding, 4 non-blocking.**

**What works.**
- UX-41 holds on the direct path. When the CEO fails to start, `send` answers `not-running`, and the composer shows «CEO не запущен…», never «занят» (`CeoComposer.test.tsx` new case). The popup shows «Попробовать снова» in the failed state.
- UX-42 holds. A new message goes behind the waiting ones, and they are delivered in order (`FIRST`, `SECOND`).
- UX-43 holds. A queued line naming files gets the settled Enter when the queue types it (`head.files`, `enterAfterFiles`).
- UX-44 holds. My probe on `noteOutput('  ?\x1b[1Cfor\x1b[1Cshortcuts')` gave `ready true`.
- UX-45 holds. Once the prompt is drawn, an item waits 30 s.
- UX-47 holds. My probe on an `isMeta` user line alone gave `hasPersonTurn false`, and on a person's line `true`.
- UX-48 holds on the direct path. An unknown write answers `delivery-unknown`, gets the new «Неизвестно, дошло ли сообщение…» line, and is not queued.
- The voice's `ask_ceo` now tells the voice that a queued line waits.
- The new strings carry no em dash.
- Tests on the candidate all pass: `ceo-agent` 65/65, `delivery-queue` 11/11, `claude-transcript` 3/3, `console-open` 14/14 (`node --experimental-strip-types --test`), and `CeoComposer.test.tsx` 6/6 (vitest).

**Blocking, one line each.**
- **UX-49.** While any message waits in the queue, writing to a stopped or ended CEO no longer starts it. The composer then points to a «Попробовать снова» button that those states do not show. This worked in b5683470 and 0.3.26, and the popup's own text says «нажмите «Запустить» или напишите ему».

| UX-49 | Blocking | **A new message no longer starts a stopped or ended CEO when anything already waits in the queue.** The run-four order fix added a queued-first branch to `send`. When `queued.length > 0`, that branch only enqueues and drains. It skips `waitPersonStop`, does not clear `held`, and never calls `ensure`. So a CEO the owner stopped stays stopped, and a console that ended stays ended, and nothing will ever type the messages. The popup's stopped panel says «CEO остановлен. Он не запустится сам: нажмите «Запустить» или напишите ему.», and SCN-189's alt path says "writing to it is the operator asking it back (SCN-187)". Both are now false in this case. The composer then says «…Запустить его можно кнопкой «Попробовать снова»». The popup shows that button only in the `failed` state. For `stopped`, `ended` and `idle` it shows «Запустить». The likely path: the CEO is stuck, so a message is queued, the owner presses Stop, then writes again as the panel says. In b5683470 every send went through `held = false; ensure()`, so this worked. | `main/ceoAgent.ts#send` (queued-first branch, around lines 404-413, before `held = false` and `ensure()`). `renderer/src/ceo/CeoPopup.tsx` (`stopped && state !== 'stopped'` gives `ceoAgent.start`; `state === 'failed'` gives `ceoAgent.retry`). `ru.ts` `ceoAgent.stopped`, `ceoAgent.composer.queuedStopped`. Probe (A queued by `readiness_timeout`, then `stop()`, then `send('B')`): `{"ok":true,"queued":true,"reason":"not-running","state":"stopped","waiting":2}`, consoles opened before/after `1 1`. The same for a console that ended by itself: `state":"ended"`, opened `1 1`. Control with an empty queue after `stop()`: `send('B')` gives `state":"running"`. | In the queued-first branch, do what the direct path does before draining: `await waitPersonStop()`, wait for `stopping`, set `held = false`, `await ensure()`, then `drain()`. Word «CEO не запущен» by state: name «Запустить» for stopped, ended and idle, and «Попробовать снова» only for failed. Add a test: queued, stop, send, and the CEO runs with both lines typed in order. |
| UX-50 | Non-blocking | **A message the queue types with an unknown outcome is said as «Отправлено CEO.».** In the queued-first branch, `send` awaits `drain()` and answers `ok: true` once the item has left the queue. But `drain` also takes a line off the queue when the write's outcome is unknown (`queue-unknown`). So the owner reads «Отправлено CEO.» for a write that broke off. SCN-189's alt path says such a write "is said as unknown". A queued line that ends unknown during a later timer drain is never said at all. The only trace is the ops log. | `main/ceoAgent.ts#drain` (`if (typed === 'unknown') { … continue }`), `#send` (`const waiting = queued.includes(item); if (!waiting) return { ok: true … }`). Probe: A queued, then `send('B')` where the write of B answers `outcome_unknown`. The result is `{"ok":true}`, with no reason. | Have `drain` return the outcome per item, and answer `delivery-unknown` when the sender's own item ended unknown. For a timer drain, raise a status flag the composer can show once. |
| UX-51 | Non-blocking | **After the owner starts or restarts the CEO, queued messages can wait up to five minutes, while the window says they go «как только CEO запустится».** Nothing calls `drain` when a start succeeds. The queue waits for its timer, and the new backoff (ER-40) has grown the timer to 300 s after five busy tries. `drainMisses` is reset only by a successful write, so a restart does not shorten the wait. An owner who presses «Запустить» and sees nothing typed for minutes is the person SCN-189 says should never paste by hand. If they paste, the queue types the same text again later. | `main/ceoAgent.ts#drainLater` (`CEO_QUEUE_RETRY_MS * 2 ** drainMisses`, capped at 5 min), `#start` and `#restart` (no `drain`). `ru.ts` `ceoAgent.composer.queuedStopped`. Probe (timer intercepted, console busy): delays `[10000,20000,40000,80000,160000,300000,300000]`. After `restart('person')`, `delivered []`, next try armed in `300000` ms, `queued 1`. | After `state = 'running'` in `start`, reset `drainMisses` and call `void drain()`. Optionally drain on the first output after a turn ends. |
| UX-52 | Non-blocking | **A message sent while the CEO is restarting is said as «CEO не запущен», while the head says «запускается».** The queued-first branch picks `reason` as `state === 'running' ? 'not-delivered' : 'not-running'`. During a restart, `state` is `starting`. SCN-189 step 1 says a starting console is said as busy («CEO занят…»).
