- **DA-73 is fixed.** `start` returns at `if (held) { state = 'idle'; return finish() }` right after `writeHold(held)`. No runner is opened. The test «run twelve: a stop during the lookup opens no console…» passes.
- **The atomic write half of DA-74 is fixed.**
  - `ceo.json` is written to `ceo.json.tmp` (0600) and renamed over the old file.
  - Failed writes are recorded as `ceo.agent.meta-write-failed`, and failed reads other than ENOENT as `ceo.agent.meta-read-failed`.
  - Both log lines carry only the error class and code (`errorClass`, `ceoAgent.ts:101`), never a path or the file's text.

- **Migration 130 is sound at the data level:**
  - It creates no table and moves no data, so no RLS is needed.
  - `board_message_via` is `security definer` with a fixed `search_path`. Execute is revoked from public, anon and authenticated and granted to service_role only. The DB test asserts `has_function_privilege('anon', …) = f`.

  - `board_message_json`, which agents read through `com.list` and `com.get`, is unchanged.
  - `ceo_private_archive_canonical` differs from migration 129's only by adding `'103'`. `PRIVATE_ARCHIVE_LIMITS.sourceSchemas` and `schemaContract.json` (103/103) agree with it.
  - `commsOperatorRead.ts#messageOf` refuses a `via` value it does not know, and the schema pin is exact.
  - The four operations the CASE maps are the only ones that call `board_insert_fenced_message` (`20261012000104…:641,671,744`, `…129:92`).
