**Not ready. 2 blocking findings, 6 non-blocking.**

I wrote probes P1 to P3 in the session scratchpad and ran them against the checkout's sources. P1's temporary folders were under the home folder and were removed after the run. Nothing was written in the checkout.

**The run-eight ux fixes hold, except where noted.**
- **UX-63 holds.** P1: «SEO», «шеф» and «Сео» are refused with "«SEO» is the CEO itself, not a project", by console and by voice, and nothing opens. `knowledge_search` with `project: "SEO"` is refused, and `projects.list` with `query: "SEO"` answers empty with a note.
- **UX-64 holds.** `brief` gives whole ids. `board_task` opens a task by a whole id with no project, and by an id prefix within its project.
- **UX-65 holds.** P1: `start` with `<root>/myapp/` beside `myapp-legacy` admits the folder and opens it (`["p9","claude-code","go"]`). A `~/…` path is no longer misattributed either. It is refused as "no project", as before.
- **UX-66 holds.** The order is running, then review, then backlog. `project_tasks.started_at` is `not null default now()` (`supabase/migrations/20260831000004_tasks.sql:19`), so the date tie-break is real.
- **UX-68 holds.** SCN-110 step 3 now matches `openCeoWindow`: no parent, and the button calls show and focus.
- **UX-69 holds, but breaks something else.** The hover text now shows, but the window's drag area shrank (UX-74).
- **UX-70 holds for the tool descriptions.** P1 checked every voice tool description (session_*, knowledge_*, board_*, ceo_reply, machine_status, board_search, recap). None names a tool the voice lacks.
- **UX-71 holds.** The address rule is in the brief, and the brief is rewritten at every start (`ceoAgent.ts#prepareFolder`). Its wording is wider than the code's rule (UX-76).
- **UX-73's description changed, but it is not true for every id the tool invites (UX-75).**
