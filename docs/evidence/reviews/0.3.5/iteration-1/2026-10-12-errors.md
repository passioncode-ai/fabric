### Checked and found sound (no finding)

- **Link parameters are treated as a claim.** `parseFabricLink` refuses prompt-like or credential-like parameters, repeats, bad grammar and links over 2,048 characters. `routeForLink` only picks a view and a notice, and starts nothing. The URL itself is never logged (`ops.record` carries the notice only). The outbox holds at most 8 links and resets on reload. `linksOpen`/`linksPending` are `MAIN_ONLY` (`ipcWindowPolicy.ts:84-85`).
- **The door token may only ask.** `fabric.session.enroll` through the door returns `needs-grant` and never a session (`sessionEnroll.ts:175-178`). `fabric.access.status` through the door needs the poll secret (`accessService.ts` `status`). The prompt says the runner name is a claim (`accessWords.ts:73-76`, `access.enroll.floor`). The folder shown is Fabric's own resolution, and a folder of another project is refused (`accessService.ts` enrollment branch).
- **The binding credential is shown once.** Its sha256 is kept, and a claim racing a revocation is refused by the projector and answered as "since revoked". A credential that cannot be *checked* returns 503, not 401 (`agentSurface.ts:915-920`), so `fabric-mcp` does not forget a valid credential. A refused one (401/403) is forgotten (`fabricMcp.ts:268-272`).
- **Enrollment** is capped per binding (8), re-checks liveness after minting, and ends the session if the journal write fails. Revoking a binding or grant ends its sessions (`sessionEnroll.ts:184-217`).
- **Hub files** are written atomically at 0600, read without following links and bounded (FIFOs refused), and `withdrawHub` removes only this pid's files. The origin is the loopback literal, and the token file must sit under the root (`hub.ts:186-246`).
- **Hub refusal spans** are windowed per binding and code, flushed at quit and on revoke, and a summary that fails is logged (`hubCall.ts` `notSentSpan`, `summarize`).
- **Claims:** every read checks `error` and throws (`workTools.ts`, `workRead.ts#must`). The operator release reads back (`workRelease.ts:54-56`). Claims of a session that ended are released, with a 3 s bound at quit (`agentSurface.ts:464-470`).
- **The Comms read** returns `unavailable`, never an empty list, on any error or throw (`commsOperatorRead.ts:121-176`).
- **Quit:** the deadline (10 s, exit 3) and the outside guard are armed before the stops run, and a failing stop does not stop the quit (`quit.ts:96-110`). The start-up failure dialog is a sheet on a parent window, so SIGTERM is still served.
- **Windows/Linux data folders and paths:** `stackFolderFor` matches `userData/stack`, `PATH` is split and joined with `path.delimiter`, the Claude config uses `homedir()`, the Keychain read is darwin-only, and the vault refuses on Windows with a reason. `fabric-mcp.cmd` resolves `..\..\Fabric.exe` from `resources\bin`, and the `runAsNode` fuse is on.
- **`release.yml`:** every job that holds the `release` environment (`macos`, `windows`, `linux`) has `needs: [guard, preflight]`. `publish` needs those three. The environment deploys from tags `v*` only. Secrets are passed per step (Apple and ASC only to the macOS signing and build steps; `FABRIC_ANALYTICS_APP_KEY` only to the build steps). The Windows job has `id-token: write` for OIDC signing, and an unsigned Windows build must say so in the CHANGELOG (step at `release.yml:158-160`). There is no `pull_request` trigger and no cache in the signing jobs. One residual note, not a finding: `publish` uses `secrets: inherit` into the org's reusable workflow, so its scope is that workflow's.
