| UX-1 | **Yes** | **Comms «Earlier» silently skips messages and then says "The beginning of the thread."** The initial page is read from `initialAfter = lastSeq − 50`, but the cursor for older pages, `earliestAfter`, starts at 0 and is never set to `initialAfter`. The first Earlier therefore reads `after_seq = max(0, 0 − 50) = 0`, i.e. the thread's first 50 messages, and because `after === 0` it hides Earlier and shows "The beginning of the thread." Everything between those first 50 and `initialAfter` is never shown, and the screen implies the history is complete. Example: one thread, 120 messages at seqs 1–120. The first page is 71–120, Earlier shows 1–50, then "beginning of the thread". Messages 51–70 are missing without a word. Seqs are estate-wide, so with interleaved threads the gap can be larger. This breaks SCN-143 step 5 ("one page further back by the same cursor") and the CHANGELOG claim that the screen reads "the estate's threads and messages". | `apps/desktop/src/renderer/src/launch/CommsScreen.tsx:200` (`earliestAfter = useRef(0)`), `:207` (`initialAfter`), `:226` (`setHasEarlier(initialAfter > 0)`), `:251` (`after = Math.max(0, earliestAfter.current - PAGE)`), `:268` (`if (after === 0) setHasEarlier(false)`), `:314` (`launch.comms.historyStart`); `supabase/migrations/20261011000094_project_board_operator_read.sql:60-63` (`m.seq > p_after_seq … order by m.seq limit`: seq is per estate, filtered by thread). | Seed `earliestAfter.current = initialAfter` when the first page lands. Show "beginning of the thread" only once the read reaches the thread's `createdSeq`. Add a test with more than 100 messages. |
