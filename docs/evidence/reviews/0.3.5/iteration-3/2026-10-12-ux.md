The CO-268 rulings (V2-4…V2-9, V2-11…V2-13) are acceptable for an early preview. None loses data. The two closest to misleading:

- **V2-4:** "No project has work in flight right now" can be said while the review read failed.
- **V2-11:** there is no in-app route to register `fabric-mcp`. The Agent access panel's own description (`access.what`) also still describes product access only.

The CHANGELOG and README carry the registration commands. I would keep both in CO-268 and not hold the release on them.

Other CHANGELOG claims checked and found true in code:

- The `fabric://` scheme is registered for all three OSes (`electron-builder.yml` `protocols`, `setAsDefaultProtocolClient`).
- A link is held during startup and the first run, and offered when the first run is left.
- The first run is one radio choice, and an agent that cannot be picked says why.
- SCR-31 has claims, «related», «Release…» with its confirmation, and leases only with `agent-sync.json`.
- SCR-78 is in the rail and its last row is always shown.
- Comms is read-only, with two labels per request and "unavailable" never shown as empty.
- The schema refusal is in the app's language and the details stay in English (`startupDialog`, `translator(readSettings().locale)`).
- `fabric-mcp` and `fabric-mcp.cmd` ship in `resources/bin` and match the paths the CHANGELOG gives.
- `unsupportedOs` covers CO-244, and CO-245 covers the Connect button.
- No string names the Mac (`platformWords.test.ts`). The one Keychain sentence is reachable only on darwin (`quota.ts#readToken`).
