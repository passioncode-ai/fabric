## Verdict
**Ready. 0 blocking findings, 9 non-blocking.**

**What works:**
- **Migration 131 follows migration 4's shape.**
  - It adds no table. The table grants of migration 4 cover the two new columns: `authenticated` may select `rank_proposal`, and `anon` may neither select it nor update `rank`. The RLS policy is unchanged.
  - `apply_task_rank` is `security definer` with its `search_path` set. It is revoked from all four roles. Under Supabase's default privileges, no role can execute it, `apply_projections` or `ceo_private_archive_canonical`.
- **The three event types are registered with `projects = true`.** Each has a feed sentence in `en.ts:1643-1645` and `ru.ts:2863-2865`.
- **The dispatcher and the archive function changed by one line each.**
  - The dispatcher equals migration 124's plus the one line `perform apply_task_rank(e)`. Checked with a diff of the two function bodies.
  - The archive function equals migration 130's with `'104'` added. The app side admits 104 too (`ceoPrivateArchive.ts#PRIVATE_ARCHIVE_LIMITS`, codec test).
- **The ledger and the contract match the file.** The ledger sha256 `29b5abd9…180e1` matches the file. `schemaContract.json` reads 104/104.
- **The upgrade works from both older schemas.** On my own throwaway clusters, a database at 103 and one at 102 each took the step. Their rows were kept, `rank` and `rank_proposal` were null, and `schema_version()` read 104. Running 131 a second time is harmless.
- **`run-task-rank-db.mjs` passes 8 of 8 checks.** It needs `LC_ALL` set on this Mac, or the cluster does not start.
- **Single test files are green:**
  - task-rank 23/23
  - task-rank-write 14/14
  - behaviour-journal 3/3
  - approval-mode 3/3
  - ceo-access 8/8
  - effect-tools 7/7
  - people-ask-run 25/25
  - ceo-private-archive-codec 1/1
  - board-cycle 4/4
  - check-build-private 3/3
  - vitest `peopleAsk.test.ts` and `appSettings.test.ts`: 64/64
- **The routes file is handled safely.** `setPeopleChoice` keeps every entry the file had and writes a fresh exclusive temp file (0600, fsync, rename). It never writes over a file that does not read. The owner's routes file still holds its 3 routes, including the route to PassionCode's PM project. I checked only the shape, no names.
- **The approval mode fails safe.** A missing or unknown value reads as `important`, and an unreadable settings file does too.
- **The ops log holds no account email.** It records only the account id (`ceoTools.ts:639`).
- **Nothing of one machine is in the build.** `check-build-private` reports PASS on the release worktree's `out/`, and the home path appears in no file. That build dates from 12:25, before the candidate commit (12:39, CO-625). It must be checked again on the candidate's own build in the release procedure.

**Blocking:** none.
