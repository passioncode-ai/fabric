# Fabric 0.3.28 release review, iteration 1: errors
Level errors, candidate acbff40cab29096a292efd5771aba40a8906af10, baseline v0.3.27, reviewer Claude Opus 5.5, read-only. HEAD before/after acbff40cab29096a292efd5771aba40a8906af10/acbff40cab29096a292efd5771aba40a8906af10, dirty files before/after 0/0.

## Verdict
**Not ready. 1 blocking finding, 10 non-blocking.**

What works:
- Every changed test file passes on the candidate:
  - `operator-door.test.mjs` 5/5
  - `people-ask-run.test.mjs` 25/25
  - `memory-read.test.mjs` 8/8
  - `scripts/test/check-build-private.test.mjs` 3/3
  - vitest on `peopleAsk.test.ts`, `dockIcon.test.ts` and `SettingsScreen.test.tsx`: 70/70
- The operator door refuses a wrong Host, a browser Origin, a foreign account and a bad token before it reads the body. It compares the token in constant time, writes the token file before the document, and stop() only removes files that name its own pid.
- The Dock icon refuses anything that is not a PNG data URL under 4 MB, and refuses an image that does not decode. A failed write is logged without the image's bytes.
- Detached windows never call the MAIN_ONLY dock door, because the preload does not give them that method (`preload/api.ts#exposedApi`).
- The build check does not print values. It matches whole words in Unicode, and it fails loudly when the org checker returns no JSON.
- On this machine, the owner's routes file still holds the route 0.3.27 had built in, so removing `DEFAULT_PEOPLE_ROUTES` costs nothing today.

Blocking:
- **ER-1.** If `people-ask-routes.json` exists but is not valid JSON, choosing any route in Settings overwrites the whole file. The hand-written organization routes are lost, and Settings gave no warning that the file was unreadable.
