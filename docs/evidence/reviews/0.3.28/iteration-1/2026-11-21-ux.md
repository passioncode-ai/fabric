# Fabric 0.3.28 release review, iteration 1: ux
Level ux, candidate acbff40cab29096a292efd5771aba40a8906af10, baseline v0.3.27, reviewer claude-opus-5-5, read-only. HEAD before/after acbff40cab29096a292efd5771aba40a8906af10/acbff40cab29096a292efd5771aba40a8906af10, dirty files before/after 0/0.

## Verdict
**Ready. 0 blocking findings, 11 non-blocking.**

What works:
- **«Куда уходят вопросы».** It lists every active project with its PM agent, whether that agent answers now and where the link came from. Settings and the runtime bridge use the same order: chosen first, then the routes file, then the agent found by itself (`shared/peopleAsk.ts#resolveRoute`, `main/peopleAskRun.ts` route block).
- **«Не отправлять в Telegram».** It is honoured as `chosen-off`.
- **Texts.** The ru and en texts carry the same 23 keys, have no em dash and no longer name the owner's agent.
- **The owner's routes file still reads.** Read on this Mac: `{routes: [...]}` with 3 routes (the organizations' names redacted for this public repository, ADR-0096). With `DEFAULT_PEOPLE_ROUTES` now empty, nothing regresses for him.
- **Dock icon at the next start.** `main/appIcon.ts#applyAppIcon` sets the kept face before the splash, in a packaged build too.
- **Detached windows.** They never call the Dock door: the preload subset has no `persona.dockIcon` (`preload/api.ts#exposedApi`).
- **The avatar refactor.** `FabricAvatar.tsx` now uses `shared/avatarSvg.ts` and draws the same markup as 0.3.27.
- **Memory's map.** It drops source nodes of kind project (`mail:project:…`), and a real project keeps its counts (`main/memoryRead.ts#memoryGraph`).
- **Tests run on the candidate, all green:**
  - `npx vitest run` on dockIcon, SettingsScreen, peopleAsk, MemoryScreen and PersonaScreen: 5 files, 82 passed.
  - `node --experimental-strip-types --test`: people-ask-run 25/25, memory-read 8/8, app-icon 1/1.

Nothing blocks. UX-1 is the one to fix first: the Dock can show, and keep, the default face instead of the chosen one.
