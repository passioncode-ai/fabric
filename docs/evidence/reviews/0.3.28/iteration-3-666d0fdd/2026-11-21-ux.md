# Fabric 0.3.28 release review, iteration 3: ux
Level ux, candidate 666d0fdd295502d2ed0e2a82569b97f8a372ecf6, baseline v0.3.27, reviewer Opus 5.5 (Claude Code subagent), read-only. HEAD before/after 666d0fdd295502d2ed0e2a82569b97f8a372ecf6/666d0fdd295502d2ed0e2a82569b97f8a372ecf6, dirty files before/after 0/0.

## Verdict
**Not ready. 1 blocking finding, 11 non-blocking.**

**What works.**
- The Settings panel «Что ждёт вашего одобрения» shows all five modes in ru and en, marks the mode in force, says what each one makes wait, and saves a new choice. This closes UX-12.
- The queue's «Выше» and «Ниже» buttons are disabled when the move would cross the waiting line, and a drop across that line is refused. This closes UX-13. «Принять» is hidden when every project is shown (UX-15).
- While the routes file does not read, nothing is sent to Telegram, and the Settings line now says so in both locales (ER-12, UX-16).
- `fabric_ceo_accounts` and a successful start say an account as «name@…» and give its `account_id`.
- A start that asks for a model and effort passes them as flags to the runner that actually starts, on a chosen account too (through `switchboard launch … --`). A runner with no such flag is said as not applied.
- Single test files I ran are green:
  - `ceo-access` 8/8, `ceo-agent` 88/88, `launch-model` 2/2, `people-ask-run` 26/26, `voice-board` 11/11 (`node --experimental-strip-types --test`).
  - `KanbanBoard.test.tsx` and `SettingsScreen.test.tsx` 62/62 (`npx vitest run`).

**Blocking.**
- UX-21: the release notes and the ledger say CO-622 is not in 0.3.28. Its items 1, 2 and 5 ship in the candidate, including a new tool that types into consoles, and no release note names them.
