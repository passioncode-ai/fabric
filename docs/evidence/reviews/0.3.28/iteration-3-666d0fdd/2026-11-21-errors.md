## Verdict
**Ready. 0 blocking findings, 11 non-blocking.**

What works, against the code changed since iteration 2 (618551f7..666d0fdd):
- **ER-12, the routes file that does not read.** The skip is placed after the quitting check and before the pass bound. While the file does not read, no new ask and no re-ask is sent. The skip is logged once per change of the count (`peopleAskRun.ts#createPeopleAskBridge`).
- **ER-20, the temp file.** `setPeopleChoice` removes its temp file when the write fails and throws again. The IPC handler records the failure as `settings.people-route`.
- **ER-14, the kill.** `pendingExits` kills through `platform.ts#killPty`, so Windows no longer throws on a signal. `settleExits` counts a refused kill in `left`.
- **ER-18, the settle's failure.** `index.ts` records a throwing settle as `quit.settle`.
- **ER-13, the drain race.** The drain is raced against `hardDeadlineMs - QUIT_SETTLE_BUDGET_MS`, and the settle always runs.
- **CO-622 start.** An account launch passes `args: []` (`consoleOpen.ts:185`), so the model and effort flags reach `switchboard launch <id> --in-place -- …`. The CEO's own console and resumes carry their own flags, so nothing is doubled.
- **Wiring.** `hubPorts` and `index.ts` hand `ceoBoardReads` to the CEO server beside the behaviour journal.

Single test files run on the candidate, all green: quit 25/25, pty-settle 5/5, people-ask-run 26/26, launch-model 2/2, voice-board 11/11, ceo-agent 88/88, ceo-access 8/8, board-cycle 4/4, `scripts/test/install-mac-update.test.mjs` 11/11.

The findings below are failure paths that work less well than they say: the installer (CO-626), the new board summary, the CEO's board door, and the account refusals. None of them breaks 0.3.27 behaviour or turns a test red.
