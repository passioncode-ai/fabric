## Checked and sound

- `readTurnVerdict`: every read is row-bounded and under the client's fetch deadline; a refused or thrown read is
  logged `work.turn-verdict-unread` and gives no verdict, never a failed turn; `session_heartbeats` is one row per
  session (primary key), so `limit(1)` is that row; the turn is appended before the verdict is read; unknown facts are
  never a change, so a folder git cannot read never keeps a session going.
- `fabric_work_release` `wait`: refused with `done`, refused when it names nothing checkable, refused past 7 days;
  journalled on `work.released@1`; `onReleased` runs after the append.
- `sessionHolds`: no shell, 10 s `timeout`, bounded buffer; a timeout (null code) or spawn error rejects and is logged
  `session.hold`; a bad session id is never passed; a change asked while a call runs is kept, newest wins; the lookup is
  shared and a missing binary is said once. The hold is released at a session's real end and kept when Fabric quits.
- `leave` (fb5b790a): the decision is synchronous, so two clients leaving together end the session once; only another
  own, initialised, non-rejoin bearer that called within five minutes keeps the session; the end record is written only
  when the session ends; both cases are tested.
- `boardResumeRead`: every main read throws, the wiring logs `board.dispatch.resume-read` failed and the pass goes on;
  a capped read and unread limit stops are said once per change; `readResumeState` gives null on any failure, judged
  again on a later pass.
- T5: the remote question is idempotent by `asked_command_id` (projected from `command_id`), so a lost append answer is
  found on the next pass; a thrown `ask` is a counted, logged refusal; an unclear question ends the run with its reason
  logged; an unread board files nothing; a question read that throws is logged once as `unread`; `questions.status` is
  only `open`, `answered`, `withdrawn` or `stale`, so `state` never reads a settled question as unknown; a `waiting`
  record holds no run slot and its workflow is closed through the remote close loop.
- `createRemoteQuestions` and `fabric_question_ask`: a retry with the same key answers the stored question before the
  clarity rule is applied, so a question stored under 0.3.21 is not refused on a retry.
- Hand-back at enrollment: waits at most `RESUME_CLAIMS_WAIT_MS` (timer cleared, unref'd), logs a failure as
  `hub.session.resume-claims`; two enrollments handing back one claim are arbitrated by the projection and the loser is
  read back as refused.
- `task-to-operator`: in `ABANDONED_KINDS` and the `requests` kinds; no further run starts for that release.
- The console: «Новая сессия» only in the embedded console, disabled while it starts, its failure said in our words with
  the machine's text apart; «Завершить сессию» is the same `SessionStop`, one press; an already ended agent shows the
  check, not the end act.
