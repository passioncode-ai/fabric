## Checked and sound

- `sessionHolds.ts`: every `monitor hold` runs through `execFile` with a 10 s timeout and no shell; a timeout or spawn
  error (no numeric `code`) rejects and is said through `failed` (`ops.failed('session.hold')`, `index.ts:1345-1346`);
  a non-zero exit is said with its stderr; nothing failed is remembered, so the next change asks again; holds asked
  together share one binary lookup; a change asked during a call is kept, newest wins, and asked after it.
- `agentSurface.ts#leave`: synchronous between the `otherLive` check and the end or drop, so two clients leaving at once
  end the session exactly once; a bearer that never called is not counted live; the end is recorded once
  (`claimEndRecord`); a session ended (not by a quit) releases its hold before its claims.
- `turnVerdictRead.ts`: every read is limit-bounded, a refused or thrown read gives no verdict and is said
  (`work.turn-verdict-unread`), and the turn's answer waits on it with `.catch(() => null)`, so a failed read never fails
  a recorded turn; the journal read is served by `journal_by_session_id`; `session_heartbeats` has one row per session.
- `turnVerdict.ts`: a loop that changes nothing ends within three turns; unknown git facts never count as a change.
- `boardResumeRead.ts`: every read whose loss would read as «nothing to continue» throws; the supervisor logs a failed
  read (`board.dispatch.resume-read`) and goes on with the rest of the pass; `resumeSince` keeps its start in the process
  and says a failed write once.
- `boardDispatchRun.ts`: filing a remote run's question is idempotent by `dispatch-question:<dispatchId>`
  (`asked_command_id`), a thrown or refused filing is logged and asked again with the same key up to `CLOSE_ATTEMPTS`,
  then the run ends as a blocked one did; an unread board files nothing; a `waiting` record starts no run while its
  question is open or unread, and a failed question read is said once per request (`questionUnread`). Every question
  status (`open`, `answered`, `withdrawn`, `stale`) is handled by `createRemoteQuestions().state`.
- `sessionEnroll.ts`: the resumed-claims hand-back is awaited at most 5 s, its failure logged
  (`hub.session.resume-claims`), never the enrollment's; each claim given back is read back from the projection.
- `questionTools.ts`: an unclear question is refused before any write, with the fix in the answer.
- `SessionWindow.tsx`: «Новая сессия» shows only embedded in the main window (the detached window offers none, iteration
  2 ER-1 holds), is disabled while starting, and says a failed start with the machine's words.
