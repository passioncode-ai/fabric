## Checked and sound

- `readTurnVerdict` never throws into the turn: every read's refusal and a thrown read go to `unread`, which logs
  `work.turn-verdict-unread` and gives no verdict (`turnVerdictRead.ts:27-63`); the turn is appended before the verdict
  is read, so its own row is in the three turns. Two quiet turns give none, so no loop (`turnVerdict.ts:41`).
- `fabric_work_release` refuses a `wait` on a done release, a wait that names nothing checkable and a time or limit past
  7 days, before any write (`workTools.ts`, the release tool); each release calls `onReleased`, whose hold sync is
  newest-wins per session (`sessionHolds.ts:98-125`).
- Holds: a missing Switchboard is said once and then a no-op; lookups asked together share one (`sessionHolds.ts:60-73`);
  a non-zero exit or a spawn error is said and not remembered, so the next change asks again; a session's end releases
  its hold only for `ended`, never for Fabric quitting (`agentSurface.ts:598-600`).
- `leave`: a client leaving ends the session only when no other own (non-rejoin) bearer of it called within five
  minutes; the last client's leave ends it, since the earlier leave dropped its bearer (`agentSurface.ts:1006-1032`).
- The supervisor's read throws on every failed core read and the dispatcher logs it and goes on with the requests
  (`boardDispatchWiring.ts`, `board.dispatch.resume-read`); capped and limit-stops-unread states are said once per
  change; a resume run on a Switchboard without `--reason resume` is refused and said once (`resume-reason`).
- The remote question: a refusal is asked again with the same key until `CLOSE_ATTEMPTS`, an unclear one ends the run as
  before, both logged as `board.dispatch.question`; a filed question survives a quit before the record is saved, since
  `createRemoteQuestions.ask` finds it again by `asked_command_id` (`boardDispatchWiring.ts:389-412`); a failed read of the
  filed question is said once per request and holds the request (`boardDispatchRun.ts:1162-1173`); a `waiting` record is
  kept by the trim while its request is on the board (`afterPass`) and its workflow is closed by the remote closing loop.
- A resumed session's claims: the enrollment waits at most 5 s and logs a failure without failing the enrollment
  (`sessionEnroll.ts:445-452`); a claim given back is read back from the projection before the task is moved, so a task
  someone took meanwhile is refused, not doubled (`resumedClaims.ts:96-99`).
- The console: «Новая сессия» is disabled while it starts, says a failure under itself, and is offered only in the main
  window (`SessionWindow.tsx:135-150`, `:172-195`); the person's end is marked before the stop in `terminalEnd` and
  History's stop (`index.ts:5784-5785`, `:4555`); a mark whose stop is refused lingers in a set of at most 200 and can
  only turn a later end of that session into the person's own, the safe direction.
- `questionClarity`'s patterns are linear or near-linear on the bounded question text; a question in an unexpected
  status reads as unread, never as answered.
