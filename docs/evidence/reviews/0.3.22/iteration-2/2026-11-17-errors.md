## Checked and sound

- `readTurnVerdict`: every read is row-bounded; a refused or thrown read is logged `work.turn-verdict-unread` and gives
  no verdict, never a failed turn (`turnVerdictRead.ts:35-36`, `:54-63`); `session_heartbeats` has one row per session
  (primary key `session_id`), so `limit(1)` is that row; the turn is appended before the verdict reads, so `turns[0]`
  is this turn; unknown facts never count as a change (`turnVerdict.ts:22-27`).
- `sessionHolds` child: no shell, 10 s `timeout`, bounded buffer; a timeout (null `code`) or a spawn error rejects and
  is logged `session.hold`; a non-zero exit is logged with at most 300 characters of stderr and not remembered; a bad
  session id is never passed; the queued change after a call is asked once and the recursion holds no lock across an
  await. The hold is released at a session's real end and kept when Fabric quits (`agentSurface.ts:598-600`).
- `leave`: the decision is synchronous, so two clients leaving together end the session once; a rejoin bearer is never
  counted as another live client; the end record is written only when the session ends.
- `fabric_work_release` `wait`: refused with `done`, refused when it names nothing checkable, refused past 7 days
  (`waitTooFar`), journalled in `work.released@1`; `onReleased` runs after the append, so the hold follows what was
  journalled.
- `boardResumeRead`: every main read throws on failure and the dispatcher logs `board.dispatch.resume-read` failed and
  goes on with requests and inboxes; `access_requests` is read through the estate store the main process uses, which
  the `service_role` grant covers; a capped read and unread limit stops are said once per change.
- T5: the remote question is idempotent by `asked_command_id` (projected from `command_id`), so a lost append answer
  is found on the next pass; a thrown `ask` counts as a refusal with its reason logged; an unclear question ends the
  run with the reason logged; an unread board files nothing; the `waiting` record is not an empty run; the
  `dispatch-run:` asker id no longer breaks the Board's read of askers (`boardReads.ts`, fixed in this candidate, with
  a failed askers read now logged as `board.read-askers`).
- Enrollment waits for handed-back claims at most `RESUME_CLAIMS_WAIT_MS` (timer cleared and unref'd) and logs a
  failure as `hub.session.resume-claims`; two enrollments handing back the same claim are arbitrated by the
  projection and the loser is read back as refused (`resumedClaims.ts:96-99`).
- `task-to-operator`: in `ABANDONED_KINDS` and in the `requests` kinds, so a failed sweep read keeps its last telling;
  the dispatcher starts no further run for that release (`boardDispatchRun.ts:1146`) and a refused start
  (`resume_unsupported`) never counts as an empty run.
- The console in the main window: «Новая сессия» is disabled while it starts, says a failure in our words with the
  machine's text on its own line, and the shell's `openConsole` never rejects (`App.tsx:913-920`), so a started
  session is never reported as not started there. «Завершить сессию» is the same `SessionStop`; a session already
  ended shows «Check stop again» instead of the end act.
- `peopleAskRun.ts`: one pass at a time (`busy`), no new pass while quitting, and every caught read or write failure
  is logged through `deps.log`.
