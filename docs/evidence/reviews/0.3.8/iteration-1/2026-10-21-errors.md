Judged on the brief's questions:

- **16 sessions per project:** a reasonable bound (ER-6 for what it does not change); 16 x 4 projects reaches the 64 ceiling, and the binding's hub ingress guard (`BINDING_INGRESS_FACTOR = 10`) counts hub calls, not session traffic, so it is not tightened by the rise.
- **Typed refusals at warn with `error_code`:** correct for the trace contract. `trace_outcome` stays `threw`, `TOOL_OUTCOMES` is unchanged, no reader in the tree keys on `trace_outcome` or on the coarse outcome of `tool.*` (`git grep trace_outcome` finds only the writer). The code cannot be injected: it is read only from Fabric's own `refusal()` and board `reply` answers, a product's error is replaced with the fixed `product-error` inside the envelope's `output` (not top-level `error`, so it reads `null`), and `fromObject` admits only `^[a-z][a-z0-9_-]{1,63}$`; `JSON.parse` is guarded and the probe found no throw. ER-2 is about which codes should count as `ok`.
- **The 3 GB disk line:** honest in its words (it reports and does not diagnose); ER-3 to ER-5 for coverage, persistence and units.
- **The renumbering:** consistent apart from ER-1 and ER-8.

Checked and found sound (no finding):
- `statfsSync` sits only on the failure path (`explainAndQuit`, after `app.whenReady`, so `getPath('userData')` is valid), is wrapped in `try` with a `null` fallback the dialog treats as "no disk line", and a call that throws (or Windows, where Node implements `statfs` through `GetDiskFreeSpace`) cannot stop the dialog.
- `startupDialog`'s new `{free}` interpolation replaces only known keys and leaves an unknown `{x}` as written; the main-process `say` passes the vars through to `translator`.
- `dockerSocketFrom`: the optional `npipe:` prefix still matches the CLI's `npipe:////./pipe/…` from its first character, the unix forms are tried first, the name stops at `:` and trailing dots are stripped; a percent-encoded `%2F%2F.%2Fpipe` earlier in Docker's message does not match, and the decoded form that follows it does.
- `refuse()` bodies (`{"error": "<reason>"}` on 4xx) carry no `result`, so `typedRefusalCode` is `null` and they stay `refused`.
