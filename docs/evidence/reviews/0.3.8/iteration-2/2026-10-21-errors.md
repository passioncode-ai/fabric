## Judged on the brief's questions

- **The per-project cap (8, the 16 withdrawn):** consistent. `sessionEnroll.ts:69` is `MAX_ENROLLED_PER_BINDING = 8`, the file is unchanged against `v0.3.7`, and no living document still says 16 (`grep` over CHANGELOG, AGENTS, the backlog, the carry-over, ADR-0134, the scenarios and `src`). DA-1's measurement (the evictions were on 0.3.6) is the right reason to keep 8.
- **Typed refusals at warn with `error_code`:** right for the trace contract: `trace_outcome` stays `threw`, the code is read only from Fabric's own answers and admitted by a strict pattern, and failures named by the hub stay errors. ER-6 for the board's code.
- **The 202 / `undefined` distinction:** holds. Only a response with no bytes is `undefined` and only a 202 of that kind is `returned`; a 202 with bytes is `unknown`, a 200 with no bytes stays `unknown` (`toolTrace.ts:154-156`, `toolOutcome.ts:44-48`).
- **The backoff:** it does not starve a recovery that `fabric_whoami` reaches: whoami wakes it and resets the count (probe (a)); Fabric quitting or restarting changes the kind and resets it too. ER-4 and ER-5 for what it misses and how long a person's fix waits.
- **The disk line and `statfs`:** read once per failure before the dialog loop, guarded with a `null` fallback, carried into the log and the copied details. ER-3 and ER-9.
- **Renumbering wave 4 to 0.3.9:** outside this level; `check-plan-ids.mjs` and `check-docs.sh` exit 0.
