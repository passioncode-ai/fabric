### PL-1

**Claim.** CHANGELOG Unreleased, first bullet: «two runs that left the request unsettled go to the operator in «На
проверке»». On board thread `b3e60686` Fabric told fabric-agent-adapter (message `203d545b`, 2026-11-04 21:26Z):
«Fabric показывает оператору в «На проверке» любой запрос с его workflow, чей срок прошёл … и закрывает workflow
blocked», then (`84b048ad`, 22:02Z) «в main Fabric f0dd20d6 … неулаженный accepted или in_progress без держателя после
срока идёт оператору». `b1ccb1be` (20:33Z) adds: on «На проверке» or deadline Fabric takes the workflow back and writes
the last checkpoint with close and status blocked.

**Code.** `decideDispatch` returns `{ path: 'to-operator' }` (`apps/desktop/src/shared/boardDispatch.ts`, past the
deadline for accepted/in_progress with no holder, and at `EMPTY_RUNS_TO_OPERATOR`). Its only consumer is
`boardDispatchRun.ts#createBoardDispatch`, `said()`, which writes one `board.dispatch.decided` line to the operations
log; then `if (decision.path !== 'launch') continue`. `grep -rn "to-operator" apps/desktop/src` outside tests prints
only `boardDispatch.ts`. No `close: true` or `status: 'blocked'` checkpoint is written anywhere in
`boardDispatch*.ts`. The file comment relies on the sweep: «the sweep of abandoned work already shows such a request
to the operator», but `shared/abandonedSweep.ts#findAbandoned` emits `request-unmoved` only for `r.state === 'queued'`
(«Only a queued request stands still: a claimed or accepted one is being worked»). A run that claimed or accepted the
request and ended, which is exactly the two-empty-runs and past-deadline case, leaves it `claimed`, `accepted` or
`in_progress`, so nothing reaches «На проверке».

Also narrower than the code: the CHANGELOG says a request is dispatched «in a project with no live session»; the
decision dispatches after the 2-minute grace even with a live session (`if (input.liveSession && waited < GRACE_MS)`
only), as spec §3.2 intends. A person with an open session in that project can get a second agent started there.

**Disposition.** Build the operator item for `to-operator` (a review row the sweep or the board shows, any state) and
close the workflow `blocked` as promised, with a test that fails on today's code; or correct the CHANGELOG and post a
dated correction on `b3e60686` with a row. Say in the CHANGELOG that a live session that does not take the request
within two minutes does not stop a run.
