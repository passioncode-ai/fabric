### UX-1

**What.** CHANGELOG `## Unreleased`: "Agent access opens as a full page." The page mode adds the class `ceo-page` (`AgentAccessPanel.tsx`, `className={page ? 'ceo-panel ceo-page' : 'ceo-panel'}`) and `rail.css` gives it its page shape:

```css
.fab-place>.shell>.ceo-panel.ceo-page{flex:1;width:auto;max-width:960px;border-left:0;box-shadow:none}
```

But App renders the page inside `main.content`, not as a child of `.shell`: `App.tsx` `<div className=... 'shell'>` (the `shell` div before Settings), then `<main className="content" hidden={showSettings}>`, then `{active.kind === 'access' && (<AgentAccessPanel page … />)}`. The DOM is `.fab-place > .shell > main.content > aside.ceo-panel.ceo-page`, so the selector requires a parent it does not have. The base rule wins: `styles.css` `.ceo-panel { width: 22rem; max-width: 40vw; flex: none; border-left: 1px solid var(--app-line); … }`.

**Evidence.** Probe 4: `override selector matches: false`, `computed width: 352px`. The person who opens «Доступ агентов» from the rail gets a 352 px column with a left rule at the left of an otherwise empty page, the side panel's look, not the page the CHANGELOG and `docs/ux/2026-10-26-simple-fabric.md` §1 amendment ("a full page, no longer a panel") promise. No test renders the place (grep for `ceo-page` finds only the component and the CSS).

**Fix.** Make the selector match the real nesting, `.fab-place>.shell>.content>.ceo-panel.ceo-page` (or simply `.ceo-panel.ceo-page`), and drop `border-left` there; add a browser or jsdom check that the access place is wider than 22rem. While there: the page is an `<aside>` (complementary landmark) as the whole content of `main`; in page mode a `<section aria-labelledby>` reads better.

### UX-2

**What.** Agent access left Settings (`SettingsScreen.tsx`, the `settings-access-title` section removed), but the words that tell the person where to revoke, connect or clear a denial still name Settings:

- `en.ts` `access.enroll.revoke`, `access.respond.revoke`, `access.allowedConnect`, `access.lasts`, `access.denyStands`, `access.queue.allowedNotConnected` ("… under Agent access in settings", "open Agent access in settings")
- `ru.ts` the same six keys («…в «Настройки → Доступ агентов»», «…в «Настройки → Доступ агентов → Отклонённые запросы»»)

They are used by `main/consentPresenter.ts` (the native consent prompt), `shared/accessWords.ts`, `launch/ObligationActs.tsx` (the queue) and `AgentAccessPanel.tsx` (the Agent access page itself, which now tells the person to go to Settings to find the page they are on). Agent-facing refusals in main also say "Settings → Agent access" (`main/hubCall.ts` 236, 238, 454; `main/agentSurface.ts` 931; `main/pty.ts` 541; `main/taskRetry.ts` 73), which agents relay to the operator.

**Why blocking.** These are instructions the person acts on at a consent decision, about how to revoke access. In 0.3.15 they were true; following them now leads to a Settings screen without the place. It is a shipped claim made false by this change.

**Fix.** Reword to the rail place: en "unless you revoke it in Agent access, in the left column" (or just "in Agent access"); ru «…если вы не отзовёте его в «Доступе агентов» в левой колонке». Run them through the text checker as the commit did for the new strings, and update the agent-facing texts in main the same way.

### UX-3

**What.** The rail's foot links take their name from the word only: `LaunchShell.tsx` `<a … aria-labelledby={\`rail-name-${place}\`}>`, and the count is a sibling `<span className="rail-c" aria-label={t('rail.commsUnread', …)}>`. `aria-labelledby` replaces name-from-content, so the count's `aria-label` never reaches the link's name; a `span` with `aria-label` and no role is not announced on its own either.

**Evidence.** Probe 3: the rail link computes to `"Comms"`; the 0.3.15 Settings button (`settings.more.comms` with its `lp-pill` count) computed to `"What projects tell each other New messages: 4"`. The tooltip is `title={t('rail.comms')}`, also without the count. `Rail.test.tsx` checks only `textContent`. So a screen-reader user lost the unread count when Comms moved to the rail, which worked in 0.3.15.

**Fix.** Give the count an id and add it to the label: `aria-labelledby={\`rail-name-${place} rail-count-${place}\`}` with `<span id="rail-count-comms" …>`; or drop `aria-labelledby` for that link and let the content name it (the project rows already do that with `rail-c`). Assert the name with `getByRole('link', { name: /New messages: 4/ })`.

### UX-6

**What.** `LaunchShell.tsx`: `const title = a.projectName ?? runnerLabel(a.runner, t)`, then the small line always starts with `<span className="rail-runner">{runnerLabel(a.runner, t)}</span>`. A session in no project reads "Claude Code / Claude Code · fabric-co409 · Idle". In 0.3.15 that row said "Claude Code · Без проекта" (`rail.agentTitle` with `launch.home.agents.noProject`). The Agents screen does it right (`AgentsScreen.tsx#agentSubline` returns «Без проекта» there) and the agent page guards with `name !== runnerLabel(agent.agent, t)`.

**Fix.** When `projectName` is null, put `t('launch.home.agents.noProject')` in the small line instead of the runner.

### UX-7

**What.** `SwitchboardSessions.tsx`: `<span>{r.agent}</span>`, where `r.agent` is a catalog id (`shared/vendor/dashboardsSessions.ts` sets `agent: s.provider === 'codex' ? 'codex' : 'claude-code'`); every other screen prints `runnerLabel(...)` ("Claude Code"). `agentsPlace.switchboard.partial` is filled with `read.unread.map((u) => u.source)`, i.e. the words `sessions` / `recovery` (`shared/switchboardSessions.ts`), and the test pins that (`SwitchboardSessions.test.tsx`: `replace('{sources}', 'recovery')`). After a successful read, a later failed read sets `problem` and keeps `read`, so the panel says "Switchboard's sessions could not be read." above the earlier rows without saying they are the last reading.

**Fix.** `runnerLabel(r.agent, t)`; map the two sources to words ("the session list", "the limit stops"); when `problem && read`, say the rows are from the last reading (the pattern of `rail.agents.stale`).

### UX-8

**What.** (a) `TaskPage.tsx`: `who: detail.lease.owner_session === task.session_id ? agentName : detail.lease.owner_session.slice(0, 8)`. A task held by a different session (a hand-over, a second agent) still shows 8 hex characters although the shell knows that session's runner and project (`sessions`, the home reading). (b) `ProjectStar.tsx` toggles through `window.fabric.favourites.toggle` and keeps its own `pins`; the rail's pins are re-read only when `active` changes (`App.tsx`, the rail-wiring effect with deps `[active, isMainWindow]`). With the star now on the project page, pinning leaves the rail row of the same, highlighted project without its star until the person goes elsewhere. (The same staleness existed with the home's star in 0.3.15, so this is not a regression, but it is now side by side.)

**Fix.** (a) Name the holder from the sessions list when it is known, else «другая сессия» with the id on hover. (b) Pass an `onPins` callback from App to `ProjectStar` and set the shell's pins from its result.

### UX-9

**What.** `LaunchShell.tsx` resize separator: `role="separator" aria-valuemin={180} aria-valuemax={420} aria-valuenow={railWidth}`, no `aria-valuetext`, so VoiceOver reads "216"; only ArrowLeft/ArrowRight are handled (APG's window splitter also uses Home/End). `startResize` adds `pointermove` / `pointerup` on `window` without `setPointerCapture` or a `pointercancel` handler, so a cancelled pointer leaves the move listener in place until the next pointerup.

**Fix.** `aria-valuetext={\`${railWidth} px\`}` (or a localized string), Home/End to the bounds, `e.currentTarget.setPointerCapture(e.pointerId)` and remove the listeners on `pointercancel` too.
