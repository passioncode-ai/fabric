### PL-1

**What.** Three living texts promise behaviour the code does not have:

- `CHANGELOG.md:85-86` (`## Unreleased`, «Fabric starts Docker when it is not running»): «It never changes the docker
  context itself».
- `AGENTS.md:169` (Lifecycle, the local stack row): «it never changes the docker context (`src/main/dockerLaunch.ts`…)».
- `docs/ux/scenarios.md:4022` (SCN-161 amendment, CO-294): «Fabric never changes the machine's docker context.»

`apps/desktop/src/main/dockerLaunch.ts` starts Colima with `args: profile === 'default' ? ['start'] : ['start',
'--profile', profile]` and never passes `--activate=false`. CO-508 (`carryover.md:523`) records that `colima start`
activates its own context by default, so «it never changes the docker context» (CO-294) is false on a Mac that uses
another context, and says «pass `--activate=false` or say so». Neither happened. Ruling the code defect to CO-508 does
not make the release notes true: the CHANGELOG section is what the person reads, and it ships as written.

**Proposed disposition.** Fixed before the tag, either way: add `--activate=false` to both Colima arguments in
`dockerAppToStart` with a test in `test/docker-launch.test.mjs` that is watched failing without it (then CO-508 keeps
only the `app.started` half), or reword the three texts to say that starting Colima makes Colima's context current, and
leave CO-508 as is. The first keeps the promise CO-294 made to fabric-workspace on 2026-10-27; it is a two-argument change.
