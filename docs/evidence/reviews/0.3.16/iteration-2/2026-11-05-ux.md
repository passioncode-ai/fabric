### UX-1

The new switch in Settings → «Запуск агентов» is on by default (`shared/appSettings.ts:167`, `raw.dispatchBoardRequests !== false`). Its help is the only text a person reads about it:

- ru `settings.dispatchHelp` (`i18n/ru.ts:297`): «… Агент делает работу, отвечает в треде и завершается. Перед шагами с продакшеном он останавливается.»
- en `settings.dispatchHelp` (`i18n/en.ts:980`): "… It stops before any step that touches production."

What the code does: the stop is one line of advice in the workflow's constraints, `'Stop before any step that touches production and hand it to a session the person is in or to the operator.'` (`main/boardDispatchRun.ts:133`), and the run is started with every permission: `switchboard --json dispatch … '--permissions', 'all'` (`main/boardDispatchWiring.ts`, `launch`, beside `defaultProvider` at line 108). Nothing checks or enforces the stop; the same release's CHANGELOG board-rule bullet itself calls it the board rule a session "gets". So the help states as a property of Fabric what is an instruction to a model running with all permissions. This is the same class as iteration 1's ER-5/DO-2 (help text promising a behaviour the code did not have), and here it is consent text for a default-on switch that starts unattended agents.

Proposed fix: say what Fabric does, not what the agent will do, for example ru «Fabric поручает ему остановиться перед шагами с продакшеном и передать их вам; агент запускается со всеми разрешениями, поэтому это поручение, а не запрет.» and the same in en; check both with the text checker. Alternatively launch with the machine's own permission choice (`agentPermissions`) and say so.

### UX-2

`defaultProvider()` (`main/boardDispatchWiring.ts:108`) returns null when the `switchboard` binary is not found, when `agents status` names no default ("Auto"), or when the default is any agent other than `claude-code` or `codex`. The dispatcher then records `deferred-no-agent` in the operations log and moves on every minute (`main/boardDispatchRun.ts:305`), forever, with no surface: nothing in the renderer reads dispatch state (`grep -rn "deferred-no-agent\|board-dispatches" apps/desktop/src/renderer` prints nothing). With the switch on by default, Settings tells the person «Fabric запускает агента по умолчанию в папке проекта» while on such a machine it starts nothing and never says why; a request just waits out its seven days.

Proposed fix: beside the switch, say when it cannot act, from the same `switchboard --json agents status` read Settings already runs for the catalogue (`main/agentCatalogRead.ts`): «Switchboard не найден» or «В Switchboard не выбран агент по умолчанию (нужен Claude Code или Codex)»; or show a request held for that reason in «На проверке» after its two minutes.

### UX-3

The CHANGELOG says the left column, Агенты, the agent's page and the task card now name an agent by its project first. The page heading does (`AgentPage.tsx`, `<h3 id="agent-page-title">{name}</h3>` with `name` = `agentTitle`, the project), but the top bar of the same screen still reads «{runner} · {project}» (`App.tsx:997`, `t('rail.agentTitle', …)`), as do the rail row's tooltip and the console button's accessible name (`LaunchShell.tsx:357`, `name` used in `title={name}` and `rail.agents.openSession`). A person sees «Claude Code · AdOps» above and «AdOps» below on one screen; a screen reader hears the old form when it reaches the row's console button.

Proposed fix: build the top-bar title and the row's tooltip from the same `title` the row shows (project first, runner after), or update the parity comment above `placeTitle` if the old form is kept on purpose.

### UX-4

CHANGELOG `## Unreleased`: "the task page's agent card name it the same way … the project first, then what runs it and its folder". The card renders the project and the runner only (`TaskPage.tsx:207`, `agentName = projectDisplayName(project)`; `TaskPage.tsx:254`, `<p className="lp-meta">{agentLabel}</p>`); no folder is read or shown. Also, a task no agent ever ran (no `session_id`, no `option_id`) now shows the project's name as the card's heading with «Агент» under it, where 0.3.15 said only «Агент»: the card reads as if the project were an agent at work on it.

Proposed fix: either show the folder (the run's session folder, when known) or narrow the CHANGELOG sentence to what the card shows; for a task with no session keep a neutral heading (for example «Агент не назначен»).

### UX-5

`rail.resizeValue` is «Ширина {px} пикселей» (`i18n/ru.ts:2904`), one fixed plural form, read aloud as the separator's `aria-valuetext`. The probe shows the arrow keys alone reach 184, 232, 264, 344 and 392, all of which need «пикселя» («Ширина 232 пикселей» is wrong Russian), and a drag reaches any integer, so 181, 201, 221 … need «пиксель». The registry already has plural keys (`launch.home.inWork.agentsIdle.one/.few/.many`, `pluralForm` exported from `i18n/index.tsx:10`).

Proposed fix: three keys `rail.resizeValue.one/.few/.many` chosen with `pluralForm`, for example «Ширина: {px} пиксель / пикселя / пикселей», and a case in `plural.test.ts`.

### UX-6

`.rail-resize` is 6 px wide at `right:-3px` (`rail.css:29`) inside `.rail`, which has `overflow:hidden` (`rail.css:9`), so the outer 3 px are clipped: the handle a person can hover and grab is 3 px wide, and its hover shade is the same colour as the rail's 1 px border (`--app-line`). The keyboard path works (arrows, Home, End), but a pointer user has only the drag; WCAG 2.2 asks for a single-pointer alternative to a drag (2.5.7) and a larger target (2.5.8).

Proposed fix: place the handle inside the rail (`right:0; width:8px`) or lift the clip for it, and either add a single-pointer way to change the width (for example «Шире» and «Уже» buttons that appear on the handle's hover or focus) or record in the register that the keyboard path is the accepted alternative.

### UX-7

The column is now 180 to 420 px (`LaunchShell.tsx#RAIL_MAX`), but every page breakpoint is still on the viewport, tuned for 216 px: the agent page switches to one column only below a 1000 px window (`AgentPage.tsx:131`, `useMediaQuery('(max-width: 1000px)')`; `launch.css:1044`), and its wide layout keeps a fixed 300 px side column (`launch.css:958`, `.as-cols{grid-template-columns:minmax(0,1fr) 300px}`). At a 1001 px window with the column at 420 px the page gets about 580 px, so the agent's task list is left about 185 px after the side column and the gap, against about 450 px at the default width. The same holds for the 1150 px home and project grids (`launch.css:217`).

Proposed fix: make these layouts follow the page's own width (container queries on `.fab-place`, or the breakpoints offset by `--rail-w`), or cap the column lower on windows under, say, 1200 px.
