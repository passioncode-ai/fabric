### DA-1

Evidence. The privacy gate's rules do not see quoted Russian speech, so they pass these lines; `git grep -F` finds each phrase absent at `v0.3.15` and present at `HEAD`. The operator's own words, in quotation marks, attributed to the operator with a date:

- Source and tests (comments): `apps/desktop/src/renderer/src/launch/LaunchShell.tsx:140`, `apps/desktop/src/shared/appRoute.ts:86`, `apps/desktop/src/shared/types.ts:480`, `apps/desktop/src/main/accessService.ts:465`, `apps/desktop/test/session-enroll-request.test.mjs:362`.
- Docs: `docs/evidence/specs/2026-08-16-software-fabric-carryover.md:500`, `:502`, `:507`, `:509`, `:510`, `:511` (CO-485, CO-487, CO-492, CO-494, CO-495, CO-496; the last one a statement made in another business's project session and relayed to the board), `docs/reports/2026-11-03-board-delivery-and-delegation/README.md:21`, `:23`, `docs/adr/0188-fabric-reads-its-own-logs-observatory-keeps-what-every-agent-learned.md:6`, `docs/adr/README.md:147`, `:148`, `docs/evidence/plans/2026-10-27-release-1105-plan.md:78`, `docs/evidence/specs/2026-11-04-on-demand-sessions.md:60`, `docs/reports/map.html:210`, `:211`, and a short fragment in the published review report `docs/evidence/reviews/0.3.16/iteration-1/2026-11-05-plan.md:134`.

ADR-0096 decision 5: "From here on, operator statements are recorded as paraphrases. A brief records what was asked and how it was read; it does not quote the person who asked." The ledger row V1-35 (`docs/evidence/plans/2026-11-05-release-0316-verification.md`) and `docs/evidence/reviews/0.3.16/iteration-1/data.json` (DA-1, `fixed`) say "the operator's words paraphrased (ADR-0096 §5)". The on-demand spec's header was paraphrased; these were not. The repository is public and the candidate is pushed (`origin/feat/nav-wave1`).

Why blocking: the release gate records a privacy fix that did not happen, on data ADR-0096 classes as private, in a public repository (the two criteria "a leaked private datum" and "a shipped claim made false").

Proposed fix: replace each quoted statement with a neutral English paraphrase of the request (ADR-0096 decision 2), keeping the date, the session or thread id and the row id; UI strings the product shows («…» labels) stay. Add a check to the release gate for added lines that attribute a quoted Cyrillic sentence to the operator (for example `operator[^«]{0,200}«` with three or more Cyrillic words), since `check_private.py` cannot see it. The history question for the earlier commits stays the operator's (ADR-0096).

### DA-2

Evidence. `main/boardDispatchRun.ts:327` keeps "the newest 500 records" by position: `records = records.slice(-500)`. Everything the dispatcher knows about a request lives in those records: `emptyRuns` comes from the request's last record (`:283`, `emptyRuns: last?.emptyRuns ?? 0`), `toOperator()` is `records.filter((r) => r.outcome === 'to-operator')` (`:340`), and the sweep shows that set in «На проверке» (`shared/abandonedSweep.ts#findAbandoned`, `SweepRequest.toOperator`). Each refused start pushes a new record (`:320-324`, a new `dispatchId` per try after `REFUSAL_BACKOFF_MS`), up to 20 per project a day (DA-3), and a board request lives 7 days (`boardDispatchWiring.ts`, `WINDOW_MS`). So 500 records cover about 25 project-days of refusals: four projects whose starts Switchboard keeps refusing (for example `not_in_group` for projects outside a Switchboard group, or a group's ceiling) evict a request's records inside its 7-day life.

Probe `dispatch-evict.mts` with the real `createBoardDispatch`: A goes to the operator after two empty runs (`A sent to the operator: true`, `runs for A 2`); with 30 refusing projects, A's records are evicted at +171 min and A is dispatched again (`records before: 501, A records: 1`), twice per cycle, at +171, +172, +341, +342, +511 min …, 20 runs in 26 h. Between evictions `toOperator()` loses A, so it also leaves «На проверке» until two more empty runs put it back.

Contradicts `CHANGELOG.md` `## Unreleased`: "after two runs that left the request unsettled it starts no more, closes the request's workflow and shows the request in «На проверке»", and spec §3.6.

Why blocking: a shipped claim is false under a reachable condition, and the result is unbounded agent runs (each with every permission) on a request the operator holds.

Proposed fix: keep one record per request (attempts, last refusal time, `emptyRuns`, `outcome`) instead of one per try, or evict only records that are ended and whose request is settled or past its deadline, never a non-ended or `to-operator` record of a request still on the board; add a multi-project eviction test to `test/board-dispatch-run.test.mjs`.

### DA-3

Evidence. `dispatchesToday` is `records.filter((r) => r.projectId === req.target && now - r.startedAt < DAY_MS).length` (`boardDispatchRun.ts:282`), refused records included. Probe `dispatch-refused-cap.mts`: 20 refusals in 3 h 20 min, then `skip: skipped-daily-cap`, so when the refusal clears (a ceiling raised, the project put in a group) the project gets no run until 24 h after the first refusal. The CHANGELOG says "20 per project a day" of runs; `shared/boardDispatch.ts` `DispatchLimits.maxPerProjectPerDay` says "per UTC day"; the code is a rolling 24 h.

Proposed fix: count only records that reached `running` (a `launchId`) toward the daily cap; align the comment (rolling 24 h) or the code (UTC day).

### DA-4

Evidence. `boardDispatchWiring.ts` `load()`: `JSON.parse(readFileSync(o.file, 'utf8')) as DispatchRecord[]`, and any throw answers `[]` ("a torn one: nothing was started that this process can watch"). The write is a `.tmp` and a rename with no `fsync`, so a power loss can leave an empty file; that file reads as `[]`, so a run in flight is forgotten (a second run can start for its request) and a request sent to the operator is dispatched again (as DA-2). A file that parses to a non-array (`null`, `{}`) is accepted as records, and `records.some(...)` in `pass()` throws every minute (`board.dispatch.pass failed`) until the file is removed by hand.

Proposed fix: validate the parsed value (an array of records with the known fields, unknown ones dropped), keep the last good file as `.bak` and read it when the main one fails, log a `board.dispatch.load failed` once when either is unreadable, and `fsync` the temporary file before the rename.

### DA-5

Evidence. `noteOf` (`boardDispatchRun.ts:83-85`) matches a path only up to whitespace. Probe `noteof.mts`: a folder `/Users/example/DATA/My Project/app` leaves `Project/app`, `Application Support/x.json` leaves `Support/x.json`. The notes that reach it in this flow are Observatory refusals (`observatory_resolve` is called with the project folder as `id`, `boardDispatchRun.ts:214`, and a refusal body is quoted into the error, `observatoryMemory.ts:82`) and `defaultProvider` failures. The operations log stays on the machine; iteration 1's DA-7 asked for no paths.

Proposed fix: log a fixed code and the tool name (`observatory-refused`, `switchboard-failed`) instead of the message, as iteration 1 proposed.
