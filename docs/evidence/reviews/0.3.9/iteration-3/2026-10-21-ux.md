| UX-1 | No | When Docker is not running, the person is no longer told to start it. In 0.3.8 a start that met Docker away ended in the dialog whose remedy said «запустите Docker Desktop или OrbStack и повторите» (Linux: «запустите Docker Engine (sudo systemctl start docker)»). In 0.3.9 that cause heals by waiting, so it never reaches the dialog; the wait window says only «Docker … пока не отвечает. Fabric продолжает пробовать и откроется сам, как только Docker ответит», and the running notice says «Fabric поднимает её снова». Neither can bring Docker up: a Docker Engine not enabled at boot, or an OrbStack the person quit, is waited for indefinitely with words that suggest Fabric is handling it. Not a false sentence and not a broken flow (Fabric opens as soon as Docker is started), so not blocking; but the actionable step 0.3.8 gave is gone. | `apps/desktop/src/shared/stackWatch.ts:73` (`startupHeals`: Docker unreachable or "Docker did not answer within" heals); `apps/desktop/src/main/index.ts:5405`; `i18n/en.ts:983-985`, `:993-995`; `i18n/ru.ts:329-331`, `:339-341`; contrast `en.ts:1032-1034`, `ru.ts:387-389` (0.3.8 remedies, now unreachable for this cause) | Add one clause per OS to `startup.wait.docker*` and `stack.health.docker*`: "If Docker is not running, start it (OrbStack or Docker Desktop / Docker Desktop / `sudo systemctl start docker`)", in en and ru |
