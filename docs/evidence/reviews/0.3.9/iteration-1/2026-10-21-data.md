## What holds

- The migration applies to the live shape: constraint name, no name collisions, the applied list is the repository's prefix, the widened check admits every row, and each replaced body differs from the live one only by the intended lines.
- Grants and RLS: `board_cursor_keys` has RLS on and every API role's rights revoked; helpers are nobody's, doors are `service_role`'s only (`run-function-privileges-db`, core-holds case 16).
- Event type `comms.read_acked_many@1` has its `event_types` row (migration line 41) and both feed sentences (`en.ts:25`, `ru.ts:34`); `answer` reuses `comms.request_transitioned@1`, whose projector (`apply_comms_requests`) applies any `to`, and `board_cancel` already takes `answered` to `cancelled`.
- The cursor key is one row per estate, written only by `board_cursor_key`, listed in `NOT_MIRRORED` and `TABLE_SCOPE`; a failed read falls back to the run's key and is logged once.
- The runtime-id rename is in memory only (`EnrolledSessions.renameRuntime`, the surface's `live` map); journal readers join turns by Fabric `session_id`, so the unchanged `session.enrolled@1` payload misleads nothing.
- An outage stays visible: `stack.lost`/`stack.back` are written once per change and never sampled, the stack-refusal 503 is decided before `beginAttempt` (no per-call noise), and the 60 s `cycle.ran@1` receipts that measure availability are untouched.
