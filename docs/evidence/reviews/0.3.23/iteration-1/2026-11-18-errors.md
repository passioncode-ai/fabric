## Checked and sound

- The hub moved to `board.ts#startBoardHub` as it stood: a normalized diff against v0.3.22 `index.ts:1174-1515` shows only the named ports, the slots and the hand-backs; `registry.watch()` and `agentCall.flush()` are still stopped at quit, the standby is still released after `startHub`, and the hub is still withdrawn at quit.
- The cycle moved to `boardCycle.ts#startBoardCycle` as it stood: `runCyclePasses` with per-step `failed`, `tickBoard`'s own try (`boardService.ts:841-854`), the sweep, digest tick and receipt each in their try; the dispatcher's and people-ask intervals are cleared at quit (and now `unref`), the dispatcher and Observatory children closed at quit, and the 60 s ticker cleared at quit (`board-cycle.test.mjs`).
- `localStore.ts`: a store read before the entry names the folder throws `LocalStoreDirUnset` by name; the window names it at module scope (`index.ts:452`) after its imports and before any read, and no imported module reads a store at import (`settings.ts:31` only creates it).
- `hubPorts.ts#handlerFor` keeps the empty-path-is-no-handler rule; `productConnect.ts#handlerOf` still catches and records a failed read.
- The Switchboard control timeout: the matched sentence is Switchboard's own (`control.rs:508`, v0.7.117); the start stays `starting`, is asked again with the same workflow and ends `failed-to-start` after `START_ATTEMPTS`; only the fixed sentence is logged.
- `LIVE_SESSION_TAKE_MS`: a request the live session claimed or accepted is not a candidate (`boardDispatch.ts#candidate`), so only an untaken request goes to a run after 12 minutes; a left task stays with the live session.
- People-ask re-ask: bounded to `ASK_ATTEMPTS` (2) per item and revision; an answer the pass could not judge keeps its request open (`pending`); a failed thread read leaves no request state, so nothing is closed on it; the second ask has its own idempotency key; the withdrawn line has its own key and its failure is logged.
- `boardMain.ts`: the quit runs each stop once in its own try, has an unref'd deadline (exit 3) and a second signal forces exit; the presenter without a window never throws; `openWithSystem` opens only http(s), with no shell, and rejects on spawn error or a non-zero exit; database calls carry `fetchWithDeadline`; the ops log is written synchronously (`ops.ts` `appendFileSync`), so the failed-start line survives `process.exit`.
- Login item re-registration: inside `applyLoginItem`'s try, `launchctl print` has a 3 s deadline and no shell, a job that names no version is left alone, the outcome is read back and logged `ok` or `unknown`; a re-register that throws after the unregister is recorded and the next start registers the job again.
- «Новая сессия»: a launch check that cannot be read is shown (`checkLaunch` answers `unread`), never a silent start.
- Stack disk hold: the hub's refusal and the renderer name the `disk` hold (`shared/stackWatch.ts` `hubRefusalFor`, `StackHealthNotice.tsx`); an external stack is never stopped (`stopForDisk: local ? ... : null`, `index.ts:5520`).
