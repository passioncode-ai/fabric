## New findings

All non-blocking. No blocking defect found in the iteration-1 fixes or the wider diff at this level.

- ER-8 (non-blocking): `BoardQuit.release` (failed-start cleanup, added for ER-7) has no deadline. A shutdown that never settles keeps `board-main` alive after a failed start instead of exiting 1. `quit()` has an unref'd deadline; `release()` does not (`main/boardMain.ts`). Nothing starts board-main in 0.3.23. Fix: race the shutdown against `deadlineMs` and log `board.quit-deadline`.
- ER-9 (non-blocking): `hasAnswerBlock` treats any untagged fenced block (a stack trace in a PM progress note) as an answer attempt, so the note gets the «не применено» refusal posted in the thread. Bounded by ASK_ATTEMPTS and one refusal per message. Fix: count an untagged fence only when it parses as a JSON object or names the schema (`shared/peopleAsk.ts`, `main/peopleAskRun.ts`).
- ER-10 (non-blocking): the launch-time disk refusal also fires when the stack is already up healthy and the disk is under 1 GB; the splash waits and says «It is started once space is freed», which is untrue then (`main/env.ts#startStackOnce`, `shared/stackWatch.ts#startRefusedForDisk`). Fix: reword, or skip the refusal when the stack already answers and let the watch stop it.

Considered and found sound: stale-server retry (one retry on a fresh child, a concurrent stale call shares `connecting`, a broken child is dropped); capacity state machine (free/held/unread transitions logged once); disk-stop success path publishes the stopped state at once and a failed stop does not set `diskStopped`; `said(req.id, ...)` on the capacity wait keeps the request decided once per pass.
