## Not findings

- **`overflow:clip` support.** Chromium has supported it since 90; Electron 44 ships a far newer Chromium, and headless Chrome 155 reports `CSS.supports('overflow','clip')` true with `.fab-place` computing to `clip` (probe E). No element relies on `.fab-place` scrolling: the only `position:sticky` left in the renderer is `.st-foot` (`start/start.css:68`), whose scroller is `main.content` (shipped `scan` cases pass); `.fabric-launcher` (the only `position:fixed` rule) is rendered by no component.
- **Fixes that do fail without themselves.** V1-1 (plants p3, p4), V1-3 (p2, p5) and V1-4 (L1) are each caught; the effect's key (L2) and its dependency (L3) are caught by `Rail.test.tsx`.
- **The scroll key does not reset when it should not, apart from ER-6.** It is a string of the route kind, the project id and `workspaceFor` (`App.tsx:773`, `928`): typing, a project-list refresh (`projects` is not in it) and opening a side panel (only `.shell`'s class changes) leave it equal, so the effect does not run. Clicking the current place again keeps the position (asserted by `Rail.test.tsx`). Releases opened from the plan differ from the plan's key; a different release requires leaving the releases place.
- **`revealSection`.** Its align loop walks to the nearest `overflow-y:auto|scroll` ancestor with content to scroll (`LaunchShell.tsx:38` to `48`), which is the page's `main`; when the page is still short it falls back to `scrollIntoView`, which can no longer scroll `.fab-place` (clip). It re-aligns for 1500 ms, so the key's reset to the top after `openProject` does not leave the section out of view.
- **Settings beside a side panel.** Settings is 712 px wide beside the 22rem panel, scrolls to its last row above the act line, and the panel keeps its place (probe C).
- **Consoles and the editor.** `TerminalView` fits on a `ResizeObserver` (`TerminalView.tsx:113`), so a notice appearing or a Settings toggle refits the terminal; the shipped console cases pass with and without a notice. `EditorWindow` and `SessionWindow` in detached windows return before the shell (`App.tsx:886` to `887`) and no `rail.css` rule reaches them.
- **Onboarding.** `Onboarding.launch.css` 165 to 205 targets `.workbench` and `.app-main`, which no markup renders (`grep` of the renderer finds them only in CSS); dead, not a defect, and `launch.css:487` already records it.
- **The smaller `.content` padding** (`rail.css:68` overrides `styles.css:126`'s room "for the fixed controls in the bottom corner"): no fixed control is rendered, so no card ends up under one.
- **The act line as a flex footer instead of `position:sticky`** (plant p6): same layout in every shipped case; the change is not a regression.
- **The reset runs in `useEffect`, after paint.** A new place can show one frame at the old offset before the reset; not measured here and cosmetic, recorded only.
