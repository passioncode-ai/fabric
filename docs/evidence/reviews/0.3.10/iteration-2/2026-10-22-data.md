## Not findings

The shipped stack folder is byte-identical. The workflow and `scripts/workspace*.mjs` changes are CI and publication checks that read the receipt and Git; they are not in the bundle and write no new file.
- **The ledger's rollout is right: upgrade and rollback are the bundle alone at schema 95.** The live database is at 95 with exactly the repository's 95 migrations; 0.3.9 and 0.3.10 both admit exactly 95. Nothing persists a version: the only `app.getVersion()` in main feeds analytics (`index.ts:1130`), `APP_VERSION` reads `package.json`, and `analytics-state.json` holds no version. Going back to 0.3.9 has nothing to reverse. The rollout's premise holds today: Fabric 0.3.9 runs as pid 51906, `startedBy: person` (`lifecycle.status`), started 12:05:29 UTC, so the broker will not stop it and the person step (Cmd+Q, open again) is needed.
- **App's `placeKey` is unchanged.** Lines 773 and 774 of `App.tsx` (the `placeKey` expression and `setPlaceSince` on it) are identical to v0.3.9's; the new scroll key is a separate template string passed only as LaunchShell's `placeKey` prop (line 928), so adding the project id and the workspace does not move «new since». LaunchShell uses it only as an effect dependency that calls `scrollTo({ top: 0 })`; it is never stored, logged or sent, though it may contain a folder path (`start:<path>`).
- **The renderer sends and records nothing new.** The diff adds a `useRef`, one effect that scrolls the place and its `.shell > main` children to the top, CSS, one prop and one selector in `ProjectHome.tsx`; no IPC call, so no new `ipc.*` log line, and no analytics event (counted in main, unchanged).

The live queued request has a null deadline in its row and its event (seq 14121), its message time is 2026-10-21 23:19:41.56Z, message time + 168 h is 2026-10-28 23:19:41.56Z, matching "the first tick after 2026-10-28 23:19 UTC"; no target reply exists, so pass (a0) will not answer it first.
