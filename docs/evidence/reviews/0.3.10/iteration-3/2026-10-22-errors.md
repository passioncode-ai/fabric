| ER-1 | minor | **A plain-object failure without a message is written with its credential fields in clear.** `errorShape` turns a message-less object into JSON text BEFORE `redactPayload` runs, so the credential-field rule, which works on an object's keys, never sees it; only the shape rules run over the string, and they do not match a lowercase `"password":"..."` or `"token":"..."`. The same object passed as `detail` is redacted. A `toJSON` on the object is also called and its output written. In 0.3.9 the same input wrote «[object Object]», which leaked nothing, so this is a new path past the module's stated rule "Nothing secret reaches it". Latent: no call site in `main/` was found passing such an object today (callers pass Errors, PostgREST errors with a message, strings, or `error ?? new Error(...)`), and the new test "redacts a secret in a plain-object error too" covers only a URL password, which the shape rules catch anyway. | `shared/opsLog.ts:171` (`JSON.stringify(e)`), `shared/redact.ts:204` (key rule on objects only), `opsLog.ts:25` (header property 3), `opsLog.test.ts:83`; probe: `{ok:false,password,token}` as `error` gives message `{"ok":false,"password":"correcthorsebattery","token":"tok_abc123"}` with no redaction; as `detail` both are `[redacted: credential-field]`; a `toJSON` returning `{password:...}` is written verbatim | Redact before serialising: put the bounded object (`boundStructure({ v: e }).v`) into the payload, let `redactPayload` walk it, then stringify the redacted object into `message` (or keep it as a structured field). ## Not findings

- **The window that never scrolls breaks nothing that relied on the document scrolling.** In the main window the shell's children are Settings' `main`, `main.content` and four `aside.ceo-panel` panels (`App.tsx` 983 to 1281); there is no portal, `<dialog>`, `showModal`, `popover` or `role="dialog"` in the renderer (grep empty); the only `position:fixed` rule, `.fabric-launcher` (`launch.css:505`), is rendered by no component; no renderer code reads `window.scrollY` or `scrollingElement` (grep). The boot screen, `BootFailure`, `EditorWindow` and `SessionWindow` return before `.launch-root` exists (`App.tsx` 885 to 887), so `html:has(...)` does not match them; the startup wait window is a `data:` page without `rail.css`, and its `document.body.scrollHeight` fit is unaffected (`main/index.ts:5244`). The first run focuses each step's heading on Next (`FirstRun.tsx:35`), so a new step is brought into view in the page's scroller.
- **`position:relative` on the mains and asides moves no menu, tooltip or dropdown.** Every `position:absolute` rule has a positioned ancestor inside the page (`.lp-feed article`, `.lp-timeline article`, `.lh-spark button`, `.fp-bar`), so only the visually hidden helpers change their containing block, which is the intent. A chart tip near the page's top edge is clipped by the scroller, as it has been since 5f828e29 made `main` a scroller; that is overflow, not the new `position`.
- **V2-1's two halves each hold alone** (B1 and B2 green, B3 red): defence in depth, as V2-5 ruled for `clip`.
- **Fixes that do fail without themselves:** V2-1 (B3), V2-3 (O1), V2-4 (B4), V2-6 at the function (A1), V1-1 (P3), V1-3 (P2, P5), V1-4 (L1).
- **Print.** 40 cards print on 3 A4 pages without the rail, the top bar or the act line; with a side panel open the panel prints after the page (5 pages); with Settings open Settings prints and the hidden page does not. The app has no print command.
- **`scrollKeyOf` over every `AppRoute` variant.** `home`, `agents`, `history`, `where`, `comms`, `persona`, `help`, `quota`, `welcome` key by kind; `draft` by `id`; `project` and `guide` by `projectId` (and differ by kind); `board` by `projectId` and `item`; `plan` and `pulse` by `projectId`; `releases` by `projectId` and `release`; `start` by `path`; `console` by `sessionId`; plus `workspaceFor`. Not in the key, deliberately: `project.at` and `asOf` (moving within a project is revealed by `revealSection` and `ProjectHome`'s task effect) and `board.topic`. `null` and an absent `projectId` give the same key, as they mean the same page.
- **`errorShape` with ordinary odd inputs:** a number gives `42`, `null` gives `null`, an array its JSON, an empty message with a null code the object's JSON, a NaN code `m (NaN)`; a URL password in a message and a secret-shaped `code` are redacted; a 2 MB object took 11 ms and was capped at 600 characters after redaction. A message longer than 600 characters loses its appended code to the cap; PostgREST messages are far shorter, so this is recorded only.
- **The act line at 40 %** works where nothing else is fixed-size: 1280 x 360 with a short act line and three notices keeps it inside the window with «Отменить» visible; in a 120 or 200 px tall window the act line scrolls inside itself and focus brings «Отменить» into view.
