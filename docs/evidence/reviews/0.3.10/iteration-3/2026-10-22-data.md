## Findings

| ID | Severity | Finding | Evidence | Proposed fix |
|---|---|---|---|---|
| DA-1 | minor | **A plain-object failure without a message is written to the log with its credential-named fields in clear.** `errorShape` turns such an object into a JSON string before `redactPayload` runs, so the key-name rule `credential-field` (which only sees object keys) never applies; only the shape rules run over the string, and a lowercase `"password":"..."` or `"token":"..."` with a shape-less value matches none of them. The same object passed as `detail` is redacted. Before 0.3.10 this path wrote `[object Object]` and leaked nothing, so this is new in the release, against the module's own promise ("Nothing secret reaches it", `opsLog.ts` header) and the comment on `errorShape` ("Redaction runs after"). Reachability is narrow: no `main` site throws a plain object, PostgREST errors carry a `message` and take the other branch; the reachable sources are an unexpected non-Error thrown into one of the 88 `ops.failed(op, e)` catches (for example `index.ts:301`). The file is local and 0600. The new test covers a secret inside `message` only, not the JSON branch. | `apps/desktop/src/shared/opsLog.ts:175` (`JSON.stringify(e)`), `:144` (redaction after); `redact.ts:203-207` (key rule on object keys); scratch `sink.mjs` through `createOps`: `{"ok":false,"password":"synthetic-plainpw"}` in `operations.jsonl`, the same as `detail` `[redacted: credential-field]`; `opsLog.test.ts:83` (message case only) | Do not stringify before redaction: put `boundStructure(e)` (bounded, no getters) in the payload, let `redactPayload` and `cap` run over it, then serialize the sanitized object for `message`; add a test with a lowercase `password` field and no `message`. |
| DA-2 | minor | **`errorShape` runs the error value's own code and is unbounded, which the rest of the log refuses.** `boundStructure` never invokes getters (line 78) and `ops.test.mjs` asserts that serialization hooks are inert, but `errorShape` reads `message` and `code` through any accessor and calls `JSON.stringify`, which runs `toJSON` and every getter on the whole object. ## Not findings

- **The only changed code outside the renderer is in `shared/`, and the one piece the main process loads is `opsLog.ts#errorShape`.** `appRoute.ts#scrollKeyOf` is imported by `App.tsx` only (no match under `main` or `preload`); `opsLog.ts` is loaded by `main/ops.ts:20`. Everything else outside the renderer is CI, publication scripts, tests, the submodule pin and documents, none of which ships in the bundle or writes a new file.
- **The shape of an operations record is unchanged.** `error` is still `{ name, message }` with two strings (`OpsRecord.error`, `opsLog.ts:52`); `name` is `'Error'` for every non-Error, as before; `message` runs through `redactPayload` and then `cap` (5 000 000 chars became 627; 20 MB became 628), so a line grows by at most about 620 characters. The readers take it as before: `ops.read` parses lines and filters by level and correlation id only, `DiagnosticsSection.tsx:108` renders `name: message` as text, no script reads the file, and sampling (`sampledByDefault`) never looks at `error` and never samples a `failed` record, so retention and the week's budget are unaffected (`ops-retention.test.mjs` 6 of 6). A 0.3.9 reading lines written by 0.3.10 sees the same field types, so going back reads the log.
- **A circular or huge object cannot break a write.** Circular and BigInt-bearing objects fall back to `[object Object]`; a huge one is capped after redaction; the line written is always one JSON object. The two loss cases are DA-2's, and they drop a record rather than corrupt the file.
- **Redaction still covers the message.** A credential inside a plain object's `message` is redacted (`Authorization: Bearer ...` gave `[redacted: authorization]`; `opsLog.test.ts` url-password case passes); PEM and named credentials in `detail` stay scrubbed (`ops.test.mjs`).
- **The rollout is right: the upgrade and the rollback are the bundle alone at schema 95.** No migration (`supabase/` unchanged, 95 files, 95 applied, last `20261021000120`), `schemaContract.json` minimum and maximum 95 as in v0.3.9, no event type, feed sentence, IPC channel, preload or hub change (`git diff --quiet` over all of them, exit 0; `check-ipc-contract.mjs` exit 0), no packaging change. `release-mac.md:306` and `:375` say the same.
- **`scrollKeyOf` and LaunchShell touch no stored state.** The key is computed from the route and passed as a prop; LaunchShell uses it only as an effect dependency that calls `scrollTo({ top: 0 })` on the place and its pages. No storage, IPC, analytics or log call is added anywhere in the renderer diff. It may contain a folder path (`path` part) but it is never persisted, logged or sent.
- **The ledger's measured facts hold.** Schema 95; journal contiguous (16 719 = max seq) and 15 493 at or below seq 15493, with 15494 at 11:14:19Z one second after the broker's start; 9 of 10 requests answered, all at 11:16:18Z, the first tick at 11:15:22Z failed; the open request has a null deadline and expires at 2026-10-28 23:19:41.56Z, matching "the first tick after 2026-10-28 23:19 UTC"; `board_tick` exists, `board_request_tick` does not; three idle stops at 11:29:56Z, 11:46:33Z and 12:04:46Z (`broker.log` lines 215, 219, 223); Fabric 0.3.9 runs as pid 51906, `startedBy: person`, so the rollout's person step (quit and open) is still needed. The only number that does not hold is DA-3's.
