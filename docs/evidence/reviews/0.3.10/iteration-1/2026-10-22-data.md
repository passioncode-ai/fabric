## Not findings

- **No data surface changed.** No migration, no `migration-ledger.json` change, no schema contract change, no event type, no feed sentence, no IPC channel, no hub tool, no main-process file and no persisted file shape (settings.json, `analytics-state.json`, `installation.json`, `hub.json`, the operations log) differs from v0.3.9. The shipped stack folder (`electron-builder.yml`, `../../supabase` to `stack/supabase`) is byte-identical to 0.3.9's because `supabase/` has no diff.
- **Upgrade and rollback.** The live database is at 95 with exactly the repository's 95 migrations; 0.3.9's and 0.3.10's compiled contracts both admit exactly 95 (`schemaReadiness.ts` reads it). 0.3.10 writes no new event type or row shape, so an install at 95 upgrades by replacing the bundle only, and going back to 0.3.9 is the same swap with nothing to reverse.
- **CO-381's resolution is true.** Pass (a) of `board_tick` expires a `queued` or `claimed` request whose `coalesce(deadline, board_messages.at + board_request_default_ttl())` is past (`:484-485`); the TTL is 168 h live; the queued request was stored by 0.3.8 with a null deadline (journal seq 14121) and its target never replied, so the tick will expire it, not answer it, at 2026-10-28 23:19:41Z. `project-board-core-holds-db.test.mjs:118` holds it, and it fails when the `coalesce` is removed (planted run above). The test briefly redefines `board_request_default_ttl()` to 1.5 s inside its own disposable cluster and restores it in `finally`; it never reaches a real database.
- **The renderer sends and records nothing new.** The diff adds a `useRef`, a `useEffect` that calls `scrollTo({ top: 0 })` on the place and its `.content` children, a CSS rewrite and one prop; no IPC call, so no new `ipc.*` operations-log line, and no analytics event (analytics is counted in the main process, unchanged).
- **The scroll-to-top effect and `placeKey` touch no stored state.** `placeKey` was already computed in 0.3.9 (`App.tsx:773`, feeding `setPlaceSince`); 0.3.10 only reads it as an effect dependency in `LaunchShell`. It may carry a folder path (`start:<path>`) but is never stored, logged or sent.
- **The workspace scripts persist nothing new.** `check --allow-pending` is a read of the receipt and Git; `sync-status.json` and the launchd job's log are untouched. They are not in the bundle.
- **The candidate still says 0.3.9** (`apps/desktop/package.json` `"version"`), so a build of this SHA would report `appVersion` 0.3.9 to analytics. That is the release process: 0.3.9's reviewed candidate `8100be6b` also carried the previous version, and the bump came in the release commit `1266a7d6`. The release commit for 0.3.10 must carry it.
- **Live state is consistent with the 0.3.9 notes as corrected:** 9 requests `answered` at 2026-10-22 11:16:18Z, one `queued`, journal 16 318 events with `count = max(seq)`.
