| ER-1 | Yes | **The Docker wait that closed iteration 1's ER-4 never sees Docker come up with the wording Docker and Supabase actually print, so a login start before OrbStack or Docker Desktop is ready still ends in the failure window, now after 90 s.** `dockerSocketFrom` takes the socket path up to the first space, colon or quote. Both real refusals put punctuation right after the path: the Docker client (28.x, `docker` on this machine) says `at unix:///…/docker.sock; check if the path…`, and the Supabase CLI 2.114.0 on PATH says `Cannot connect to the Docker daemon at unix:///…/docker.sock. Is the docker daemon running?`. The parsed socket is `…docker.sock;` or `…docker.sock.`, which never exists, so every `GET /_ping` fails, `waitForDocker` runs to its 90 s `timeout`, and `startWithRetry` throws "Docker did not answer within 90 s" even when Docker answered at second 5. Measured: against a live fake engine the clean path pings `true`, both parsed paths `false`. The unit test passes only because its fixture invents a wording (`docker.sock: connect:`) that neither tool prints, and `test/docker-ping.test.mjs` tests `dockerTarget`, not the parse. The npipe branch has the same defect (its class `[A-Za-z0-9_.-]` swallows the full stop of `…/docker_engine. Is the docker daemon running?`). Iteration 1 marked ER-4 "fixed" (ledger V1-20) after the operator hit it; it is not fixed for that case. | `apps/desktop/src/shared/stackStartRetry.ts:37-42` (`/unix:\/\/(\/[^\s:'"]+)/`, npipe class), `:128-138` (the wait uses only that socket); `apps/desktop/src/main/env.ts:129`; `apps/desktop/src/shared/stackStartRetry.test.ts:6,63` (fixture wording); probes `sock.mts`, `fake.mts` above; `docker version` with a missing socket and `supabase-go` strings above | Stop the path at `;` and strip a trailing `.`/`,` (unix and npipe); better, when the named socket does not exist fall back to `DOCKER_HOST`, then the current Docker context's endpoint, then the platform default (on this Mac `/var/run/docker.sock` links to OrbStack's socket).
