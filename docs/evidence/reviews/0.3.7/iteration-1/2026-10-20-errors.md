Checked and found sound (no finding):
- `sessionHistory.ts`: the session id inside the PostgREST `.or()` string is checked against a strict UUID pattern first (`:28,49`), so the new `actor->>id` term adds no injection; История's text filter goes through `escapeLike` and is capped at 100 characters (`actIpc.ts`).
- New IPC channels (`draftsDiscard`, `draftsRestore`, `actsHistory`, `actsUndo`, `hubDisconnectAgent`, `hubLetAgentIn`) are `MAIN_ONLY`; `terminalAttestOver` is `MAIN_AND_OWN_SESSION` and checks the UUID and the session's own `outcome_unknown` receipt before acting; `actsUndo` validates a safe positive integer; `actQueryOf` bounds every field.
- `act.recorded@1` is writable only through the desktop ingress (`desktopIngress.ts`), so an agent cannot plant an inverse that a person's «Отменить» would run.
- Migration 115: both functions are `security definer`, revoked from `public, anon, authenticated` and granted to `service_role` only; they refuse a non-person actor, a running session (trusted `terminal.closed@1` or the backend's exit receipt only), and an undo once the task moved on; the hold returns on undo because `task_has_unresolved_run_at` reads `run_has_verified_stop`. The DB scenario passed twice.
- `fabric.project.resolve` never returns a remote URL: the contract's `recordOrigin` strips credentials, and the answer carries only project ids, a root path or a reason; a failure is a typed `hub-unavailable` with the cause in `ops` only.
- Codex consoles: the bearer travels only in an environment variable with a random name; argv carries the endpoint and the fixed preamble (`sessionBundle.ts`); Codex is still `containment: none`, so running in the operator's `CODEX_HOME` does not make the policy believe a gate exists.

- `claudeTrust.ts` never creates or overwrites a file it could not read, re-reads under Claude's lock, and writes through a same-mode temporary file and rename.
