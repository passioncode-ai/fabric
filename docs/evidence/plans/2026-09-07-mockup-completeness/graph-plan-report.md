# Fabric — editable graph plan fixture

Commit `e7a3bdd`, following `dc79c4d`. Only graphs.mjs/graphs.css and two new dedicated tests changed. No product/runtime, DB, canonical ADR or shared UX register was changed.

G27 now has an expandable Project plan editor: dependency or membership; exact from/to IDs; explicit add/remove and reason; atomic cycle/self/duplicate/unknown-object refusal. Save creates a new local prototype revision. Source baseline and each successor retain their original membership/relations; historical selection disables writing. Membership progress counts distinct tasks, including completed tasks. Current task completion can update the current view without changing the plan relation snapshot. Running run/history pins are never changed.

The plan reads governance goals from `fixtures.goals`: array/object rows `{id, project, title, revision, criteria?, tasks?:[taskId], state?}`. `fixtures.tasks` retains project IDs. `fixtures.taskLinks` accepts `{project,from,to,rel:'needs'|'follows'|'blocks'|'depends-on',payload?,source?}` in prerequisite→dependent direction. Membership can also use goal.tasks, task.goal_id/goalRef, or link rel=membership (goal→task) / member-of (task→goal). An explicit goals field enables the source-driven plan even for Atlas; no old goal label is substituted.

Pass `options.graphPlanEdits=state.graphPlanEdits` to renderGraph. Persist the `onPlanChange(next,{project,revision,operation,error})` callback from attachGraphInteractions. The full store is replaced by `next`, not appended twice. UI state still uses onStateChange separately. Preserve `graphPlanRevision` in route keys.

Exports: `projectGraphState(input)` clones the store; `transitionGraphPlan(store,action,{project,fixtures,read,memberRole,actor,planRevision})` returns the next store with per-project revisions, operations, draft and error. Action shape `{type:'dependency'|'membership',from:taskId,to:taskId|goalId,operation:'add'|'remove',reason,payload?}`. Membership action is task→goal; the rendered relation is goal→task. An explicit `{type:'rebase',reason}` reconciles current source changes while preserving older snapshots. Its source signature is a deterministic fixture content comparison, explicitly not a security hash.

A governance goal or relation change after an edit is detected. The previous pinned plan is shown with a stale-source message until explicit rebase; no silent conflict resolution or discarded goal change. Parent owns obtaining current governanceStore fixtures and applying these callbacks to its integrated state. No new production policy or proposed ADR is accepted by the demonstration.
