## Decisions

- **UX-5, the count itself is left in SQL as it is.** The home's figure is `board_waiting_operator` (migration
  `20261021000120_board_core_holds.sql`), which counts open requests whose slot no session holds; the receipt's
  `noResponder` uses `board_responder_possible` (a holder or a listed `board.respond` capability). One definition needs
  a new migration (the function is SQL; the app receives only the number), which this branch does not write. The
  words now claim only what the count measures: no agent is answering now. One definition, together with data DA-1 (a
  lapsed lease counted as a holder, in the same three tests), is a migration: a board row, not this branch.
- **ER-2: a pid that is not known keeps the recency guard.** `agentAlive` is null without a pid (codex and kimi without
  one, a rejoin with no session file), and then the guard holds as before. `pidAlive` treats EPERM as not running (the
  hub's own rule); the agent runs as the same user as Fabric, so a reused pid of another user does not keep a dead
  agent's session.
- **ER-3: past the budget the log stops, it does not truncate.** Truncating in place would rewrite the file (ST-9's
  defect) and destroy evidence; stopping and counting keeps what is there and says how much was not written, once
  rotation works again.
