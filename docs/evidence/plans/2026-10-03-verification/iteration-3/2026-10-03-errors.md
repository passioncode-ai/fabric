## Findings, most severe first

1. **A scanned repository can still execute code in the main process, through a submodule's config** — boundary · blocking. A superproject with submodule `sub`, `filter.evil.clean=<script>` in `.git/modules/sub/config` and `* filter=evil` in its `info/attributes`, `sub/f.txt` stat-dirty: `gitRun(super, ['status','--porcelain=v1'])` ran the script. `repositoryDrivers` (`gitRun.ts:118-142`) neutralises only the superproject's drivers; `git status` spawns a child status per submodule. Reached through `repoState.ts:117` for every attached repository. No submodule test. Fix: `-c diff.ignoreSubmodules=all` or `--ignore-submodules=all` (both verified); a planted-submodule test.
2. **A kept-scan candidate admits any folder, including `/`, into every window's roots** — boundary · blocking. A recorded candidate replaced by a symlink to `/` and recorded as kept: `admitRepoPaths([foo])` and `admitRepoPaths(['/'])` both returned `['/']`. `ScanCandidates.record` re-runs realpath on stored strings at `startLastScan` (`index.ts:2958`); `parseStoredScan` checks only types; the fresh-scan record has the same gap. Fix: keep the walk's canonical path; admit only if `realpath === stored`, under the stored root, no symlink by `lstat`, `.git` exists; refuse filesystem roots and `$HOME`.
3. **The release gate can be passed without a real exit line** — harness · major. `release-mac.mjs` reads the gate and ledger from the working tree and checks cleanliness by `git status --porcelain`, which `--skip-worktree` defeats; the regex matches any line in the section (an early "none." followed by a blocking line clears; a single line with both clears); `gate.ledger` is not confined. Fix: `git show HEAD:<path>`; the exit line the last non-blank line with exactly one "Blocking findings open:"; the ledger under `docs/`.
4. **One hung suite in the full tier erases the verdict list** — harness · major. `run-test-chains.mjs` spawns with no per-link timeout; the outer with-timeout kills the whole group and the summary never prints.
5. **A few slow repositories stop the scan from listing healthy ones** — minor. Eight repositories with `include.path` at a FIFO plus one healthy: 30 s, truncated, the healthy one never listed. The driver probe's hard-coded 5 s ignores `GIT_TIMEOUT_MS`; inspection runs inside the walk, one at a time.
