# Iteration 2 — data, memory, orchestration and harness (whole project)

Independent reviewer, 2026-10-03, against `0ca25630..57f4080c`. Kept as written.

## Findings, most severe first

**1. Another estate can still overwrite hand-offs and heartbeats, and the documents say it can't** — data / orchestration · blocking.
- Migration 70's header says it covered "every `do update` keyed on a global id" and that `apply_heartbeats` "already carried the predicate". Neither is true: `apply_handoffs` (`20260905000027_chains.sql:59`) upserts on `(task_id, name)` with no estate predicate; `apply_heartbeats` (`20260909000040_agent_heartbeat.sql:66-79`) checks only `beat_seq` and sets `estate_id = excluded.estate_id`. `refuse_foreign_identity` checks neither event type.
- Probe on an owned cluster with 71 migrations: estate B's `task.handoff@1` naming A's task was accepted and A's row became "WRITTEN BY B"; B's `agent.heartbeat@1` naming A's session moved the row to estate B.
- `chainAdvance.ts` passes hand-off values into `fillBrief`, so B's text reaches the brief of an unattended agent in A.
- Fix: extend `refuse_foreign_identity` to both events; estate predicates on both upserts, never overwrite `estate_id`; cases in `estate-identity-db.test.mjs`.

**2. `ci.sh full` fails at HEAD, and the failures are recorded nowhere** — harness · blocking.
- `node scripts/test-stack.mjs run -- pnpm -r test` exits 1: P21 (`planted.test.mjs:876`) flags 11 tables made private on purpose in 63–66; P32 (`planted.test.mjs:1393`) expects the pre-62 refusal; `usage-observation.test.mjs:134` expects the quota reader to return null, which `8209d923` changed.
- Each package's test script chains with `&&`, so ~50 desktop suites never ran after the first failure. Run by hand on a disposable stack, the rest pass.
- Fix: P21 excludes `scope.ts`-private tables; P32 ends the run through managed stop; usage-observation expects `noReading`; run suites so one failure cannot hide the rest.

**3. File roots are read with one capped request and then reset** — data · major. `index.ts#refreshFileRoots` reads `project_repos` unpaged, then `fileRoots.reset(paths)`; past 1000 rows roots and git watching drop silently and vary. Fix: `selectAll` ordered by path, fail loudly on `failed`.

**4. Search labels come from a capped read with no error** — memory · major. `searchRead.ts#searchFor` reads `projects` unpaged; past 1000 a hit renders with a blank project and `labelProblem` stays null. Fix: `selectIn` on the ids in the hits.

**5. New journal scans every cycle with no index** — orchestration · major. `launchesExhausted` (two exact counts on `payload->>id` per waiting follower per minute), `contextDemandFor` and `admit_task_launch` (`payload->>session_id`) scan the estate's journal. Fix: partial expression indexes in migration 63's style.

**6. Foreign ids are journalled and then skipped in about 12 projector arms** — data · minor. `on conflict (id) do nothing` arms (agents, goals, routines, proposals, releases, questions, task runs, deliveries, retrievals). Fix: generalise `refuse_foreign_identity` to every create.

**7. The context requirement can refuse the person's own session** — memory · minor. On a failed journal read `contextDemandFor` returns the unattended sources; the `project` source counts as met with no row; the facts read has no limit, so `omittedFacts` is low past 1000. Fix: pass the trigger from the caller; require the project row; exact count.

**8. Smaller harness and orchestration gaps** — minor. `test-stack.mjs#chooseBase` port race between concurrent runs; the walk never removes its temp folders and kills the app without waiting; a throwing append in the chain launch-failure catch is not counted; `selectAll` pages by offset; one-agent-per-name is read-then-append with no constraint.
