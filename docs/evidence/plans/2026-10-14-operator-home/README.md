# Главная, проект и настройки: кто что делает — простым языком

Дата: 2026-10-14. Запрос оператора (по смыслу): на главной сразу видно основное — живые агенты и кто что делает
(клик открывает агента, его консоль, если она запущена в Fabric); доска — самое главное; сверху профиль и статистика
активности; проекты — сверху избранные, ниже по последней активности, и по каждому понятно, что это и какая
актуальная задача у агентов. Все задачи и подсказки харнеса — простым языком («делаем версию, в которой компьютер не
засыпает, пока работает агент, и выкатываем»). Открыв проект — откуда пришли и куда идём, пайплайн работ, доска,
вопросы ко мне, агенты на проекте. Плюс экран настроек (запрос Switchboard: каталог агентов, «не засыпать», режим
разрешений, отправка статистики, порядок резерва). Пройти по экранам и сценариям, спроектировать, делать волнами.

## Проверка видением

Антивидение (`docs/ux/vision.md` §6) запрещает «пульт множества чатов, где человек надзирает за сессиями». Запрос с ним
**согласуется**, если строить главную вокруг проектов, а не сессий: «кто что делает» — это **текущая задача проекта
словами агента**, живой агент — вход в его консоль и в его проект. Фраза видения «перестать управлять агентами по
одному и начать управлять проектами» сохраняется: агенты видны под проектами, первым — то, что требует решения.

## Целевой дизайн

### Главная (SCR-30)

1. **Верхняя полоса — профиль и активность**: аватар и имя Fabric, мини-ритм 28 дней (есть), три числа — агентов
   работает, задач в работе, ждут вас; клик — профиль и Пульс.
2. **Доска — главное**, три колонки по всем проектам:
   - **Нужно вам** — вопросы и обязательства (как сейчас), первым — самое важное;
   - **В работе** — заявленные задачи: что делаем (простым языком), какой агент, проект, этап N/M, сколько идёт;
   - **На проверке** — задачи в review.
3. **Живые агенты**: каждая работающая сессия — агент, проект, **что делает сейчас** (последний `stage` агента, иначе
   «работает над: <задача>»), последний сигнал, «застыл» при молчании. Клик — консоль, если Fabric её держит, иначе —
   проект. Ссылка «все агенты».
4. **Проекты**: сначала избранные (их ручной порядок сохраняется), затем остальные **по последней активности**.
   Карточка: имя, назначение одной строкой, **сейчас: <что делают агенты>** или «тихо с <даты>», живые агенты, ждут
   вас, на проверке.

### Проект (SCR-31)

Сверху вниз: заголовок (имя, назначение, **сейчас**), **Путь** (откуда: сделанное → сейчас: в работе → куда: цели и
следующие задачи плана), **Вопросы ко мне**, **Доска** (канбан backlog / в работе / проверка / готово — наверх),
**Агенты на проекте** (живые, «что делает», консоль), затем остальное («Все разделы»).

### Настройки (новый экран)

Группы: **Агенты** (агент по умолчанию — чипы; установленные: команда запуска, включён, по умолчанию, документация;
доступные к установке — из `switchboard --json agents status`, без Switchboard — своё обнаружение), **Запуск** (режим
разрешений, порядок резерва SCN-135), **Компьютер** («Не засыпать»: всегда / пока работают агенты / выкл.),
**Данные** (отправка статистики SCN-134).

### Простой язык — откуда берётся

- **Что делает агент сейчас** = последний `fabric_stage_report.stage` его сессии (+ `note`), иначе название задачи.
- **Что за задача** = `brief_what`, иначе `title`; **никогда** не `instruction` (это промпт).
- **Подсказки харнеса**: описание `fabric_stage_report.stage` и `fabric_task_brief` просит одно предложение для
  владельца проекта, на его языке, без внутренних терминов, с примером; правило `fabric_whoami` — сообщать этап
  простыми словами.

## Данные

Одно чтение главной `home.read` в main (только чтение, без миграций): сессии и заявки — из существующего
`work.estate` (SCR-78), этапы — из `agent_stages` по всему estate, сводки задач — `brief_what`/`title`, активность
проекта — `project_stats.last_activity_at`, ожидание и проверка — из доски и `attention`. Ошибка любого источника —
явная, никогда не «никто не работает».
