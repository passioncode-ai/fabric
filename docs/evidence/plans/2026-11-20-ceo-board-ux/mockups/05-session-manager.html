Под капотом: список читает switchboard --json sessions show и machines; «Продолжить» идёт через продолжение сессии Switchboard (MCP switchboard_session_continue), «Перенести» через switchboard --json dispatch --target; «Остановить» через ту же остановку, что в консоли (ADR-0160). Экраны «Сессии этого компьютера вне Fabric» и «Сессии Switchboard» на «Агентах» уходят сюда, второго списка нет.

Права в сессии: кто может писать и кто может остановить

  • Вы: всегда писать, остановить, продолжить, перенести.
  • CEO: писать и останавливать сессии этой машины (уже есть, SCN-183); на других машинах только через Switchboard dispatch.
  • Агент проекта: писать в свою сессию; чужие сессии только читать.
  • Права показываются в строке словами, меняются на странице сессии («Кто может писать»). Вход на другую машину остаётся за Switchboard (ssh), Fabric ключей не видит.

Что здесь решаем

Слова владельцаменеджер сессии… какие на этом компьютере, на другом, какие машины… связь, менеджинг прав, команды… свитчборд, сюда же можем допилить, как встроенный

Выбор

  1. Группировка по умолчанию: А) по машинам; Б) по проектам (переключатель есть в обоих).
  2. Где пункт «Сессии»: в нижнем списке колонки (как в макетах) или наверху рядом с «Создать».
  3. Перенос сессии: только между машинами, где уже есть папка проекта (рекомендуем), или с клонированием по запросу.
  4. Два старых блока на «Агентах» («вне Fabric», «Switchboard»): убрать сразу или оставить ссылкой на «Сессии» на один выпуск.

РекомендуемА, по машинам: отвечает на вопрос «где что идёт» и прямо показывает машину без связи. Пункт «Сессии» в нижнем списке. Перенос только туда, где есть папка. Старые блоки на «Агентах» заменить ссылкой на один выпуск.

Что меняетSCN-180 (все сессии в виду), SCN-183 (CEO управляет сессиями), новый сценарий «менеджер сессий по машинам».
