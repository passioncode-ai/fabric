## Not verified

  `comms.*` events in the archive, not `read-schema-db`, not the function-privilege suite. The instruction was not to
  touch the running stack, and I did not start a disposable one. The migration-81 checks above are by reading only.

    (`restore_estate_events`, migration 77). For an estate restored beside its source, the global key
    `board_requests.message_id` silently drops the restored rows (`on conflict do nothing`). This is harmless today,
    because a restored board keeps no messages (ADR-0117 §6).

  Hermes 0.21.4 does the same before its provider API was not checked. The recorded Hermes probe ran against a fake

  `served: 4`), not the real surface.
