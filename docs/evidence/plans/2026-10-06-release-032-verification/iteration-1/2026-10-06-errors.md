## Findings

| ID | Severity | Finding | Evidence | Suggested fix |
|---|---|---|---|---|
| ER-1 | **blocking** | **"Stopping an agent ends its whole process group" (CHANGELOG 0.3.2, ADR-0119 am. 3, fix-list A7-003) is false for a well-behaved agent.** The shell signals the agent's group only from timers that fire if the agent is *still alive* 3 s / 6 s after end of input. An agent that exits promptly on EOF — the normal ACP behaviour — is never group-signalled, so every tool process it started survives, reparented to launchd. The same happens on the ordinary Ctrl-D end. The SIGTERM test only checks the direct child (`s.child().exitCode`), and its `spawnAgent` is not even detached, so it cannot see a group. | `acpShell.ts:254-260` (`if (exited === undefined) { … setTimeout(() => proc.kill('SIGTERM'), KILL_GRACE_MS) … await agentExit; clearTimeout(term) … }`). Probe `scratchpad/i1/probe/run.sh` with `agent-with-child.mjs` (agent spawns `sleep 300`, exits on stdin close), shell started from `src/main/acpShellMain.ts`, then `kill -TERM <shell>`: `shell exit=143` / `ORPHAN: tool child 86162 still alive, ppid=    1`. Test gap: `test/acp-shell.test.mjs:185-192` and its `kill: (sig) => child.kill(sig)` at line 41. | After `agentExit` resolves (and on every return path of `end()`), always `proc.kill('SIGTERM')` the group (then SIGKILL after a short grace if `process.kill(-pgid, 0)` still succeeds) — a group outlives its leader. Extend the fixture to start a grandchild and make the test spawn detached with `process.kill(-pid)`, asserting the grandchild is gone. |
| ER-2 | non-blocking | **Fabric's own stop path bypasses the shell's escalation, and the shell has two more exits that skip it.** (a) The Stop UI offers *Force stop* on every agent stop (no provider adapter ⇒ always "Stop unverified"); force sends SIGKILL to the PTY group at sample 8 (≈0.8 s), before the shell's 3 s grace, and the detached agent is in a different group that `processBoundary` never signals. (b) `SIGINT` is only handled after the session opens, so Ctrl-C during `initialize` / the 15-min sign-in prompt kills the shell with the default handler (exit 130) and leaves the agent. Measured with the fixture agent in its "stubborn" mode (ignores EOF and SIGTERM). | (a) `nativeStopRuntime.ts` `unmanaged()` — escalation `Math.min(samples - 1, 8)` × `sampleIntervalMs` 100; `index.ts:872` passes no `provider`, so `nativeStopRuntime.ts:180-182` returns `outcome_unknown` for every non-shell agent; `SessionStop.tsx:66` shows Force on `outcome_unknown`. Probe `scratchpad/i1/probe/stop-probe.mjs` with `FAKE_ACP_STUBBORN=1 FORCE=1`: `SIGKILL: {"sent":true}` / `shell exit SIGKILL` / `after 7 s: agent alive = true ppid=1`. (b) `acpShellMain.ts:22` registers SIGINT only via `io.onInterrupt`, called at `acpShell.ts:332` after the session opened; probe `scratchpad/i1/probe/sigint.sh` (`FAKE_ACP_AUTH=1 FAKE_ACP_STUBBORN=1`, SIGINT at the sign-in prompt): `shell gone, exit=130` / `ORPHAN agent 41450 alive, ppid=    1`. | Register SIGINT at shell start (before `initialize`): before a session exists, treat it as `stop(130)`. Give the PTY stop a grace ≥ the shell's (or have the shell record the agent's pgid somewhere Fabric's stop can also signal it). |
| ER-3 | non-blocking | **The ACP shell crashes with an unhandled `EPIPE` when the agent dies before reading its input**, printing a raw Node stack instead of A7-005's "initialize failed (cause)" sentence, exit 1 instead of 2. Any later write to a dead agent (a permission answer, `session/cancel` from `end()` which is sent even when the agent already exited) takes the same path. No `'error'` listener exists on the agent's stdin. | `acpShell.ts:145` (`proc.stdin.write(...)` with no error handler), `acpShell.ts:252` (cancel sent regardless of `exited`). Probe: `node --experimental-strip-types src/main/acpShellMain.ts -- /usr/bin/true` 60 times → `exit2=58 crash=2`; crash output: `node:events:505 throw er; // Unhandled 'error' event … Error: write EPIPE … at send (…/acpShell.ts:145:54)`. | `proc.stdin.on('error', () => {})` (the exit/close path already reports the end) and skip writes when `exited !== undefined`; add a test with an agent that exits without reading (`process.exit(0)` as first statement already exists — run it with a large first frame or loop it). |
| ER-4 | non-blocking | **The redactor misses the ACP credential shapes this release introduced.** The A6-005 fix covers Kilo's `"Authorization": "Bearer …"` and `x-agw-key` *keys*, but not ACP's `{"name":"Authorization","value":"Bearer …"}` header form (session spec and `session/new`), the bridge's `FABRIC_BRIDGE_AUTHORIZATION=Bearer …` (`assignment` only matches names containing KEY/TOKEN/SECRET/PASSWORD/CREDENTIAL), or `{"name":"x-agw-key","value":"…"}`. An agent that logs its MCP config to stderr — printed raw to the PTY at `acpShell.ts:204` — puts the bearer in the transcript. "Removed from this process's environment" also does not hide it from `ps -E` (same user, e.g. the agent's own bash tool). | Probe `scratchpad/i1/probe/redact-probe.mjs` against `src/shared/redact.ts`: Kilo shapes `ok`; `LEAK FABRIC_ACP_SESSION={"http":{"headers":[{"name":"Authorization","value":"Bearer f3a1…"}]}}`, `LEAK {"name":"FABRIC_BRIDGE_AUTHORIZATION","value":"Bearer …"}`, `LEAK {"name":"x-agw-key","value":"…"}`, `LEAK FABRIC_BRIDGE_AUTHORIZATION=Bearer …`. `ps -E` probe: a var deleted with `delete process.env.X` → `visible in ps after delete`. Comments that overclaim: `mcpStdioBridgeMain.ts:13`, `acpShellMain.ts:15-17`. | Add a rule for `"name"\s*:\s*"(authorization|x-[^"]*(key|token|secret)[^"]*)"\s*,\s*"value"\s*:\s*"…"` and add `AUTHORIZATION` to the `assignment` name list; reword the two comments (the env copy is unset, the kernel's copy is not). |
| ER-5 | non-blocking | **No in-flight guard on save.** `base.current` advances only after the write returns, so a second Cmd+S (or a double click on "Keep mine and save") during a save sends the same content with the old hash; main's sync write order makes the second one a conflict against the person's own just-written text, and on the grant path spends a second overwrite grant and records a `failed_known` effect. Reasoned from code, not reproduced in a running app. | `EditorWindow.tsx:195` (compares with the stale `base.current`), `:202-207` (grant + write with `base.current.hash` / `conflict.currentHash`), `:221` (base updated after the await), `:389` (button not disabled while saving). | Hold a `saving` ref: ignore Cmd+S and disable both conflict actions while a save is in flight (or queue one follow-up save). |

Neither the boundary, `ops.rendererError`, the `uncaughtException`/`unhandledRejection` handlers nor `render-process-gone` is exercised by any test; only `listen()` is gated (`check-ops.mjs`, by source text). | `renderer/src/main.tsx` header comment vs. `grep -rn "unhandledrejection\|addEventListener('error'" src/renderer src/preload` → no output; `grep -rln "app.crash\|ErrorBoundary\|opsRendererError\|uncaughtException\|render-process-gone" src test scripts` → only source files and two native harnesses, no unit test. `index.ts:553-554`. | Add `window.addEventListener('error'…)` and `('unhandledrejection'…)` → `reportRendererError`; a vitest that throws in render and asserts the recovery screen + one `ops.rendererError` call. |

IPC sender wall (A7-002): `csp.test.mjs:55` checks only that `senderFrame?.url` appears in the source. | `test/mcp-stdio-bridge.test.mjs` (4 tests; none ends stdin); planted copy `scratchpad/i1/plant` + `probe/bridge-eof.mjs`: real bridge `exit after stdin end: 0 in 4 ms`, planted `exit … 13`. `index.ts:4170-4182` vs `src/shared/sessionHistory.test.ts`. `pty.ts#resize`, `TerminalView.tsx` doResize: `grep resize test/pty*.mjs` → only fakes. `test/files.test.mjs` A2-003 block. `test/csp.test.mjs:55`. | A stateful fixture (sessionIdGenerator) that records `DELETE`; a store-level test of the history query's order; a pty test that resizes after exit; a behavioural test of `handle()` with a fake `senderFrame.url`. |

## Sound

Each with its receipt; "plant" = a scratch copy with the fix reverted, run against the same test.

- **A4-001 binary files never written** — `files.ts:237-244` (`textOf`: NUL byte or fatal UTF-8 ⇒ null), `:288-299` (read-only, `text: false`, hash over bytes), `:341-342` (`not-text` refusal), `EditorWindow.tsx:104,186,331-335,397` (no Monaco, no Save, no recovery offer). BOM round-trips byte for byte (`files.test.mjs`). Plant `textOf → bytes.toString('utf8')` ⇒ `FAIL: a binary file opened as text`, exit 1. Untouched Cmd+S writes nothing (`EditorWindow.tsx:195`; vitest "Cmd+S on an untouched buffer writes nothing").
- **Deleted-while-open** — `files.ts:326-339`: absent file is a conflict, only `ABSENT_HASH` recreates it, with `wx` so a file that appeared meanwhile is not overwritten. Plant removing the absent check ⇒ `FAIL: a deleted file was not a conflict`.
- **A2-003 no write skips the compare** — `writeFile` has no `force` parameter; both call sites (`index.ts:3854`, `:3878`) pass none; `tsc` exit 0 on both configs.
- **A2-002 / A2-004** — the base lives in a ref (`EditorWindow.tsx:64-66`), Monaco is not re-created on save, and focus goes to the banner sentence (`:174`); covered by four new vitest cases that pass.
- **File-root boundary** unchanged and green (`file-roots.test.mjs`: traversal, sibling-prefix, link, firmlink cases all `ok`); the recovery flush and keep handlers resolve through the same roots (`index.ts:3826-3839`).
- **A6-001 turn without deadline** — `acpShell.ts:325` passes `null`; plant (default timeout) ⇒ `✖ a turn longer than the request deadline is not an error`. One prompt at a time is enforced by `if (turn) await turn` (`:344`).
- **A7-007 fresh line for a permission** — `acpShell.ts:220-221,232`; plant (`nextLine`) ⇒ `✖ a line typed during a turn stays a prompt`.
- **A7-003, SIGTERM path itself** — the handler is registered before `initialize` (`acpShell.ts:264`) and SIGTERM to a shell whose agent exits on EOF ends both with 143 (test + `stop-probe.mjs`: `shell exit 143`). Removing the handler makes the test hang rather than fail (no per-test timeout) — the CI tier's bounded run is what turns that red.
- **A6-007 bridge** — `mcpStdioBridge.ts:34-45`; plant (any error closes) ⇒ the relay test fails (`ℹ fail 1`). The bridge ends on agent EOF against the real fixture (`exit after stdin end: 0 in 4 ms`).
- **A6-004 / A6-006** — granted servers go only over HTTP and are named otherwise (`acpShell.ts:281-285`, test passes); a bundle-carried mode with no bundle is refused before spawn (`pty.ts:331-340`, `pty-launch-failure.test.mjs:92-99` passes). Credential never in argv (test asserts on `spawnargs`).
- **A6-005 Kilo shapes** — `redact-probe.mjs`: `KILO_CONFIG_CONTENT={…"Authorization":"Bearer [redacted: authorization]"}` and `"x-agw-key":"[redacted: header-credential]"`.
- **A7-002 window guard** — `index.ts:4520-4536`: `will-navigate` and `will-redirect` refuse anything but the app document, `setWindowOpenHandler` always denies and hands only http(s)/mailto to the browser; a malformed escape is refused rather than thrown (`navigationGuard.ts:32`, test 4/4). No WebContentsView/BrowserView/webview exists (`grep` → none), so the `getType() !== 'window'` early return exempts nothing today. Every `ipcMain.handle`/`ipcMain.on` in `src/main` is the wrapper's own (`grep ipcMain` outside `index.ts` → none; `check-ops` exit 0).
- **CSP** — the scratch build's `renderer/index.html` carries `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; … object-src 'none'; frame-src 'none'; base-uri 'none'; form-action 'none'`, no inline script, the entry is `./assets/index-*.js`; the bundle contains no `eval(` / `new Function(` (`grep -c` → 0); Monaco workers are separate `assets/*.worker-*.js` files loaded by `new Worker(new URL(…, import.meta.url))`. The renderer makes no network calls (`grep fetch( / WebSocket / EventSource / createClient(` in `src/renderer` → none; no `<iframe>`/remote `img src`).
- **A7-009 main side** — `listen()` records instead of throwing and checks the sender (`index.ts:219-231`); `terminalWrite`/`terminalResize`/`filesRecoveryFlush`/`opsRendererError` all go through it.
- **A2-001** — `pty.ts#resize` returns for an ended or unknown session; `TerminalView.tsx` does not send it (code read; see ER-7 for the missing test).
- **A4-003 digest paging** — `scopedStore.ts#selectAll`: stable order, exact count, a refused page is `failed` (never a short list), `maxRows` 50 000 ceiling, `page.length === 0` ends the loop. `digestRead.ts:82-103` uses it for all four reads and throws on `failed`; `digest-boundary.test.mjs` reads 2 500 rows past a 1 000-row cap.
- **A4-002** — `DigestSection.tsx`: refresh effect only reads; the acknowledge lives in a `[project.id]` effect cleanup and clears its ref; the component is keyed by project (`App.tsx:838`), so a slow read for a project just left cannot land in the next one. Vitest passes.
- **A5-001 + filter injection** — `index.ts:4171-4181`: the session id is UUID-checked before it enters the PostgREST `.or()` expression; newest 200 by `seq desc`, returned in order.
- **A7-001 stack exposure** — `stackExposure.ts`: every connect settles (connect / error / timeout destroy the socket), runs off the startup path (`void checkStackExposure`), failures recorded with a note, the log carries interface names not addresses. Live, read-only probe on this Mac: `exposed: en0:54321, en0:54322, bridge100:54321, bridge100:54322` in 6 ms, matching `lsof` (`OrbStack … TCP *:54321 (LISTEN)`). The Diagnostics warning will fire on the operator's machine today.
- **Helper resolution** — `helperProcess.ts`: built entry first, TS source second, refusal if neither (test 3/3); the scratch build emits `out/main/acp-shell.js` and `mcp-bridge.js` beside `index.js`.

## Not verified

- The renderer running under the CSP in a real window (Monaco workers, xterm, fonts): not launched — a second Fabric instance would contend with the operator's running app for the single-instance lock, hub port and stack. Only the built HTML and bundle were inspected.
- The helper programs from a packaged `.app` (Electron-as-Node reading `out/main/acp-shell.js` from inside `app.asar`, and an agent spawning the bridge with `ELECTRON_RUN_AS_NODE`): no packaged build was made.
- Real Hermes / Cline / Kilo behaviour on EOF, SIGTERM and `session/cancel` (all ACP findings use the repository's fixture agent or a scratch agent).
- `surface.terminateSession()` against Fabric's real (possibly stateful) agent surface, and whether it can hang the bridge when Fabric's main process is unresponsive (no timeout on that fetch).
- DB-backed suites (`agent-surface.test.mjs`, board/project DB tests): they require `node scripts/test-stack.mjs run` / `ci.sh full`, which start a disposable stack — not run under the read-only rule.
- Whether `ops.failed` inside the new `uncaughtException` handler can itself throw (disk full) and what Electron does then.
- Analytics (`analytics.ts`) network/timeout behaviour — outside this level's list.
