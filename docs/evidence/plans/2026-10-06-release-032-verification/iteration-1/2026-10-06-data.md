## Sound (checked, with receipts)

**Migration 81 privileges (P21).**
- RLS is enabled on all seven board tables (`:124-130`), and every API role, `service_role` included, has `revoke all` on them (`:133-134`).
- Access is only through `security definer` commands, granted to `service_role` alone (`:426-429`). Helpers, `apply_comms` and `board_append` are revoked from every role (`:422-425`), and `apply_projections` is revoked again (`:524`).
- No app code reads a board table directly: `grep "from('board_\|select('board_"` returns nothing. `TABLE_SCOPE` (`shared/scope.ts`) and `NOT_MIRRORED` (`shared/storageContract.ts`) mark all seven private and unmirrored. So "missing grant reads as empty table" cannot happen here; it is deliberate.

**Migration 81 writes and journal shape.**
- `comms.*` events can only come from the board commands. The `append_event` gate checks a same-transaction `board_write_authorizations` row with an equal payload (`:471-475`), and `board_append` deletes it after the append (`:159-161`).
- Restore inserts journal rows directly, not through `append_event` (`20260910000056_restore_estate.sql:70`, `…065:109`, `…077:535`), so the gate cannot refuse a restored board event.
- The projector is replay-safe: `ON CONFLICT DO NOTHING` (`:410-417`), and `rebuild_estate_projections` replays without clearing (`20260831000005_agent_surface.sql:151-161`).
- Primary rows are immutable by trigger (`:117-122`). The body is kept apart from the message so it can be redacted (`:63-70`). Every refusal runs before the first write (`:184-301`).
- Idempotency is taken under an advisory lock; the same digest returns the stored receipt and a different one returns `idempotency_conflict` (`:219-230`).
- The comms payload keys are not in `refuse_noncanonical_identity`'s list (`…080:17`), and its ids come from `gen_random_uuid` in canonical form.
- The archive's accepted versions gain `'79'` in `ceo_private_archive_canonical` (`:539`), and export uses `schema_version()` (`:630`). Migration 80 had the version list at exactly those two places (`…080:403, 494`).
- Schema contract 79/79 equals the 79 migration files.

**Board host.** Caller identity is closed over the session scope, never taken from the arguments (`agentSurface.ts`: `registerBoardTools(…, () => ({estateId: scope.estateId, projectId: scope.projectId, …}))`). Inputs are strict zod objects, so a forged `estate_id` is refused. The cursor is MAC-bound to estate, reader, thread and grant, with a timing-safe compare (`boardService.ts:109-119`). A failed read answers `not_available`, never an empty page (`:121-132, 199-201`). `board-service.test.mjs`: 8/8.

**A4-002, digest acknowledgement.**
- A refresh no longer acknowledges anything; leaving the digest acknowledges exactly the boundary on screen (`DigestSection.tsx` split effects, `displayed.current` cleared on leave).
- `ProjectHome` is keyed by project (`App.tsx:832-838`), so a late read for another project cannot land in this panel.
- `setMark` never moves backwards (`digestMark.ts`).
- The changed test asserts `seen` is not called on refresh. The pre-fix code called it, so the test would fail without the fix.

**A4-003, digest paging.** All four reads use `selectAll` with an exact count and a stable order (`digestRead.ts:82-100`), and a failed page throws (`:103`). The new test feeds 2500 rows through a fake capped at 1000 per answer and asserts row 2499 is present. The old unpaged read returned 1000, so the test would fail without the fix. Residual edge: DA-11.

**A5-001, session history.** The newest 200 events are shown in order (`index.ts:4176-4181`, `sessionHistory.ts`), and the full-window note is rendered and tested (`EstateAgents.test.tsx` "the agent history window"). The PostgREST `.or()` filter only takes a UUID-shaped id (`index.ts:243, 4172`; `/i` flag, anchored, no `m`). The missing test is DA-5.

**A1-001, refusals in the attention queue.**
- `openRefusals`: a refusal is resolved by a later grant or allow with the same class and target, in the same project or estate-wide. Repeats collapse into the newest item, dated from the first.
- A grant for another project, class or target, or an earlier grant, resolves nothing.
- `GrantAct` is disabled while busy, then shows "until …"; a failed grant offers the act again. 5 attention cases and 2 `ObligationActs` cases pass.
- The grant read has its own source receipt, so a failed read shows the queue as partial (`index.ts:2560`).
- The missing main-process test is DA-6.

**A3-001, board answers.** The answered row and its receipt stay in the detail after the re-read drops the question (`BoardScreen.tsx` `lastChosen` / `answeredHere`). The new test's re-read returns the list without the question, as the projection does, so the pre-fix `chosen = null` would fail it. Passes.

**A6-001 and A7-007, ACP turns and typed-ahead input.**
- `session/prompt` is sent with `timeoutMs: null` (`acpShell.ts:325`), and `initialize` / `session/new` keep their deadline.
- A permission question reads only fresh input (`freshLine`, `:220-221`). Lines typed ahead stay prompts and are sent in order after the turn.

- `answeredChoice` maps `y` to `allow_always` when only that is offered (A7-007's sub-case).

**A6-006, no bundle means no launch.** With no bundle, `config-content-env` and `acp-session` launches throw before spawn, journal nothing and list no session (`pty.ts`, A6-006 block). `compile` returns null before minting any credential when the surface is down.
