## 2. The events

|---|---|---|---|
| `task.ranked@1` | `task_id`, `rank` (a finite number, lower first) | the person | `project_tasks.rank`; clears `rank_proposal`. Ignored when the actor is not a person |
| `task.rank.proposed@1` | `task_id`, `after_task_id` (null: first), `why` | an agent | `project_tasks.rank_proposal` `{after_task_id, why, by, by_kind, at, seq}`. Ignored when the actor is a person |

A payload the journal accepted never makes the projector raise (ADR-0014): a rank that is not a number, or an id that
is not a UUID, changes nothing. `task.prioritised@1`, `goal_id` and `position` (order inside a goal, the Plan screen)
are untouched. The payloads are declared at the command door (`apps/desktop/src/shared/commandIngress.ts`).

## 3. The order

`apps/desktop/src/shared/taskRank.ts#orderQueue`, pure. Input: the open tasks (`backlog`, `running`, `review`) with
their ranks and filing order, and the links with rel `blocks` (the link's task is the prerequisite of its target) and
`follows` (the target is the prerequisite of the link's task). Output: the queued tasks in order, each with why.

The walk is topological and picks by priority, so a prerequisite in the queue always stands before what waits for it.
Among the tasks that may come next, in this order:

1. ready before blocked (a task with an open prerequisite cannot be worked now);
2. the owner's rank, the task's own or inherited from anything that waits for it, through any number of steps;
3. on the critical path, the longest chain of open tasks, before off it;
4. the longer chain behind it;
5. the more tasks it unblocks;
6. filed earlier.

A closed or unknown prerequisite blocks nothing. A task in work or in review counts as an open prerequisite and is
never placed. A cycle that reached the tables despite the write door still gives every task one place. The owner's
rank beats the critical path: he moves, and the walk makes his order workable by pulling up what his task waits for.

## 4. The readers

`apps/desktop/src/main/taskOrderRead.ts#readQueueOrder` reads the open tasks (newest 2 000) and the dependency links
(newest 5 000), reads by id the status of a linked task outside the read, and answers each queued task's place in its
own project. A read at its bound is named in `capped`; a failed read throws.

| Reader | What changed | When the order cannot be read |
|---|---|---|
| The Board's kanban (`workRead.ts#readTaskBoard`, `taskBoard.ts#composeTaskBoard`) | «Очередь» in order; the tasks the owner placed are read on their own (100, lowest rank first) beside the newest 100, so the cap never hides one; each card carries `order` and an open `proposal` | the queue is shown newest first and the column says so (`orderUnread`) |
| The backlog routine (`routineTick.ts`, `backlogBrief.ts#backlogBrief`) | the brief lists tasks in the board's order and names one that waits | falls back to the order inside goals and says so in the brief |
| `fabric_work_list` (`workTools.ts`) | the first 15 queued tasks by place come before the newest open ones; each queued task carries `order {place, ready, waits_for, unblocks, critical_path, placed_by_owner}` | `queue_order {read: false, why}`, tasks newest first |

With every project in the column, the first task of each project comes before any project's second; the owner orders
inside one project's board.

## 5. The writes

- `tasks.reorder(taskId, afterTaskId | null)` (`apps/desktop/src/main/taskRankWrite.ts#reorderTask`): the order is
  read fresh in the main process, `taskRank.ts#rankWrites` computes the ranks, and each is appended as the person's
  `task.ranked@1`. A move between placed tasks is one event. A drop under unplaced tasks pins them too, so the list
  the owner arranged is the list he gets. A rank above the drop point that already fits is not written. A gap that
  ran out of numbers respaces the list. Refused: a task not in the queue, a task of another project, a queue that
  changed under the move.
- `tasks.rankProposal(taskId, accept)` (`taskRankWrite.ts#decideRankProposal`): accepting moves the task where the
  proposal said and always writes its own `task.ranked@1`, which clears the proposal; declining writes
  `task.rank.declined@1`. A proposal whose anchor left the queue can only be declined.
- `fabric_task_rank_propose {taskId, afterTaskId?, why}` (`taskTools.ts`): an agent proposes; it cannot place. Only a
  queued task of its own project, after a queued task of the same project.

## 6. The screen

The Board's kanban (SCN-173), `apps/desktop/src/renderer/src/launch/KanbanBoard.tsx`. «Очередь» says how it is ordered.
A card says why it stands where it does: «Критический путь», «Ждёт задач: N», «Её ждут задач: N», «Место задали вы»,
«Поднята: её ждёт задача, которую поставили вы». On one project's board the owner drags a card onto another (it takes
that card's place) or presses «Выше» and «Ниже»; one act at a time, a failed one is said. An agent's proposal shows
under the card with its why, «Принять» and «Отклонить». Strings in `en.ts` and `ru.ts`, checked with the copy checker
(reports `71315a57` to `dfc9059d` for en, `4605cae9` to `00dfef2e` for ru: no blocking finding).

## 7. Decisions the agent took (tactics, ADR-0205)

| Question | Decision | Why |
|---|---|---|
| Does the owner's rank or the critical path win? | The rank, inherited by prerequisites | «двигает владелец»; the critical path orders everything he did not place, and what he placed pulls its prerequisites up |
| Rank per project or per goal? | Per project | the research's recommendation; `position` per goal ties between goals |
| Store the computed order? | No, compute on read | one function, no second truth to drift (ADR-0014, ADR-0035) |
| Who may propose? | Any agent of the project, the CEO among them | the projector cannot tell the CEO's session from another agent's; the owner decides either way |
| A drop among unplaced tasks | Pin the tasks above it | otherwise the task lands elsewhere than where he dropped it |
| Agents and the owner's order | The projector ignores a rank not written by a person | enforced where it cannot be bypassed by a tool |
